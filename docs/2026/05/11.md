# 2026年05月11日

## [General] Claude Platform on AWS is now generally available

- **公開日**: 2026-05-11 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/05/claude-platform-aws/

### 概要

Claude Platform on AWS が一般提供（GA）になりました。Anthropic が提供するネイティブな Claude Platform（API、コンソール、早期アクセス機能）へ既存の AWS アカウントで直接アクセスできるようになります。

### 変更内容・新機能の詳細

本サービスは AWS 上で動作する Anthropic のネイティブな Claude Platform を AWS アカウント経由で利用可能にするもので、AWS が初めてネイティブ体験を提供するクラウドプロバイダーとなります。運用は Anthropic が行い、顧客データは AWS のセキュリティ境界外で処理されますが、アクセス制御は既存の AWS IAM を用い、請求は統合された AWS 請求で行え、CloudTrail による監査ログも取得できます。提供される機能には Claude Managed Agents（beta）、advisor strategy（beta）、web search、web fetch、code execution、files API（beta）、Skills（beta）、MCP connector（beta）、prompt caching、citations、batch processing、および Claude Console（プロンプト開発・評価用）などが含まれます。ターゲットは開発チームやエンタープライズで、特に地域的なデータ居住要件（data residency）を厳格に求めないユースケース向けです。サービスは複数のリージョンで利用可能になっており（例：米国東部（バージニア・オハイオ）、米国西部（オレゴン）、カナダ中央、南米（サンパウロ）、欧州（ダブリン・ロンドン・フランクフルト・ミラノ・チューリッヒ・パリ・ストックホルム）、アジア太平洋（東京・ソウル・メルボルン・ジャカルタ・シドニー）など）、詳細は製品ページ／ドキュメントで最新情報を確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 開発者、MLエンジニア、プロダクトチーム、エンタープライズ（特にAnthropicのネイティブ体験を既存AWSアカウントで使いたい組織）
- **利用シーン**: プロンプト開発・評価、エージェント（Managed Agents）を使ったワークフロー構築、外部検索やWebフェッチを組み込んだアプリケーション、コード実行やファイル操作を含む生成系ワークロード、バッチ処理による大量推論
- **運用効果**: AWS の既存IAM・請求・CloudTrail と統合されるため、アカウント管理や監査が簡素化され、別アカウント・別請求の管理コストを削減できる。ベータ機能により迅速な実験・イノベーションが可能
- **制約・注意点**: 顧客データは Anthropic 側で処理される（AWS のセキュリティ境界外）ため、データ居住性や厳格な法規制対応が必要なケースでは利用に制約がある
- **利用可能リージョン**: 記事公開時点で複数リージョンに展開（例：US East (N. Virginia), US East (Ohio), US West (Oregon), Canada (Central), South America (São Paulo), Europe (Dublin, London, Frankfurt, Milan, Zurich, Paris, Stockholm), Asia Pacific (Tokyo, Seoul, Melbourne, Jakarta, Sydney)）。最新の対応リージョンは公式ページで確認してください。

### 技術的な注意点

- **IAM権限**: 既存のAWS IAM資格情報でアクセス可能。ただしClaude Platform上の操作に必要な権限やロールを事前に確認・付与する必要あり
- **データ保護／セキュリティ境界**: サービスは Anthropic により運用され、顧客データは AWS のセキュリティ境界外で処理されます。データの保存・利用・暗号化方針、契約（DPA）やログ保持ポリシーを Anthropic 側ドキュメントで必ず確認してください
- **CloudTrail／監査**: CloudTrail によるアクセス監査は提供されますが、収集されるイベントの詳細や保持期間は仕様を確認してください
- **リージョン制限**: 一部リージョンでの提供。データ居住性や法規制要件がある場合は未対応のリージョンが影響するため要確認
- **ベータ機能**: 多数の機能が beta 表示のため、APIや挙動が変更される可能性がある点に留意
- **コスト**: Anthropic の利用料金と AWS 上での統合請求が発生します。料金モデル（APIコール、機能別の課金等）やネットワーク転送料を事前に確認してください
- **互換性・API**: ネイティブ Claude API／コンソールが提供されるため、Anthropic のドキュメントに沿った実装が必要。既存のAWS AIサービス（SageMaker等）との直接互換性は保証されないため統合設計時に検討が必要
- **運用分担**: サービス運用は Anthropic 側が担当するため、インシデント時の対応フロー（SLA、サポート窓口）を事前に確認すること
- **注意点がない場合**: 特になし

## [General] AWS Transform adds containerization capability during migrations

- **公開日**: 2026-05-11 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/05/aws-transform-containerization/

### 概要

AWS Transformは、移行中にアプリケーションをコンテナ化（replatform to containers）できる機能を追加しました。ソースコード解析からDockerイメージ作成、ECRへの公開、ECS/EKSへのデプロイ用アーティファクト生成までを自動化します。

### 変更内容・新機能の詳細

新機能はAWS Transformのエージェント的AI機能を拡張し、GitHub/Bitbucket/GitLabや.zipファイルのソースリポジトリを解析してDockerfileを生成、コンテナイメージをビルドします。ビルド時に一般的な脆弱性（CVE）に対するセキュリティスキャンを統合し、生成物としてAmazon ECRへプッシュ可能なコンテナイメージ、TerraformのInfrastructure-as-Code、及びHelmチャートを出力します。出力物はそのままAmazon ECSまたはAmazon EKSへデプロイできる構成になっており、モノリポ（monorepo）や複数リポジトリ構成をサポート、AWS CodeArtifactを使ったプライベート依存関係の解決も可能です。数千アプリケーション規模でのコンテナ化を想定したスケーラビリティを持ち、移行計画（migration wave）時に各アプリを「リホスト」か「コンテナ化によるリプラットフォーム」へ割り当てることで、モダナイゼーションと移行を並行して進められます。新機能はAWS Transformが提供されるリージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド移行チーム、SRE／プラットフォームエンジニア、アプリケーション開発者
- **利用シーンまたは効果**: オンプレ／VMベースからクラウドネイティブ（コンテナ）への移行を同時に進め、移行期間の短縮とアプリ近代化を実現
- **運用効果**: 手作業でのDockerfile作成やイメージビルド、デプロイ用テンプレート作成の工数削減により移行速度と品質が向上
- **スケール影響**: 数千アプリ規模の一括コンテナ化をサポートするため、大規模移行プロジェクトでの効率化が期待できる

### 技術的な注意点

- **IAM権限**: ソースリポジトリ（GitHub等）への読み取り、ECRへのプッシュ、ECS/EKSやTerraformによるリソース作成に必要なIAM権限が必要です（サービスロール／連携トークンの準備を推奨）
- **リポジトリ認証**: プライベートリポジトリやサブモジュールへのアクセスにはPATやSSHキー等の認証情報が必要です。資格情報の安全な取り扱いを確認してください
- **CodeArtifact/依存解決**: プライベート依存関係を解決する場合、CodeArtifact レポジトリ設定および認可が必要です
- **出力アーティファクト**: 生成されるDockerfile、Terraform、Helmチャートは自動生成品のため、セキュリティ・運用要件や命名規約に合わせてレビュー／カスタマイズが必要です
- **セキュリティスキャン**: 組み込まれたCVEスキャンは一般的な脆弱性検出を行いますが、組織のコンプライアンス基準に合わせた追加スキャンやSBOM生成を検討してください
- **コスト**: AWS Transformの利用料金（該当する場合）、ECRストレージ・データ転送、ECRのイメージスキャン、ECS/EKSクラスタ運用、CodeArtifactの利用料金など追加コストが発生します。規模に応じた見積りを行ってください
- **リージョン制限**: 記事によればAWS Transformが提供される全リージョンで利用可能ですが、アカウントや組織ごとのサービス有効化状況を事前に確認してください
- **モノレポ対応**: モノリポの場合、アプリやサービスの分離（フォルダ単位の抽出）や起動順序、共有ライブラリの扱いに注意が必要です
