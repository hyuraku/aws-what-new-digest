## [Neptune] Amazon Neptune Analytics is now available in 7 additional regions

- **公開日**: 2026-02-10 (JST)
- **カテゴリ**: Neptune
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/02/amazon-neptune-analytics-in-seven-additional-regions

### 概要

Amazon Neptune Analytics（Neptuneのグラフ分析機能）が新たに7つのリージョン（バーレーン、UAE、イスラエル、ケープタウン、カルガリー、マレーシア、チューリッヒ）で利用可能になりました。これにより、これらのリージョンで直接グラフを作成・管理し、高度なグラフ分析を実行できます。

### 変更内容・新機能の詳細

今回の拡張で、Amazon Neptune Analyticsを中東（バーレーン・UAE）、イスラエル（テルアビブ）、アフリカ（ケープタウン）、カナダ（カルガリー）、アジア太平洋（マレーシア）、欧州（チューリッヒ）リージョンで利用可能になりました。Neptuneはサーバーレスのグラフデータベースで、グラフワークロードに対して瞬時にスケールし、容量管理の手間を排除します。データをノードとエッジのグラフとしてモデル化することで、生成系AIの精度や説明性を向上させるコンテキストを保持できます。NeptuneはGraphRAGによるAmazon Bedrock Knowledge Basesとのフルマネージド統合や、Strands AI Agents SDK、一般的なエージェント記憶（agentic memory）ツールとの連携をサポートし、AIアプリケーション開発を容易にします。また、構造化／非構造化データ間で数十億件規模の関係性を数秒で解析できるパフォーマンスを提供します。新リージョンでの利用開始はAWS Management ConsoleまたはAWS CLIから新しいNeptune Analyticsグラフを作成することで行えます。料金やリージョン対応状況の詳細はNeptuneの料金ページおよびAWSリージョン表を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: グラフデータを扱うアプリケーション開発者、生成系AI開発者、データサイエンティスト、SRE/運用チーム
- **利用シーン**: ローカル規制やデータ主権要件があるワークロードのために近接リージョンでグラフ分析を実行／AI知識ベース（GraphRAG）を構築する場面、数十億件規模の関係探索やパターン検出、詐欺検出や推奨エンジン、ナレッジグラフの構築
- **運用効果**: リージョン追加によりレイテンシ低下とデータ主権対応が改善され、サーバーレスによる自動スケーリングで容量管理負荷と運用コストを削減可能

### 技術的な注意点

- **IAM権限**: Neptune Analyticsの操作には適切なIAMポリシー（Neptuneと関連リソースの作成・管理権限）が必要です。Bedrockや他サービス連携時は追加のサービス権限が求められます
- **リージョン制限**: 本アップデートで7リージョンが追加されましたが、すべてのリージョンで未だ利用できない機能やAPIの差分が存在する可能性があります。利用前に対象リージョンのサービス提供状況を確認してください
- **ネットワーク/接続**: Neptuneは通常VPC上で動作します。VPC設定、サブネット、セキュリティグループ、必要に応じてVPCエンドポイントやトラフィックルーティングを事前に構成してください
- **データ移行/レプリケーション**: 既存のNeptuneクラスタや他データソースから新リージョンへデータを移行する場合は、スナップショットのクロスリージョンコピーやETLを利用する必要があります（自動的なクロスリージョン同期は想定しない）
- **コスト**: サーバーレスの利点はあるものの、クエリ実行・ストレージ・データ転送に基づく課金があります。大量データの解析や頻繁なクロスリージョン転送はコスト増につながるため料金ページで見積もりしてください
- **互換性/統合**: GraphRAGやBedrock連携、Strands AI Agents SDKなどの機能を利用する場合、対象リージョンでこれらの連携サービスが利用可能かを確認してください
- **CLI/コンソール**: グラフ作成はAWS Management ConsoleまたはAWS CLIで行えます。自動化する場合はCLI/SDKの最新バージョンを使用してください

## [Health] AWS HealthOmics introduces a Kiro Power and Kiro IDE extension for bioinformatics workflow development

- **公開日**: 2026-02-10 (JST)
- **カテゴリ**: Health
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-healthomics-introduces-kiro-plugin-for-bioinformatics-workflow-development/

### 概要

AWS HealthOmics が Kiro Power（Model Context Protocol を含むパッケージ）と Kiro IDE 拡張を提供開始しました。AIエージェント支援で Nextflow/WDL などのバイオインフォマティクスワークフローの作成・実行・デバッグ・最適化を高速化します。

### 変更内容・新機能の詳細

本アップデートは二つの要素から成ります。1) Kiro Power for HealthOmics: HealthOmics 用にキュレーションされた MCP（Model Context Protocol）サーバ、steering ファイル、エージェントフックをパッケージ化したリポジトリで、Kiro エージェントに HealthOmics ワークフロー作成・最適化のドメイン知識を与えます。これによりワークフロー生成やエンジン設定（例: Nextflow / WDL 対応）のガイダンスをエージェントに任せられます。2) HealthOmics Kiro IDE 拡張: Kiro IDE（Open VSX 経由で入手可能）向けにシンタックスハイライト、コード補完、トラブルシューティングガイダンス、HealthOmics エンジン互換性チェック、パフォーマンス最適化の推奨、実行結果の自動解析および失敗診断、ワークフローのインポート/エクスポートなど開発生産性を高める機能を提供します。AWS HealthOmics は HIPAA 対応が可能なフルマネージドサービスであり、本拡張はローカル開発環境とクラウド上の HealthOmics 実行環境間のワークフロー移行と最適化を支援します。導入は Kiro の配布ページ（https://kiro.dev/powers/）から Kiro Power を取得し、Open VSX Registry 経由で Kiro IDE 拡張をインストールすることで開始できます。

### 影響範囲・利用シーン

- **対象ユーザー**: バイオインフォマティクス研究者、パイプライン開発者、クラウドエンジニア、SRE/運用チーム
- **利用シーン**: Nextflow/WDL ベースのパイプライン開発、HealthOmics 上での実行・デバッグ・性能チューニング、既存ワークフローの移行と最適化
- **運用効果**: 開発サイクルの短縮（AIエージェントによるテンプレート生成・修正支援）、障害診断の効率化、自動的なエンジン互換性チェックと最適化提案による運用負荷低減

### 技術的な注意点

- **IAM権限**: HealthOmics を操作するための AWS IAM 権限（HealthOmics の実行、S3 アクセス、CloudWatch ログなど）が必要です。Kiro 側は別途アクセス制御を確認してください。
- **リージョン制限**: HealthOmics の提供リージョン制限に注意してください。HIPAA 対応やサービス可用性はリージョンごとに異なるため事前確認が必要です。
- **コスト**: HealthOmics の実行（ジョブ実行時間、ストレージ、データ転送等）に応じた通常の AWS 課金が発生します。Kiro の配布や外部ツールに追加コスト／ライセンスが発生する場合があるため確認してください。
- **データ保護・コンプライアンス**: HealthOmics は HIPAA 対応可能ですが、Kiro（ローカル IDE/外部サービス）を利用する際は PHI/機密データの取り扱い・送信先に注意し、ログやデバッグ情報が外部に渡らないよう設計・設定してください。
- **ネットワーク要件**: Kiro Power のダウンロードや MCP サーバとのやり取り、拡張機能の更新等にインターネット接続が必要です。企業ネットワークではプロキシやアウトバウンド制限の確認が必要です。
- **互換性**: Nextflow や WDL のバージョン差異に依存する部分があります。HealthOmics エンジン互換性チェック機能を利用してバージョン・ランタイム要件を確認してください。
- **セキュリティ**: Kiro エージェントが外部の MCP やテンプレートを取得する場合、サプライチェーンリスク（改ざんや不正コード）を考慮し、信頼できる Power のみ利用するなど対策してください。

## [Redshift] Amazon Redshift now supports allocating extra compute for automatic optimizations

- **公開日**: 2026-02-10 (JST)
- **カテゴリ**: Redshift
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/02/amazon-redshift-allocate-extra-compute-for-automatic-optimizations

### 概要

Amazon Redshiftが自動最適化（autonomics）向けに追加のコンピュートを割り当てられるようになりました。これにより、ユーザーワークロードが高負荷のときでもATO/ATS/Auto Vacuum/Auto Analyzeなどの自動最適化を安定して実行できます。

### 変更内容・新機能の詳細

データベース管理者はクラスタ（プロビジョンド）やワークグループ（Serverless）に対して、自動最適化で利用するための追加コンピュートリソースを割り当てられるようになりました。割り当てた追加リソースは、ユーザーのクエリ処理に影響を与えずにAutomatic Table Optimization (ATO)、Automatic Table Sorting (ATS)、Auto Vacuum、Auto Analyzeなどの自動メンテナンス処理（autonomics）で使用されます。プロビジョンドクラスタ向けには、autonomicsが利用できるリソース量を制限するコストコントロール機能が提供され、最小／最大の利用量を設定して意図しない追加料金を抑制できます。さらに、SYS_AUTOMATIC_OPTIMIZATIONというシステムテーブルが新設され、autonomicsの実行履歴・ステータス・影響テーブルなど詳細な可観測性情報をプロビジョンドクラスタとServerlessワークグループの両方で取得可能になりました。機能はAmazon Redshiftがサポートされているすべてのリージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者（DBA）、SRE、データエンジニア
- **利用シーン**: 大規模/ピーク時トラフィックのある本番クラスターで、手動スケジュールを不要にして自動最適化を継続実行したいケース
- **運用効果**: 自動最適化がユーザークエリを邪魔せず安定稼働することで性能劣化や手動メンテナンス作業の削減、運用負荷と人的ミスの低減が期待できる

### 技術的な注意点

- **IAM権限**: クラスタ設定を変更するためにRedshift管理権限（例: redshift:ModifyCluster 等）や該当ワークグループの管理権限が必要です。SYS_AUTOMATIC_OPTIMIZATIONを参照するにはデータベース内での読み取り権限も必要です。
- **リージョン制限**: Amazon Redshiftがサポートする全リージョンで利用可能とされています（記事時点）。
- **コスト**: 追加コンピュートはリソース消費に応じた料金が発生する可能性があります。プロビジョンドクラスタ向けのコスト制限機能で上限は設定できますが、割当による課金影響を事前に見積もってください。
- **SYS_AUTOMATIC_OPTIMIZATION**: 新しいシステムテーブルはautonomicsの実行状況や対象オブジェクト、実行時間などを出力します。監査・アラート化や運用ダッシュボードに組み込む際はクエリ権限とスキーマの扱いに注意してください。
- **互換性/影響**: 追加コンピュートは自動最適化用に確保されるため、通常のクエリ負荷への直接的な干渉は減りますが、リソース割当量の不適切な設定はコスト増やリソース競合を招くため、段階的に適用・監視することを推奨します。
