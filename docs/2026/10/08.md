## [General] AWS Capabilities by Region now offers availability notifications for individual features and advanced filters

- **公開日**: 2026-10-08 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/awscapabilities-enhancements/

### 概要

AWS Builder Centerの「AWS Capabilities by Region」が、サービス内の個別機能単位での提供状況通知と、API操作／CloudFormationリソースに対する高度なフィルタ／リージョン比較機能を追加しました。通知はアプリ内および週次のメールダイジェストで受け取れます。

### 変更内容・新機能の詳細

主な追加機能は以下の通りです。

- 機能レベルの提供通知: サービス単位だけでなく、サービス内の個別機能（feature）単位で特定リージョンの可用性通知を設定可能。サービスに対する通知はそのサービス配下の全機能をカバーします。"All regions"オプションで今後追加されるリージョンも含めて一括購読できます。通知はインアプリ（Builder Center内）と週次メールダイジェストで届きます。

- 高度なフィルタ: 19,000以上のAPI操作と5,000超のCloudFormationリソースタイプを対象に、"availability status"（利用可／未提供など）でフィルタリング可能。これにより長大な一覧を素早く絞り込み、特定のリージョン間の差分把握が容易になります。

- リージョン比較機能: アカウント不要でリージョン同士を比較でき、全ての機能を表示／一致する機能のみ／差分のみ　といった表示切替が可能。検索や既存の表示設定と組み合わせて利用できます。

- 要件: リージョン比較はアカウント不要で利用可能。提供状況通知の設定には無料のBuilder IDが必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドアーキテクト、SRE、DevOpsエンジニア、プラットフォーム／SaaS事業者、インフラ自動化（IaC）担当者
- **利用シーン**: 新リージョン展開の計画、CloudFormationテンプレートやSDK利用時のAPI互換性確認、リージョン間のサービス差分確認、特定機能の提供開始監視
- **運用効果**: リージョン差分の迅速な把握によりデプロイ計画とガバナンスが改善され、機能提供開始の自動通知でリリース対応やコスト最適化の意思決定が早まる

### 技術的な注意点

- **Builder ID**: 提供状況通知を設定するには無料のBuilder IDが必要です（リージョン比較のみはアカウント不要）。
- **IAM権限**: 比較表示自体はアカウント不要だが、Builder Centerへログインして通知を設定する場合は該当アカウント／認証方法でのアクセス権（組織のSSOポリシー等）を確認してください。特別なIAM API権限は不要ですが、通知先メールやアカウントの管理権限は必要となる場合があります。
- **リージョン制限**: データはリージョン別の提供状況に基づきます。"All regions"オプションは将来のリージョンもカバーしますが、個別機能の情報は一部リージョンで遅延や差分が生じる可能性があります。
- **コスト**: Builder IDや通知機能自体に追加料金は発生しません。ただし、通知を受けて実際にAWSリソースを利用／試験する場合は通常のサービス利用料金が発生します。
- **データ更新頻度**: 週次ダイジェストが提供されますが、表示中の一覧は更新タイミングの差により最新状態と若干ずれることがあります。重要な判断は公式リリースや各サービスのドキュメントで最終確認してください。

## [Config] AWS Config now supports 77 new resource types

- **公開日**: 2026-10-08 (JST)
- **カテゴリ**: Config
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-config-new-resource-types

### 概要

AWS Config が 77 種類のリソースタイプを新たにサポートしました。これにより、より広範なリソースの検出・評価・監査・自動修復が可能になります（記録を「すべてのリソースタイプ」にしている場合は自動的に追跡されます）。

### 変更内容・新機能の詳細

今回の追加は Amazon EC2、Amazon S3 Files、Amazon Q Business を含む主要サービスにまたがる 77 の AWS::... 形式のリソースタイプを対象としています（記事にリストされた CloudFormation リソースタイプ名を参照）。技術的には、これらのリソースは AWS Config の設定項目（configuration items）として記録され、Config Rules の評価対象および Config Aggregator によるクロスアカウント／クロスリージョン集約の対象になります。既に「すべてのリソースタイプ」での記録を有効にしている場合は追加作業なしで追跡が始まりますが、特定リソースのみを記録している環境では設定の更新が必要です。新しくサポートされた代表例には AWS::EC2::VPCCidrBlock、AWS::S3Files::FileSystem／AccessPoint、AWS::QBusiness::Index／DataSource、AWS::APS::AnomalyDetector、AWS::LicenseManager::License などが含まれます。これらを利用することで、リソースの変更履歴、コンプライアンス判定、ドリフト検知、自動修復ワークフロー（AWS Systems Manager、Lambda 等との連携）をより幅広いリソースに対して実行できます。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティ／コンプライアンス担当、クラウド運用（SRE/DevOps）、ガバナンスチーム、アーキテクト
- **利用シーンまたは効果**: 追加されたリソースタイプの構成変更や状態を追跡できるため、コンプライアンスチェック、インシデント調査、変更監査、リスク評価、自治的な自動修復ルールの適用が可能
- **運用効果**: リソースカバレッジの拡大により監視漏れが減り、ポリシー違反や設定ドリフトの早期検出、クロスアカウント集約による一元監査が容易になる

### 技術的な注意点

- **IAM権限**: Config の記録／集約を操作する権限（例: config:PutConfigurationRecorder, config:PutDeliveryChannel, config:StartConfigurationRecorder, config:CreateConfigurationAggregator, config:PutAggregationAuthorization）および該当サービスの読み取り権限が必要です
- **リージョン制限**: 記事記載のとおり「リソースが利用可能なすべての AWS リージョン」でサポートされます。各リソースはそのサービスの提供リージョンに依存するため、リージョンごとの可用性を確認してください
- **コスト**: 記録される構成アイテム数および Config Rules の評価回数が増えるため、AWS Config の課金（記録アイテム単価、ルール評価単価、アグリゲータ料金など）に影響します。事前に現在の記録設定と見積りを確認してください（Config の料金ページ参照）
- **既存ルール／自動修復**: Managed Rule やカスタムルールで新リソースを扱う場合、ルールのリソース指定（ResourceTypes）や Lambda 関数のロジックを更新する必要がある場合があります。新しいリソースタイプは既存のルール条件に自動的に含まれないことがあるため確認が必要です
- **有効化手順**: もし「すべてのリソースタイプ」を有効にしていない場合は、Configuration Recorder の設定で記録対象に追加するか再設定してください。また、Config Aggregator で集約する場合はアグリゲータの設定・権限を確認してください
- **データ量／保持**: 新たなリソースの記録は S3 への配信量や保持データ量を増やします。ライフサイクルポリシーや履歴保存期間を見直してコストと運用負荷を管理してください
