## [Bedrock] Grok 4.7 is now available on Amazon Bedrock in AWS GovCloud (US)

- **公開日**: 2026-10-19 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-bedrock-grok-4-7-govcloud/

### 概要

Amazon BedrockでSpaceXAIのGrok 4.7がAWS GovCloud (US)で利用可能になりました。コード生成、エージェント処理、ナレッジワーク向けに改善されたフロンティアモデルです。

### 変更内容・新機能の詳細

Grok 4.7はGrok 4.6をベースに、複数形式・混在ドキュメントの取り扱い精度向上、リポジトリ規模のコーディングワークフローでの計画（planning）生成とエラー回復（error recovery）の強化、ブラウザ操作エージェントの改善（フォーム入力やポータルナビゲーションを含む）を特徴とするモデルです。Amazon Bedrock上ではコンソール操作またはBedrockのAPI経由で呼び出せます。利用にあたっては、対応リージョン、エンドポイント、利用可能なAPI/推論プロファイル、スループット制限および料金体系をAmazon Bedrockのドキュメントで確認してください。Grok 4.7は高度な推論能力を持つため、推論コストやレイテンシ、トークン/スループット制限を考慮した設計（バッチ化、キャッシュ、リトライ戦略など）を推奨します。GovCloud (US)での提供は、米国政府／規制対応ワークロードやデータ居住要件を持つ顧客に適した選択肢となります。

### 影響範囲・利用シーン

- **対象ユーザー**: ソフトウェアエンジニア、SRE/DevOps、RPA/オートメーション担当者、ナレッジワーカー（GovCloud利用企業）
- **利用シーン**: リポジトリ全体のコード生成・リファクタリング、複数ドキュメントにまたがる情報抽出と要約、ブラウザ操作を伴う自動化（フォーム入力、ポータル操作）やエージェント駆動ワークフローの実行
- **運用効果**: リポジトリ規模のタスクでの堅牢性向上（計画立案と自動的なエラー回復）、混在ドキュメントからの高精度な情報統合、ブラウザベース作業の自動化による手作業削減と応答性向上

### 技術的な注意点

- **IAM権限**: Amazon Bedrockの呼び出しに必要な権限（例: bedrock:InvokeModel、bedrock:ListModels 等）を付与する必要があります。IAMロール/ポリシーで最小権限を適用してください。
- **リージョン制限**: 提供対象は AWS GovCloud (US) です。パブリックAWSリージョンでの利用可否や展開状況はドキュメントで確認してください。
- **コスト**: フロンティアモデルのため推論コストが高くなる可能性があります。推論プロファイル、料金表、スループット単価を事前に確認し、バッチ化やキャッシュでコスト最適化を検討してください。
- **ネットワーク/エンドポイント**: GovCloud専用エンドポイントへのアクセスが必要です。VPCやファイアウォールからの接続経路、プロキシ設定、PrivateLinkの有無（該当する場合）を確認してください。
- **コンプライアンス・データ処理**: GovCloudを利用することで特定の政府／規制要件に対応できますが、データ分類やログ保持ポリシー等、組織のコンプライアンス要件を確認してください。
- **API/スループット**: BedrockのAPI（InvokeModel等）のレート制限や推論プロファイル（レイテンシ/コスト/スループットの性質）を確認し、リトライやバックオフ、バッチ処理戦略を設計してください。

## [Iam Identity Center] AWS IAM Identity Center now supports optimistic locking for users and groups in its identity store

- **公開日**: 2026-10-19 (JST)
- **カテゴリ**: Iam Identity Center
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/iam-identity-store-optimistic-locking/

### 概要

AWS IAM Identity Center（Identity Store）がユーザーとグループに対する楽観的ロック（ optimistic locking ）をサポートしました。これにより、更新・削除要求は最後に読み取った状態（Revision）が一致する場合にのみ成功します。

### 変更内容・新機能の詳細

Identity Store の各ユーザーとグループに対してRevisionフィールドが導入されました。Revisionはユーザー／グループの属性が変更されるたびに更新され（SCIMプロビジョニング、Active Directory同期、コンソール操作を含む）、Create/Describe/Update/Listのレスポンスで現在のRevisionが返されます。クライアントは後続のUpdateUser、UpdateGroup、DeleteUser、DeleteGroupリクエストにそのRevisionを渡すことで条件付き更新（楽観的ロック）を行えます。渡したRevisionが現在のRevisionと一致しない場合、リクエストはConflictExceptionを返し、クライアントは最新のリソースを再取得して再試行できます。Revisionの提供は任意で、省略した場合は従来通りの動作（互換性保持）です。なお、楽観的ロックはIdentity Store のAPIでサポートされ、SCIMエンドポイント経由では条件付き要求は受け付けられません。グループメンバーシップ操作（メンバーの追加・削除）はRevisionを受け取らず、ユーザー／グループのRevisionも変更しません。本機能はIAM Identity Centerが利用可能な全リージョンで有効で、追加料金は発生しません。

### 影響範囲・利用シーン

- **対象ユーザー**: IAM Identity Centerを管理するクラウドエンジニア、SRE、ID管理の自動化ワークフロー開発者
- **利用シーンまたは効果**: 複数管理者や自動化プロセスが同一のユーザー／グループを同時に変更する環境での競合防止
- **運用効果**: 上書き競合の検出が可能になり、変更失敗時に再取得→再試行という安全な更新パターンが実現できる
- **互換性**: Revisionを渡さない既存の統合は変更不要で引き続き動作する
- **制限**: グループのメンバー追加・削除はRevisionの対象外で、これら操作はRevisionを変更しない
- **リージョン**: IAM Identity Centerが利用可能なすべてのAWSリージョンで利用可能
- **コスト**: IAM Identity Centerの機能として提供され、追加料金は発生しない

### 技術的な注意点

- **IAM権限**: UpdateUser/UpdateGroup/DeleteUser/DeleteGroupなどIdentity Store APIを呼ぶための適切なIAM権限が必要です（identitystore:* あるいは個別API権限）。
- **リージョン制限**: 本機能はIAM Identity Centerが利用可能なすべてのリージョンで提供されています（記事参照）。
- **コスト**: 機能自体に追加料金は発生しませんが、API呼び出し量増加によりCloudWatchログやAPIコールに伴う標準的な請求が増える可能性があります。
- **SCIMエンドポイント**: 条件付きリクエスト（Revision指定）はIdentity Store APIでのみサポートされ、SCIMエンドポイントでは利用できません。
- **グループメンバーシップ**: メンバーの追加/削除はRevisionを受け取らず、ユーザー／グループのRevisionも更新されません。並行してメンバー操作と属性変更を行う際は挙動に注意してください。
- **エラーと対処**: Revision不一致時はConflictExceptionが返されます。推奨パターンはエラー時に最新のリソースをDescribeして変更差分を解消のうえ再試行することです。
- **対応API/操作**: CreateUser/DescribeUser/UpdateUser/ListUsers および CreateGroup/DescribeGroup/UpdateGroup/ListGroups が現在のRevisionを返します。Update/Delete操作にRevisionを渡すことができます。
- **注意事項**: Revisionは属性変更で更新されますが、メンバーシップの増減では変更されない点を設計時に考慮してください。

- https://docs.aws.amazon.com/identitystore/latest/APIReference/API_UpdateUser.html

## [Elemental Mediaconnect] AWS Elemental MediaConnect Router now supports high bitrate mode

- **公開日**: 2026-10-19 (JST)
- **カテゴリ**: Elemental Mediaconnect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/mediaconnect-router-high-bitrate/

### 概要

AWS Elemental MediaConnect Routerが高ビットレートモード（250 Mbpsと500 Mbpsの2階層）をサポートしました。放送品質の高い映像を信頼性を保って伝送できるようになり、業界標準ワークフロー（例：VSF TR-07準拠のトランスポートストリーム分配）をサポートします。

### 変更内容・新機能の詳細

今回の拡張でMediaConnect Routerは新たに250 Mbpsと500 Mbpsの高ビットレートモードを提供します。これにより、放送局やプロダクション向けに高価値な映像コンテンツを高いビットレートで伝送可能です。高ビットレートモードは最大2つの冗長ソース（プライマリ＋セカンダリ）をサポートし、可用性を向上させます。さらにデータプレーン側の最適化によりジッタ（パケット間の遅延変動）が低減され、リアルタイム性や同期が重要なリモートプロダクションや放送伝送でのパフォーマンスが改善されます。業界標準のワークフロー（VSF TR-07準拠のトランスポートストリーム分配、放送貢献、コンテンツ配信、リモート制作など）に直接適用できる設計です。既存の低ビットレート設定は残り、高ビットレートは追加オプションとして利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: 放送局、リモートプロダクション業者、ライブイベントプロダクション、映像ポスプロチーム
- **利用シーン**: VSF TR-07 準拠のトランスポートストリーム分配、放送貢献（contribution）、高品質リモート制作、長尺高ビットレートコンテンツの信頼伝送
- **運用効果**: 高ビットレート伝送により画質劣化を抑えつつ冗長化で可用性を確保、データプレーン最適化でジッタが減り同期・遅延の安定化が期待できる

### 技術的な注意点

- **IAM権限**: MediaConnectのフロー作成/更新やRouter設定には対応するIAMポリシー（mediaconnect:CreateFlow, UpdateFlowなど）が必要です
- **リージョン制限**: 新機能はリージョンごとに段階展開される場合があるため利用前に対象リージョンでの対応状況を確認してください
- **コスト**: 高ビットレートモードは転送量・帯域幅利用増加により料金が上昇する可能性があります。MediaConnectの料金ページで新しい階層の課金条件を必ず確認してください
- **ネットワーク要件**: エッジ側のエンコーダ/ネットワーク機器が250/500 Mbpsの安定送信をサポートしていること、帯域幅とMTU、QoS設定を事前に確認してください
- **冗長性/フェイルオーバ**: 最大2つの冗長ソースをサポートします。冗長構成の設計（同期方式、切替ポリシー、監視）を検討してください
- **プロトコル/互換性**: VSF TR-07準拠のトランスポートストリーム等、既存の放送ワークフローとの互換性を前提としていますが、エンコーダ/デコーダの設定確認が必要です
- **運用監視**: ジッタやパケットロスなど指標の監視を強化してください。CloudWatchやフローのメトリクス確認を推奨します
- **クォータ**: ビットレート上限や同時フロー数に関するアカウントクォータが影響する可能性があるため、必要に応じて引き上げ申請を行ってください

## [Rds For Sql Server] Amazon RDS Custom now supports the latest Cumulative Update and GDR updates for Microsoft SQL Server

- **公開日**: 2026-10-19 (JST)
- **カテゴリ**: Rds For Sql Server
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-rds-custom-supports-latest-cumulative-update-gdr-microsoft-sql-server/

### 概要

Amazon RDS Custom for SQL Serverが、Microsoftが提供する最新のCumulative Update(CU)とGeneral Distribution Release(GDR)をサポートしました。SQL Server 2019および2022向けの指定KBを適用したRDSエンジンバージョンが利用可能です。

### 変更内容・新機能の詳細

今回のリリースで、Amazon RDS Custom for SQL Serverは以下の更新をサポートします：
- SQL Server 2019: CU32 + GDR KB5122772（RDSエンジンバージョン 15.00.4490.9.v1）
- SQL Server 2022: CU26 + GDR KB5122768（RDSエンジンバージョン 16.00.4275.2.v1）

CU（Cumulative Update）は機能改善やバグ修正を含む包括的な更新であり、GDR（General Distribution Release）は主に重要なセキュリティ修正を含むリリースです。これらの更新内容の詳細（修正点や既知の変更）は、各KB文書（KB5122772、KB5122768）で確認してください。

インスタンスのアップグレードは、Amazon RDSマネジメントコンソール、AWS SDK、またはAWS CLIを使って実行できます。RDS Customは通常のRDSよりOSや設定に対するカスタマイズ権限が大きいため、OSやドライバ、カスタムエージェント等の互換性確認が必要な場合があります。アップデートはエンジンの再起動や短時間のサービス停止を伴う可能性があるため、事前のスナップショット取得とステージングでの検証を推奨します。詳細な操作手順や注意点はAmazon RDS Customユーザーガイドを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon RDS Custom for SQL Serverを利用しているDB管理者、SRE、アプリケーション開発者
- **利用シーン**: セキュリティパッチやバグ修正を取り込み、SQL Serverの安定性・セキュリティを向上させたい場合の定期メンテナンス
- **運用効果**: 重要なセキュリティ修正と累積的なバグ修正を適用することで、脆弱性低減と不具合の解消が期待できる（ただし事前検証により回帰リスクを抑えることが重要）
- **ダウンタイム影響**: エンジン再起動が必要になるケースがあり、短時間のサービス停止や接続再確立が発生する可能性がある
- **互換性影響**: カスタムドライバや拡張、OSレベルのカスタマイズを行っている環境では事前検証が必須

### 技術的な注意点

- **IAM権限**: アップグレード実行にはrds:ModifyDBInstance、rds:DescribeDBInstances、rds:RebootDBInstanceなどの権限が必要（運用方針に合わせて最小権限を設定）
- **バックアップ/復旧**: 事前にスナップショットを取得し、ステージング環境でリストア/検証を実施してください
- **再起動/ダウンタイム**: エンジンバージョン変更やパッチ適用でインスタンスの再起動が発生する可能性があります。メンテナンスウィンドウの設定やダウンタイム計画を行ってください
- **リージョン制限**: 本記事に特定リージョンの言及はありませんが、新機能はリージョン単位でロールアウトされるため、利用前に対象リージョンでの提供状況をコンソールで確認してください
- **互換性検証**: アプリケーション互換性、サードパーティ製ドライバ、拡張機能はアップデート前にテストが必要です（特にRDS CustomでOSレベルの変更を加えている場合）
- **コスト**: パッチ適用自体による追加料金は通常発生しませんが、ダウンタイムやテスト環境用のリソース確保に伴うコストは考慮してください
- **監視**: アップグレード後はCPU/IO/遅延などのパフォーマンス指標を監視し、予期しない挙動がないか確認してください

## [Rds For Sql Server] Amazon RDS for SQL Server now supports snapshots on read replicas

- **公開日**: 2026-10-19 (JST)
- **カテゴリ**: Rds For Sql Server
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/rds-sqlserver-supports-snapshots-on-read-replicas

### 概要

Amazon RDS for SQL Serverで、リードレプリカ上に直接DBスナップショットを作成できるようになりました。プロモートせずにスナップショットを取得できるため、バックアップやDRワークフローの柔軟性と予測可能性が向上します。

### 変更内容・新機能の詳細

これまでRDS for SQL Serverではスナップショット作成はスタンドアロンまたはプライマリDBインスタンスでのみ可能でした。今回の更新により、リードレプリカ（in-regionおよびcross-region）上で手動スナップショットを直接作成できるようになり、プロモート（昇格）を行わずにバックアップを取得できます。さらにリードレプリカはライフサイクルを通じてスナップショット用データを保持するため、リードレプリカをプロモートした直後に必要となる「最初のフルスナップショット」が高速に完了しやすくなり、Multi-AZ化の開始やDR手順実行時の所要時間が短縮・予測しやすくなります。対応操作としては、手動スナップショットの取得、バックアップ保持期間を0より大きく設定しての自動バックアップ有効化、リードレプリカ削除時に自動バックアップを保持する設定が可能です。一方で、リードレプリカからのポイントインタイムリカバリ（PITR）はサポートされません。この機能はSQL Server Enterprise Editionの、リードレプリカをサポートする全てのSQL Serverバージョンで利用可能で、RDS for SQL Serverのリードレプリカが利用可能なすべてのリージョン（AWS GovCloud (US) 含む）で有効です。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者(DBA)、SRE、クラウド運用チーム
- **利用シーン**: リードレプリカ上でのバックアップ取得、DR準備、リードレプリカからの迅速なMulti-AZ切替準備
- **運用効果**: プロモート前にスナップショットを作成できることで、プロモート後の初回スナップショット時間が短縮され、Multi-AZ化やDR演習の復旧時間が予測可能になる
- **コスト影響**: スナップショットストレージと（クロスリージョンにコピーする場合の）データ転送/ストレージ費用が発生する可能性がある

### 技術的な注意点

- **PITR制限**: リードレプリカ上からのポイントインタイムリカバリはサポートされません
- **自動バックアップ設定**: 自動バックアップを有効にするにはバックアップ保持期間を0より大きく設定してください
- **スナップショット保持**: リードレプリカ削除時に自動バックアップを保持するオプションが利用可能です
- **エディション/バージョン**: SQL Server Enterprise Editionの、リードレプリカをサポートする全バージョンで利用可能です
- **リージョン制限**: RDS for SQL Serverのリードレプリカが利用可能な全リージョン（AWS GovCloud (US) 含む）で有効です。未対応リージョンでは利用できません
- **コスト**: スナップショット保存分のストレージ料金、クロスリージョン転送やクロスリージョンに保存する場合の追加ストレージ料金が発生する可能性があります
- **IAM権限**: スナップショット作成/削除やバックアップ設定変更を行うためのRDS関連IAM権限（rds:CreateDBSnapshot, rds:ModifyDBInstance など）を事前に確認してください
- **運用注意**: 大容量(io2等で数十TiB)環境では初回のスナップショット時間短縮の恩恵が大きいですが、スナップショットの保存や復元には時間とコストが伴うため事前に検証を推奨します

- https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/SQLServer.ReadReplicas.html
