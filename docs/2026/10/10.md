## [Security Hub] AWS Security Hub now exports findings to S3 in CSV or JSON format

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Security Hub
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/security-hub-exports-s3-csv-json/

### 概要

AWS Security Hubがファインディングのエクスポート機能を強化し、コンソールからオンデマンドでAmazon S3へCSVまたはJSON（Open Cybersecurity Schema Framework: OCSF）形式で出力できるようになりました。これにより独自の抽出パイプラインを構築せずに監査やレポート用途でデータを取り出せます。

### 変更内容・新機能の詳細

今回のアップデートでは、Security Hubの各ファインディングページ（Threats、Exposure、Vulnerabilities、Posture Management、Sensitive Data、All Findingsなど）から、表示中の結果をそのままオンデマンドでエクスポートして、指定した自アカウントのS3バケットに配信できます。出力フォーマットはCSV（スプレッドシートでの閲覧や共有向け）とJSON（OCSF準拠、SIEMや他ツールとの互換性向上向け）を選択可能です。エクスポートはSecurity Hubコンソールから開始し、結果はS3上のオブジェクトとして保存されます。本機能はSecurity Hubが提供されるすべてのAWSリージョンで利用可能です。OCSF形式はセキュリティイベントの共通スキーマであるため、他のセキュリティ製品や解析基盤との連携が容易になります。なお、記事ではオンデマンドでのエクスポートを説明しており、スケジュール/継続的な自動エクスポートに関してはドキュメントで確認が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティチーム、コンプライアンス担当者、監査担当者、SRE/運用チーム
- **利用シーン**: 監査証跡やコンプライアンス報告書の作成、スプレッドシートでのレビュー、OCSF対応SIEM/解析基盤へのインポート
- **運用効果**: 独自の抽出パイプラインを構築・維持する負担を削減し、コンソール上の任意のファインディングセットを簡単に外部保存・共有できることで監査対応やインシデント調査の効率が向上します

### 技術的な注意点

- **IAM権限**: Security Hubのファインディング閲覧権限に加え、エクスポート先S3バケットへの書き込み権限（s3:PutObject、s3:PutObjectAcl など）が必要です。詳細はドキュメントで確認してください。
- **S3バケット設定**: バケットはエクスポート先として自身のアカウントで用意します。サーバー側暗号化（SSE）や適切なバケットポリシー、ライフサイクル設定の検討を推奨します。
- **リージョン制限**: 本機能は「Security Hubが利用可能な全リージョン」で利用可能と明記されています。特定リージョンの可用性はAWSコンソール/ドキュメントで再確認してください。
- **コスト**: 記事ではエクスポート自体の追加料金は明示されていませんが、S3の保存・リクエスト料金および関連するデータ転送コストは発生する可能性があります。
- **フォーマット/互換性**: JSON出力はOCSF準拠で提供され、汎用的なスキーマで他ツールへ取り込みやすくなっています。CSVは可読性重視で列構成を確認してから共有してください。
- **大容量エクスポート**: 大量のファインディングをエクスポートする場合、処理時間やオブジェクト分割、S3オブジェクト数の増加に注意してください。タイムアウトや部分出力の可能性についてはドキュメントで確認することを推奨します。
- **自動化**: 記事はコンソールからのオンデマンドエクスポートを説明しています。定期的な自動エクスポートやAPI経由の同等機能が必要な場合は、関連API/ドキュメントで対応可否を確認してください。

## [Ec2] Amazon EC2 R8gd instances are now available in additional regions 

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-ec2-r8gd-thf/

### 概要

Amazon EC2 の R8gd インスタンスが AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。Graviton4 プロセッサー＋最大11.4TBのローカルNVMeストレージを備え、高帯域・低遅延のローカルストレージを必要とするワークロードに適しています。

### 変更内容・新機能の詳細

R8gd は AWS Graviton4 ベースのメモリ最適化インスタンスファミリーで、今回ドイツの欧州ソブリンクラウド領域に追加されました。主な仕様は最大11.4 TB のローカル NVMe ベースのインスタンスストア（ブロックレベル）、最大50 Gbps のネットワーク帯域、最大40 Gbps の Amazon EBS 帯域をサポートします。インスタンスは Nitro システム上に構築され、24xlarge／48xlarge／metal-24xl／metal-48xl のサイズでは Elastic Fabric Adapter (EFA) に対応し、HPC や分散トレーニング向けの低レイテンシ通信が可能です。サイズは合計12種。さらに、EC2 のインスタンス帯域ウェイト設定（bandwidth weighting）を使ってネットワークおよび EBS 帯域を最大25% 調整できるため、ワークロードに応じた帯域配分の最適化が可能です。Graviton4 は Graviton3 比で最大約30% の性能向上が見込まれ、ARM（aarch64）向け最適化バイナリでより高いコスト効率を実現します。

### 影響範囲・利用シーン

- **対象ユーザー**: 高パフォーマンスなローカルストレージ（NVMe）を必要とするデータベース、キャッシュ、ビッグデータ処理、HPC、分散機械学習ワークロードの開発者／運用者
- **利用シーンまたは効果**: ローカル NVMe を活用した低遅延 I/O を要求するデータベース（例：オンプレ寄せのインメモリDB／ローカルキャッシュ）、高スループットの一時ストレージを使う ETL／バッチ処理、EFA を使った MPI ベースのクラスタ通信による HPC／分散トレーニング
- **運用効果**: Graviton4 による性能向上と帯域ウェイト調整により、性能あたりのコスト削減やネットワーク／EBS 帯域の柔軟な割当てでワークロード最適化が可能

### 技術的な注意点

- **インスタンスストアの特性**: ローカル NVMe はインスタンスストア（ephemeral）です。停止や終了でデータが消失するため、永続化には EBS や S3、レプリケーション設計が必要です
- **アーキテクチャ互換性**: Graviton4 は ARM（aarch64）アーキテクチャのため、既存 x86 バイナリは再ビルド／再配布が必要な場合があります。対応 AMI を利用してください
- **EFA 要件**: EFA を利用するサイズでは対応 ENA/EFA ドライバと MPI ライブラリのセットアップが必要です。EFA は起動時に有効化する必要があります
- **帯域ウェイト設定**: ネットワークおよび EBS 帯域を ±25% 調整可能ですが、設定変更はワークロード性能に直接影響するためテストが必要です
- **IAM 権限**: RunInstances、CreateNetworkInterface、AttachVolume、ModifyInstanceAttribute など EC2 起動とネットワーク／EBS 操作に必要な IAM 権限を確認してください
- **リージョン制限**: 今回は AWS European Sovereign Cloud (Germany) に追加されたものです。全リージョンにまだ展開されていないため、利用前に対象リージョンでの提供状況を確認してください
- **コスト**: Graviton4 の性能向上によりコスト効率が改善する可能性がありますが、インスタンス料金、リージョン毎の価格、ストレージ（インスタンスストアは追加料金なしだが EBS/データ転送等は別途課金）を事前に確認してください

## [Ec2] Amazon EC2 R8g instances now available in additional regions 

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-ec2-r8g-instances-thf/

### 概要

Amazon EC2のGraviton4搭載メモリ最適化インスタンスR8gが、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。Graviton3世代比で最大30%程度の性能向上を提供します。

### 変更内容・新機能の詳細

R8gインスタンスはAWS Graviton4プロセッサを採用したメモリ最適化ファミリーで、データベース、インメモリキャッシュ、リアルタイム大規模分析などメモリ集約型ワークロード向けに設計されています。Nitro System上で動作し、CPU仮想化、ストレージ、ネットワーク機能を専用ハードウェア/ソフトウェアでオフロードすることで性能とセキュリティを向上させます。R8gはR7g（Graviton3）と比べ、より大きなインスタンスサイズを提供し（最大でvCPU数がR7g比で3倍、最大サイズで48xlarge相当、メモリは最大約1.5TB）、Webアプリで最大30%高速、データベースで最大40%高速、大規模Javaアプリで最大45%高速とするベンチマーク差が示されています。インスタンスは12種類のサイズ（うち裸金属が2種類）を用意し、最大50 Gbpsの強化ネットワーク帯域および最大40 GbpsのAmazon EBS帯域をサポートします。Gravitonへの移行支援としてAWS Graviton Fast StartプログラムやPorting Advisorが利用可能で、コンソールから起動・管理できます。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者、SRE、バックエンドアプリケーション開発者、メモリ集約型ワークロードを運用するチーム
- **利用シーンまたは効果**: 高性能・高効率なメモリ最適化インスタンスを必要とするDB（RDS以外のセルフマネージド含む）、Redis/Memcached等のキャッシュ、大規模リアルタイム分析やJavaアプリの高速化に利用可能
- **運用効果**: 同等の処理でコスト効率が改善する可能性（Graviton4の高い性能効率によりインスタンスサイズ削減や台数削減が可能）
- **リージョン制限**: 本リリースは AWS European Sovereign Cloud (Germany) に追加されたもので、他リージョンでの配備状況は別途確認が必要
- **移行効果**: Arm (aarch64) アーキテクチャへ移行することでCPUコスト効率とエネルギー効率が向上するケースが多い

### 技術的な注意点

- **アーキテクチャ**: Graviton4はArm（aarch64）アーキテクチャのため、実行バイナリやコンテナイメージはArm対応（またはマルチアーキテクチャ）である必要があります
- **AMI/OS**: Arm64対応のAMI（Amazon Linux 2 for Graviton、Ubuntu arm64等）を使用してください
- **ドライバ要件**: ENA（Enhanced Networking）およびNVMe/EBSドライバをサポートするOSカーネルが必要です
- **IAM権限**: ec2:RunInstances等の標準的なEC2起動権限と、必要に応じてEBS/ENI関連の権限を確認してください
- **インスタンス制限**: アカウントのインスタンス数上限（クォータ）があるため、必要ならサポート経由で引き上げを申請してください
- **コスト**: Graviton4は高い性能効率を提供しますが、実際のコストはワークロード特性とリージョンの価格設定に依存します。料金、Savings Plans、リザーブドインスタンスを確認してください
- **リージョン制限**: 現時点で本発表はGermany（European Sovereign Cloud）向けの追加であるため、他リージョンの可用性はAWSドキュメントで確認してください
- **移行支援**: コンパイルやライブラリ互換性のチェックにはAWS Porting AdvisorやGraviton Fast Startを活用してください
- **裸金属注意**: 裸金属インスタンスを利用する場合はハードウェアアクセス要件やホストの違いに留意してください

## [Bedrock] Amazon Bedrock now supports reasoning summaries for OpenAI models

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-bedrock-reasoning-summaries-openai/

### 概要

Amazon BedrockがOpenAIモデル向けにResponses APIでreasoning.summaryパラメータをサポートしました。モデルの応答と併せて人間向けの「推論（reasoning）要約」を取得でき、複雑なタスクのアプローチを理解しやすくなります。

### 変更内容・新機能の詳細

Responses APIのreasoning.summaryパラメータを指定することで、OpenAI GPT系モデルの応答に対しモデルがどのように考えたかを人間向けに要約した情報を返せるようになりました。要約はResponses APIのレスポンス内にあるreasoning出力アイテムのsummary配列として返され、モデルの最終回答と並んで取得できます。これによりコーディング、分析、マルチステップの問題解決といった場面で、モデルの思考経路や根拠を把握しやすくなります。この機能はOpenAI GPTモデルが利用可能なすべてのAWSリージョンで利用可能（インリージョン推論、GEOクロスリージョン推論、グローバルクロスリージョン推論含む）です。実装側ではResponses API呼び出し時にreasoning.summaryフラグを設定し、返ってくるsummary配列をパースして表示・ログ保存・評価に利用します。なお、要約テキストは追加のトークンを消費するため、出力トークン増加および潜在的なレイテンシ増加、コスト増加につながる点に注意が必要です。また、要約はモデルが生成する2次的な説明であり、必ずしも完全に正確とは限らない（ハルシネーションなど）ため、クリティカルな用途では検証プロセスを組み込むことを推奨します。

### 影響範囲・利用シーン

- **対象ユーザー**: アプリ開発者、データサイエンティスト、SRE/運用担当、AI評価者
- **利用シーン**: コード生成の根拠説明、複雑な分析手順の可視化、マルチステップ推論のデバッグ、ユーザー向け説明（モデルがどう判断したかの提示）
- **運用効果**: バグや誤応答の原因追跡が容易になり、モデル出力の説明性・透明性が向上してユーザー信頼性や監査対応が改善される

### 技術的な注意点

- **IAM権限**: BedrockのResponses APIを呼び出す権限が必要（例: bedrock:InvokeModelや関連のIAMポリシーを付与してください）
- **リージョン制限**: OpenAI GPTモデルが利用可能なAWSリージョンで利用可能です。利用予定のリージョンでOpenAIモデルの提供状況を事前に確認してください
- **コスト**: 要約は追加の出力トークンを生成するため、トークンベースの利用料が増加します。コスト見積もりに要約分のトークン消費を含めてください
- **レスポンス構造**: reasoning.summaryはreasoning出力アイテム内のsummary配列として返却されるため、APIレスポンスのJSONを適切にパースする必要があります
- **遅延**: 要約生成により応答レイテンシが増加する可能性があります。リアルタイム性が必要な用途では影響を評価してください
- **品質・信頼性**: 要約はモデル生成物のため誤りやハルシネーションが含まれる可能性があります。重要な判断や自動処理の根拠として使う場合は検証やルールベースのチェックを併用してください

## [Connect] Amazon Connect Customer now provides automated checks to improve performance evaluation forms 

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-connect-customer-automated-checks-evaluation-forms/

### 概要

Amazon Connect Customerに、評価フォームをAIで自動採点する際の精度を高める「自動チェック」機能が追加されました。ワンクリックでフォームをベストプラクティスと照合し、AIが信頼性高く採点するために不足している文脈や具体化の提案を受け取れます。

### 変更内容・新機能の詳細

評価フォーム作成時にマネージャーがワンクリックで「自動チェック」を実行できる機能が追加されました。自動チェックは既存の評価質問をベストプラクティスと比較し、AIが一貫して採点するために必要な文脈（期待される回答の具体的基準や例示）が欠けている質問を検出します。検出された質問には、より具体的にするための文言修正案や期待される行動・フレーズの定義が提示されます（例：「Did the agent provide a sales disclosure?」という質問に対して「販売前にエージェントが顧客へ〜と明示する必要がある」等を明記するよう促す）。これにより、人間オペレーターとAIの双方を公平かつ正確に採点しやすくなり、評価フォームの微調整にかかる時間を削減できます。機能はUS East (N. Virginia)、US West (Oregon)、Canada (Central)、Europe (Frankfurt)、Europe (London)、Asia Pacific (Singapore)、Asia Pacific (Sydney)、Asia Pacific (Tokyo)で利用可能です。導入後は推奨事項を手動で採用・編集し、社内の評価ポリシーやコンプライアンス要件に合わせて調整してください。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンターのマネージャー、品質管理（QA）担当者、SRE/運用チーム
- **利用シーン**: 評価フォーム作成・更新時の品質改善、AI自動採点ルールの精度向上、評価の一貫性確保
- **運用効果**: 評価基準の曖昧さを減らすことでAIおよび人間スコアのばらつきが低減し、フォーム改善に要する工数を削減

### 技術的な注意点

- **IAM権限**: 評価フォームの作成・編集・実行に必要なAmazon Connect権限（例: connect:CreateEvaluationForm, connect:UpdateEvaluationForm, connect:DescribeEvaluationFormなど）を付与する必要があります
- **リージョン制限**: 本機能は以下のリージョンで利用可能です — US East (N. Virginia)、US West (Oregon)、Canada (Central)、Europe (Frankfurt)、Europe (London)、Asia Pacific (Singapore)、Asia Pacific (Sydney)、Asia Pacific (Tokyo)
- **コスト**: 機能自体の利用可否や追加課金の有無はドキュメントおよび価格ページを確認してください。AI評価やConnect利用に伴う通常の使用料が発生する可能性があります
- **AI評価の注意点**: 自動チェックはベストプラクティスに基づく文言改善案を提示しますが、業務上のコンプライアンス要件やローカルの規制、組織固有の評価基準は自動的には反映されないため、必ず人間が最終レビューを行ってください
- **既存フォームとの互換性**: 既存の評価フォームに対してもチェックは実行できますが、提示された修正案は自動適用されないため、適用前に確認・テストを行うことを推奨します

- https://docs.aws.amazon.com/connect/latest/adminguide/evaluation-forms.html

## [S3] Amazon S3 Vectors metadata pre-filtering is now available in AWS GovCloud (US) Regions

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: S3
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/s3-vectors-metadata-pre-filtering-in-govcloud-regions/

### 概要

Amazon S3 Vectorsのメタデータ事前フィルタリングがAWS GovCloud (US-East/US-West) リージョンで利用可能になりました。フィルタを実行してから類似検索を行うことで、選択的なフィルタ使用時に最大5倍の一致ベクトルを返せるようになります。

### 変更内容・新機能の詳細

S3 Vectorsはメタデータ事前フィルタリング（metadata pre-filtering）をGovCloudリージョンに展開しました。事前フィルタリングはまずメタデータ条件を評価して検索候補を絞り、その後に類似検索（ベクトル検索）を行うため、フィルタが選択的な場合に検索結果の網羅性（より多くの一致ベクトル）を高めます。あわせてプレフィックス一致の演算子 $startsWith が追加され、パスやURLのような値に対する部分一致フィルタが容易になりました。新しいベクターバケットに作成されるインデックスではデフォルトで事前フィルタリングが有効化され、PutVectorsやQueryVectorsの呼び出し方法は変更されません。既存インデックスで事前フィルタリングを利用するには UpdateIndexMode API で既存のインデックスをインプレース更新します。更新前に、QueryVectorsのクエリ単位パラメータで事前フィルタリング有無を比較し、影響を確認できます。GovCloudでのローリング展開は進行中で数日内に完了予定。商用リージョンおよび中国リージョンでは事前フィルタリングは追加料金なしで利用可能とされています。操作はAWS CLI、SDK、またはS3コンソールから行えます。

### 影響範囲・利用シーン

- **対象ユーザー**: 検索レコメンド、RAG（retrieval-augmented generation）、エージェント型アプリ、セマンティックサーチを利用するアプリ開発者およびSRE/運用チーム
- **利用シーン**: 特定のメタデータ（例: 顧客ID、データパス、ドメイン、バケット内サブセット）で絞り込んだうえでの類似検索。URLやパスの先頭一致によるフィルタリング（$startsWith）を使った結果絞り込み
- **運用効果**: フィルタが選択的な場合に戻るベクトルの網羅性が向上（最大5xの一致ベクトル）。フィルタ適用前に候補を絞るため検索コストとレイテンシの改善、より関連性の高い応答が得られやすくなる

### 技術的な注意点

- **IAM権限**: PutVectors、QueryVectors、UpdateIndexModeなどのS3 Vectors関連API呼び出しに対する権限をロール/ポリシーに付与する必要があります。具体的なアクション名は実運用前にドキュメントで確認してください。
- **リージョン制限**: 本リリースは AWS GovCloud (US-East) と AWS GovCloud (US-West) に展開されました。商用リージョンと中国リージョンでは既に利用可能で、GovCloudはローリング展開中です。対応リージョンは公式アナウンスで随時確認してください。
- **コスト**: 公式発表では商用リージョンと中国リージョンで事前フィルタリングは追加料金なしとされています。ただし、返却ベクトル数やクエリ回数の変化によりストレージ、データ転送、クエリ実行に伴う間接的なコストが増減する可能性があるため請求影響は事前に検証してください。
- **既存インデックスの対応**: 既存のインデックスを事前フィルタリングに切り替えるには UpdateIndexMode API を使用してインプレースで更新する必要があります。更新前に per-query パラメータで事前フィルタリングの有無を比較できます。
- **互換性/操作**: PutVectors と QueryVectors の呼び出し方法自体に変更はありません。$startsWith のような新しいフィルタ演算子をフィルタ条件に組み込めます。
- **注意点**: デプロイは段階的に行われているため、リージョンやアカウントによって有効化タイミングが異なる場合があります。特にGovCloudアカウントは商用リージョンと異なるため、展開状況と課金ルールを確認してください。

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/10/s3-vectors-metadata-pre-filtering-in-govcloud-regions/
- https://docs.aws.amazon.com/s3/vectors/latest/userguide/

## [General] AWS Lambda supports OAuth authentication for self-managed Apache Kafka event sources

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-Lambda-supports-oauth-kafka-esm/

### 概要

AWS Lambdaが自己管理型のApache Kafkaイベントソースマッピング（ESM）に対するOAuth認証をサポートしました。これにより、企業のIDプロバイダを使ってLambdaのKafkaコンシューマをOAuthで認証でき、規制対応や一貫したIDガバナンスが可能になります。

### 変更内容・新機能の詳細

今回のリリースでは、自己管理型Kafkaクラスター（自社で運用するKafka）およびConfluent Cloud、Aiven、RedpandaなどのマネージドKafka環境を対象に、LambdaのKafkaイベントソースマッピングでOAuth認証が利用可能になりました。OAuthを使うことで、Amazon CognitoやOktaなどのエンタープライズIDプロバイダから発行されるトークンを用いてKafkaコンシューマを認証できます。Kafka ESMは自動スケーリング、エラーハンドリング、バッチ処理、イベントフィルタリングなどを提供しており、支払い処理、詐欺検出、リアルタイムデータパイプライン等のイベント駆動ワークロードで利用されます。従来はSASL/PLAIN、SASL/SCRAM、相互TLS（mTLS）のみサポートされていたため、OAuthが必須の規制要件を持つ環境では利用が制限されていました。本機能は「自己管理型Kafka ESMが利用可能なすべてのAWS商用リージョン」で利用可能です。OAuth認証を利用するには、新しいKafka ESMを作成して認証設定を指定します（作成方法はAWS Management Console、Lambda API、AWS CLI、AWS CloudFormation、AWS SAMが利用可）。設定時にはIDプロバイダのトークンエンドポイント、クライアントID/クライアントシークレット、必要なスコープ等の情報が必要になります。クライアントシークレット等の機密情報はAWS Secrets Manager等で安全に管理することを推奨します。詳細はAWS Lambda開発者ガイドと料金ページを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: サーバーレスでKafkaコンシューマを構築するアプリケーション開発者、SRE、セキュリティ/コンプライアンス担当者
- **利用シーンまたは効果**: 企業のIDプロバイダ（例: Amazon Cognito、Okta）によるOAuth 2.0を利用してLambdaのKafkaコンシューマを認証し、支払い処理、詐欺検出、リアルタイムETLなどで一貫したアクセス制御と監査を実現
- **運用効果**: 組織のIDガバナンス・ポリシーをKafkaクラスターとLambdaコンシューマ間で統一でき、規制準拠やセキュリティ強化が容易になる

### 技術的な注意点

- **IAM権限**: LambdaでのESM作成/更新権限（例: lambda:CreateEventSourceMapping / lambda:UpdateEventSourceMapping）や、クライアントシークレットをSecrets Managerに格納する場合はsecretsmanager:GetSecretValue等の追加権限が必要となる場合があります。具体的なIAMポリシーは実装に応じて確認してください。
- **リージョン制限**: 本機能は自己管理型Kafka ESMが利用可能なAWS商用リージョンで提供されます。利用可能リージョンはドキュメントで確認してください。
- **ネットワーク要件**: Lambdaが自己管理Kafka（またはIDプロバイダのトークンエンドポイント）へ到達可能であることが必要です。VPC内部のKafkaに接続する場合はLambdaのVPC設定（サブネット/セキュリティグループ/ENI）やルーティングを適切に構成してください。
- **機密情報管理**: OAuthクライアントシークレット等はAWS Secrets Managerやシステムマネージャーパラメータストアを使って安全に保管・参照することを推奨します。
- **既存ESMの対応**: 記事では「新しいKafka ESMを作成」と記載されており、既存のESMが自動的にOAuthに切り替わるとは限りません。既存マッピングの移行方法は事前に確認し、必要に応じて再作成やリプレースを検討してください。
- **コスト**: Lambdaの標準的な実行時間・リクエスト課金が適用されます。Secrets Managerの利用やデータ転送、追加の監視/ログ保管により別途費用が発生する可能性があるため、料金ページで確認してください。

- https://docs.aws.amazon.com/lambda/latest/dg/with-kafka.html

## [Aiml] Amazon Quick now supports brand templates for on-brand presentations and documents

- **公開日**: 2026-10-10 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-quick-brand-templates-on-brand-presentations-documents/

### 概要

Amazon Quickがブランドテンプレートのアップロードをサポートしました。組織の承認済みビジュアルを一元管理し、PowerPoint/Wordテンプレートから色・フォント・ロゴ・レイアウト・ルールを抽出してオンブランドな資料作成を自動化します。

### 変更内容・新機能の詳細

ブランドマネージャーはPowerPointまたはWordテンプレートをアップロードするか、SharePointなどの接続済みファイルストアからテンプレートを取得できます。Quickはテンプレートから色、フォント、ロゴ、レイアウト、ブランドルールを抽出し、ブランドマネージャーが抽出結果を確認・編集して組織配布できます。作成時にはテンプレートのルールを適用し、ルールに違反する要求があれば理由を説明してオンブランドな代替案を提示します。各タスクではブランドマネージャーが記述したガイダンスに基づき最適なテンプレートを選択しますが、ユーザーは別テンプレートを選ぶことも可能です。管理者はカスタム権限でテンプレートの作成・公開権限を制御でき、ブランド・マーケティング等の適切なメンバーのみがビジュアル基準を設定できるようにします。ブランドアセット機能は現時点でAmazon Quickのデスクトップアプリで一般提供されています。

### 影響範囲・利用シーン

- **対象ユーザー**: ブランドマネージャー、マーケティングチーム、デザインチーム、資料作成を行う全社員
- **利用シーン**: 会社フォーマットに準拠したプレゼン資料・ドキュメント自動生成、社内テンプレートの一元管理、外部委託や複数チーム間でのブランド一貫性維持
- **運用効果**: ブランドチェックの工数削減、デザイン整合性の自動担保、管理者による公開フローで誤ったテンプレート配布を防止可能
- **導入効果**: テンプレート準拠率の向上によりレビュー回数や手戻りを減らし、資料作成速度を向上できる

### 技術的な注意点

- **IAM権限**: 管理者はQuick固有のカスタム権限でテンプレート作成・公開権を付与する必要があるため、事前に権限設計を行ってください
- **対応ファイル形式**: PowerPoint (.pptx 等) と Word (.docx 等) がサポートされています（記事記載による）
- **テンプレート抽出とレビュー**: 色・フォント・ロゴ・レイアウトの自動抽出は行われるが、ブランドマネージャーによるレビュー/編集が必須。抽出結果が完全でない場合があるため公開前の確認を推奨します
- **外部ストレージ接続**: SharePointなどの接続を利用可能。接続先のアクセス権やAPI/コネクタ設定、社内ポリシーに従った権限管理が必要です
- **リージョン制限**: 記事ではリージョン制限に関する明示がないため、利用可否やデータ保存先は公式ドキュメント/管理コンソールで確認してください
- **コスト**: 記事に追加料金の明記はないが、Amazon Quick自体の利用形態や外部ストレージ（例: SharePoint）接続、データ転送に伴うコストが発生する可能性があるためコスト影響を確認してください
- **セキュリティ・コンプライアンス**: ブランド資産やロゴ等を格納・共有するため、アクセス制御、監査ログ、機密データ管理（社外秘扱いのテンプレートがある場合）を事前に設計してください
- **クライアント対応**: ブランドアセット機能は現時点でAmazon Quickのデスクトップアプリで一般提供と記載。Web/モバイルの対応状況はドキュメントで確認してください
