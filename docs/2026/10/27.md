## [Govcloud Us] Amazon Corretto October 2026 Patch Updates

- **公開日**: 2026-10-27 (JST)
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-corretto-oct-2026-patch-updates

### 概要

2026年10月26日、Amazon Correttoの複数バージョンに対するパッチアップデートが公開されました。Correttoは無償の商用利用可能なOpenJDKディストリビューションです。

### 変更内容・新機能の詳細

今回公開されたパッチは、以下のCorretto（OpenJDKのLTS/FR）バージョン向けです：Corretto 27.0.1.0.11、25.0.5.0.10、21.0.13.0.11、17.0.21.0.11、11.0.33.0.10、8u512。これらはバグ修正やセキュリティパッチ、依存ライブラリの更新を含むマイナーパッチリリースとして配布されています。ダウンロードはCorrettoのホームページから直接行えるほか、Linux環境ではAPT/YUM/APKリポジトリを設定することでパッケージマネージャ経由で取得・適用できます。Correttoはマルチプラットフォーム対応で商用利用に追加コストは発生しません。詳細な修正点やCVE情報は各バージョンのリリースノートで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Javaをプロダクションで運用する開発者、SRE、プラットフォームエンジニア
- **利用シーン**: Web/バッチアプリケーション、マイクロサービス、コンテナ基盤上のJavaランタイム更新作業
- **運用効果**: セキュリティ修正やバグ修正を適用することでランタイムの安定性と安全性が向上
- **互換性/移行**: LTS（8,11,17,21）とFeature Release（25,27）を含むため、既存のJavaバージョン戦略に合わせて段階的に適用可能
- **ダウンタイム影響**: ランタイム差し替えが必要なケースでは再起動などの運用影響が発生する可能性

### 技術的な注意点

- **インストール方法**: Corretto公式ページからバイナリをダウンロードするか、APT/YUM/APKリポジトリを設定してパッケージ管理で導入
- **パッケージ管理**: Debian/Ubuntu 用APT、RHEL/CentOS/Amazon Linux 用YUM/DNF、Alpine 用APKに対応（リポジトリ設定手順は公式ドキュメント参照）
- **互換性**: CorrettoはOpenJDK互換を目標としているが、JVMやネイティブライブラリ依存のアプリは事前にステージング環境で動作確認を推奨
- **セキュリティ**: 各パッチに含まれるCVEや修正内容はリリースノートで確認し、必要に応じて優先適用を検討
- **コスト**: Corretto自体は無償だが、更新作業に伴う運用コスト（テスト、ロールアウト、再起動等）は発生する
- **リージョン制限**: Correttoのバイナリ配布・パッケージはグローバルに提供されており、リージョン制限は特に無し（GovCloud等の特殊環境ではアクセス経路を確認）
- **サポート/ライフサイクル**: 各Correttoバージョンのサポート期間は公式のLTSポリシーに準拠。長期サポートが必要な場合はLTSバージョンを選択
- **IAM権限**: Correttoのダウンロード/インストール自体にAWS IAM権限は不要（AWSサービス上での自動配布やAMI更新などを行う場合は該当サービスの権限が必要）

## [Neptune] Amazon Neptune now supports online index rebuild to reclaim storage

- **公開日**: 2026-10-27 (JST)
- **カテゴリ**: Neptune
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/neptune-online-index-rebuild/

### 概要

Amazon Neptuneがオンラインでインデックス再構築する機能をサポートしました。ダウンタイムなしでインデックスの断片化を解消し、未使用ストレージを回収してクエリ性能やI/O効率を改善できます。

### 変更内容・新機能の詳細

オンラインインデックス再構築機能は、インサート／更新／削除によって生じたデータページ内の空き領域（断片化）をオンラインで再編成し、VolumeBytesUsedが高止まりする問題を解消します。処理中もライターインスタンスおよびリードレプリカ上で読み書きクエリは継続されるため、可用性を落とさずにメンテナンスが可能です。対象は全インデックス、quadインデックス、dictionaryインデックスのいずれかを選択でき、削除後のクリーンアップ、定期メンテナンス、ストレージ上限管理、性能チューニングに適しています。再構築時の並列度（concurrency）と書き込みバッファサイズを書き込み負荷と再構築速度のトレードオフとして調整可能であり、ストレージ枯渇を防ぐための組み込み保護機構も備えています。利用はAmazon Neptuneエンジン1.5.0.0以降、プロビジョンドのライターインスタンスで有効で、Gremlin／openCypher／SPARQLワークロードに適用されます。詳細な設定方法、API参照、チューニングガイダンスは公式ドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者、アプリケーションチーム、SRE/運用チーム
- **利用シーンまたは効果**: 大量の削除や更新でインデックスが断片化したデータベースのストレージ回収、定期メンテナンス、クエリ性能改善
- **運用効果**: ダウンタイムなしで未使用領域を回収できるため、I/Oコスト削減・クエリレイテンシ低減・ストレージ拡張の延期が可能

### 技術的な注意点

- **エンジンバージョン**: Amazon Neptune エンジン 1.5.0.0 以降が必要です
- **インスタンスタイプ/モード**: プロビジョンドのライターインスタンスで利用可能（Serverlessは非対応の可能性あり）
- **ターゲットインデックス**: 全インデックス、quadインデックス、dictionaryインデックスを個別に指定可能
- **パフォーマンス設定**: concurrency（並列度）と write buffer size を調整して再構築速度と運用負荷のバランスを取る必要があります
- **安全機構**: ストレージ枯渇を防ぐ保護メカニズムが組み込まれているが、運用中はVolumeBytesUsed等のメトリクスを監視してください
- **互換性**: Gremlin、openCypher、SPARQL ワークロードで効果あり
- **リージョン制限**: Amazon Neptune がサポートする全リージョンで利用可能と発表されています（詳細は公式ドキュメントで確認してください）
- **IAM権限**: 再構築APIを呼び出すためのNeptune管理操作実行権限が必要です。具体的なAPI/アクションは公式ドキュメントで確認してください
- **コスト**: 直接的な追加課金は明記されていませんが、再構築中の追加I/OやCPU使用により通常の使用料（I/O、インスタンス時間等）が増加する可能性があります

## [General] Amazon WorkSpaces Core Managed Instances now supports ModifyVolume API

- **公開日**: 2026-10-27 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-workspaces-cmi-modifyvolume/

### 概要

Amazon WorkSpaces Core の Managed Instances が ModifyVolume API に対応しました。これにより、インスタンスを停止・ボリュームを取り外すことなくボリュームサイズやボリュームタイプ、IOPS、スループットをインプレースで変更できます。

### 変更内容・新機能の詳細

ModifyVolume API を使うと、デプロイ済みの WorkSpaces Core Managed Instance にアタッチされた EBS ボリュームを再作成せずに変更できます。主な機能は次のとおりです：
- ボリュームサイズの拡張（最大 16,384 GiB まで）
- サポートされる Amazon EBS ボリュームタイプ間の切替
- gp3、io1、io2 の IOPS 調整
- gp3 のスループット変更
API は冪等性トークンをサポートしており、同一操作の重複実行を防げます。ボリューム変更の進捗と状態は Amazon EC2 の DescribeVolumesModifications で追跡できます。ModifyVolume は WorkSpaces Core Managed Instances が利用可能なすべてのリージョンで使用可能で、直接 API を呼び出すか、WorkSpaces Core のパートナーソリューション経由で利用できます。詳細な制約や振る舞い（例えば変更可能な組み合わせや制限値）は Amazon EBS User Guide の「Limitations」や WorkSpaces Instances API Reference の ModifyVolume 項目を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: WorkSpaces Core を利用するデスクトップ仮想化導入者、SRE、クラウド運用チーム
- **利用シーン**: ストレージ不足や性能要件の変化に応じて、稼働中インスタンスのボリュームをオンラインで拡張・性能変更するケース（例：ユーザーデータ増加、I/O 負荷増大対応）
- **運用効果**: インスタンスの再ビルドや停止を伴わずにストレージの拡張・性能調整が可能になり、ダウンタイム削減と運用効率向上につながる
- **コスト影響**: サイズ増加や高性能ボリューム（高IOPS/高スループット）へ変更するとストレージ料金・プロビジョニング料金が増加する可能性がある
- **可用性/リージョン**: WorkSpaces Core が提供されるすべてのリージョンで利用可能（ただし各リージョンの WorkSpaces の提供状況に依存）

### 技術的な注意点

- **IAM権限**: WorkSpaces Instances の ModifyVolume 実行権限に加え、DescribeVolumesModifications（EC2）などの権限が必要になる場合があります。事前にポリシーを確認してください
- **ファイルシステム/OS対応**: ボリュームを拡張した場合、ゲスト OS 側でパーティション/ファイルシステムの拡張操作が必要になることがあります（自動拡張されない環境があるため確認を推奨）
- **変更の可逆性**: 一般にボリュームサイズの縮小はサポートされないため、サイズ変更は取り消し不可となることに注意してください
- **EBS の制約**: ボリュームタイプや IOPS/スループットの上限や組み合わせには EBS 側の制約があります。具体的な制限は EBS User Guide を参照してください
- **進捗監視**: 変更処理の状態は DescribeVolumesModifications で取得可能。API は冪等性トークンをサポートしているため同一操作の二重実行を防げます
- **互換性**: 一部のボリュームタイプ間の切替や IOPS 設定は、特定の条件下で制約がある可能性があります（詳細は API リファレンスと EBS ドキュメントで確認）
- **コスト**: ボリューム性能や容量を上げると追加料金が発生します。事前に料金影響を評価してください

Amazon SageMaker Unified StudioがIdentity Center (IDC) ベースのドメインに対してライトモード（明るいテーマ）をサポートしました。ダークモードと合わせて表示モードを選べるようになり、ユーザーの視認性やアクセシビリティが向上します。

### 技術的な注意点

- **設定方法**: SageMaker Unified Studioの画面右上のProfile設定 -&gt; 'Customize appearance' で dark / light / device setting を選択します
- **必要な権限**: ユーザープロファイルの表示・更新を行う権限が必要（例: sagemaker:UpdateUserProfile 等）。IDCベースのドメインではIdentity Center経由のアクセス管理に注意してください
- **リージョン制限**: SageMaker Unified Studio が提供されているすべてのリージョンで利用可能（記事時点）
- **コスト**: 本機能自体に追加課金はありません
- **互換性/挙動**: 'Device setting' を選ぶとブラウザ上でOSのテーマ設定に合わせて表示が切り替わります。選択内容はユーザープロファイルに保存され、ブラウザや端末間で持続されます

## [Connect] Amazon Connect Customer expands testing and simulation to validate flow action outcomes

- **公開日**: 2026-10-27 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/connect-customer-validate-flow-actions/

### 概要

Amazon Connect Customerがテストおよびシミュレーション時にフロー内アクションの完了時に返す結果（Lambda応答、Amazon Lexの解決インテント、Agentic CXブロックで設定された変数など）を検証できるようになりました。これにより、失敗時にどのアクションが期待と異なる結果を返したかを直接特定でき、変更の本番投入前に問題を早期発見できます。

### 変更内容・新機能の詳細

これまではテストで「アクションが開始されたか」を確認する機能が中心でしたが、今回の拡張により「アクションが完了した際に返すデータ」を検証できるようになりました。検証対象には、AWS Lambda関数のレスポンス、Amazon Lexの解決済みインテント、Agentic CX（Agentic AI）ブロックが設定したフロー変数などが含まれます。テスト実行時に期待値を指定することで、実際の出力が期待と一致しない場合にそのアクションを特定して失敗として報告します。これにより、下流ステップから逆に辿って原因を特定する必要がなくなり、デバッグ時間が短縮されます。機能はConnect Customerのテスト＆シミュレーションUI／フレームワーク上で動作し、既存のフロー設計ワークフローやCI/CDの検証プロセスに組み込んで自動化することが可能です。リージョンごとの利用可能機能は「Availability of Connect Customer features by Region」で確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Connect Customerを使ってカスタマー向けフローを設計・運用する開発者、SRE、CXアーキテクト
- **利用シーン**: フロー変更の事前検証（LambdaやLexの応答を含むエンドツーエンド動作確認）、回帰テスト、自動化されたCI/CDの検証ステップ
- **運用効果**: 失敗時にどのアクションが期待と異なる結果を返したかを直接把握できるため、デバッグ時間と本番障害リスクを低減し、フロー変更をより短時間で安全にデプロイ可能

### 技術的な注意点

- **IAM権限**: テスト中に呼び出すLambdaやLex、その他バックエンドのリソースに対する実行・参照権限が必要です。テストUIや管理コンソールの表示にはConnect Customer関連の管理権限も必要です。
- **リージョン制限**: 機能の利用可否はリージョン依存です。正式なリージョン対応状況は「Availability of Connect Customer features by Region」を確認してください。
- **コスト**: テストやシミュレーション自体に追加課金モデルがある可能性や、テスト実行時に呼び出すLambda／Lex等の利用料が発生します。大規模な自動テスト実行では料金影響を見積もってください。
- **前提／互換性**: 検証対象のアクションは、完了時に構造化されたレスポンスやフロー変数を返す必要があります。エラーやタイムアウト時の挙動（部分的な出力や例外の伝播）が検証ポリシーに合致するか確認してください。
- **可観測性**: 期待値と実際のレスポンスの差分や、失敗したアクションの詳細ログ（トレースやイベント履歴）を活用すると問題の特定が容易になります。CloudWatchログやX-Rayなどとの連携を検討してください。
