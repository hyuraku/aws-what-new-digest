## [Cloudtrail] AWS Private CA now provides detailed certificate issuance logs

- **公開日**: 2026-10-05 (JST)
- **カテゴリ**: Cloudtrail
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-private-ca-certificate-issuance-logs/

### 概要

AWS Private CAが新たに詳細な証明書発行ログ（CloudTrailイベント IssueCertificateDetails）を出力するようになりました。発行予定のTBS証明書の全X.509フィールドや拡張、発行CA情報、リクエスター識別、成功／失敗の状態まで記録されます。

### 変更内容・新機能の詳細

新しいCloudTrailサービスイベント IssueCertificateDetails は、従来の IssueCertificate API 呼び出し成功を示す証明書ARNだけを残す管理イベントに代わり、発行対象の "to-be-signed (TBS)" 証明書の完全な内容（すべての X.509 フィールドと拡張）をキャプチャします。加えて、サブジェクト／発行者／シリアル番号／有効期間／テンプレート／署名アルゴリズムといった利便性のためのフィールドも含みます。発行が成功した場合だけでなく、署名前の失敗（例: name constraints 違反）で発行が中止されたケースも失敗理由つきでイベントが生成されます。各イベントはリクエスターを識別し、直接APIを呼ぶ場合はアカウントとIAMプリンシパル、コネクタや統合サービス経由の場合はサービスプリンシパルが記録されます。クロスアカウント設定ではイベントは CA オーナーアカウントに配信されます。これらのイベントは自動的に CloudTrail の管理イベントとして送信され、追加の有効化作業や追加料金は不要（標準の CloudTrail 料金が適用）です。CloudTrail 経由のため、Amazon EventBridge を用いたリアルタイム処理や、Amazon Athena でのバッチクエリによる監査・インベントリ作成・アルゴリズム移行追跡・失敗発行の監視などに利用できます。機能は AWS Private CA が提供されている全リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: 証明書を管理するセキュリティ/インフラ/プラットフォームチーム、監査担当者、SRE/運用チーム
- **利用シーン**: 証明書発行の監査証跡作成、環境全体の証明書インベントリ構築、署名アルゴリズム移行のトラッキング、失敗発行（事前検証エラー）監視
- **運用効果**: 署名前エラーも含めた完全な発行履歴が取得できるため、コンプライアンス証跡の充実、問題解析の迅速化、不正発行の検出精度向上
- **セキュリティ影響**: 証明書の TBS 内容（サブジェクト等）がログに残るため、ログアクセス制御と暗号化ポリシーの強化が必要
- **自動化適用**: EventBridge でリアルタイムアラートやワークフロー起動、Athena を使った定期レポート生成が容易に実装可能

### 技術的な注意点

- **イベント名**: IssueCertificateDetails（CloudTrail管理イベント）として送信されます
- **IAM権限**: CloudTrail イベントの閲覧や EventBridge トリガー、Athena でのクエリ実行に必要な権限を事前に設定してください（CloudTrail/EventBridge/Athena/S3 の権限）
- **リージョン制限**: AWS Private CA が提供されているすべてのリージョンで利用可能です
- **コスト**: CloudTrail の標準料金が適用されます。EventBridge や Athena、S3 による保存/クエリは別途料金が発生する可能性があります（Athena はスキャン量に応じた課金）
- **プライバシー/セキュリティ**: TBS（証明書内容）がログに含まれるため、ログの保存先（S3バケット）やCloudTrailログのアクセス制御、暗号化（SSE-KMS）を検討してください
- **ログ保持**: CloudTrail コンソールのイベント履歴は短期間（約90日）で、長期保存や分析が必要な場合は CloudTrail を S3 に配信してライフサイクルを管理してください
- **クロスアカウント**: クロスアカウント発行構成ではイベントは CA オーナーアカウントへ配信されます。受信側/送信側の権限設計に注意してください
- **注意点**: 証明書の最終的な発行（署名後）を確認する用途では引き続き実際の発行結果（署名済み証明書）を検証してください。IssueCertificateDetails は TBS と署名ステータス／失敗理由を提供しますが、運用フローに応じた確認処理を組み合わせてください

## [General] Announcing Amazon Nova 2.5 Sonic with improved reasoning for voice agents

- **公開日**: 2026-10-05 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-nova-2.5-sonic/

### 概要

Amazon Nova 2.5 Sonicが一般提供されました。リアルタイム音声エージェント向けの音声→音声モデルで、推論能力、指示遂行、ツール呼び出し精度とレイテンシが改善されています。

### 変更内容・新機能の詳細

Nova 2.5 Sonicはリアルタイム音声エージェント用のspeech-to-speechモデルのアップデートで、以下を主に改善しています。推論力の向上により会話中の文脈保持や複数ステップの指示遂行が安定し、外部ツール（バックエンドAPIやDBなど）の呼び出し精度と非同期ツール呼び出しの扱いが改善されています。これにより、たとえば顧客対応会話の中で注文照会→返品可否確認→返品開始といった一連処理を会話内で完結しやすくなります。パフォーマンス面ではレイテンシ短縮により応答が速く自然な対話が可能です。既存の機能も踏襲しており、堅牢な音声理解、7言語の表現豊かな音声（合成）、ターンテイキングの制御、音声とテキストを同一セッションで扱う能力、256Kトークンのコンテキストウィンドウをサポートします。また、Strands Bidi Agents（GA）と組み合わせることで数行のコードで本番レベルのボイスエージェントを構築でき、長時間会話や他エージェントとの連結が容易になります。提供はAmazon Bedrock経由で、対応リージョンは US East (N. Virginia)、US West (Oregon)、Europe (Stockholm)、Asia Pacific (Tokyo) で、価格は Nova 2 Sonic と同等です。

### 影響範囲・利用シーン

- **対象ユーザー**: 音声エージェント開発者、コンタクトセンター／カスタマーサポート、SaaSプロダクトの音声機能担当者
- **利用シーンまたは効果**: リアルタイム顧客対応（注文照会・返品処理等）、パーソナルAIアシスタント、IVRの高度化、マルチステップワークフローの自動化
- **運用効果**: レイテンシ低下による自然な対話体験、推論精度向上でのタスク完了率改善（人手介入削減）、ツール呼び出し精度向上によるバックエンド連携の信頼性向上

### 技術的な注意点

- **リージョン制限**: 提供リージョンは US East (N. Virginia)、US West (Oregon)、Europe (Stockholm)、Asia Pacific (Tokyo) のみです。未対応リージョンでは利用不可。
- **IAM権限**: Bedrockの利用権限（Bedrockへのアクセス権、関連するKMSやAPI呼び出し権限）が必要です。実行ロールやポリシーで音声ストリーミングやS3/KMSアクセスを適切に付与してください。
- **コスト**: Nova 2.5 Sonic自体はNova 2 Sonicと同価格ですが、リアルタイムストリーミング、長いコンテキスト（256Kトークン）や頻繁なツール呼び出しは総費用を押し上げる可能性があります。想定トラフィックでコスト試算を行ってください。
- **コンテキストウィンドウ**: 最大256Kトークンをサポートします。クライアント/SDKが大きなコンテキストを扱えるか、トークン管理やサマリー戦略を検討してください。
- **レイテンシ/パフォーマンス**: モデル側でレイテンシ改善がある一方、ネットワークや音声ストリーミング実装、外部ツール応答時間が総合的な体験に影響します。低遅延が必要な場合はネットワーク設計とバックエンドAPIの最適化を行ってください。
- **データ保護**: Bedrock経由のモデル呼び出しはログやメトリクスが残る可能性があります。機密データを扱う場合は暗号化・アクセス制御・ログ削減の設計を確認してください。
- **互換性/統合**: Strands Bidi Agents（GA）との組み合わせで開発が容易になります。既存の音声パイプラインやテキストエージェントとの連携設計を見直し、非同期ツール呼び出しやターンテイキング制御を利用する実装に対応させてください。
- **サポート言語**: 7言語の表現音声をサポートしますが、言語ごとの音声品質やチューニングの挙動は確認してください。
