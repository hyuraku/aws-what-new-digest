## [Security Hub] AWS Security Hub now supports resource criticality for prioritization

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: Security Hub
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/security-hub-resource-criticality/

### 概要

AWS Security Hubがリソースの「クリティカリティ（重要度）」を露出優先度に追加しました。これにより、組織の中でビジネスにとって重要なリソースに対する脆弱性や検出結果の優先順位付けが容易になります。

### 変更内容・新機能の詳細

Security Hubは自動化ルールでリソースごとのクリティカリティを設定できるようになりました（例：特定アカウント内のすべてのコンピュートリソースを Very High にマーク）。このルールは既存のインベントリと、Security Hubが新たに検出するリソースの双方に適用されます。さらに、Security Hubはリソースタグやリソース名からクリティカリティを推定し（追加設定不要）、どのソースが値を決定したかを記録します。クリティカリティはコンソールの Resources ページに列として表示され、ソート・フィルタ・グループ化が可能です。また、検出結果の「Impact assessment」タブにも表示され、優先対応すべき問題の判断材料になります。リソースクリティカリティ機能は Security Hub Essentials に含まれ、追加料金不要で全顧客に自動的に有効になっています。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティ運用チーム、中央セキュリティチーム、SRE、クラウドアーキテクト
- **利用シーンまたは効果**: ビジネスクリティカルなリソースに関連する検出結果を優先的に対処することで、限られた運用リソースを重要度の高い対応に集中可能
- **運用効果**: 自動化ルールやタグベースの推定により、既存資産と新規発見資産の両方に一貫した重要度付けができ、トリアージ効率やインシデント対応のスピードが向上する

### 技術的な注意点

- **IAM権限**: 自動化ルールの作成・編集やリソース属性の更新を行うには、Security Hubの管理操作を実行できるIAM権限（コンソール/APIアクセス権）が必要です
- **リージョン制限**: 機能の利用は Security Hub が利用可能なリージョンに依存します。利用可否はリージョン一覧で確認してください
- **コスト**: Security Hub Essentials に含まれており、追加料金は発生しません（ただし Security Hub 自体の料金体系は別途適用されます）
- **有効化**: 追加の有効化操作は不要で、全顧客に対して常時オンです
- **タグ/ネーミング依存**: クリティカリティの推定はリソースタグや名前に依存するため、正確な結果を得るにはタグ付け・命名規約の整備が望ましい
- **自動化ルールの適用範囲**: ルールは既存のインベントリと新規検出リソースの双方に適用されます。ルールの設定による意図しない上書きや優先度設定の競合に注意してください

## [ECS] Amazon ECS adds LiveTaskCount and removes the charge for RunningTaskCount metric

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: ECS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/ecs-service-metrics/

### 概要

Amazon ECSに新しいサービスメトリクス「LiveTaskCount」が追加され、サービス利用状況メトリクスとして無償で提供されます。あわせて、CloudWatch Container Insightsの既存メトリクス「RunningTaskCount」も2026年10月1日から追加料金なしで利用可能になります。

### 変更内容・新機能の詳細

LiveTaskCountはサービス内で「アクティブに稼働している」タスク数を報告する新しいメトリクスで、タスクのdesired/current状態に関わらずACTIVATING、RUNNING、DEACTIVATINGの各状態を含みます（スケールイン時のconnection drainingなど、停止遷移中のタスクもカウントされる）。このため、 autoscalingポリシーやキャパシティプランニングで“実際にメトリクスを生成する可能性がある全タスク数”を把握したい用途に適しています。LiveTaskCountはECSのサービス利用状況メトリクスの一部として無償で提供され、CloudWatch Container Insightsへのオプトインは不要です。既存のCloudWatch Container InsightsのRunningTaskCountは「currentとdesiredの両方がRUNNINGのタスクのみ」をカウントし、サービスの健全性・安定性の指標として引き続き有用です。今回の更新により、このRunningTaskCountもContainer Insightsユーザー向けに追加料金が発生しなくなります。変更はECSが提供されているすべてのリージョンで有効で、RunningTaskCountの価格変更は2026年10月1日から自動的に適用されます。特別な設定やアクションは不要です。

### 影響範囲・利用シーン

- **対象ユーザー**: コンテナ運用者、SRE、プラットフォームチーム、DevOpsエンジニア
- **利用シーンまたは効果**: オートスケーリングポリシー（スケールイン/スケールアウト）とキャパシティプランニングにおいて、遷移中タスクを含めた正確な稼働タスク数に基づく判断が可能
- **運用効果**: Container Insights課金を抑えつつ（RunningTaskCountの無償化）、より完全なアクティブタスク数を参照できるため誤スケールや容量不足のリスク低減が期待できる
- **コスト影響**: LiveTaskCount自体は無償。RunningTaskCount（Container Insights内）は2026-10-01以降無償となり、CloudWatch利用コストの削減効果が見込めるが、Container Insightsの他メトリクスやログ収集は引き続き課金対象となる可能性がある

### 技術的な注意点

- **IAM権限**: メトリクス参照にはCloudWatchの読み取り権限（例: cloudwatch:ListMetrics、cloudwatch:GetMetricData、cloudwatch:GetMetricStatistics 等）が必要です。ECS管理操作とは別にCloudWatch権限を確認してください。
- **リージョン制限**: 全AWSリージョンで利用可能（ECSが提供されているリージョンに準拠）。リージョンごとのサービス提供状況は確認してください。
- **コスト**: LiveTaskCountは無償。RunningTaskCount（Container Insights内）のメトリクスは2026-10-01以降自動で無償化されます。ただしCloudWatchの他メトリクス、ログ、アラーム、Container Insightsの追加データ収集などは別途課金されます。詳しくはCloudWatch料金ページを確認してください。
- **互換性/挙動差**: LiveTaskCountはACTIVATING/DEACTIVATINGも含むため、既存のRunningTaskCount（currentとdesiredがRUNNINGのみ）と値が異なります。既存のスケーリング閾値や監視アラートを移行・併用する際は閾値調整や評価が必要です。
- **設定/運用**: LiveTaskCountは追加設定不要でECSサービス利用状況メトリクスとして利用可能。Container Insightsのオプトインは不要だが、Container Insights固有の他メトリクスを使う場合は引き続き有効化が必要です。
- **適用日**: RunningTaskCountの料金変更は2026-10-01から自動適用。特別な操作は不要です。

## [General] AWS Agent Registry now supports custom metadata for registry records

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-agent-registry-custom-metadata-registry-records

### 概要

AWS Agent Registryがレジストリレコードに対するカスタムメタデータをサポートしました。組織固有の構造化フィールドをレコードに付与して検索・ガバナンスを改善できます。

### 変更内容・新機能の詳細

各レジストリについて一度スキーマを定義し、共通属性とタイプ固有フィールド（例：エージェントのモデルファミリ）を追加できます。各フィールドはフリーテキスト、URL、Boolean、または許可値リスト（choice）をサポートし、必須フィールドや許容値の検証はレコード作成・更新時に実行されます。パブリッシャーはチーム所有者、データ分類、レビュー状況などの組織固有メタデータを直接レコードに記録できます。カスタムメタデータはAWS Management Console、AWS CLI、AWS SDK、およびレジストリのMCPエンドポイントからの検索・フィルタリングに利用可能です。利用可能リージョンは米国東部（バージニア北部）、米国西部（オレゴン）、アジア太平洋（シドニー）、アジア太平洋（東京）、欧州（アイルランド）です。

### 影響範囲・利用シーン

- **対象ユーザー**: 組織内でエージェント、MCPサーバー、エージェントスキル、ゲートウェイ、カスタムリソースを管理するSRE/プラットフォームチーム、ガバナンス/コンプライアンス担当者、開発者
- **利用シーンまたは効果**: 組織固有の属性（チーム所有、データ分類、レビュー状況、モデルファミリ等）でレコードをタグ付けして検索・フィルタ可能になり、リソース発見性と一貫したガバナンスが向上する
- **運用効果**: 自動化パイプラインやコンソールでのフィルタにより、ポリシー違反や期限切れレビューの早期検出、責任範囲の明確化が可能
- **導入影響**: 既存の発行ワークフローやCI/CDでカスタムメタデータの設定・検証を組み込む必要がある（必須フィールドが追加される場合、既存レコードの更新が必要）

### 技術的な注意点

- **IAM権限**: カスタムメタデータのスキーマ作成・変更やレコード更新には該当するAgent RegistryのPut/Update系権限が必要（具体的なアクション名はドキュメントを確認してください）
- **リージョン制限**: 対応リージョンは US East (N. Virginia)、US West (Oregon)、Asia Pacific (Sydney)、Asia Pacific (Tokyo)、Europe (Ireland) のみ
- **スキーマ設計**: スキーマはレジストリ単位で一度定義する設計。共通属性とタイプ固有フィールドを使い分け、必須フィールドや許容値を慎重に設計すること
- **バリデーション**: レコード作成・更新時に必須フィールドと許容値が検証されるため、自動化フローではバリデーションエラー処理を実装する必要がある
- **API/ツール**: カスタムメタデータはコンソール、CLI、SDK、およびMCPエンドポイントから参照・検索・フィルタ可能。既存の検索・表示処理を更新して新フィールドを扱う必要がある
- **コスト**: 記事に追加料金の言及はないが、メタデータの追加によりCloudTrailやバックアップ、クエリ実行によるAPIコール増加が発生する可能性があるため間接的なコスト増を検討すること
- **互換性**: 必須フィールドを後から追加すると既存レコードがエラーになる可能性があるため、変更は段階的に適用し既存データのマイグレーション計画を立てること

## [General] Amazon DCV releases version 2026.0 with RHEL 10 support and new clients

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-dcv-2026-0/

### 概要

Amazon DCV 2026.0 がリリースされ、RHEL 10/ Rocky Linux 10/ CentOS 10/ Ubuntu 26.04（Wayland セッション対応）や macOS クライアントの追加、Windows/Linux/macOS クライアントの性能改善やリダイレクト機能が導入されました。リモートデスクトップ/アプリ配信の帯域・遅延改善とプラットフォーム互換性の拡張が主な狙いです。

### 変更内容・新機能の詳細

主な変更点と技術的説明:
- Linuxプラットフォーム対応拡張: RHEL 10、Rocky Linux 10、CentOS 10、Ubuntu 26.04 をサポート。これらの Linux ホスト／セッションはモダンな Wayland ディスプレイサーバ上で動作可能になり、Wayland ベースのグラフィックスタックと互換する。既存の X11 ベース環境とは動作差異が生じる可能性がある。
- 新しい macOS クライアント: ゲームパッドサポートを追加し、macOS クライアントでの入力デバイス対応を強化。
- クライアント更新（Windows / Linux / macOS）: パフォーマンス改善を含む最新クライアントを提供。Linux と macOS クライアントでは H.264 のフレームスライス（frame slice）サポートとスライス単位のマルチスレッドデコードを導入し、低遅延化と CPU/GPU の並列デコード効率を向上。
- Windows ホストでの URL リダイレクト: リモートセッション内で設定されたリンクを、クライアント側のローカルブラウザで開けるようにする機能。セキュリティとポリシー設定に基づき制御可能。
- Windows のプリンタ設定リダイレクト: クライアント側のプリンタプリファレンス（既定プリンタなど）をリモートセッションへ渡せるようになり、印刷ワークフローが改善。
- macOS サーババージョンの EC2 サポート: Amazon EC2 上の新しい macOS サーババージョンをサポートし、macOS ベースのリモートワークフローが EC2 で利用可能に。
- 互換性と運用: 多くの新機能はサーバ（DCV サーバー）とクライアントの両方を 2026.0 へ更新することで有効。H.264 スライスやマルチスレッドデコードはクライアント／サーバ双方の対応と、適切なコーデックハードウェアまたはドライバが必要。

### 影響範囲・利用シーン

- **対象ユーザー**: リモートグラフィックス/デスクトップ配信を利用する開発者、CG/ビジュアライゼーション担当、リモートワークを提供するSRE/VDI運用者
- **利用シーン**: GPU/高解像度アプリのリモート作業（レンダリング、CAD、ゲームストリーミング）、macOS を含むマルチプラットフォーム環境でのリモートデスクトップ提供、クライアント側のブラウザやプリンタ設定連携
- **運用効果**: Wayland 対応による最新 Linux 環境での互換性向上、H.264 スライスとマルチスレッドデコードによる遅延低減と帯域効率化、URL/プリンタリダイレクトでユーザビリティが向上

### 技術的な注意点

- **バージョン互換性**: 新機能（例: H.264 スライス、URL/プリンタリダイレクト）はサーバとクライアント双方の対応が必要。クライアントを古いままにすると機能制限が発生します。
- **Wayland 注意点**: Wayland 上で動作するため、アプリケーションやコンポジタ（例: GNOME, KDE の Wayland セッション）の互換性確認が必要。X11 固有の操作や拡張は動作しない場合があります。
- **コーデック/ハードウェア**: H.264 フレームスライスとスライスベースのマルチスレッドデコードはクライアント／サーバ側のコーデック実装やハードウェア（GPU デコード/エンコード）に依存します。ドライバとライブラリの更新を推奨します。
- **設定/ポリシー**: URL リダイレクトやプリンタリダイレクトはホスト側の DCV 設定（dcv.conf 等）とクライアント設定で有効化/制御が必要。組織のセキュリティポリシーで情報漏えいリスクを検討してください。
- **ネットワーク/ファイアウォール**: DCV のデフォルトポート（例: TCP 8443 など）を適切に開放し、TLS 証明書設定を行ってセキュアに運用してください。
- **EC2/mac インスタンス**: macOS サーバサポートは EC2 Mac インスタンス（または対応 AMI）が必要。これらインスタンスは全リージョンで利用できない/キャパシティ制限がある可能性があります。
- **IAM/権限**: DCV 自体は OS レベルのソフトウェアですが、EC2 インスタンス作成・EBS・IAM ロールなどの操作には適切な AWS 権限が必要です。
- **コスト**: DCV ソフトウェア自体は通常の利用で追加料金はないが、EC2（特に GPU インスタンス、mac インスタンス）やデータ転送、ストレージのコストが増加します。
- **リージョン制限**: 新しいプラットフォームサポートや EC2 上の macOS サポートはリージョンによって未対応の場合があります。事前に利用リージョンでのサポート状況を確認してください。

## [Deadline Cloud] AWS Deadline Cloud now helps users find their accessible resources in the Deadline Cloud monitor

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: Deadline Cloud
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/deadline-cloud/resources

### 概要

AWS Deadline Cloud のモニター画面が、ユーザーが実際にアクセス可能なキュー／フリート／ジョブを直接表示するようになりました。これにより、ファーム全体へのアクセス権がないユーザーでも必要なリソースを簡単に発見できます。

### 変更内容・新機能の詳細

今回のアップデートにより、Deadline Cloud のモニター（単一のエントリポイントURL）にアクセスしたユーザーは、自分がアクセス権を持つキュー、フリート、ジョブを一覧で確認できるようになりました。表示内容には、対象リソースの識別に必要な親ID（例：ファームID 等）と、そのユーザーに対するアクセスレベル（直接付与された権限およびグループ経由で継承された権限の両方）が含まれます。従来は、たとえばあるキューのみアクセス可能なユーザーが作業を始めるために管理者からファームIDを受け取る必要がありましたが、今回の機能でそのやり取りが不要になります。結果として、チームは権限レベルが異なるメンバー間で単一のモニターURLを共有しても、各自が見えるリソースのみが自動的に表示される安全な運用が可能になります。機能は Deadline Cloud が提供されているすべての AWS リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: Deadline Cloud を利用するアーティスト、レンダーファーム運用者、テクニカルディレクター、SRE/運用チーム
- **利用シーン**: 権限が限定されたユーザー（特定キューのみアクセス等）がモニター経由で自分のジョブやキューの親IDを確認して作業開始する場面
- **運用効果**: 管理者による手動のID共有を減らし、エントリポイントURLをチームで共有しても各ユーザーに見える範囲だけが表示されるため、運用の手間とヒューマンエラーを削減できる

### 技術的な注意点

- **IAM権限**: ユーザーが表示されるリソースは Deadline Cloud のアクセスコントロール（直接付与とグループ継承の両方）に基づきます。事前に該当キュー／フリート／ジョブへの適切な権限設定が必要です
- **リージョン制限**: 本機能は Deadline Cloud が利用可能なすべての AWS リージョンで提供されています（リージョンによる未対応情報は記事では言及されていません）
- **コスト**: リソース発見機能自体に追加料金は明記されていませんが、Deadline Cloud の利用料金や生成されるジョブの計算コストは通常どおり発生します
- **互換性／クライアント要件**: モニターはウェブベースのエントリポイントで機能する想定です。ブラウザでのアクセスが前提となるため、ブラウザ側の制限やネットワーク接続（VPC/プロキシ等）の確認が必要になる場合があります
- **既存ワークフローへの影響**: 管理者からファームIDを配布する運用は不要になりますが、権限設計（グループ権限と直接権限の整理）は引き続き重要です

## [General] Amazon Location Service launches an interactive API Playground featuring Places, Routes and Maps APIs

- **公開日**: 2026-10-14 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-location-service-api-playground

### 概要

Amazon Location ServiceにインタラクティブなAPI Playgroundが追加され、Places、Routes、Mapsの全14APIをコードを書かずに試せる可視化ツールが利用可能になりました。コンソール上で実際のAPIコール、地図上での結果確認、パラメータ調整、リクエストスニペットのコピーが行えます。

### 変更内容・新機能の詳細

今回のリリースで、Places（Geocode, ReverseGeocode, Autocomplete, Suggest, SearchText, SearchNearby, GetPlace）、Routes（CalculateRoutes, CalculateRouteMatrix, CalculateIsolines, OptimizeWaypoints, SnapToRoads）、Maps（Dynamic Map, GetStaticMap）を含むAmazon Location Serviceの全14 APIを対象にした対話型API Playgroundが提供されます。開発者はコンソール上で実際のAPIリクエストを発行してレスポンスを確認でき、結果はインタラクティブな地図上にレンダリングされます。パラメータを変更して挙動を確認したり、そのまま使えるリクエストスニペット（RESTリクエストやSDK呼び出し例）をコピーしてアプリに貼り付けることが可能です。これにより、SDKやテストスクリプトの初期セットアップなしで、住所検証、トラック向けの複数停留所ルート設計、走行時間アイソクローヌ（到達可能領域）の可視化、アプリへのマップ埋め込みなどを素早くプロトタイプできます。Playgroundは以下リージョンで利用可能です：US East (Ohio), US East (N. Virginia), US West (Oregon), Asia Pacific (Mumbai), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Malaysia), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (Ireland), Europe (London), Europe (Spain), Europe (Stockholm), South America (São Paulo)。

### 影響範囲・利用シーン

- **対象ユーザー**: フロントエンド/バックエンド開発者、地図／位置情報サービス担当者、SRE、プロダクトマネージャー
- **利用シーンまたは効果**: 住所検証やジオコーディングの確認、トラック対応のマルチストップ経路設計テスト、到達時間/サービスエリア可視化、地図埋め込みのプロトタイプ作成が短時間で可能
- **運用効果**: SDKやテスト環境構築コストを削減し、プロトタイプ～本番移行の初期検証を迅速化。パラメータ調整やレスポンス確認が容易なためデバッグ時間が短縮される

### 技術的な注意点

- **IAM権限**: API Playgroundでの操作は実際のAPI呼び出しを行うため、Amazon Location Serviceの呼び出し権限（コンソール利用者には適切なgeo:権限またはマネージドポリシーの付与）が必要です。実運用では最小権限の付与を検討してください。
- **リージョン制限**: Playgroundは限定されたリージョンで利用可能（記事記載のリージョン一覧を参照）。サポート外リージョンでは利用できません。
- **コスト**: Playground自体のUI利用は無料でも、Playgroundから発行したAPIリクエストは通常のAmazon Location Serviceの課金対象（Places/Routes/Mapsのリクエスト単価）になります。大量テストはコストに注意してください。
- **リソース前提**: Mapsの描画や一部APIはMapリソースやPlace Index、Route Calculatorなどのリソース設定が必要になる場合があります。Playgroundが生成するリクエストスニペットを本番で使う際は対応するリソースの作成・設定を行ってください。
- **データプロバイダと精度**: ジオコーディングやルーティングの結果精度・利用可能機能は地域やデータプロバイダに依存します。地域特性やプロバイダ仕様を確認してください。
- **スロットリング/クォータ**: 実環境同様にAPIにはレート制限やクォータがあります。負荷テスト時はスロットリングに注意してください。
