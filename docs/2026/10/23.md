## [Connect] Amazon Connect Customer now supports customizing the Customer Profiles app on the agent workspace

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/connect-customer-customize-cp

### 概要

Amazon Connect Customer Profilesで、管理者がProfile Explorerで作成したレイアウトを使ってエージェントワークスペースに表示する顧客情報の項目と表示方法をカスタマイズできるようになりました。エージェントの業務ごとに最適化した情報表示を割り当てられます。

### 変更内容・新機能の詳細

Customer Profilesはコンタクト履歴と複数ソースの顧客データを統合してリアルタイムに表示する機能を提供します。今回の更新により管理者はProfile Explorerでウィジェット（例：コンタクト履歴、連絡先情報、算出属性（ライフタイムバリュー等）、専用フィールド）を組み合わせたレイアウトを作成・保存でき、従来のCustomer Profiles表示の代わりに特定のエージェントやエージェントグループに割り当てられます。レイアウトは業務別に最適化でき、例として手荷物紛失担当にはコンタクト履歴、現在のフライト・手荷物チケット情報を、ロイヤリティ担当には会員ステータス、嗜好、今後のフライト情報を表示するように設定できます。また、AI Profile Summaryウィジェットを含めることで、顧客プロファイルを要約しエージェントが注視すべきポイントを強調表示できます。Profile Explorerは管理者向けの画面で編集・割当を行い、実行時はエージェントワークスペースに割当済みのレイアウトが反映されます。影響するのは表示レイヤー（UI）であり、バックエンドの顧客データ統合やAPI自体の仕様変更は伴いません。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンター管理者、スーパーバイザー、エージェント、導入担当エンジニア
- **利用シーン**: 業務別に必要な顧客情報のみを表示して対応効率を上げる（例：航空の手荷物担当・ロイヤリティ担当で異なる表示）
- **運用効果**: エージェントの対応時間短縮、フォローアップ精度向上、研修負担の軽減、顧客体験（CX）の改善

### 技術的な注意点

- **IAM権限**: Profile Explorerの編集・割当にはAmazon Connect管理者権限や関連するCustomer Profilesの権限が必要です。必要なIAMポリシーを事前に確認してください。
- **リージョン制限**: 利用可能リージョンは US East (N. Virginia)、US West (Oregon)、Africa (Cape Town)、Asia Pacific (Seoul)、Asia Pacific (Singapore)、Asia Pacific (Sydney)、Canada (Central)、Europe (Frankfurt)、Europe (London) です。上記以外のリージョンでは未対応です。
- **コスト**: 既存のCustomer Profiles利用料金や、AI要約などの追加機能に別途料金が発生する可能性があります。サービスの料金ページで確認してください。
- **既存表示の扱い**: 管理者が新レイアウトを割り当てるとレガシーのCustomer Profilesビューの代わりに表示されます。ロールアウト前にステージングで挙動確認を推奨します。
- **データとプライバシー**: AI Profile Summaryや統合データを表示するため、個人情報の取り扱い・保存場所（データロケーション）やコンプライアンス要件を確認してください。
- **互換性**: この変更は主にUI（エージェントワークスペースの表示）に関するもので、既存のAPIやデータ統合フローは影響を受けませんが、ウィジェットで参照する属性が適切にCustomer Profilesに存在することを確認してください。

## [General] AWS Continuum for code vulnerabilities is now generally available 

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-continuum-for-code-vulnerabilities-is-now-generally-available

### 概要

AWS Continuum for code vulnerabilities が一般提供されました。コード脆弱性の検出から検証、優先度付け、修復までを自動化し、開発ワークフローへ直接パッチをプルリクエストで提供します。

### 変更内容・新機能の詳細

Continuum for code vulnerabilities は AWS 環境からリソーストポロジー、アイデンティティ関係、ネットワーク到達性などを含むコンテキストグラフを構築し、既存の脆弱性検出結果を取り込み、ソースコードをスキャンします。検出した問題は隔離されたサンドボックスで実際にエクスプロイト可能かを検証し、ビジネスインパクト（ブラスター半径等）に基づいて優先度を付けます。修復案は開発者ワークフローへプルリクエスト（PR）として提出され、エクスプロイト証明や影響範囲の評価が添付されます。タスクごとに適切なAIモデルを選択し、まず「Learn」モードで修復案を提案・承認し、信頼が得られれば設定したガードレール内で自律的に動作する「Enforce」モードへ移行できます。Amazon GuardDuty や AWS Security Hub など既存のセキュリティサービスと連携して動作します。利用可能リージョンはリージョンテーブルで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: アプリケーション開発者、セキュリティチーム、SRE/運用チーム
- **利用シーン**: 継続的なコードベースの脆弱性検出と実証（実行可能性）検証、開発ワークフローへの自動パッチ提案（PR）
- **運用効果**: 脆弱性の誤検知を減らし、本当に影響する問題を優先的に修正できるため、対応工数削減と修復のスピードアップが期待できる

### 技術的な注意点

- **IAM権限**: リポジトリ（CodeCommit/GitHub等）や環境メタデータへのアクセス、脆弱性スキャン・サンドボックス実行用の権限が必要。最小権限でのロール設計と承認フローの設定を推奨。
- **リージョン制限**: 対象リージョンは限定されるため、使用前に AWS リージョンテーブルで Continuum の提供状況を確認してください。
- **コスト**: Continuum サービス利用料に加え、サンドボックス実行（コンピュート）、スキャン処理、データ転送等の追加コストが発生する可能性があります。価格ページを確認してください。
- **データ取扱い/コンプライアンス**: ソースコードや環境のコンテキスト情報を解析するため、機密情報や個人情報の取り扱いに注意。データ保持・転送のポリシーを確認・適用してください。
- **自動修復リスク**: Enforce（自律運用）モードでは自動で修正を適用する可能性があるため、まず Learn モードで十分に精度を検証し、マージルールや承認フロー、CI テストを必須にすることを推奨します。
- **ログと監査**: CloudTrail、CloudWatch Logs 等で Continuum の操作とサンドボックス実行を記録・監査できるよう設定してください。
- **既存ツールとの互換性**: 既存の脆弱性スキャナやセキュリティ製品からの取り込みに対応していますが、入力フォーマットや統合方法は事前に確認してください。
- **ネットワーク/サンドボックス設計**: エクスプロイト検証用サンドボックスは厳密に隔離し、プロダクションリソースへのアクセスを防ぐネットワーク制御を行ってください。

## [Opensearch Service] Amazon OpenSearch Serverless now supports a 5-second default refresh interval

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: Opensearch Service
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-serverless-supports-5-second-refresh-interval/

### 概要

Amazon OpenSearch Serverlessの既定のリフレッシュ間隔が10秒から5秒に短縮されました。検索コレクションとベクターコレクションの両方に適用され、書き込み直後のデータがより早く検索可能になります。

### 変更内容・新機能の詳細

リフレッシュ間隔は、新たにインジェストされたドキュメントが検索可能になるまでの遅延を決める設定です。本変更によりデフォルトが10秒から5秒に短縮され、追加の設定や操作を行わなくても次世代のAmazon OpenSearch Serverless上の検索コレクションおよびベクターコレクションで自動的に適用されます。結果として読み取り後の可視性（read-after-write）が向上し、頻繁に更新される全文検索コンテンツや、RAG（retrieval-augmented generation）、セマンティックサーチ、レコメンデーション／パーソナライゼーションなどのベクター利用ケースで、新規データに対する検索応答がより早く反映されます。本機能はAmazon OpenSearch Serverlessが提供されている全24リージョンでデフォルト有効です。なお、リフレッシュ頻度の増加はインデクシングオーバーヘッド（CPU・I/O・メモリ使用量、スループット）を高める可能性があるため、ワークロードに応じたモニタリングと負荷試験が推奨されます。詳細や構成方法は公式ドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: OpenSearch Serverlessを利用するアプリケーション開発者、データエンジニア、ML／AIチーム（RAG・セマンティック検索・レコメンド運用者）
- **利用シーンまたは効果**: 頻繁にデータをインジェストするシステムで、書き込み後すぐに最新データを検索・応答したいケース（ログ解析のリアルタイムビュー、チャットボットの最新ナレッジ参照、RAGの最新ドキュメント取得）
- **運用効果**: 検索・RAG応答の鮮度が向上し、ユーザ体験や生成回答の正確性が改善される（追加設定不要で自動的に反映）
- **パフォーマンスの影響**: リフレッシュ回数増加によりインデクシング負荷とリソース消費が増す可能性があるため、スループットや遅延の監視が必要
- **コスト影響**: リソース消費増（CPU・I/O）により間接的に料金に影響する可能性があるため、負荷状況を監視して最適化を検討すること
- **適用範囲**: 次世代（Next generation）Amazon OpenSearch Serverlessの検索コレクションとベクターコレクションにデフォルト適用（全24リージョン）

### 技術的な注意点

- **IAM権限**: 本変更はデフォルト設定の変更のため通常追加のIAM権限は不要だが、コレクション設定を変更・確認する場合は該当の管理権限（serverless関連の権限）が必要
- **リージョン制限**: Amazon OpenSearch Serverlessが利用可能な全24リージョンでデフォルト適用（サービス未提供リージョンは対象外）
- **コスト**: リフレッシュ頻度の増加はインデクシング負荷を高め、結果的にコンピューティング／ストレージI/Oコストに影響する可能性あり。負荷状況によってはスケーリング設計の見直しを検討
- **モニタリング**: インデックス/コレクションの書き込みスループット、レイテンシ、CPU・メモリ、ディスクI/O、refresh関連メトリクスを監視し、しきい値超過時は調整やバッチ処理方式の導入を検討すること
- **設定の上書き/互換性**: 本記事では「デフォルトが5秒に短縮」と記載。既にカスタム設定を行っている場合や特定のチューニングを適用している場合は、ドキュメントや管理画面で現在のコレクション設定を確認して運用方針を決定すること
- **テスト推奨**: 本番適用前にステージング環境でインデクシング負荷と検索応答の観察を行い、必要に応じて設計（バッチ化・スロットリング・リソース割当）を調整すること

## [General] AWS CloudFormation now simplifies stack update rollback operations

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-cloudformation-cdk/

### 概要

CloudFormationがスタックの更新ロールバック完了を単一操作で簡素化する「force rollback」オプションを提供開始しました。CLI、SDK、AWS CDK、AIエージェントなどあらゆるワークフローで利用でき、ロールバックの手順を簡素化します。

### 変更内容・新機能の詳細

更新ロールバックはスタックを既知の正常な状態へ戻す操作ですが、従来は一部のリソースが自動ロールバックできない場合、影響を受けた各リソースを特定して個別にリトライする必要がありました。今回の機能では「continue update rollback」に対してforce rollbackオプションを指定することで、CloudFormationがロールバックを単一の操作で完了し、スタックをデプロイ可能な状態に戻します。自動でロールバックできなかった（例：CloudFormation外での変更があった）リソースは一覧として記録されるため、次回デプロイ前にドリフトや設定差分を確認・修正できます。推奨ワークフローは、force rollbackでロールバックを完了し、その後ドリフト対応を有効にした（drift-aware）変更セットを作成して差分を確認してから次のデプロイを行うことです。この機能はCLI、各種SDK、AWS CDK、AIエージェントから利用可能で、追加料金不要で全リージョンで提供されています（詳細はリージョン表を参照）。

### 影響範囲・利用シーン

- **対象ユーザー**: CloudFormationを利用するインフラエンジニア、SRE、DevOps、プラットフォームチーム、AWS CDKユーザー
- **利用シーン**: 更新中に一部リソースで自動ロールバックできない問題が発生した際に、個々のリソース対応をせずにスタックを迅速にデプロイ可能状態へ戻したいケース
- **運用効果**: ロールバック作業負荷と復旧時間の短縮、人的ミスの低減、CI/CDパイプラインの復旧高速化
- **影響範囲**: すべてのCloudFormationワークフロー（AWS CLI、SDK、AWS CDK、AIエージェント）で利用可能。ロールバックできなかったリソースは記録され、手動での修正が必要になる可能性あり

### 技術的な注意点

- **IAM権限**: cloudformation:ContinueUpdateRollback の実行権限が必須。加えて Describe/Detect/ChangeSet 関連（cloudformation:DescribeStacks, cloudformation:DetectStackDrift, cloudformation:CreateChangeSet など）や対象リソースに対する変更権限が必要です
- **リージョン制限**: 記事では「全リージョンで利用可能」とありますが、組織の利用リージョンでのサービス可用性は AWS Region table で確認してください
- **コスト**: Force rollback 操作自体に追加料金は発生しません。ただし、ロールバックやその後のリソース再作成・変更による通常のリソース利用料は発生します
- **動作上の注意**: force rollback はロールバック不能なリソースをスキップしてスタックをデプロイ可能状態に戻しますが、スキップされたリソースは手動での確認・修正が必要です。根本原因の特定（外部変更や依存関係）の対応を必ず行ってください
- **自動化/CI**: CDKやCI/CDパイプラインからこのオプションを使用する場合、ロールバックを自動完了させるポリシーが適切かどうか検討し、スキップされたリソースの通知や追跡を組み込んでください

- https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/using-cfn-continuing-rollback.html

## [Aiml] Amazon SageMaker AI announces training session APIs for serverless model customization

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/training-session-apis-on-sagemaker-ai

### 概要

Amazon SageMaker AI のサーバーレス型モデルカスタマイズが「トレーニングセッション API」を一般提供開始しました。これにより GPU インフラを管理せずに、ユーザーが独自のトレーニングループを API 呼び出しで実行できるようになります。

### 変更内容・新機能の詳細

トレーニングセッション API は状態保持されるライブセッションを提供し、forward_backward(), optim_step(), sample() といった操作を API として呼び出せます。SageMaker AI は GPU 割当、モデル・LoRA の読み込み、分散実行、フォールト回復、チェックポイント保存、セキュリティ管理を代行するため、利用者は SFT（Supervised Fine-Tuning）や DPO（Direct Preference Optimization）、各種強化学習アルゴリズムを自分のコード内で再現・拡張できます。これによりカスタム損失関数、独自の RL 報酬信号、データカリキュラム、最新研究のアルゴリズム実装などが可能です。課金は「処理したトークン単位」で行われ、報酬スコアリング等のローカル計算は GPU 時間として請求されません。あわせて SFT/RL の実装例を集めた「SageMaker training sessions cookbook」も提供され、開始手順としては SageMaker Python SDK をインストールしてクックブックをクローンするか、SageMaker Studio のノートブックから開始できます。一般提供リージョンは US East (N. Virginia)、US West (Oregon)、Asia Pacific (Mumbai) です。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、研究者、ML プラットフォームチーム
- **利用シーン**: カスタムトレーニングループ（SFT/DPO の再現、独自の RL 報酬関数、LoRA を使った微調整、最新論文のアルゴリズム実装）をクラウド上で実行したい場面
- **運用効果**: GPU インフラや分散処理の運用負荷を軽減しつつ、柔軟なトレーニング設計（チェックポイント・再開・フォールト回復含む）が可能になり、開発速度と再現性が向上する
- **コスト影響**: トークン処理に基づく従量課金に変わり得るため、トークン量が多いワークロードではコスト影響を評価する必要あり
- **開発体験**: Python コードから直接 API を呼び出す形で既存のトレーニングループを移植しやすく、クックブックでテンプレートを素早く利用できる

### 技術的な注意点

- **リージョン制限**: 一般提供は現時点で US East (N. Virginia)、US West (Oregon)、Asia Pacific (Mumbai) のみ。その他リージョンは順次対応の可能性あり
- **IAM権限**: SageMaker の実行権限（トレーニングセッション作成/操作）、S3 への読み書き、KMS（暗号化を利用する場合）、必要に応じて ECR/AWS-ManagePolicy の権限を確認してください
- **チェックポイント/ストレージ**: チェックポイントは S3 等に保存されるため S3 ストレージ料金が発生します。長期保持やバージョン管理は運用設計を検討してください
- **課金の注意**: 課金は「処理したトークン単位」で計算される点を確認してください。ローカルでの報酬計算等の CPU 作業は GPU 時間としては請求されないが、S3 やデータ転送など他の費用は別途発生します
- **依存ライブラリ/SDK**: SageMaker Python SDK の最新版が必要。クックブックやサンプルは SDK と互換性のあるバージョンを前提にしているため、互換性を確認してください
- **分散/性能**: SageMaker が分散実行を管理するものの、アルゴリズムの通信パターンやバッチ設計によりパフォーマンスが変わるのでベンチマークとチューニングを推奨します
- **セキュリティ/ネットワーク**: VPC エンドポイント、KMS、IAM ロール等を適切に設定してデータアクセス制御とログ監査を行ってください
- **互換性/移植性**: 既存のローカルトレーニングループは API 呼び出しへ移植可能だが、状態管理（セッションの状態・チェックポイント）の扱いを明確にする必要があります

## [Direct Connect] AWS Direct Connect announces 100G expansion in Bangalore, India

- **公開日**: 2026-10-23 (JST)
- **カテゴリ**: Direct Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-direct-connect-100g-bangalore/

### 概要

AWS Direct Connectがインド・バンガロールの既存ロケーション（Netmagic DC2）で100 Gbps専用接続を拡張しました。同ロケーションから中国リージョンを除くパブリックリージョン、AWS GovCloud、Local Zonesへプライベート接続が可能です。

### 変更内容・新機能の詳細

今回の拡張により、Netmagic DC2（バンガロール）で100 Gbpsの専用物理ポートを利用したDirect Connect接続を確立できるようになりました。Direct Connectはお客様のデータセンター、オフィス、コロケーション環境とAWS間の専用物理ネットワーク接続を提供し、インターネット経由よりも一貫したレイテンシとスループットを実現します。100 Gbpsポートは従来の1/10/40 Gbpsと同様にVirtual Interface（Private/Public/Transit）の作成、BGPピアリング、Direct Connect Gatewayを介した複数リージョンやTransit Gatewayとの統合といった既存のDirect Connect機能と組み合わせて利用できます。なお、本ロケーションからは中国（北京/寧夏）リージョンは対象外です。世界で150以上のDirect Connectロケーションの一つとして提供されます。

### 影響範囲・利用シーン

- **対象ユーザー**: 大量データ転送や低遅延接続を必要とするエンタープライズ、メディア/エンターテインメント、ハイパフォーマンスコンピューティング、機械学習ワークロードを持つクラウドアーキテクト・ネットワークエンジニア
- **利用シーン**: 大容量のバックアップ/レプリケーション、データレイクへの大量インジェスト、オンプレミスとAWS間のハイブリッドクラウド接続、マルチリージョンVPC接続（Direct Connect Gateway経由）、高スループットのメディア配信やリアルタイム分析
- **運用効果**: インターネット経由より安定したスループットと低遅延を実現し、大容量転送時間短縮とネットワークパフォーマンスの一貫性向上により運用効率とアプリケーション可用性が向上する

### 技術的な注意点

- **IAM権限**: Direct Connectの作成/管理にはdx:CreateConnection、dx:CreatePrivateVirtualInterface、dx:CreatePublicVirtualInterface、dx:CreateDirectConnectGatewayなどの権限が必要です。事前に適切なIAMポリシーを用意してください
- **リージョン制限**: 本ロケーションからは中国リージョン（北京/寧夏）への接続はできません。パブリックリージョン、AWS GovCloud、Local Zonesには接続可能です。
- **接続仕様**: 100 Gbpsは専用物理ポート（Dedicated Connection）として提供されます。Virtual Interface（Private/Public/Transit）とBGPピアリング、Direct Connect Gateway/Transit Gatewayとの統合が可能です。
- **冗長化/設計**: 可用性のために複数ポートやLAG（Link Aggregation）による冗長構成、別ロケーションでのスタンバイ接続を検討してください。
- **調達/運用**: ポート在庫や設置工事（ローカルデータセンター事業者とのクロスコネクト）に時間がかかるため、導入前にAWS/Netmagicおよびコロケーション事業者と調整し、リードタイムを確認してください。
- **コスト**: 100 Gbpsポートのポート時間課金とデータ転送費用、コロケーション側（Netmagic）でのクロスコネクト費用などが発生します。料金は地域・構成で異なるため事前にDirect Connectの価格ページで確認してください
