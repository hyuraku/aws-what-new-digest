## [Govcloud Us] Amazon Bedrock expands API support and introduces Cross-Region Inferencing for OpenAI models in AWS GovCloud (US)

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-openai-runtime-govcloud/

### 概要

Amazon BedrockがOpenAI GPT-5.6（Terra／Luna）をbedrock-runtimeエンドポイントでサポートし、Responses／Converse／Chat CompletionsのネイティブOpenAI APIをAWS GovCloud (US)で利用可能にしました。さらにGovCloud (US)内でリージョン間推論（Cross-Region Inferencing）を提供し、スループットと冗長性を向上させます。

### 変更内容・新機能の詳細

主な追加機能は次のとおりです。1) OpenAI GPT-5.6（TerraおよびLuna）をbedrock-runtimeエンドポイント上で利用可能にし、Responses API、Chat Completions API、Converse APIのネイティブAPI呼び出しがBedrock上で動作するようになりました。これにより既存のOpenAIクライアントや統合をほぼそのままBedrockで利用できます。2) Cross-Region InferenceをAWS GovCloud (US)リージョン内でサポートし、推論リクエストを自動的に両GovCloudリージョン間へルーティングして高スループットと冗長性を実現します（ユーザー側でマルチリージョンのキャパシティ管理は不要）。3) bedrock-runtimeでネイティブOpenAI APIが動作するため、これらのモデル呼び出しは他のBedrockモデルと同様にアカウントレベルの管理対象となり、モデル呼び出しログ（Amazon S3またはCloudWatch Logsに配信可能）、CloudWatchメトリクス（呼び出し数、トークン数、レイテンシ、スロットル、エラー等）、およびAWS Cost Explorer / AWS Cost and Usage Reportでの課金内訳に含まれます。4) Cross-Region Inferenceは、Bedrock上でOpenAIモデルを提供しているすべてのAWSリージョンでも利用可能です。導入にあたっては各モデルのモデルカード（GPT-5.6 Terra/Luna）をBedrockユーザーガイドで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: GovCloud (US)を利用する政府機関、コンプライアンス重視の企業、セキュア環境で高スループットなLLM推論を必要とする開発者およびSREチーム
- **利用シーン**: 機密データをUS国内に留めつつ高トラフィックのチャットボット／生成AI推論（Responses/Chat/Converse）のスケール処理、災害時やスパイク時の冗長化
- **運用効果**: リージョン間で自動ルーティングされることでキャパシティ管理負荷を低減し、ピーク時のスループット増大と高可用性を確保可能
- **コンプライアンス効果**: GovCloud内でルーティングが行われるため、USデータ主権要件を満たしつつ外部リージョンへのデータ移転を回避できる
- **コスト影響**: クロスリージョンでの利用により処理量が増えると利用料およびトークンベース課金が増加する可能性がある（課金はCost Explorer/CURでモデル別に把握可能）

### 技術的な注意点

- **IAM権限**: Bedrockの実行権限（bedrock:InvokeModel等）およびCloudWatch/S3へログ出力するための許可を事前に確認・付与してください
- **リージョン制限**: Cross-Region InferenceはAWS GovCloud (US)内の両リージョン間でルーティングします。OpenAIモデルのCross-Region Inferenceは、BedrockでOpenAIモデルが提供されているリージョンで利用可能です。利用前に対象リージョンでの提供状況を確認してください
- **コスト**: モデル呼び出しはトークン／呼び出しベースで課金されます。クロスリージョン利用により総処理量が増えるとコスト増の可能性があるため、事前に想定トラフィックで試験を行って見積もってください
- **ログ／監視**: 呼び出しはBedrockのモデル呼び出しログおよびCloudWatchメトリクスに統合されます。ログの配信先（S3/CloudWatch Logs）やメトリクスの監視設定を確認してください
- **データ主権・セキュリティ**: GovCloud内でのルーティングによりUSデータ主権を維持できますが、実際のデータフローと保存場所についてはモデルカードと導入環境の設定を必ず確認してください
- **設定／有効化**: Cross-Region Inferenceやbedrock-runtimeでのOpenAI API利用に関する具体的な有効化手順や設定は公式ドキュメント（モデルカード／ユーザーガイド）を参照してください
- **モデル確認**: GPT-5.6（Terra／Luna）の性能、制約、利用上の注意点は各モデルカードに記載されています。安全性・出力制御要件がある場合はモデルカードを確認のうえ追加のフィルタリングやポリシーを適用してください

## [Govcloud Us] Web Search now available on Kiro in AWS GovCloud (US)

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/kiro-web-search-aws-govcloud-us/

### 概要

Kiro の Web 検索機能が AWS GovCloud (US) で利用可能になりました。これにより、Kiro エージェントがインターネット上の最新情報にリアルタイムでアクセスし、最新の検索結果やページ内容を参照して回答できます。

### 変更内容・新機能の詳細

Kiro の Web 検索は、モデルの訓練データに含まれない最近の変更や最新トピックに関する問いに対して自動的に外部ウェブ検索とページ取得（web fetch）を行い、検索結果や取得したページ内容を用いて回答を生成します。Web 結果を使った回答には出典（引用）が付与されます。組織単位の管理者は Kiro コンソールの Settings から Web 検索および Web fetch を無効化できます。チームや個別のカスタムエージェント単位では、エージェントから Web ツールを削除したり、能力ベースのアクセス制御（capability-based permission rules）でブロックすることが可能です。監査・利用状況の追跡にはモニタリング／トラッキングガイドを参照してください。本機能は AWS GovCloud (US) リージョン向けに提供されており、政府系や規制対応が必要なワークロード向けのリージョンでの利用が想定されています。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS GovCloud (US) を利用する政府機関、公共機関、規制対象企業、セキュリティ重視の組織およびKiroを利用する開発者・SRE・AI/MLチーム
- **利用シーンまたは効果**: インシデント対応時の最新情報取得、法令・規制の最新動向リサーチ、サポートチャットボットの最新回答提供、ナレッジベース外の最新技術情報の参照により回答精度が向上
- **運用効果**: 人手での検索を減らし応答品質を改善。出典が付くことで検証性が高まり監査対応が容易になる
- **セキュリティ/コンプライアンス影響**: 外部サイトへのリクエストが発生するため、CUI や機密情報の取り扱いポリシーの確認と適切な制限が必要
- **コスト影響**: Web fetch に伴うデータ転送や Kiro の利用量増加により、間接的なコスト増が発生する可能性がある

### 技術的な注意点

- **リージョン制限**: 現時点では AWS GovCloud (US) リージョンでの提供（他リージョンの対応状況はドキュメント参照）
- **IAM権限**: Kiro コンソール上での設定変更は管理者権限が必要。組織・チームレベルのポリシー設定やカスタムエージェントの編集権限も確認すること
- **データフロー/外部通信**: エージェントが外部ドメインへアクセスしてページ内容を取得するため、アウトバウンド通信・DNS・プロキシ設定、及びログに記録されるメタデータの扱いを確認すること
- **コンプライアンス**: GovCloud は政府向けコンプライアンス特性を持つが、Web 検索で取得される外部情報の保存・共有については組織のコンプライアンスポリシー（例: CUI、分類情報）を遵守する必要あり
- **監査/ログ**: モニタリングとトラッキングの設定を行い、検索クエリや取得先のログを監査できるようにすること（監査要件がある組織は必須）
- **コスト**: 直接の追加料金モデルは製品仕様を確認するが、データ転送や API 呼び出し増加による間接コストが発生する可能性あり
- **設定運用**: 組織レベルで無効化、チーム/エージェントレベルで除外や権限制御が可能。導入前にテスト環境で影響範囲を確認すること

## [Connect] Amazon Connect Customer automatically saves in-progress emails as drafts

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-connect-email-draft-save/

### 概要

Amazon ConnectのエージェントUIが編集中のメールを自動でドラフト保存する機能が追加されました。接続断やブラウザの誤閉じ・更新後でも、作業中のメールを復元して継続できます。

### 変更内容・新機能の詳細

エージェントが作成中のメール（本文、宛先、件名、添付ファイルの参照情報）は、編集途中でも自動的に保存されます。エージェントが再接続したりブラウザを再度開いた際に、保存されたドラフトが復元され、作業を中断した時点の内容を引き継げます。さらに、保存されたドラフトデータは顧客のAmazon S3バケットに出力してアクセスできるため、外部アプリケーションやワークフローと連携してドラフト情報を利用・分析できます。この記事の説明からは、ドラフトには本文・受信者情報・件名・添付ファイル参照が含まれるとありますが、添付ファイルの実データの保持方法（参照のみかオブジェクトとしてS3に保存されるか）は、S3保存設定やAmazon Connectの実装設定に依存します。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Connectを利用するコンタクトセンターのエージェント、スーパーバイザー、システム管理者
- **利用シーン**: エージェントの編集中メールが接続断やブラウザ誤操作で失われるリスクを低減。中断復帰時に作業を継続可能にするため、応対品質維持や応答時間短縮に寄与
- **運用効果**: 作業のやり直しや顧客への再確認が減り、エージェント生産性が向上。ドラフトデータをS3経由で外部システム（CRMや監査ログ基盤）と連携することにより、ワークフロー自動化やコンプライアンス監査が容易になる

### 技術的な注意点

- **IAM権限**: S3バケットにアクセスする連携を構成する場合、該当バケットへのPut/Get/List権限やAmazon Connect側で必要なIAMロール設定が必要です。管理者は権限を適切に付与してください。
- **データ保持・暗号化**: ドラフトデータの保持期間や暗号化はS3側のバケットポリシーやライフサイクル設定で管理します。機密情報の保存・転送に関するコンプライアンス要件を確認してください。
- **添付ファイル**: 記事では「添付ファイルの参照」が復元されるとありますが、添付データの実体保存方法（S3にオブジェクトとして保存されるか、一時参照か）は設定に依存する可能性があるため、実装時に確認してください。
- **コスト**: S3への保存はストレージ・リクエスト課金の対象になります。ドラフトの量・保持期間によっては運用コストが発生するため、ライフサイクルや削除ポリシーを検討してください。
- **リージョン制限**: 機能の提供リージョンは随時拡張されるため、利用を予定しているリージョンでサポートされているかAWSコンソールまたはWhat's Newの該当記事で事前に確認してください。

## [Bedrock] Daybreak Red from OpenAI now available to eligible customers on Amazon Bedrock in AWS GovCloud (US-East)

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/openai-daybreak-red-govcloud-east/

### 概要

OpenAIのDaybreak Red（GPT-5.6 Cyber）が、承認済みユーザー向けにAmazon Bedrock上でAWS GovCloud (US‑East)および米東部（オハイオ）で利用可能になりました。脆弱性調査・エクスプロイト再現・緩和策開発向けに設計された、より審査されたアクセスとハードウェアレベルの保護を備えたモデルです。

### 変更内容・新機能の詳細

Daybreak Red（GPT-5.6 Cyber）はOpenAIのDaybreakサイバーディフェンス計画の一部で、許可された脆弱性研究者や検証済み防御者が複雑なセキュリティ問題を安全に調査できるよう設計されています。主な技術点は以下の通りです：
- 用途設計: 許可された脆弱性調査、エクスプロイトの再現、緩和策（ミティゲーション）開発向けに最適化。
- アクセス管理: 強力な本人性確認（identity verification）、監視、アクセス制御が導入され、従来よりも拒否（refusal）が少ない設定で調査を許可。
- ハードウェア保護: Bedrockの次世代推論エンジン上で動作し、チップレベルでのzero-operatorアクセス（オペレーターによるアクセス禁止）を強制。これにより推論時の機密性が向上。
- データ利用: 推論（inference）データはモデルの学習には使用されず、OpenAIにデータを共有する必要はないと明記。
- 提供領域と入手方法: 米東部（オハイオ）およびAWS GovCloud（US‑East）で提供。利用にはOpenAIのDaybreakアクセスへの申請・承認が必要で、承認後にAWSアカウントチームと連携して有効化するフロー。

### 影響範囲・利用シーン

- **対象ユーザー**: 政府機関や規制の厳しい環境にあるセキュリティチーム、脆弱性研究者、レッドチーム、フォレンジック/IR担当者
- **利用シーンまたは効果**: 許可された脆弱性調査、エクスプロイト再現、パッチ/緩和策の検証、セキュリティ製品の評価および運用上の脅威ハンティング
- **運用効果**: チップレベルのアクセス制御と厳格なID確認により機密データの安全な取り扱いが可能になり、脆弱性検証の迅速化と誤拒否による作業停止の低減が期待できる

### 技術的な注意点

- **IAM権限**: Amazon Bedrockと該当リージョンのリソースに対する適切なIAMポリシー（Bedrockの推論呼び出し権限など）が必要です
- **リージョン制限**: 利用可能リージョンは米東部（オハイオ）とAWS GovCloud (US‑East)のみです
- **コスト**: Bedrockの推論料金に準じ、GovCloud利用や追加のデータ処理/監査ログ保存により追加コストが発生する可能性があります
- **アクセス/承認プロセス**: OpenAIのDaybreakアクセスへの申請と承認が必須。承認後はAWSアカウントチームと連携してアクセスを有効化します
- **データ利用とコンプライアンス**: OpenAIは推論データをモデル学習に使用しないとしていますが、組織のデータガバナンス・コンプライアンス要件（分類、保管、ログ管理）は引き続き満たす必要があります
- **利用制限**: Daybreakは「許可された」脆弱性研究向けであり、不正利用（悪用目的のエクスプロイト生成など）は明確に禁止されています
- **Bedrock統合**: Bedrockの次世代推論エンジンAPI/SDKを介して利用可能。既存のBedrockインテグレーション（認証、監査ログ、ネットワーク設定）を活用してください
- **ハードウェア保証**: チップレベルでのzero-operatorアクセスが適用されるため、運用者やクラウドオペレータによる推論データへの物理的/ソフト的アクセスが制限されます

## [CloudFront] Amazon CloudFront now provides viewer ISP and post-quantum TLS details 

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: CloudFront
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-viewer-isp-post-quantum-visbility/

### 概要

Amazon CloudFrontが、視聴者のISP（インターネットサービスプロバイダ）情報と、各ビューアーのTLS接続で使用された暗号情報（ポスト量子暗号を含む）を示す2つのオプションヘッダをオリジンへ転送できるようになりました。これにより、ネットワーク別のトラフィック解析やPQC（ポスト量子暗号）採用状況の可視化が可能になります。

### 変更内容・新機能の詳細

追加されたヘッダは以下の2つです。
- CloudFront-Viewer-ISP: 視聴者が接続してきたネットワーク事業者（ISP）の名称を含みます。これにより、どのプロバイダ経由のリクエストかをオリジンで把握できます。
- CloudFront-Viewer-TLS-Details: 各ビューアーのTLS接続で用いられた暗号情報（鍵交換方式、署名スキーム、署名公開鍵の種類など）を返します。これにより、接続がポスト量子暗号（PQC）を利用しているかどうかを判別できます。
実装方法は、対象ヘッダをオリジンリクエストポリシーに追加し、そのポリシーを該当のCloudFrontディストリビューションに紐付けることです（キャッシュキーへの影響は別途キャッシュポリシーで制御します）。オリジン側は受け取ったヘッダを解析してログ記録／振り分け／集計に利用できます。詳細と手順はCloudFront開発者ガイドの「Adding CloudFront headers」と「Controlling origin requests with a policy」を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: CDN利用者全般（クラウドエンジニア、SRE、セキュリティチーム、プロダクト分析者）
- **利用シーン**: ネットワーク別のトラフィック集計・パフォーマンス比較、特定ISP起因の異常トラフィックの隔離・対処、PQC採用率の測定と対応クライアントの特定
- **運用効果**: ネットワーク単位での障害切り分けやパフォーマンス最適化が容易になり、PQC移行の進捗把握や非対応クライアントの検出による段階的対応が可能
- **セキュリティ／コンプライアンス**: TLS暗号情報により暗号強度の確認やポリシー違反の検出ができる一方、ISP情報は個人関連データに該当する可能性があり、取り扱いに注意が必要

### 技術的な注意点

- **ヘッダ名**: 正確なヘッダ名は CloudFront-Viewer-ISP と CloudFront-Viewer-TLS-Details です
- **有効化手順**: 対象ヘッダをオリジンリクエストポリシーに追加し、そのポリシーをディストリビューションにアタッチします（キャッシュキーは別のキャッシュポリシーで制御）
- **IAM権限**: Distribution の更新権限（例: cloudfront:UpdateDistribution など）を持つ必要があります。ポリシー管理を行う権限も必要です
- **リージョン制限**: CloudFrontはグローバルサービスのためリージョン単位の制限は基本的にありません（ただし関連するログ保存先やオリジンのリージョンは考慮してください）
- **コスト**: 新機能自体に追加料金は通常ありませんが、オリジンへ送信されるヘッダ増加によりオリジン側の受信データ量やログ保管量が増え、結果的にコスト増加する可能性があります
- **キャッシュ影響**: オリジンリクエストポリシーはオリジンに送るヘッダを制御しますが、キャッシュ挙動への影響はキャッシュポリシー（Cache Policy）で制御します。ヘッダをキャッシュキーに含める設定を誤るとキャッシュ効率が低下する可能性があります
- **プライバシー/コンプライアンス**: ISP情報は位置情報や個人情報に関連する可能性があるため、ログ保存・解析・外部共有時は法規制（GDPR等）や社内ポリシーを確認してください
- **オリジン対応**: オリジン側でヘッダ値のパース処理・フォーマット変換・ログ記録を実装する必要があります。ヘッダの値の表記やアルゴリズム名は将来的に更新される可能性があるため、柔軟に扱ってください
- **セキュリティ注意**: オリジンに直接届く外部入力のため、ヘッダ値は信頼せず入力検証とログの機密管理を行ってください

### 変更内容・新機能の詳細

Amazon MSKは、データ転送時の暗号化でTLS 1.3をサポートする名前付きセキュリティポリシーを提供します。管理者はクラスタ設定で用意されたポリシーを選択して、そのクラスタが受け入れるTLSバージョン（例: TLS 1.2のみ、TLS 1.2+1.3、TLS 1.3のみ）および許可される暗号スイートを定義できます。ポリシー適用後、ポリシー要件を満たさない接続は拒否されます。TLS 1.3を許可するポリシーは、TLSハンドシェイクの高速化やより強いセキュリティ（改良された鍵派生・簡素化されたハンドシェイク・AEAD暗号の利用）を提供し、将来のポスト量子暗号導入の前提条件にもなります。両方のバージョンを許容するポリシーを選べば、クライアントはサポートする最高バージョンでネゴシエートできるため、クライアントを段階的にアップデートしながら移行できます。既存クラスタはボタン操作（ポリシー選択）で切り替え可能で、追加料金は発生しません。機能はAmazon MSK Provisionedが提供されている全リージョン（GovCloud (US)含む）で利用可能です。

- **利用シーン**: ストリーミングデータの通信路保護、コンプライアンス適合（PCI/DSS、金融機関要求等）、ポスト量子準備作業
- **運用効果**: TLS 1.3採用により接続の暗号強度とハンドシェイク性能が向上し、段階的なクライアント移行が可能でセキュリティポリシー管理が容易になる

### 技術的な注意点

- **IAM権限**: クラスタ設定（セキュリティポリシー）の変更にはMSKの管理権限（例: msk:UpdateClusterConfiguration等）が必要です
- **クライアント互換性**: TLS 1.3はクライアント側のTLSスタック（JVMバージョン、OpenSSLバージョン、Kafkaクライアント実装など）のサポートが必要です。古いJVMやライブラリはTLS 1.3非対応のため、混在ポリシーでの段階的移行を推奨します
- **切替影響**: ポリシー適用後は要件に合致しない接続が拒否されるため、本番適用前にステージングで接続互換性を確認してください
- **リージョン制限**: すべてのAmazon MSK Provisioned提供リージョンで利用可能（GovCloud (US)も含む）
- **コスト**: 機能自体に追加料金は発生しませんが、クライアント/ミドルウェアのアップグレードや検証作業に伴う運用コストは発生する可能性があります
- **運用上の注意**: インター・ブローカー通信やクライアント証明書（相互TLS）等、既存のTLS設定との整合性確認が必要です
- **移行手順（概略）**: 1) クライアントがTLS 1.3をサポートしているか確認 2) ステージングでTLSポリシーを適用して接続検証 3) 本番クラスタにポリシーを適用 4) モニタリングで接続失敗を確認しロールバック準備

## [Rds For Oracle] Amazon RDS for Oracle no longer requires automatic minor version upgrades for JVM, Spatial, Locator, and OLAP options

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Rds For Oracle
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/oracle-jvm-spatial-locator-olap-options-amvu-optional/

### 概要

Amazon RDS for Oracleで、JVM／Spatial／Locator／OLAPオプションを使用するDBインスタンスに対して、自動マイナーバージョンアップグレード（automatic minor version upgrades）を無効化できるようになりました。従来はこれらのオプションを使うと自動アップグレードが必須でしたが、今回オプション利用時でもユーザー側で適用タイミングを制御できます。

### 変更内容・新機能の詳細

これまでRDS for OracleでJVM、Spatial、Locator、OLAPオプションが有効なDBインスタンスは自動マイナーバージョンアップグレード（AMVU）を必須設定として要求されていました。今回の変更により、新規および既存の該当DBインスタンスでAMVUフラグをオフにできるようになり、マイナーバージョンの適用を手動または計画的に行う運用が可能になります。注意点として、AMVUをオフにした場合はセキュリティフィックスやバグ修正の適用がユーザーの責任になるため、定期的なマイナーバージョン適用（パッチ適用）の運用が推奨されます。自動的にアップグレードを維持しつつ環境ごとの適用順序を制御したい場合は、AWS Organizationsのアップグレードロールアウトポリシーを利用できます。本機能は、Amazon RDS for Oracleが利用可能なすべての商用リージョンおよびAWS GovCloud (US) リージョンで利用可能です。詳細はAmazon RDSユーザーガイドの「Oracleへのオプション追加」ページを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: RDS for Oracleを利用しており、JVM／Spatial／Locator／OLAPオプションを有効化しているDB管理者・データベースエンジニア
- **利用シーン**: 本番と検証環境でアップグレードタイミングを分けたい、リリース窓口や検証完了後にマイナーバージョンを適用したい運用（例: 検証環境で先行適用→問題なければ本番へ適用）
- **運用効果**: 自動アップグレード必須の制約から解放され、パッチ適用のタイミングを業務影響に合わせて制御可能。検証やステージング運用がしやすくなる
- **リスク**: AMVUをオフにするとOracleのマイナーリリースに含まれるセキュリティ修正やバグフィックスが自動で適用されなくなるため、未適用のまま放置するとセキュリティ・互換性リスクが増える
- **ガバナンス**: 自動維持したい場合はAWS Organizationsのアップグレードロールアウトポリシーで組織単位の適用順序管理が可能

### 技術的な注意点

- **IAM権限**: DBインスタンスのパラメータや設定を変更するためのRDS関連IAM権限（rds:ModifyDBInstance 等）が必要です
- **リージョン制限**: Amazon RDS for Oracleが利用可能なすべての商用リージョンおよびAWS GovCloud (US) リージョンで有効（記事時点）
- **コスト**: 本機能自体に追加料金は発生しませんが、手動パッチ適用に伴うメンテナンス作業・ダウンタイムや検証コストは運用負荷として発生する可能性があります
- **互換性**: 一部のOracleオプションやバージョンで特別な注意が必要な場合があるため、マイナーバージョン適用前にオプションの互換性を確認してください
- **運用推奨**: AMVUをオフにする場合は定期的（例: セキュリティポリシーに基づくスケジュール）にマイナーバージョンを適用する運用フローを整備し、スナップショットやバックアップを必ず取得してください
- **自動化**: AWS Organizationsのアップグレードロールアウトポリシーや、Infrastructure as Code／CI/CDパイプラインで適用順序やタイミングを制御する設計が有効です

## [WAF] AWS WAF announces automatic SDK integration for Amazon CloudFront distributions

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: WAF
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-waf-automatic-sdk-integration-amazon-cloudfront/

### 概要

AWS WAFがAmazon CloudFront配信に対する自動的なJavaScript SDK組み込みを発表しました。CloudFrontが配信するHTMLに自動でAWS WAF JavaScript SDKの&lt;script&gt;タグを挿入し、アプリケーション側のコード変更やデプロイ作業なしでクライアントサイドのシグナルを提供します。

### 変更内容・新機能の詳細

有効化すると、CloudFrontは配信するHTMLレスポンスにAWS WAF JavaScript SDKへの&lt;script&gt;タグを自動で追加します。追加されたSDKは、以下3つのAWS WAF管理ルールグループで利用されるクライアントサイドのシグナルを供給します：Bot Control（targeted inspectionレベル）、Fraud Control - Account Takeover Prevention（ATP）、および Fraud Control - Account Creation Fraud Prevention（ACFP）。従来は保護したい全てのページに手動で&lt;script&gt;タグを追加・維持する必要があり、多数アプリケーションを運用するチームや外部生成ページではミスや抜けが発生しやすかった点が解消されます。自動SDK組み込みは、CloudFrontと紐づくWeb ACLで、上記の管理ルールグループが少なくとも1つ含まれる場合に利用可能です。設定はAWS Management Console、CLI、SDK、CDK、CloudFormationで行えます。AWS WAFコンソールでは管理ルールグループの設定とともに表示され、新規にコンソールで作成した該当ルールグループ付きWeb ACLではデフォルトで有効です（プログラム的に作成したWeb ACLはデフォルトで無効）。本機能は既存のWeb ACLを自動で変更しません。追加料金は発生しません。要件、制限、Content Security Policy（CSP）に関する案内はAWS WAF Developer Guideの該当章を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Webアプリ運用者、セキュリティチーム、SRE、CDN経由で配信する多数のアプリケーションを管理する組織
- **利用シーンまたは効果**: CloudFront経由で配信するHTMLページに対するBot検出やアカウント関連の不正行為防止（ATP/ACFP）でのクライアントシグナル収集を自動化し、アプリ側の変更不要で保護を有効化できる
- **運用効果**: 各アプリにスクリプトを手動で埋め込む運用負荷と設定ミスを削減でき、保護設定が有効になっているにもかかわらずクライアント統合が抜けているケースを減らせる

### 技術的な注意点

- **必須ルールグループ**: Web ACLにBot Control（targeted）、Fraud Control ATP、またはFraud Control ACFPのいずれか少なくとも1つが含まれている必要があります
- **適用範囲（リージョン制限）**: CloudFrontディストリビューションに使用されるWeb ACL（CloudFront向けのグローバルWAF設定）でのみ有効。リージョン単位のregional Web ACLには適用されません
- **デフォルト挙動**: コンソールで新規に該当ルールグループ付きWeb ACLを作成した場合はデフォルトで有効。API/CLI/CloudFormation/CDK等で作成した場合はデフォルトで無効。既存のWeb ACLは自動で変更されません
- **CSP（Content Security Policy）**: 自動挿入されるスクリプトを許可するためにCSPの調整が必要になる可能性があります。詳しくは開発者ガイドのCSP項目を参照してください
- **キャッシュとレスポンス変更**: CloudFrontがHTMLレスポンスの本文に&lt;script&gt;タグを挿入するため、レスポンスの変化がキャッシュ動作や署名/整合性チェックに影響を与える可能性があります。キャッシュ設定やオリジン側の整合性チェックを確認してください
- **対象コンテンツ**: HTML（text/html）レスポンスに対して挿入されます。バイナリや非HTMLコンテンツには影響しません
- **権限（IAM）**: Web ACLやCloudFrontの設定変更権限（waf:UpdateWebACL 等、CloudFrontの管理権限）が必要です。自動化ツールで切り替える場合は適切なIAM権限を付与してください
- **コスト**: 本機能自体に追加料金は発生しませんが、関連するWAFルールの評価やログ収集（Amazon Kinesis Data Firehose / S3 等）に伴う標準的な課金は継続して発生します
- **監視/ログ**: 管理ルールグループが生成するマッチ情報やWAFログを有効にして、意図した効果が得られているか確認することを推奨します

## [Connect] Amazon Connect Customer now supports versioning and aliasing for flows

- **公開日**: 2026-10-31 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/connect-flows-versioning-aliasing/

### 概要

Amazon Connect Customerで、フローおよびフローモジュールの「バージョン管理」と「エイリアス（別名）」が利用可能になりました。これによりフローの更新・テスト・本番展開を簡略化し、ライブの顧客トラフィックへの影響を最小化できます。

### 変更内容・新機能の詳細

今回の機能追加により、フロー（およびフローモジュール）の不変（immutable）なバージョンを作成でき、そのバージョンに対して1つ以上のフレンドリ名（エイリアス）を紐付けられるようになりました。キュー、クイックコネクト、電話番号などのリソースは特定のバージョンを直接参照するのではなく、エイリアスを参照するように設定できます。新しいバージョンを展開する際は、各リソースを個別に再公開・再リンクする必要はなく、エイリアスの指し先を切り替えるだけで一括ロールアウトが完了します。これにより、以下が可能になります：テスト環境で新バージョンを検証しながら本番は既存バージョンを継続、準備が整ったらエイリアスを切り替えて一度の更新で全電話番号等を新バージョンへ移行。バージョンは不変のため既存のバージョンを誤って変更するリスクが低減され、CI/CDやブルー/グリーン展開、段階的ロールアウトの自動化が容易になります。コンソールに加え、AWS SDK/CLI/API経由での操作が想定され、すべてのAmazon Connect Customer提供リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Connect Customerを使ってIVR/顧客体験フローを設計・運用するSRE/運用チーム、コンタクトセンター開発者、DevOpsエンジニア
- **利用シーンまたは効果**: 本番トラフィックに影響を与えずテスト環境で新しいフローを検証し、準備が整い次第エイリアス一本の更新で本番に切り替えるブルー/グリーン展開や段階的ロールアウトが容易になる
- **運用効果**: 個別リソースの再リンクや再公開作業を削減し、リリース作業の手間とヒューマンエラーを低減。CI/CDパイプラインと連携して迅速かつ安全にフローをデプロイ可能

### 技術的な注意点

- **IAM権限**: フローの作成・バージョン化・エイリアス操作に関するIAM権限（フロー管理、エイリアス更新など）を事前に付与してください。既存のConnect権限ポリシーを確認し、不足があれば追加が必要です
- **リージョン制限**: Amazon Connect Customerが提供されているすべてのリージョンで利用可能とされていますが、実運用前に対象リージョンでの有無を確認してください
- **コスト**: 新機能自体に追加料金は明示されていませんが、テスト環境／電話番号／通話量など既存リソースの利用に対する通常の課金は発生します。CI/CDや複数バージョン保持によるストレージや管理コストも考慮してください
- **既存フロー互換性**: 既存フローはバージョン化されるまで従来どおり動作します。既存の参照設定をエイリアスに切り替える作業は必要です
- **切り替え時の挙動（インフライト）**: エイリアスの指し先を切り替えても、すでに開始済みの通話/セッションが遡って新バージョンに切り替わる保証はありません。新規のインタラクションから新バージョンが適用される想定で設計してください
- **自動化/ツール**: SDK/CLI/APIによるバージョン作成とエイリアス更新が利用可能であれば、CI/CDパイプラインに組み込むことで安全なデプロイ運用が可能です
- **注意点がない場合**: 該当なし
