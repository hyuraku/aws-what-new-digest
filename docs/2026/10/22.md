## [Direct Connect] AWS announces AWS Interconnect - last mile preview with Megaport

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Direct Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-announces-AWS-interconnect-last-mile-megaport-preview/

### 概要

AWSはMegaportと協業して「AWS Interconnect - last mile」のプレビューを発表しました。数クリックで支店やデータセンター、リモート拠点とAWSを専用接続できる、フルマネージドのラストマイル接続サービスです。

### 変更内容・新機能の詳細

AWS Interconnect - last mileは、Megaportの大規模SDN（1,200以上のデータセンター／31か国）を活用し、AWS管理コンソール、CLI、またはAPIから短時間でプライベートかつ高帯域幅の接続を確立できるサービスです。ユーザーは接続時にAWSリージョン、帯域幅、Direct Connect Gateway ID、パートナーのsubscriber IDを選択すると、AWSがアクティベーションキーを発行してMegaport側でのプロビジョニングを進めます。BGPピアリング、VLAN設定、ASN割当といった複雑なネットワーク構成はあらかじめ自動化・事前プロビジョニングされており、運用上の手間を大幅に削減します。プレビュー段階ではサンノゼ(us-west-1)とバージニア北部(us-east-1)のメトロで利用可能で、GA時にはコンソールから1 Gbps〜100 Gbpsまでの動的スケーリングが可能になる予定です。高可用性を想定して設計され、ゼロダウンタイムのメンテナンスと99.99%のSLAを提供します。パートナー向けには公開APIパッケージ（GitHub）も用意され、サービス連携の導入が容易です。

### 影響範囲・利用シーン

- **対象ユーザー**: ネットワーク/クラウドエンジニア、SRE、企業のIT運用担当者
- **利用シーン**: 支店・オンプレミスDC・エッジ拠点をAWSへ高速かつ専用接続し、クラウド移行やハイブリッド構成、低レイテンシアクセスを実現する場面
- **運用効果**: 手作業のVLAN/BGP/ASN設定を削減して接続導入時間を短縮し、プロビジョニングミスを低減。将来的な帯域変更をコンソールで動的に行えるためスケール運用が容易になる
- **制約**: プレビューはSan Jose（us-west-1）とN. Virginia（us-east-1）のメトロ経由でのMegaport接続に限定。GAまでに対応リージョンが拡大される可能性あり

### 技術的な注意点

- **IAM権限**: Interconnectの作成・表示にはDirect Connectおよび関連リソース（Direct Connect Gateway等）を操作する権限が必要です。事前に必要なIAMポリシーを確認・付与してください
- **リージョン制限**: プレビューでの提供は San Jose (us-west-1) と N. Virginia (us-east-1) のメトロ経由に限定されています。GA時に対応リージョンが拡大される見込みです
- **BGP/VLAN/ASN**: BGPピアリング、VLAN構成、ASN割当は自動化されますが、既存ネットワークとのASN衝突やルーティングポリシーは事前に確認しておく必要があります。IPアドレス、プレフィックスフィルタ等の調整はユーザー側で確認してください
- **プロビジョニング手順**: コンソール/CLI/APIでの作成後、AWSが発行するアクティベーションキーをMegaportに渡して最終プロビジョニングを完了します。パートナーsubscriber IDの入力が必要です
- **スケーリング**: プレビューでは限定的な機能かもしれません。公式発表ではGA時に1 Gbps〜100 Gbpsの動的スケーリングが可能になるとされています
- **可用性/SLA**: 99.99%のSLAと「ゼロダウンタイムのメンテナンス」を謳っていますが、詳細なSLA条件（免責事項やRPO/RTO）がSLA文書でどう定義されているかを確認してください
- **コスト**: 追加料金が発生します（プロビジョニング帯域幅に基づく課金、Megaportのポート/サブスクリプション料金、Direct Connect関連料金、データ転送料金等）。見積りはドキュメントと料金ページで確認してください
- **運用統合**: 既存のオンプレ側ルータ、ファイアウォール、監視ツールとの連携（BGPの状態監視やフロー収集等）は既存運用フローに組み込む必要があります
- **API/パートナー導入**: パートナー向けの公開APIパッケージがGitHubで提供されており、自動化/統合は可能です。API版利用時は認証・権限管理を設計してください

### 参考情報

- https://docs.aws.amazon.com/directconnect/latest/UserGuide/what-is-direct-connect.html

## [SageMaker] Amazon SageMaker AI now supports serverless model customization for Muse Glimmer, Qwen 3.8 and Ministral 3 models

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: SageMaker
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-sagemaker-muse-qwen-ministral/

### 概要

Amazon SageMaker AIがMuse Glimmer、Qwen 3.8（27B）、および Ministral 3（3B/8B/14B）モデルのサーバーレスカスタマイズをサポートしました。SFT、DPO、RFTといった微調整手法を、LoRAまたはフルファインチューニングでサーバーレスに実行できます。

### 変更内容・新機能の詳細

今回のアップデートにより、Muse Glimmer、Qwen 3.8（27B）、Ministral 3（3B、8B、14B）がSageMaker AIのサーバーレスモデルカスタマイズの対象に追加されました。利用可能な適応手法は監督付き微調整（SFT）、直接的好み最適化（DPO）、報酬に基づく強化微調整（RFT）で、パラメータ効率の高い低ランク適応（LoRA）またはパラメータ全体を更新するフルファインチューニングのいずれかを選択できます。サーバーレスカスタマイズでは、SageMaker AIがインフラのプロビジョニングと学習オーケストレーションを自動で管理するため、ユーザーはデータの準備・評価に集中でき、使用した分だけ課金されます。開始方法は、SageMaker StudioのModelsページからカスタマイズジョブを起動するか、SageMaker Python SDK、またはAgentスキル（コードアシスタント）を利用することです。今回の追加により、既存のNova、Gemma 4、Nemotron 3.5、Qwen、Llama、gpt-oss、DeepSeekといったモデル群と並んで、これらのモデルをドメイン特化・コスト最適化して運用できるようになります。サーバーレスカスタマイズは、US East (N. Virginia)、US West (Oregon)、Asia Pacific (Tokyo)、Europe (Ireland)で利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、MLプラットフォーム担当者、アプリケーション開発者、データサイエンティスト
- **利用シーンまたは効果**: ドメイン固有データでの精度向上（SFT）、出力トーンや方針の整合（DPO）、新タスクへの性能最適化（RFT）を行い、より小さいモデルでフロンティア品質に近い性能を目指せます
- **運用効果**: サーバーレスでインフラ管理が不要になるため、クラスター運用コストと運用負荷を削減し、使用量に応じた課金でコスト最適化が可能です
- **開発効率**: Studio、Python SDK、Agentスキルからジョブ開始できるため、既存ワークフローへの統合が容易です

### 技術的な注意点

- **IAM権限**: SageMaker実行ロール、S3アクセス、必要に応じてKMS暗号化キーのアクセス権を付与する必要があります
- **リージョン制限**: サーバーレスカスタマイズは US East (N. Virginia)、US West (Oregon)、Asia Pacific (Tokyo)、Europe (Ireland) で利用可能（他リージョンでは未対応の可能性あり）
- **コスト**: サーバーレスでも学習実行時間とリソース消費に応じて課金されます。LoRAはフルファインチューニングより安価で、フルチューニングはより高精度だがコストと時間が増加します。ストレージ（S3）や推論コストも考慮してください
- **モデルサイズとリソース**: 27Bや14Bクラスのモデルは計算負荷が高く、カスタマイズ時間とコストが大きくなる可能性があります。ジョブ設定でバッチサイズや学習率等を調整してください
- **データセキュリティ**: 学習データはS3に置き、必要であればKMSで暗号化。機密データの取扱いやログ出力の管理に注意してください
- **互換性**: LoRAはパラメータ効率を優先する場合に有効。DPOやRFTは特定の学習データ形式（報酬/好みデータ）を要求します。評価指標と検証セットを事前に用意してください
- **ツールと開始方法**: SageMaker Studio（Modelsページ）、SageMaker Python SDK、Agentスキルからジョブを起動可能。既存のCI/CDやモデル管理ワークフローと組み合わせられます
- **モニタリングと再学習**: カスタマイズ後もモデルの性能劣化を監視し、必要に応じて再学習や追加データでの反復を計画してください

## [Bedrock] AgentCore Gateway now supports Bedrock InvokeModel APIs and model fallback

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-gateway-invokemodel-fallback/

### 概要

Amazon Bedrock AgentCore GatewayがInvokeModel / InvokeModelWithResponseStream APIを推論エンドポイントでサポートし、モデルフォールバック（代替モデル・プロバイダへの自動ルーティング）機能を追加しました。既存のBedrock SDKをリライトせずにゲートウェイ経由で複数プロバイダへアクセスでき、可用性を向上します。

### 変更内容・新機能の詳細

・InvokeModelサポート: AgentCore Gatewayの推論エンドポイントでAmazon BedrockのInvokeModelおよびInvokeModelWithResponseStream APIを受け付けるようになりました。これにより既存のBedrock SDKクライアントをゲートウェイのエンドポイントに向けるだけで、ゲートウェイ配下の任意のモデルプロバイダへ透過的にリクエストを送れます（同期・ストリーミング両対応）。
・モデルフォールバック: ゲートウェイルールで代替宛先（モデル／プロバイダ）の順序付きチェーンを定義し、スロットリング、サーバエラー（5xx）、レスポンスタイムアウトなどの条件で自動的に次の宛先へ切り替えます。フォールバックは内部で行われ、クライアントには「1リクエスト→1レスポンス」として返るため、クライアント側で個別のリトライ実装を持つ必要がありません。
・回路ブレーカー: ゲートウェイに組み込まれた回路ブレーカーが現在失敗中の宛先をスキップするため、失敗試行による追加レイテンシを抑えつつ健全な宛先に迅速に到達します。
・運用とガバナンス: ゲートウェイは単一の管理・認可・監視ポイントとして機能するため、アクセス制御、ロギング、メトリクス収集、トレーシングなどの統一が容易になります。
・リージョン対応: Amazon Bedrock AgentCore Gatewayが利用可能なすべてのAWSリージョンで利用可能（中国リージョンを除く）。

### 影響範囲・利用シーン

- **対象ユーザー**: MLアプリケーション開発者、機械学習プラットフォーム/インフラ担当、SRE/運用チーム
- **利用シーン**: マルチプロバイダ（複数モデルベンダ）環境での統一エンドポイント運用、推論の自動フェイルオーバー、ストリーミング応答を用いた低レイテンシ配信
- **運用効果**: クライアント側のプロバイダ切替やリトライ実装が不要になり開発負荷が低減、障害時の可用性が向上、フォールバックによるダウンタイム短縮とユーザー体験の安定化

### 技術的な注意点

- **IAM権限**: Gatewayの管理・推論実行に必要なBedrock/AgentCoreのIAM権限を付与する必要があります（InvokeModel系API呼び出し権限やゲートウェイルールの管理権限）。
- **リージョン制限**: 機能はAgentCore Gatewayが利用可能なリージョンで提供（中国リージョンは対象外）。利用前にリージョンでのサポート状況を確認してください。
- **コスト**: ゲートウェイ経由のリクエストは通常のBedrock/モデルプロバイダの推論コストに加え、AgentCore Gatewayの利用に関連する料金やデータ転送費が発生する可能性があります。フォールバックによる追加試行は内部で最適化されますが、長時間の再試行や大規模試行はコスト増加に繋がる可能性があります。
- **設定**: フォールバックはゲートウェイルールで順序チェーンとトリガ条件（スロットリング、5xx、タイムアウトなど）を定義して有効化します。閾値やタイムアウト値を適切に調整してください。
- **互換性**: 各モデルプロバイダ間で応答形式やトークナイゼーションが異なる場合があるため、クライアント側での出力正規化や後処理が必要になる場合があります。
- **監視/トラブルシューティング**: CloudWatchメトリクス、ログ、トレースを有効にしてフォールバック動作や回路ブレーカーの発動状況を可視化してください。
- **API互換性**: 既存のBedrock SDKをゲートウェイのエンドポイントに向ける設計ですが、SDKバージョンやAPI呼び出し方法（同期 vs ストリーミング）が正しく動作するか事前検証を行ってください。

### 参考情報

- https://docs.aws.amazon.com/bedrock/latest/userguide/

## [Lambda] AWS Lambda MicroVMs is now available in 4 additional AWS regions

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Lambda
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/lambda-microvms-4-additional-regions

### 概要

AWS Lambda MicroVMsがアジア太平洋（香港、マレーシア、タイ）とヨーロッパ（スペイン）の4リージョンで利用可能になり、合計14リージョンで提供開始されました。MicroVMsはVMレベルの分離、ほぼ瞬時の起動/再開、状態保持を備えたサーバーレスの実行環境です。

### 変更内容・新機能の詳細

Lambda MicroVMsは、各ユーザーやジョブに専用の隔離された実行環境（MicroVM）を提供するサーバーレスのコンピュートプリミティブです。特徴としてVMレベルの強い分離、ほぼ瞬時の起動・再開速度、実行状態の保持があり、AIアシスタント、インタラクティブ開発環境、脆弱性スキャナ等の用途で有効です。ユーザーはDockerfileからMicroVMイメージを作成してそれを起点にMicroVMを起動します。各MicroVMには専用のHTTPS URLが割り当てられ、HTTP/2、gRPC、WebSocketsなどの一般的なプロトコルをサポートします。操作はAWS Lambdaコンソール、AWS CloudFormation、AWS CDK、またはAgent Toolkit for AWSを通じて行えます。今回の拡張により、これらの実行環境をエンドユーザーに近いリージョンで稼働させ、レイテンシ改善やデータ居住性要件への対応が容易になります。詳細な利用手順や料金情報はそれぞれのドキュメント（開発者ガイド、料金ページ）を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: アプリケーション開発者、AI/MLチーム、SRE/運用チーム、セキュリティ／脆弱性診断担当者
- **利用シーンまたは効果**: ユーザーごとの隔離環境が必要なマルチテナントアプリ、状態を保持した短期〜中期の対話型ワークロード（AIコーディングアシスタント、IDE、対話的解析）、低遅延アクセスやデータ居住性が求められる地域ユーザー向けの配備
- **運用効果**: 仮想化基盤の運用・管理をせずにVMレベルの隔離を実現でき、起動遅延の大幅削減と状態保持によりUX改善およびスループット向上が期待できる
- **セキュリティ／コンプライアンス効果**: VMレベルの隔離によりプロセス/ユーザ間のサイドチャネルリスクを低減し、データ居住性対応のためにリージョン内デプロイが可能

### 技術的な注意点

- **IAM権限**: LambdaのMicroVM作成/起動に必要なLambda関連権限に加え、イメージ格納先（ECR）やS3、必要に応じてKMS暗号化キーへのアクセス権を付与する必要があります
- **リージョン制限**: 今回はアジア太平洋（香港、マレーシア、タイ）および欧州（スペイン）で利用可能になり、合計14リージョンで提供中。利用前に「AWS Capabilities by Region」で最新の対応状況を確認してください
- **コスト**: MicroVMsは従来のLambda実行モデルと異なる課金体系になる可能性があるため、料金ページで詳細を確認してください。長時間の状態保持やネットワーク送信（egress）はコストに影響します
- **イメージ作成**: DockerfileからMicroVMイメージを作成して使用します。イメージのサイズ、起動時間最適化、依存ライブラリの最小化など、コンテナ運用のベストプラクティスが有効です
- **ネットワーク／プロトコル**: 各MicroVMは専用HTTPS URLを持ち、HTTP/2、gRPC、WebSockets等をサポートします。TLSやCORS、認証・認可まわりの設定はアプリ要件に合わせて設計してください
- **導入手段**: AWS Lambdaコンソール、CloudFormation、AWS CDK、Agent Toolkit for AWS経由でのデプロイをサポートします。IaCを用いた管理やCI/CD統合を推奨します
- **スケーラビリティと状態保持**: MicroVMは状態を保持するため短期間のセッション維持や対話的処理に向きますが、スケーリング設計（コールド/ウォーム起動戦略、最大同時数制限など）はアプリ要件に合わせて検討してください

## [General] Amazon Quick Now Available in the AWS Singapore Region

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-quick-now-available-in-the-aws-singapore-region/

### 概要

Amazon QuickがAWSアジアパシフィック（シンガポール）リージョン（ap-southeast-1）で利用可能になりました。これにより、シンガポール内でデータを保管・処理しつつQuickのAIチャットやResearch、Spaces、QuickSightダッシュボードなどの機能を利用できます。

### 変更内容・新機能の詳細

今回のローンチにより、Amazon Quickの全機能がap-southeast-1リージョンで提供されます。Amazon Quickは業務ユーザー向けの“エージェント的なチームメイト”として、自然言語での問答（AIチャット）、調査支援（Research）、共同作業スペース（Spaces）、およびQuickSightダッシュボード連携といった機能を通じて回答の提示とアクション実行を支援します。リージョン内でデータの保存・処理が行われるため、データ主権やローカル規制への対応が可能です。リージョン固有の機能差や利用可能サービスリストについては、Quickのリージョン対応ページを確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: シンガポール拠点の事業部門、データ分析者、SRE/運用チーム、セキュリティ/コンプライアンス担当者
- **利用シーンまたは効果**: ローカルデータを用いたAIチャットによる問い合わせ対応、レポート作成支援、QuickSight連携でのダッシュボード操作、アプリ間の切替不要な業務自動化
- **運用効果**: データを国外へ送信せずに低遅延でAI機能を利用可能になり、データ主権要件やレイテンシー敏感なワークロードの改善が期待できる

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、研究者、インフラ/MLプラットフォームチーム（Trainium を利用した高性能トレーニング/推論を目指すユーザー）
- **利用シーンまたは効果**: 既存の PyTorch モデルを最小限の変更で Trn2/Trn3 に移行して高速化（torch.compile と eager の両方をサポート）。大型モデル（vLLM や動画生成など）のネイティブ実行やカスタムカーネルによる最適化、実行時のメモリ問題診断やハードウェア障害の早期検出が可能になります。
- **運用効果**: 障害検出の高速化（Neuron Observer により &lt;1 秒で影響ノード特定）が運用負荷とダウンタイムの低減につながり、Neuron Explorer によるソース行単位のメモリ割当て追跡で OOM 問題の原因特定が短縮されます。

### 技術的な注意点

- **対応インスタンス**: TorchNeuron は Amazon EC2 Trn2 および Trn3 インスタンスでサポートされています。事前にインスタンスタイプを確認してください。
- **PyTorch バージョン互換性**: 新しい AMI/コンテナは PyTorch 2.14 を含みます。既存の環境での互換性を確認し、必要に応じて依存関係を更新してください。
- **ベータ注意**: TorchNeuron と Neuron Observer は public beta 機能です。安定性やサポート範囲が GA 機能と異なる可能性があるため、本番利用前に十分な検証を推奨します。
- **NKI と実験カーネル**: NKI の新機能および追加された 25 個のカーネルは実験的な提供を含みます。性能や互換性に関する検証を行った上で本番導入してください。
- **プロファイリング制限**: Neuron Explorer の Python ソース行への割当ては PyTorch のメモリスナップショット（eager モード）に基づく機能です。torch.compile（コンパイル済みモード）や特殊な最適化経路では挙動が異なる可能性があります。
- **コスト**: Trainium（Trn2/Trn3）インスタンスは専用の高性能ハードウェアであり、通常の GPU/CPU インスタンスと異なる料金体系です。追加のコストが発生する点に注意してください。
- **リージョン制限**: Trainium インスタンスや一部の Neuron 機能は利用可能リージョンが限定される場合があります。使用前に対象リージョンでの対応状況を確認してください。
- **権限と環境**: 新しい AMI/コンテナや Observer の利用には、EC2/CloudWatch/（必要に応じて）IAM 権限などを適切に設定する必要があります。詳細は公式ドキュメントで確認してください。
