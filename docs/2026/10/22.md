## [Fsx Netapp Ontap] AWS Transform adds storage migration assessments for Amazon S3, EBS, EFS, and FSx

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Fsx Netapp Ontap
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/transform-assess-s3-ebs-efs-fsx/

### 概要

AWS Transformのマイグレーションアセスメントがオンプレミスのストレージを評価対象に拡張され、S3/EBS/EFS/FSx（NetApp ONTAP、Windows File Server、OpenZFS、Lustre）への最適なマッピング、推奨サイズ、コスト見積り（TCO）を自動生成できるようになりました。インベントリをアップロードするだけで大量のボリュームを手作業で解析する必要がなくなります。

### 変更内容・新機能の詳細

新しいストレージ移行アセスメントでは、NAS共有、SAN LUN、直接接続ディスク、バックアップリポジトリ等のオンプレミスストレージインベントリを取り込み、各ワークロードを最適なAWSストレージサービス（Amazon S3、Amazon EBS、Amazon EFS、Amazon FSx の各エンジン：NetApp ONTAP、Windows File Server、OpenZFS、Lustre）へマッピングします。対応するインベントリ入力例としてNetApp Digital Advisorのエクスポート、RVToolsファイル、その他のインベントリ形式が利用可能です。アセスメントは推奨されるボリュームサイズと構成（Single-AZ vs Multi-AZ、コスト最適化 vs パフォーマンス最適化等）を提示し、コスト見積りと総保有コスト（TCO）を作成します。さらにWhat-ifシナリオで複数の配置オプションを比較でき、結果に対してチャットでのフォローアップ質問を行うことも可能です。サービスはAWS Transformが利用可能な各リージョンで提供されています（各リージョンの可用性は確認してください）。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド移行プロジェクト担当者、インフラ/ストレージアーキテクト、SRE/運用チーム
- **利用シーン**: 大量ボリュームを持つオンプレミス環境のクラウド移行アセスメント、移行前のコスト見積りとTCO算出、複数配置（Single-AZ/Multi-AZ・コスト/性能トレードオフ）比較
- **運用効果**: 手作業のボリューム解析削減により評価工数を大幅短縮し、サービスのベストフィット割当・サイズ決定・コスト根拠を迅速に提示できるため、移行計画作成と意思決定が高速化される

### 技術的な注意点

- **IAM権限**: AWS Transformの操作権限およびインベントリをアップロードするS3等のストレージ権限が必要です。詳細なAPI/アクション権限はユーザーガイドを参照してください。
- **データ形式**: NetApp Digital Advisorエクスポート、RVToolsファイルのほか「その他のインベントリ」としてCSV/JSON等が想定されています。正確なフォーマット要件はユーザーガイドのインポート仕様を確認してください。
- **精度/前提**: 推奨は入力されたインベントリとパフォーマンス指標（IOPS、スループット、週次/時次アクセスパターン等）の精度に依存します。メタデータや性能情報が不足すると保守的な配置・サイズ提案になる場合があります。
- **コスト**: アセスメントはストレージ月額コストやTCOを推定しますが、データ転送コスト、移行ツール／データ転送サービスの一時コスト、オンプレ側の再構成費用などは別途考慮が必要です。Transformの利用に伴う追加料金の有無は公式ドキュメントで確認してください。
- **リージョン制限**: 発表では「AWS Transformが利用可能な全リージョンで利用可能」となっていますが、各リージョンでのFSxエンジンや特定機能の可否はリージョン差があるため事前に確認してください。
- **セキュリティ/データ保護**: インベントリにはファイルパスやサーバ名など機密情報が含まれる可能性があります。アップロード前に不要な機密情報のマスキングや社内ポリシーの確認を行ってください。
- **移行の次工程**: アセスメントは推奨設計とコスト見積りを提示しますが、実データ移行（データ転送、ネットワーク帯域、移行ツールの導入やテスト、ダウンタイム計画等）は別途設計・実施が必要です。

## [Direct Connect] AWS Direct Connect announces 100G expansion in Manchester, England

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Direct Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-direct-connect-100g-manchester/

### 概要

AWS Direct Connectが英国マンチェスター（Equinix MA3）で10Gbps/100Gbpsの専用接続にMACsec暗号化を追加で提供開始しました。これにより同ロケーションから多数のAWSリージョン（中国除く）、GovCloud、Local Zonesへプライベート接続が可能になります。

### 変更内容・新機能の詳細

既存のEquinix MA3（Manchester）において、10Gbpsおよび100GbpsのDedicated ConnectionでMACsec（リンク層暗号）をサポートする拡張が行われました。Direct Connectはお客様のデータセンターやオフィス、コロケーション環境とAWS間に物理的な専用ネットワーク接続を確立するサービスで、インターネット経由よりも低遅延かつ一貫したネットワーク性能を提供します。今回の拡張により、ManchesterのDirect Connectロケーションから中国リージョンを除く公開AWSリージョン、AWS GovCloudリージョン、およびAWS Local Zonesへプライベート接続を確立できます。なお、英国内では3番目の100Gbps＋MACsec対応ロケーションになります。MACsecはリンク層でのトラフィック暗号化を実現するため、通信経路上の盗聴リスクを低減しますが、TLS等の上位プロトコルの暗号化と組み合わせての利用が推奨されます。

### 影響範囲・利用シーン

- **対象ユーザー**: ハイブリッドクラウド構成のネットワーク/クラウドエンジニア、SRE、データセンター運用者
- **利用シーンまたは効果**: 大容量データ転送（バックアップ、災対レプリケーション、データレイクのシード）、低遅延を要するアプリケーション、セキュリティ要件（リンク層暗号化）がある環境での専用接続
- **運用効果**: インターネット経由より一貫した帯域・遅延特性を得られ、MACsecにより伝送路での盗聴リスクを低減。100Gbps対応により大規模データ移動の時間短縮や帯域集約が可能
- **地理的制約**: Equinix MA3（Manchester）ロケーション限定の拡張。中国リージョンにはプライベート接続不可

### 技術的な注意点

- **接続要件**: 物理クロスコネクト、対応機器（100G対応ポートおよびMACsec対応のネットワーク機器）が必要です。プロバイダ経由での接続の場合はプロバイダのサポート確認が必要
- **MACsecの性質**: MACsecはリンク層(L2)での暗号化を提供します。エンドツーエンドのセキュリティ要件がある場合はTLS等の上位層暗号との併用を推奨します
- **リージョン制限**: 中国リージョン（中国本土）は対象外です。その他の公開リージョン、GovCloud、Local Zonesへは接続可能
- **IAM権限**: Direct Connectの作成/管理操作には適切なIAM権限（directconnect:CreateConnection等）が必要です。VIFや仮想インターフェイス作成時の権限も確認してください
- **注文・デプロイ**: コンソール、API、またはPartner経由での注文が可能。ロケーションの空き状況やタイムラインは事前確認が必要
- **コスト**: Dedicated Connectionのポート時間料金およびデータ転送料金が発生します。MACsec自体の追加料金があるかはリージョン/ロケーションで異なる可能性があるため料金ページで確認してください
- **互換性/運用**: MACsec設定やキー交換に関する運用ルール（機器互換性、MTU設定、LACPなどの挙動）を事前に検証してください

## [RDS] Amazon Aurora and Amazon RDS now support On-Demand Capacity Reservations

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: RDS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-aurora-rds-on-demand-capacity-reservations/

### 概要

Amazon Aurora と Amazon RDS で、指定したアベイラビリティゾーン（AZ）に対して長期間にわたり DB インスタンスのコンピュート容量を予約できる「On-Demand Capacity Reservations」が利用可能になりました。これにより、マイグレーションや製品ローンチ、季節需要などのビジネスクリティカルなイベント時に容量不足で DB 作成やスケール、起動が失敗するリスクを低減できます。

### 変更内容・新機能の詳細

ユーザーは DB インスタンスクラス、エンジン、対象の AZ、各 AZ ごとの予約容量を指定して容量を確保できます。確保した容量は DB インスタンスの作成、リストア、コンピュートスケール、起動時に参照して利用します。複数 AZ に予約することで Multi-AZ 配備をサポートします。予約は即時利用のもの（コミットメント不要、いつでもキャンセル可）か、5～120 日先に開始するスケジュール予約（最小コミットメントあり）を選べます。課金は予約が有効な間はインスタンス稼働有無に関わらずオンデマンド料金で発生しますが、既存の Reserved DB Instances や Database Savings Plans の割引は自動適用されます。機能はすべての AWS 商用リージョンで利用可能です。予約を参照する操作（作成/リストア/変更/起動）の方法および詳細設定は公式ドキュメントで案内されています。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド運用者、DB 管理者、SRE、アプリケーション開発チーム
- **利用シーンまたは効果**: マイグレーション時の大量インスタンス作成、製品ローンチや季節トラフィックピーク時の確実なキャパ確保、DR や高可用性構成での所定リソース確保
- **運用効果**: 容量不足による DB 作成/起動/スケール失敗を回避できるため、計画的なリリースや切替えの成功率が向上し、障害対応コストが削減される

### 技術的な注意点

- **IAM権限**: Capacity Reservation の作成・参照・削除には RDS 管理用の適切な IAM 権限が必要です（具体的なアクションは公式ドキュメント参照）。
- **リージョン制限**: 全ての AWS 商用リージョンで利用可能とアナウンスされていますが、リージョン固有の UI/機能差異はドキュメントで確認してください。
- **コスト**: 予約が有効な期間は、インスタンス稼働有無に関わらずオンデマンド料金で課金されます。既存の Reserved DB Instances や Database Savings Plans の割引は自動適用されます。スケジュール予約は最小コミットメントが必要（詳細はドキュメント参照）。
- **運用上の注意**: 予約は AZ ごとに容量を指定するため、Multi-AZ 構成で利用する場合は複数 AZ にまたがる予約を行う必要があります。予約を利用する際は作成/リストア/変更/起動時に予約参照を指定してください。
- **キャパシティ設計**: 予約は「確保」するものであり、予約外の突発的増加には対応しないため、平常時のバッファやオートスケール設計とのバランスを検討してください。

- https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/on-demand-capacity-reservations.html

## [Cognito] Amazon Cognito extends multi-Region replication to AWS GovCloud (US) Regions

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: Cognito
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/cognito-multi-region-us-govcloud/

### 概要

Amazon Cognitoのマルチリージョンレプリケーション（MRR）がAWS GovCloud (US) リージョンに対応しました。これにより、認証基盤の可用性・耐障害性やデータ滞在要件に対する対応範囲が拡大します。

### 変更内容・新機能の詳細

MRRはユーザープール内のユーザー／マシン（サービス）IDデータ、認証情報（資格情報）、ユーザープール設定、フェデレーション設定などを、指定したスタンバイ（セカンダリ）リージョンのユーザープールへほぼリアルタイムに同期する機能です。スタンバイリージョンにデータが存在することで、プライマリリージョンで障害が発生した際にトラフィックをリダイレクトして認証を継続できます。従来は商用リージョン16箇所で提供されていましたが、今回の対応によりAWS GovCloud (US) リージョン間でもMRRの利用が可能になります。MRRはユーザープールのEssentialsまたはPlusの機能階層に対するアドオンとして提供され、利用にはマルチリージョン対応のAWS KMSカスタマーマネージドキー（CMK）が必須です。リージョン対応状況や詳細な設定手順は開発者ガイドを参照してください。料金はMRRアドオンおよびKMSの利用に基づく追加課金が発生します。

### 影響範囲・利用シーン

- **対象ユーザー**: 認証基盤を利用するアプリケーション開発者、セキュリティ/コンプライアンス担当、SRE/運用チーム
- **利用シーン**: リージョン障害時の認証継続（フェイルオーバー）、データレジデンシー要件への対応、規制準拠が必要なGovCloud環境での冗長化
- **運用効果**: 認証サービスのダウンタイム低減、規制に沿ったデータ所在の確保、リージョン間切替による事業継続性向上

### 技術的な注意点

- **IAM権限**: MRR設定・管理にはCognitoおよびKMSの適切なIAM権限が必要です（ユーザープール管理権限、kms:CreateGrant/kms:Encrypt等）。
- **リージョン制限**: すべてのリージョン間での組合せが自動的にサポートされるわけではありません。GovCloudはAWSの別パーティション（aws-us-gov）であり、アカウントやリソースの管理が分離されます。対象リージョンはAWS Capabilities by Regionで確認してください。
- **コスト**: MRRはEssentials/Plusのアドオン料金が発生します。加えて、マルチリージョンKMS CMKの作成・利用に伴うKMS課金（APIリクエスト、キー管理など）が発生します。データ転送に関する料金も規定に応じて発生する可能性があります。
- **KMS要件**: MRRの暗号化にはマルチリージョン対応のカスタマー管理キー（CMK）が必須です。マルチリージョンCMKはKMSの仕様に従ってレプリケート・設定する必要があります。
- **アカウント/パーティション**: GovCloud利用時は専用のGovCloudアカウントまたはロールの設定が必要になる場合があります。商用（aws）パーティションとGovCloud（aws-us-gov）は直接的なリソース共有ができないため設計に注意してください。
- **フェイルオーバー動作**: MRRはデータ同期を行いますが、アプリケーション側でのDNS切替や認証エンドポイントの切替、セッション管理の設計（トークン有効期限や再認証フロー）を合わせて実装する必要があります。

## [General] AWS Neuron 2.33 adds native PyTorch support, Neuron Observer, and other new features 

- **公開日**: 2026-10-22 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-announce-neuron-2-33-0

### 概要

AWS Neuron 2.33 が公開され、Trainium向けのネイティブな PyTorch バックエンド「TorchNeuron」（パブリックベータ）や、Trainium の健全性を1秒未満で検出する Neuron Observer（パブリックベータ）など複数の新機能が追加されました。

### 変更内容・新機能の詳細

主な追加と変更点：
- TorchNeuron（public beta）: AWS Trainium（EC2 Trn2 / Trn3）上で標準の PyTorch API をそのまま動かせるネイティブバックエンド。Eager モードと torch.compile の両方をサポートし、既存の PyTorch コードを大きく書き換えずに Trainium で実行可能にします。
- Neuron Observer（public beta）: Trainium のハードウェア／ノード健全性を 1 秒未満で検出し、影響を受けたノードまたはデバイスを特定するための診断ツール。障害の早期検出と切り分けを支援します。
- vLLM プラグイン群の更新: vLLM Neuron プラグインが vLLM 0.29.0 にアップグレード。さらに、Wan2.2 ベースの動画生成を行う vLLM Omni Neuron プラグインが Neuron リリースに含まれるようになり、両者とも TorchNeuron によるネイティブ PyTorch コンパイルをサポートします。
- Deep Learning AMI / コンテナ: PyTorch トレーニング用の新しい Neuron Deep Learning AMI と Deep Learning Container に TorchNeuron、PyTorch 2.14、TorchTitan が同梱され、Trainium 上での学習環境のセットアップが簡素化されます。
- Neuron Explorer 強化: torch.profiler で取得したプロファイルを開けるようになり、PyTorch のメモリスナップショットから割当て（allocation）をその割当てを行った Python ソース行に紐付けて表示できるようになりました。特に eager モードでの OOM（メモリ不足）デバッグが容易になります。
- Neuron Kernel Interface（NKI）強化: NKI で作成するカーネルのメタプログラミングにおいて、ジェネレータやクラス継承を含むフル Python 言語機能が利用可能になりました。高度なコード生成やカスタム最適化が行えます。
- NKI Library の追加カーネル: 実験的に 25 個の新カーネルが追加（例: DeepSeek-V3.2、Qwen3.5、Kimi Delta Attention など）、特定モデル向けの高速化や最適化が進められています。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、研究者、インフラ/MLプラットフォームチーム（Trainium を利用した高性能トレーニング/推論を目指すユーザー）
- **利用シーンまたは効果**: 既存の PyTorch モデルを最小限の変更で Trn2/Trn3 に移行して高速化（torch.compile と eager の両方をサポート）。大型モデル（vLLM や動画生成など）のネイティブ実行やカスタムカーネルによる最適化、実行時のメモリ問題診断やハードウェア障害の早期検出が可能になります。
- **運用効果**: 障害検出の高速化（Neuron Observer により &lt;1 秒で影響ノード特定）が運用負荷とダウンタイムの低減につながり、Neuron Explorer によるソース行単位のメモリ割当て追跡で OOM 問題の原因特定が短縮されます。

### 技術的な注意点

- **対応インスタンス**: TorchNeuron は Amazon EC2 Trn2 および Trn3 インスタンスでサポートされています。事前にインスタンスタイプを確認してください。
- **PyTorch バージョン互換性**: 新しい AMI/コンテナは PyTorch 2.14 を含みます。既存の環境での互換性を確認し、必要に応じて依存関係を更新してください。
- **ベータ注意**: TorchNeuron と Neuron Observer は public beta 機能です。安定性やサポート範囲が GA 機能と異なる可能性があるため、本番利用前に十分な検証を推奨します。
- **NKI と実験カーネル**: NKI の新機能および追加された 25 個のカーネルは実験的な提供を含みます。性能や互換性に関する検証を行った上で本番導入してください。
- **プロファイリング制限**: Neuron Explorer の Python ソース行への割当ては PyTorch のメモリスナップショット（eager モード）に基づく機能です。torch.compile（コンパイル済みモード）や特殊な最適化経路では挙動が異なる可能性があります。
- **コスト**: Trainium（Trn2/Trn3）インスタンスは専用の高性能ハードウェアであり、通常の GPU/CPU インスタンスと異なる料金体系です。追加のコストが発生する点に注意してください。
- **リージョン制限**: Trainium インスタンスや一部の Neuron 機能は利用可能リージョンが限定される場合があります。使用前に対象リージョンでの対応状況を確認してください。
- **権限と環境**: 新しい AMI/コンテナや Observer の利用には、EC2/CloudWatch/（必要に応じて）IAM 権限などを適切に設定する必要があります。詳細は公式ドキュメントで確認してください。
