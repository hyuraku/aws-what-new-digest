## [Bedrock] Web Search on AWS Bedrock now supports domain filtering and user location controls

- **公開日**: 2026-10-24 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-web-search-domain-user-location/

### 概要

AWS Bedrock の Web Search ツールが、応答の根拠となる検索結果に対して「ドメインフィルタリング」と「ユーザー位置（地域）制御」の2つの新しい制御をサポートしました。既存の OpenAI Responses API リクエスト内の web_search ツールで設定します。

### 変更内容・新機能の詳細

新機能は次のとおりです。
- ドメインフィルタリング: web_search の filters パラメータで最大100件の allowed_domains（許可ドメイン）または最大100件の blocked_domains（ブロックドメイン）を指定できます。これにより、応答を特定の信頼できるサイトの結果のみに基づかせたり、特定ドメインを検索結果から除外できます。
- ユーザー位置（地域）制御: オプションの位置情報パラメータを指定することで、地理的に関連する検索結果を返すようにできます。地域依存の質問（地域別の在庫、ローカルサービス、地域の提供可否など）で有効です。
- 設定箇所: いずれも OpenAI Responses API の web_search ツール内で指定します（既存のリクエスト構造にパラメータを追加する形）。
- 制限・利用可能リージョン: Web Search がサポートされている全リージョンで利用可能（US East (N. Virginia)、US East (Ohio)、US West (Oregon)、AWS GovCloud (US-West)）。
- 料金: Web Search 利用に関しては別途 Bedrock の料金が適用されるため、料金ページを確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: LLMアプリ開発者、AI/MLエンジニア、SRE/運用チーム、コンプライアンス／法務担当者
- **利用シーン**: 回答を企業が信頼する特定サイトに限定して情報の根拠を明確にしたい場合、地域ごとの情報（ローカルサービスや地域提供可否）を返したい場合、または特定ドメインを業務上除外したい場合
- **運用効果**: 応答の根拠コントロールによる誤情報・ハルシネーションの抑制、コンプライアンス順守（許可サイトのみ参照）、地域性に応じた正確な情報提供の向上

### 技術的な注意点

- **設定方法**: OpenAI Responses API の web_search ツールで filters（allowed_domains / blocked_domains）および位置情報パラメータを指定して設定します
- **ドメインマッチング**: サブドメインやワイルドカードの扱い、完全一致かプレフィックス/サフィックスか等の詳細なマッチングルールは公式ドキュメントで確認してください（実装によって期待挙動が異なる可能性があります）
- **IAM権限**: Bedrock と Web Search を呼び出すための適切な IAM 権限（例: Bedrock の実行権限など）を付与しておく必要があります
- **リージョン制限**: 現時点での対応リージョンは US East (N. Virginia)、US East (Ohio)、US West (Oregon)、AWS GovCloud (US-West) のみです。その他リージョンでは未対応の可能性があります
- **コスト**: Web Search の利用は Bedrock の料金体系に基づき課金されます。トラフィック増加でコストが増えるため、設計時に想定利用量を見積もってください
- **監査・ログ**: 検索結果を制御するため、検索クエリや結果のログ化／監査方針を設計しておくことを推奨します

## [Connect] Amazon Connect Customer Global Resiliency now supports persistent chat across linked AWS Regions

- **公開日**: 2026-10-24 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-connect-global-resiliency-persistent-chat

### 概要

Amazon Connect Customer Global Resiliencyが、リンクされたAWSリージョン間で会話のコンテキスト、メタデータ、トランスクリプト、添付ファイルを保持したままチャットを継続できる永続チャット機能を提供開始しました。ユーザーは別リージョンに戻っても前回の会話を再開できます。

### 変更内容・新機能の詳細

今回の機能により、Amazon ConnectのCustomer Global Resiliencyを利用する環境で、チャットセッションの状態（会話履歴、メッセージメタデータ、トランスクリプト、チャット添付ファイルなど）をリンクされたリージョン間で保持・参照できるようになります。具体例として、エンドユーザーがUS-East(N. Virginia)で開始したチャットをUS-West(Oregon)で再開し、同じ会話履歴と添付ファイルにアクセスしてやり取りを継続することが可能です。本機能を利用するには、Customer Global ResiliencyのGlobal routingへオンボードする必要があります。機能は、Amazon Connect Customer Global ResiliencyがサポートするすべてのAWSリージョンで利用可能です。実装面では、会話状態のリージョン間レプリケーションと参照管理（メタデータ・トランスクリプトの永続化）、およびチャットルーティングをGlobal routingで制御することが前提となります。詳細な設定、制限やAPI/コンソール操作方法についてはAmazon Connect Customer Admin Guideを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンター運用者、カスタマーサポートチーム、SRE/クラウド運用担当者
- **利用シーン**: マルチリージョンでのフォールオーバー／グローバルルーティング環境におけるチャット継続（例: ユーザー移動やリージョン切替時の会話再開）
- **運用効果**: エンドユーザーが情報を繰り返し伝える必要がなくなり、エージェントは全会話履歴に基づくパーソナライズされた対応が可能。リージョン障害時のシームレスな引継ぎ／回復が容易になる

### 技術的な注意点

- **オンボーディング**: 本機能利用にはCustomer Global ResiliencyのGlobal routingへのオンボードが必須です。Admin Guideの手順に従ってください。
- **IAM権限**: Amazon Connectの管理操作およびGlobal Resiliency設定変更を行うための適切なIAM権限（Connect管理系権限や関連リソースの更新権限）が必要です。設定前に権限を確認してください。
- **リージョン制限**: 機能はAmazon Connect Customer Global Resiliencyをサポートするリージョンでのみ利用可能です。未サポートリージョンでは動作しません。
- **コスト**: リージョン間データ転送（チャット履歴・添付ファイルのレプリケーション）や追加のストレージ、Global Resiliencyに関連する料金が発生する可能性があります。コスト試算を行ってください。
- **データ主権とコンプライアンス**: 会話内容や添付ファイルがクロスリージョンで複製されるため、個人情報や規制対象データの取り扱い、暗号化・保持ポリシーを確認してください。
- **制限・互換性**: 添付ファイルのサイズ上限、保持期間、サポートされるファイルタイプやAPIレート制限などの詳細はAdmin Guideやサービス制限ドキュメントで確認してください。

- https://docs.aws.amazon.com/connect/latest/adminguide/

## [VPC] AWS Transit Gateway and AWS Cloud WAN now support 1:1 NAT

- **公開日**: 2026-10-24 (JST)
- **カテゴリ**: VPC
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-transit-gateway-cloud-wan-1-1-nat/

### 概要

AWS Transit Gateway と AWS Cloud WAN がアタッチメント上での1:1 NAT（Regional Private NAT Gateway 統合）をサポートしました。重複するプライベートCIDRを持つネットワークをリナンバリングやNATアプライアンス不要で接続できます。

### 変更内容・新機能の詳細

今回の機能は、Transit Gateway / Cloud WAN の各アタッチメントに対して「送信元CIDR → 変換後プライベートCIDR」の1:1アドレス変換ルールを定義できる機能です。変換は両方向に自動適用され、別途リターントラフィックルールを作成する必要や、NATアプライアンスをデプロイする必要はありません。対象となるアタッチメントは Amazon VPC、AWS Site-to-Site VPN、AWS Direct Connect、Transit Gateway Connect（SD‑WANアプライアンス経由）などです。実装はRegional Private NAT Gateway を経由してAWS側で運用・スケールされるマネージドNATで提供されます。設定は AWS マネジメントコンソール、AWS CLI、SDK、CloudFormation で可能で、変換トラフィックの監視は Amazon CloudWatch のメトリクスと Amazon EventBridge イベントで行えます。商用リージョンで利用可能（記事によると各サービスが稼働する全商用リージョン）。料金は Amazon VPC の NAT 関連の課金体系（時間単位やデータ処理量）に準じます。

### 影響範囲・利用シーン

- **対象ユーザー**: ネットワーク/クラウドエンジニア、SRE、M&Aやパートナー接続を行うアーキテクト
- **利用シーン**: 異なる組織で同一プライベートCIDR（例: 10.0.0.0/16）を持つVPC間の即時接続（M&A統合、パートナーネットワーク接続、マルチクラウドブリッジ、独立構築されたVPCの相互接続）
- **運用効果**: リナンバリング作業やNATアプライアンスの導入・管理が不要になり、接続構築の時間短縮と運用負荷低減が期待できる
- **通信経路**: VPC、Site-to-Site VPN、Direct Connect、Transit Gateway Connect 経由のトラフィックに対して動作するためハイブリッド／SD-WAN環境にも適用可能
- **可観測性**: CloudWatch メトリクスと EventBridge イベントで変換トラフィックや関連イベントを監視でき、障害検知や運用自動化に利用可能

### 技術的な注意点

- **IAM権限**: Transit Gateway / Cloud WAN のアタッチメントや Regional Private NAT Gateway を作成・変更する権限（例: ec2:ModifyTransitGatewayAttachment 等）および CloudWatch/EventBridge の閲覧権限を事前に確認してください
- **リージョン制限**: 記事では "各サービスが稼働する全商用リージョンで提供" とありますが、利用前に対象リージョンでのサポート状況を確認してください
- **コスト**: Regional Private NAT Gateway による課金（時間料金、データ処理（GB）課金など）が発生します。既存のTransit Gateway/Cloud WAN利用料とは別に費用が増える可能性があるため見積りを行ってください（詳細は VPC の料金ページ参照）
- **設定注意**: 変換先に指定するプライベートCIDRは接続先と重複しないことを確認してください。1:1 NAT はアタッチメント単位／CIDR単位でのマッピング設計が必要です
- **監視/ログ**: CloudWatch メトリクスと EventBridge を用いて変換トラフィック量やエラーメトリクスを収集可能ですが、VPC Flow Logs 等との併用でトラフィックの可視化方針を設計してください
- **運用制限**: NAT アプライアンスを置かない分、特定の高度なトラフィック操作（アプリケーションレベルのプロキシや細かなパケット改変）は行えません。必要な場合は別途アプライアンスの検討が必要です
