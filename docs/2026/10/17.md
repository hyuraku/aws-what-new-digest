## [Cloudwatch Logs] Amazon CloudWatch log centralization now available in AWS GovCloud and additional commercial Regions

- **公開日**: 2026-10-17 (JST)
- **カテゴリ**: Cloudwatch Logs
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-cloudwatch-centralization-region-expansion

### 概要

Amazon CloudWatchのログ集約機能（Log centralization）がAWS GovCloud (US) と13の追加商用リージョンで利用可能になりました。複数アカウント／リージョンのログをAWS Organizationsと連携して単一の集約先アカウントへコピーできます。

### 変更内容・新機能の詳細

CloudWatch Log centralizationは、複数のAWSアカウントおよびリージョンからログデータを指定した集約先アカウントへコピー（複製）する機能です。組織単位（Organization全体）、OU（組織単位）、あるいは選択したアカウント単位で集約ルールをスコープでき、コピー時にソース情報を保持する“enriched system fields”により、元のアカウントやリージョンなどのコンテキストが維持されます。設定はAmazon CloudWatchコンソール、AWS CLI、またはAWS SDKsから行えます。今回の拡張で、Africa (Cape Town)、Asia Pacific（Hong Kong, Hyderabad, Jakarta, Malaysia, Melbourne）、Canada West (Calgary)、Europe（Milan, Spain, Zurich）、Israel (Tel Aviv)、Middle East（Bahrain, UAE）、および AWS GovCloud (US-East/US-West) を含むリージョンで利用可能になりました。集約はパーティション単位（商用パーティションとGovCloudパーティションはそれぞれ独立）で行われ、パーティション間を跨いだ直接の集約はサポートされません。料金面では、ログの1コピーは無料で、それ以降の追加コピーは$0.05/GBで課金されます（詳細はCloudWatchの料金ページ参照）。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティチーム、SRE/運用チーム、ガバナンス/コンプライアンス担当者
- **利用シーン**: 中央化された監視ダッシュボード／SIEM連携、監査ログの一元保管、跨アカウント/跨リージョンの障害調査やフォレンジック
- **運用効果**: ログ収集の運用工数削減（カスタムソリューション不要）、一元的なクエリ／アラート設定で早期検知が可能、監査やコンプライアンス対応の効率化
- **制約/注意点**: パーティション毎の集約（商用とGovCloudは別扱い）である点を考慮する必要あり
- **リージョン対応**: 新たに追加されたリージョンでの利用が可能。詳細はAWS Region tableで要確認

### 技術的な注意点

- **IAM権限**: Organizationを利用したスコープ指定やクロスアカウント操作が関係するため、CloudWatch LogsおよびAWS Organizationsに関する適切なIAM権限（集約ルール作成・閲覧・クロスアカウントアクセス許可設定など）が必要です
- **リージョン制限**: 集約は同一パーティション内での操作となり、商用パーティションとGovCloudパーティション間での直接集約は不可。利用可能リージョンは公式のRegion表で確認してください
- **コスト**: ログの1コピーは無料、追加コピーは$0.05/GB。集約先でのログ取り込み・保管に伴うCloudWatch Logsの取り込み・保存料金やリージョン間転送コストが別途発生する可能性があります
- **開始方法**: CloudWatchコンソール、AWS CLI、またはAWS SDKから集約ルールを作成して開始します。設定時に集約先アカウントへの書き込み権限などクロスアカウント設定が必要になる場合があります
- **互換性/データ項目**: コピー時にenriched system fieldsでソースコンテキストが保持されるため、集約先でソース識別やフィルタが行いやすくなります
- **推奨**: 大規模組織ではOU単位で段階的にルールを適用し、コストとパフォーマンスを評価しながら展開することを推奨します

## [Lambda] AWS Lambda durable functions are now available in AWS GovCloud (US) Regions 

- **公開日**: 2026-10-17 (JST)
- **カテゴリ**: Lambda
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/durablefunctions-govcloud/

### 概要

AWS Lambda durable functionsがAWS GovCloud (US-West)およびAWS GovCloud (US-East)リージョンで利用可能になりました。政府機関や規制業界向けに、Lambdaの開発体験のまま信頼性の高いマルチステップ処理やAIワークフローのオーケストレーションが可能になります。

### 変更内容・新機能の詳細

Lambda durable functionsは、Lambdaのイベントハンドラ内で"step"や"wait"といった新しいプリミティブを提供し、処理のチェックポイント作成、自動リカバリ、実行の一時停止（オンデマンド関数に対するコンピュート課金なしでの停止）を可能にします。今回、AWS GovCloud (US-West)とAWS GovCloud (US-East)での提供が開始され、政府系や規制対象のワークロードにおいても利用できるようになりました。対応ランタイムは、Python 3.13/3.14、Node.js 22/24、Go 1.24以降、.NET 2.2、Java 17+です。耐久機能は新規関数に対してLambda API、AWS Management Console、AWS SDKから有効化できます。また、AWS CloudFormation、AWS SAM、AWS CDKなどのIaCツールからもデプロイ可能です。詳細や料金、リージョン対応状況は公式の製品ページ、開発者ガイド、料金ページ、リージョン機能一覧をご参照ください。

### 影響範囲・利用シーン

- **対象ユーザー**: 政府機関・公共機関、規制業界（金融、医療、防衛関連）、クラウドネイティブ開発者およびSRE/運用チーム
- **利用シーン**: オーダーワークフロー、ユーザーオンボーディング、審査フロー、AI支援タスク（長時間処理や複数ステップの推論パイプライン）のオーケストレーション
- **運用効果**: 障害時の自動回復と進捗チェックポイントにより信頼性が向上し、実行の一時停止時にオンデマンドのコンピュート課金を抑えられることでコスト最適化が可能

### 技術的な注意点

- **IAM権限**: Lambdaの作成/更新権限に加え、実行ロールにCloudWatch Logs、X-Ray（必要に応じて）、およびDurable Functions関連のAPI呼び出し権限が必要です。IaCでデプロイする場合は適切なロールポリシーを用意してください。
- **リージョン制限**: 本リリースはAWS GovCloud (US-West)とAWS GovCloud (US-East)での追加提供です。他リージョンでの可用性はAWSのリージョン機能一覧で確認してください（商用リージョンですでに利用可能な場合があります）。GovCloudアカウントの登録／承認プロセスが必要です。
- **コスト**: "wait"による実行一時停止時はオンデマンドコンピュート課金が発生しない旨が示されていますが、状態保存やステート遷移、APIリクエスト、ログ出力、ストレージなど他の料金は発生する可能性があります。詳細はLambdaの料金ページを確認してください。
- **ランタイム互換性**: 指定されたランタイム/バージョン（Python 3.13/3.14、Node.js 22/24、Go 1.24+、.NET 2.2、Java 17+）以外はサポート対象外のため、既存関数のランタイムアップグレードが必要になる場合があります。
- **IaC/ツール**: CloudFormation、AWS SAM、AWS CDK、及び最新のAWS SDK/CLIでのサポートが必要です。ツール側の古いバージョンではテンプレートや構成項目が未対応の可能性があるため、CLI/SDK/CDK等を最新版に更新してください。
- **データ主権・コンプライアンス**: GovCloud利用により米国政府向けのコンプライアンス要件に対応しやすくなりますが、アカウントの分離やデータ転送制約などGovCloud固有のポリシーを確認してください。
- **監視・トラブルシュート**: Durable Functions特有の実行フローやチェックポイントを可視化するためにCloudWatchメトリクス／ログやX-Rayの設定を検討してください。

## [Aiml] Nemotron 3.5 Super VL model now available on Amazon SageMaker JumpStart

- **公開日**: 2026-10-17 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/nvidia-nemotron-3.5-super-vl-on-sagemaker-jumpstart/

### 概要

NVIDIA の Nemotron 3.5 Super VL（マルチモーダル視覚言語モデル）が Amazon SageMaker JumpStart に追加され、画像・映像・テキスト入力からテキスト出力を生成する大規模モデルをワンクリックでデプロイ可能になりました。ドキュメント解析、GUI理解、ビデオQA、マルチモーダルエージェント等を想定しています。

### 変更内容・新機能の詳細

Nemotron 3.5 Super VL は Nemotron 3.5 ファミリの視覚言語（vision-language）モデルで、画像、ビデオ、テキストを入力として受け取りテキストを生成します。アーキテクチャはハイブリッド Mixture-of-Experts (MoE) ベースで総パラメータは約1200億に相当し、アクティブパラメータは約12B（120億）で、視覚エンコーダを組み合わせています。コンテキスト長は最大100万トークンをサポートします。生成性能向上のために Multi-Token Prediction (MTP) ヘッドを内蔵し、投機的デコーディング（speculative decoding）によりテキスト生成を高速化可能で、推論時に推論／推論深度（reasoning）の有効化をリクエスト単位で切替えられます。多言語対応（英語、フランス語、スペイン語、ドイツ語、日本語、ヒンディー語、韓国語、中国語など計10言語を含む）を備え、画像・動画・ドキュメント・グラフ・GUI データでのマルチモーダル教師付き微調整（SFT）と GRPO による強化学習を経て、構造化された JSON 出力、ツール呼び出し、エージェントワークフロー向けの設定可能な推論挙動をサポートします。SageMaker JumpStart では 2 種類のバリアントが提供されます。NVFP4（G7 インスタンス上の NVIDIA RTX PRO 4500 Blackwell Server Edition GPU に最適化された推論重み）と、BF16 参照重み（ml.p5en.48xlarge）で、後者は SFT、RL、蒸留、ドメイン適応などのカスタマイズ用です。SageMaker コンソールの JumpStart モデルカタログまたは SageMaker Python SDK を使って数クリックでデプロイできます。

### 影響範囲・利用シーン

- **対象ユーザー**: AI/ML エンジニア、データサイエンティスト、アプリケーション開発者、SRE/運用チーム
- **利用シーンまたは効果**: ドキュメント自動解析（請求書、契約書等）の抽出と構造化出力、GUI の状態理解と自動操作、ビデオ質問応答、マルチモーダルエージェント（ツール呼び出しやワークフロー制御を伴う業務自動化）に適用可能
- **運用効果**: 高精度のマルチモーダル理解により手動処理を削減、JSON等の構造化出力で下流システム連携が容易になりエージェント自動化／オーケストレーションの実装コストと運用負荷を低減します。

### 技術的な注意点

- **IAM権限**: SageMaker のモデル作成・エンドポイント作成（sagemaker:CreateModel, sagemaker:CreateEndpointConfig, sagemaker:CreateEndpoint 等）、S3 への読み書き権限、ECR 参照や必要な KMS 権限などを事前に確認・付与してください
- **リージョン制限**: 高性能 GPU（G7、ml.p5en など）は提供リージョンが限定される場合があります。利用前に AWS コンソールで提供状況とインスタンスタイプの可用性を確認してください
- **コスト**: G7 や ml.p5en.48xlarge などの大規模 GPU インスタンスは時間当たりコストが高く、推論頻度やコンテキスト長（最大100万トークン）によっては料金が大きく増加します。バッチ推論や投機的デコーディングの活用などでコスト最適化を検討してください
- **モデルバリアント**: NVFP4 は G7 系インスタンス上での推論に最適化された重み、BF16 参照重みはカスタマイズ（SFT/RL/蒸留/ドメイン適応）向けです。カスタマイズする場合は ml.p5en 系のインスタンスが想定されます
- **推論最適化**: MTP（Multi-Token Prediction）や投機的デコーディングはレイテンシとスループットに影響します。高速化を有効にする場合は推論精度とコスト（GPU 使用量、並列度）を評価してください
- **カスタマイズ上の注意**: SFT や RL を行う際は学習データの品質とコンプライアンス（機密データ、個人情報）に注意し、適切なデータ取り扱いポリシーと KMS 暗号化を利用してください
- **リソース制限とクォータ**: 大型 GPU インスタンスのデプロイにはアカウントクォータの引き上げが必要になることがあります。事前にリージョンごとのクォータ確認と申請を行ってください
- **利用方法**: SageMaker JumpStart コンソールからのワンクリックデプロイ、または SageMaker Python SDK（boto3 / sagemaker SDK）経由でのプログラム的デプロイが可能です

## [Sagemaker Jumpstart] Beam model by Reflection is now available on Amazon SageMaker JumpStart and AWS Trainium

- **公開日**: 2026-10-17 (JST)
- **カテゴリ**: Sagemaker Jumpstart
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/reflection-beam-on-sagemaker-jumpstart-and-aws-trainium/

### 概要

米国のReflectionが公開したオープンウェイトモデル「Beam」が、Amazon SageMaker JumpStart（SageMaker AIのモデルハブ）で利用可能になり、さらにAWSのTrainium3向けに最適化されて提供開始されました。Apache 2.0ライセンスで配布されるため、ユーザーは自分のAWSアカウント内でモデルの重みを確認・改変しつつ、SageMakerの管理機能で本番展開できます。

### 変更内容・新機能の詳細

Beamはオープンウェイト（重みが公開されている）モデルで、推論・コーディング・エージェント系のベンチマークで高い性能を示すとされます。Amazon SageMaker JumpStartを通じてSageMaker Studioから検索・デプロイでき、SageMakerのスケーリング、監視（CloudWatch、SageMakerの監視機能等）、監査ログ（CloudTrail）といった既存の運用機能と統合して利用できます。さらにBeamはAWS Trainium3上でポーティング・最適化されており、Trainium3インスタンス上での学習・推論により高性能かつコスト効率の良い運用が可能です。モデルはApache 2.0ライセンスで配布されるため、重みの参照・改変・再配布が許可され、企業は自社データやインフラ内でモデルを適応（ファインチューニングやアダプテーション）して利用できます。利用想定例としては、コード生成やバグ修正支援を行うコーディングエージェント、複数ステップ・複数ツールにまたがる自動化ワークフロー、数学・科学分野の高度な推論タスクなどが挙げられます。公開当初はUS East (N. Virginia) と US East (Ohio) で利用可能で、SageMaker JumpStart内で"Beam"を検索するか、SageMaker AIから直接デプロイして開始できます。

### 影響範囲・利用シーン

- **対象ユーザー**: MLエンジニア、データサイエンティスト、ソフトウェア開発チーム、SRE/運用チーム、エンタープライズ/政府機関
- **利用シーン**: コード生成・レビュー、ソフトウェア問題の自動解析、自動化ワークフロー（マルチステップのエージェント化）、高度な数理／科学的推論タスク
- **運用効果**: オープンウェイトで内部監査・カスタマイズが可能なため、データガバナンス要件のある組織でも自前環境で先端モデルを利用できる。Trainium3最適化により大規模デプロイ時のコスト効率とスループットが改善される可能性がある

### 技術的な注意点

- **IAM権限**: SageMakerでのJumpStart検索・モデルデプロイ、トレーニング実行、ECR/モデルアーティファクトアクセスなどの適切なIAM権限が必要です
- **リージョン制限**: 公開当初は US East (N. Virginia) と US East (Ohio) のみ対応。ほかリージョンは順次対応の可能性あり
- **ハードウェア**: BeamはTrainium3に最適化済み。最適性能を得るにはtrn3系インスタンスの利用を推奨。Trainium未提供リージョンではGPU/CPUでの実行になるため性能差があります
- **コスト**: 大型モデルのトレーニング・推論は計算資源とストレージを多く消費します。Trainium3はコスト効率の改善が期待できるが、インスタンス時間とデータ転送のコスト見積が必要です
- **ライセンス**: Apache 2.0で公開されているため商用利用・改変・再配布が可能。ただし社内ポリシーや規制対応（輸出管理等）は別途確認してください
- **モデルサイズとリソース管理**: オープンウェイトモデルはメモリ/ネットワークI/Oが大きくなる可能性があるため、推論用に適切なインスタンスタイプと水平スケーリング設計が必要です
- **データ保護**: モデルはユーザーのAWSアカウント内で稼働するため、KMSによる暗号化、VPCエンドポイント、CloudTrail監査など既存のAWSセキュリティ機能でデータ保護を実施してください
- **ファインチューニング**: 事業特化の適応は可能。コストと計算資源、学習手法（完全ファインチューニング、LoRA等のパラメータ効率手法）を検討してください
- **運用監視**: SageMakerのモニタリング、CloudWatch、CloudTrail、モデルレジストリ（必要に応じて）を組み合わせて性能劣化やデータシフトを監視してください
