## [Connect] Amazon Connect Customer now automatically finds example agent evaluations for tailored coaching 

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-connect-customer-example-evaluations-for-agent-coaching/

### 概要

Amazon Connect Customerは、マネージャーがエージェント向けコーチングを準備する際に、該当トピックでスコアが高い/低い最近の評価例を自動的に提示する機能を追加しました。提示には人間またはAI評価者のノート（行動の説明）も含まれ、エビデンスに基づく具体的な指導が短時間で行えます。

### 変更内容・新機能の詳細

マネージャーがAmazon Connect Customer上でエージェント向けコーチングフィードバックを作成すると、システムは選択したコーチングトピック（例：「エスカレーション回避／de-escalation」）に関連する最近の評価ケースを自動的に抽出して提示します。提示される例には、該当トピックで高評価を得た通話や低評価となった通話の録音／トランスクリプトへのリンク、ならびに人間評価者またはAI評価者が記述した「どの行動がその評価につながったか」のノートが含まれます。これにより、マネージャーは手動で過去の通話を検索する手間を省き、具体的な事例を用いたテーラードコーチングを迅速に作成できます。技術的には、評価メタデータ（スコア、トピックタグ、評価コメント）、通話メディア（録音・トランスクリプト）、および評価者ノートを結び付ける検索・フィルタリングロジックとUI表示が組み合わされています。AI評価ノートは機械学習モデルによる解析を利用する場合があり、ヒューマンレビューの有無やモデルバージョンにより出力精度が変わる点に留意してください。本機能はAmazon Connect Customerを提供している全リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: コンテクトセンターのスーパーバイザー、コーチ／L&Dチーム、品質管理（QA）担当者
- **利用シーン**: コーチング用フィードバック作成、評価の根拠提示、1対1のパフォーマンスレビュー、QAサンプリングの事例抽出
- **運用効果**: 事例検索時間の短縮によりコーチング頻度と質が向上し、エージェントの改善サイクルを加速
- **組織効果**: エビデンスに基づいた一貫性のある評価で評価基準のばらつきを低減し、トレーニング投資のROI向上が期待できる

### 技術的な注意点

- **IAM権限**: マネージャー/コーチが評価データ・通話録音・トランスクリプトへアクセスするための適切なIAMロール／ポリシー（ConnectのView/Read権限など）が必要です
- **リージョン制限**: 本機能はAmazon Connect Customerが提供されている全リージョンで利用可能とされています（利用前に対象リージョンでの提供状況を確認してください）
- **コスト**: 記事で追加料金は明記されていませんが、通話録音保管、トランスクリプト作成、Contact LensやML解析の利用はストレージ／解析料金が発生する場合があるためコスト影響を確認してください
- **前提条件**: Amazon Connect Customerの該当評価機能とコーチングワークフローが有効であること、対象エージェントの評価データおよび通話録音／トランスクリプトが保存されていることが必要です
- **データ保護／プライバシー**: 通話録音やトランスクリプトには個人情報（PII）が含まれる可能性があるため、アクセス制御・マスキング・保持ポリシーを適用し、法的要件や社内ポリシーに従って処理してください
- **AI出力の注意**: AI評価ノートは補助的な情報として扱い、誤検知や文脈誤解の可能性があるため最終的な判断は人間が行う運用設計を推奨します

## [General] Amazon EFS now supports cross-account Replication in AWS GovCloud (US)  

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-efs-cross-account-replication-aws-gov-cloud-us

### 概要

Amazon EFS が AWS GovCloud (US) でアカウント間（クロスアカウント）レプリケーションをサポートしました。これにより、別アカウントの GovCloud リージョンへファイルシステムを自動的に複製し、BC/DR やコンプライアンス要件に対応できます。

### 変更内容・新機能の詳細

EFS Replication を用いて、AWS GovCloud (US) 内の任意のリージョンにある別アカウントの Amazon EFS ファイルシステムへデータのレプリケーションを行えるようになりました。コンソール、AWS CLI、CloudFormation、API から数クリック／コマンドで設定可能で、カスタム同期処理を構築する必要がなくなります。レプリケーションはソースと宛先のファイルデータを自動的に同期し、運用上の分離（マルチアカウント戦略）を維持しながらビジネス継続性や災害復旧、規制遵守に役立ちます。実装上はソース／ターゲットの指定、必要な IAM 権限（レプリケーション用ロールや信頼ポリシー）、および暗号化でカスタマー管理の KMS キーを使う場合はキー共有／許可の設定が必要です。レプリケーション対象は別の EFS ファイルシステムとなり、レプリケーションによる追加ストレージ使用とデータ転送に対して料金が発生します。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS GovCloud (US) を利用するセキュリティ重視の組織、公共機関、規制対象企業（マルチアカウント運用を行うクラウドエンジニアやSRE）
- **利用シーン**: マルチアカウントでの災害復旧（DR）構成、アカウント分離によるセキュリティ境界の維持、規制要件に基づくデータ隔離／監査対応
- **運用効果**: カスタム同期処理を不要にしてレプリケーションの運用負荷を削減、別アカウントでの迅速な復旧や検証環境へのデータ複製が容易になり可用性と耐障害性が向上

### 技術的な注意点

- **IAM権限**: ソース／宛先アカウント双方でレプリケーション用の IAM ロールや必要な権限（efs:*, kms:GenerateDataKey* 等）が必要。クロスアカウントの信頼ポリシー設定を確認してください。
- **KMS/暗号化**: カスタマー管理の KMS キー（CMK）を使用する場合、宛先アカウントやレプリケーション処理からそのキーを使用できるようにキーのポリシー／グラントを設定する必要があります。
- **リージョン制限**: 本機能は AWS GovCloud (US) 内のリージョン間でのクロスアカウントレプリケーションをサポートします。商用 AWS リージョン（パブリックリージョン）との直接的なクロスリージョンレプリケーションは別途確認が必要です。
- **コスト**: 宛先ファイルシステムのストレージ料金およびレプリケーションに伴うデータ転送料金（リージョン間転送や GovCloud の課金体系に依存）が発生します。設計時にコスト見積もりを行ってください。
- **運用・整合性**: レプリケーションは継続的な同期を目的としますが、厳密な同期ポイント（RPO/RTO）の要件がある場合は試験・検証を実施して期待する復旧時間／整合性を確認してください。
- **導入方法**: Amazon EFS コンソール、AWS CLI、CloudFormation、API から設定可能。既存のマルチアカウント運用フローに組み込む場合はアクセス権限と KMS の設定を事前に整備してください。

### 参考情報

- https://docs.aws.amazon.com/efs/latest/ug/replication.html

## [Iam Identity Center] AWS IAM Identity Center extends multi-Region support to Identity Center directory

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: Iam Identity Center
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/aws-iam-identity-center-extends-multi-region-support-to-identity-center-directory

### 概要

IAM Identity Center（旧 AWS SSO）が、Identity Center directory を ID ソースとして使う組織インスタンスに対して、プライマリリージョンから選択した追加リージョンへの自動レプリケーションによるマルチリージョン対応を拡張しました。これにより、ユーザーのアクセス耐障害性とリージョンに合わせたアプリケーション配置が向上します。

### 変更内容・新機能の詳細

今回の機能追加により、Identity Center directory を ID ソースとして構成された IAM Identity Center の組織インスタンスは、最初に有効化したプライマリ AWS リージョンから任意の追加リージョンへ「識別情報（ユーザー/グループ）、エンタイトルメント（アクセス許可）、および関連情報」を自動でレプリケーションできます。従来は外部 ID プロバイダに接続した組織インスタンス向けに提供されていたマルチリージョン対応が、Identity Center 内蔵ディレクトリでも利用可能になった形です。レプリケーションを有効化すると、プライマリリージョンで IAM Identity Center を管理しつつ、アプリケーション管理者は通常のデプロイフローで追加リージョンへアプリケーションを配備できます。プライマリリージョンで障害が発生しても、追加リージョンに既にプロビジョニングされたエンタイトルメントを使ってユーザーは AWS アカウントへアクセスを継続できます。利用には、組織インスタンスがマルチリージョン対応のカスタマーマネージド KMS キー（CMK）で構成されている必要があり、現在 17 のデフォルトで有効化された商用リージョンで利用可能です。標準の AWS KMS 課金が適用され、IAM Identity Center 自体に追加料金は発生しません。

### 影響範囲・利用シーン

- **対象ユーザー**: IAM Identity Center（Identity Center directory を ID ソースとしている組織インスタンス）を利用するクラウド管理者、SRE、ID/アクセス管理者
- **利用シーン**: リージョン単位の障害対策（DR）やデータ主権・レイテンシ要件に応じてアプリケーションを近接リージョンへ配備するケース。複数リージョンでの一貫したアクセス制御運用。
- **運用効果**: プライマリリージョンの障害時でも追加リージョンにプロビジョニング済みのエンタイトルメントでアクセスを維持できるため可用性が向上。リージョン選択によるデータレジデンシやユーザー近接性の最適化が可能

### 技術的な注意点

- **IAM権限**: CMK の作成・レプリケーション（kms:CreateKey, kms:ReplicateKey, kms:EnableKeyRotation など）や Identity Center 管理権限が必要。事前に必要な IAM ポリシーを確認してください。
- **リージョン制限**: 現時点では『17 のデフォルト有効化済み商用リージョン』で利用可能。GovCloud や中国リージョン等では未対応の可能性があります。各リージョンの対応状況を確認してください。
- **コスト**: マルチリージョン CMK を使用するため標準の AWS KMS 課金が発生します。IAM Identity Center 自体に追加料金はありませんが、KMSおよび追加リージョンでのリソース運用コストが増加する可能性があります。
- **整合性と遅延**: レプリケーションは自動だが即時整合ではない（最終的整合性）。フェイルオーバー時の挙動やレイテンシを事前に検証してください。
- **アプリケーション互換性**: すべての AWS アプリケーションが追加リージョン展開に対応するわけではありません。利用するアプリが追加リージョンで動作するか事前に確認してください。
- **設定要件**: IAM Identity Center の組織インスタンスであること、かつマルチリージョン CMK の構成が必須です。特に既存の CMK を利用する場合はそのキーがマルチリージョン用に設定されているか確認してください。

## [EKS] Amazon EKS Provisioned Control Plane now delivers faster pod autoscaling

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: EKS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-eks-provisioned-control/

### 概要

Amazon EKS の Provisioned Control Plane が Horizontal Pod Autoscaler (HPA) の同期並列度を最大で既定値の40倍まで引き上げ、HPA駆動のポッドスケーリングをより高速化しました。設定変更は不要で、Provisioned Control Plane を利用する全クラスターに適用されます。

### 変更内容・新機能の詳細

Kubernetes の Horizontal Pod Autoscaler (HPA) はワークロードのメトリクスを監視してポッド数を自動調整します。多数の HPA オブジェクト（数百〜数千）を稼働させているクラスターでは、コントロールプレーンが HPA をどれだけ並列処理できるかがスケール応答時間の鍵になります。今回の改善では、EKS の Provisioned Control Plane における HPA の sync concurrency を Kubernetes の既定値より最大で40倍まで引き上げ、コントロールプレーンが同時に評価・処理できる HPA オブジェクト数を増やしました。これにより、負荷増加の検知からポッドのスケールアウトが開始されるまでの遅延が短縮されます。適用は AWS 側で行われ、ユーザーによる設定変更は不要です。詳細は EKS Provisioned Control Plane のドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: EKS の Provisioned Control Plane を利用しているクラウドエンジニア、SRE、プラットフォームチーム
- **利用シーン**: 大量の HPA オブジェクトを持つクラスターでのオンデマンド負荷増加に対する迅速なスケーリング
- **運用効果**: HPA の評価が並列化されることでスケールアウトの応答時間が短縮され、ユーザー体感や SLA 達成に寄与する
- **注意される効果**: より早くポッドが増えるため、急激な負荷時にコスト増加やノード資源枯渇が早まる可能性がある

### 技術的な注意点

- **設定変更**: ユーザー側での設定変更は不要（AWS 側で適用）
- **対象範囲**: EKS の「Provisioned Control Plane」を使用しているクラスターに適用。Provisioned 以外のコントロールプレーンには影響しない可能性あり
- **リージョン制限**: 記載なし。Provisioned Control Plane が提供されているリージョンで利用可能と考えられるため、特定リージョンでの可用性はドキュメントで確認すること
- **IAM権限**: 本変更はコントロールプレーン側の更新のため、特別な IAM 権限変更は不要。ただしクラスタ運用でのスケールに伴うノード追加等には通常の EC2/EKS 関連権限が必要
- **コスト**: スケールの応答が速くなることでポッド数（および関連するノード/インスタンスタイプ）が増加しやすく、ランニングコストが上昇する可能性がある。オートスケーリング設定や予算アラートの見直しを推奨
- **互換性/影響**: HPA 自体の API やメトリクス（カスタムメトリクス、外部メトリクス）を利用している場合の挙動は変わらないが、スケーリングのタイミングが早まるため、Pod 側の起動時間やイニシャライザ、サイドカー挙動などを確認すること
- **監視**: スケールの頻度増加や急速なスケールアウトによるノード不足を検出するため、ClusterAutoscaler、ノードグループのキャパシティ、コスト監視を強化することを推奨

- https://docs.aws.amazon.com/eks/latest/userguide/provisioned-control-plane.html

## [Management Console] AWS Console Home now supports the Cost and Usage widget in the AWS European Sovereign Cloud (Germany) Region

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: Management Console
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/aws-console-home-cost-and-usage-eu-sovereign-cloud

### 概要

AWS Console Homeの「Cost and Usage」ウィジェットが、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。Cost ExplorerおよびCost Optimization Hubの洞察をConsole Homeダッシュボード上に表示できます。

### 変更内容・新機能の詳細

この更新により、コンソールのホーム画面にCost and Usageウィジェットを追加して、月初からの実績コスト（month-to-date）、予測コスト、サービス別の支出推移、Cost Optimization Hubによる節約候補などを一目で確認できるようになります。ウィジェットはCost ExplorerとCost Optimization HubのAPIを参照してデータを表示するため、事前にCost Explorerの有効化と必要な権限が必要です。追加方法はAWS Management Consoleにサインインして「Add widgets」を選択し、Cost and Usageウィジェットをダッシュボードにドラッグ＆ドロップするだけです。データはCost Explorer由来のため通常24時間程度の遅延がある点、予測値は推定である点に注意してください。コンソリデーティッドビリング（組織/請求管理）環境では、表示される範囲は表示権限や管理アカウントの設定によります。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドコスト管理者、FinOpsチーム、SRE/運用チーム、組織の請求担当者
- **利用シーン**: 日次／月次のコスト監視、予算超過の早期検知、サービス別コスト分析、Cost Optimization Hubの節約候補の可視化
- **運用効果**: コンソールホーム上で主要コスト指標を素早く把握でき、意思決定やコスト最適化アクションの速度が向上する
- **組織対応**: マネージメントアカウントやIAM権限に応じて、マルチアカウントの集計表示や個別アカウント表示が可能（権限設定による）

### 技術的な注意点

- **IAM権限**: Cost ExplorerとCost Optimization Hubの参照API（例: ce:GetCostAndUsage, ce:GetCostForecast等）および請求情報へのアクセス権が必要です。組織環境ではマネージメントアカウント側での権限付与を確認してください。
- **リージョン制限**: 本リリースはAWS European Sovereign Cloud (Germany) リージョン向けのサポート追加です。他のリージョンでの挙動は従来どおりです。リージョンごとのサービス可用性は公式ドキュメントで確認してください。
- **コスト**: ウィジェット自体に追加料金は通常発生しませんが、基盤となるCost ExplorerやCost and Usage Report（CUR）を利用する場合のS3保存やデータ転送等の料金、また高度なレポートや外部ツールの利用に関するコストは別途発生する可能性があります。
- **前提条件**: Cost Explorerが有効化されていること、該当アカウント/組織でCost Optimization Hubが利用可能であることが必要です。
- **データ遅延/精度**: 表示されるコストデータには一般的に最大24時間程度の遅延があり、予測は推定値です。請求確定値は別途請求書やCURで確認してください。

### 概要

第二世代の AWS Outposts ラックがアジアパシフィック（ムンバイ）リージョンでサポートされるようになりました。これにより、インド国内および周辺地域の顧客がムンバイをホームリージョンとして Outposts ラックを発注し、レイテンシやデータ主権要件を最適化できます。

### 変更内容・新機能の詳細

AWS Outposts は AWS のインフラ、サービス、API、ツールをオンプレミスやコロケーションに延長し、ハイブリッド環境を一貫性ある形で提供します。第二世代 Outposts ラックはムンバイ（ap-south-1）リージョンでサポートされるようになり、これにより対象顧客はムンバイをホームリージョンとしてラックを注文して運用できます。Outposts はローカルでの低レイテンシ処理（例：オンプレのシステムとの高速な相互接続が必要なワークロード）を実行しつつ、管理プレーンやAPI呼び出しは選択したホームリージョンへ接続して行われます。データレジデンシー要件のあるデータをオンプレで保持・処理する用途や、ネットワーク遅延を抑える必要があるアプリケーションに適しています。導入にあたっては、ラック設置のための物理スペース、電源、冷却容量、現地ネットワーク接続要件（ホームリージョンとの安定した接続）を満たす必要があります。対応サービスやインスタンスタイプ、国・地域ごとのサポート状況は随時更新されるため、第二世代の詳しい仕様は公式のブログおよびユーザーガイド、Outposts rack FAQ を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: エンタープライズ、スタートアップ、公共部門、オンプレミスで低レイテンシまたはデータ主権が必要なシステムを持つクラウド/インフラ担当者
- **利用シーン**: 金融取引やリアルタイム制御、医療・政府データのオンプレ処理、データ主権要件を満たすためのローカル処理
- **運用効果**: ムンバイをホームリージョンに選択することでリージョン間通信の遅延・帯域の影響を低減し、データレジデンシー方針の順守やユーザー体験の向上が可能

### 技術的な注意点

- **IAM権限**: Outposts の注文・管理には専用の IAM 権限が必要です（Outposts 関連の管理ポリシーやコンソール操作権限を確認してください）
- **リージョン制限**: 第二世代 Outposts ラックはムンバイで新たにサポートされましたが、利用可能な国・地域および接続先リージョンは FAQ で確認してください（すべてのリージョン/国で即時利用可能とは限りません）
- **ネットワーク要件**: 管理プレーンとデータ同期のためにホームリージョンへの安定した接続が必要です。ファイアウォールやプロキシの設定、必要ポートの開放等を事前に確認してください
- **サービス互換性**: すべての AWS サービスやインスタンスタイプが Outposts 上で利用できるわけではありません。ユーザーガイドでサポート一覧を確認してください
- **物理要件**: ラック設置には十分な床面積、電力（冗長電源要件含む）、冷却能力、重量・搬入経路の確認が必要です。設置前に AWS の事前調査を受けてください
- **コスト**: ハードウェア/サービスの注文費用と運用料金、データ転送コストなどが発生します。価格モデルはリージョンや構成により異なるため見積もりを取得してください
