## [EKS] Amazon EKS Provisioned Control Plane now delivers faster pod autoscaling

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: EKS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-eks-provisioned-control/

### 概要

Amazon EKS の Provisioned Control Plane が Horizontal Pod Autoscaler (HPA) の同期並列度を最大で既定値の40倍まで引き上げ、HPA駆動のポッドスケーリングをより高速化しました。設定変更は不要で、Provisioned Control Plane を利用する全クラスターに適用されます。

### 変更内容・新機能の詳細

Kubernetes の Horizontal Pod Autoscaler (HPA) はワークロードのメトリクスを監視してポッド数を自動調整します。多数の HPA オブジェクト（数百〜数千）を稼働させているクラスターでは、コントロールプレーンが HPA をどれだけ並列処理できるかがスケール応答時間の鍵になります。今回の改善では、EKS の Provisioned Control Plane における HPA の sync concurrency を Kubernetes の既定値より最大で40倍まで引き上げ、コントロールプレーンが同時に評価・処理できる HPA オブジェクト数を増やしました。これにより、負荷増加の検知からポッドのスケールアウトが開始されるまでの遅延が短縮されます。適用は AWS 側で行われ、ユーザーによる設定変更は不要です。詳細は EKS Provisioned Control Plane のドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: EKS の Provisioned Control Plane を利用しているクラウドエンジニア、SRE、プラットフォームチーム
- **利用シーン**: 大量の HPA オブジェクトを持つクラスターでのオンデマンド負荷増加に対する迅速なスケーリング
- **運用効果**: HPA の評価が並列化されることでスケールアウトの応答時間が短縮され、ユーザー体感や SLA 達成に寄与する
- **注意される効果**: より早くポッドが増えるため、急激な負荷時にコスト増加やノード資源枯渇が早まる可能性がある

### 技術的な注意点

- **設定変更**: ユーザー側での設定変更は不要（AWS 側で適用）
- **対象範囲**: EKS の「Provisioned Control Plane」を使用しているクラスターに適用。Provisioned 以外のコントロールプレーンには影響しない可能性あり
- **リージョン制限**: 記載なし。Provisioned Control Plane が提供されているリージョンで利用可能と考えられるため、特定リージョンでの可用性はドキュメントで確認すること
- **IAM権限**: 本変更はコントロールプレーン側の更新のため、特別な IAM 権限変更は不要。ただしクラスタ運用でのスケールに伴うノード追加等には通常の EC2/EKS 関連権限が必要
- **コスト**: スケールの応答が速くなることでポッド数（および関連するノード/インスタンスタイプ）が増加しやすく、ランニングコストが上昇する可能性がある。オートスケーリング設定や予算アラートの見直しを推奨
- **互換性/影響**: HPA 自体の API やメトリクス（カスタムメトリクス、外部メトリクス）を利用している場合の挙動は変わらないが、スケーリングのタイミングが早まるため、Pod 側の起動時間やイニシャライザ、サイドカー挙動などを確認すること
- **監視**: スケールの頻度増加や急速なスケールアウトによるノード不足を検出するため、ClusterAutoscaler、ノードグループのキャパシティ、コスト監視を強化することを推奨

## [Management Console] AWS Console Home now supports the Cost and Usage widget in the AWS European Sovereign Cloud (Germany) Region

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: Management Console
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/aws-console-home-cost-and-usage-eu-sovereign-cloud

### 概要

AWS Console Homeの「Cost and Usage」ウィジェットが、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。Cost ExplorerおよびCost Optimization Hubの洞察をConsole Homeダッシュボード上に表示できます。

### 変更内容・新機能の詳細

この更新により、コンソールのホーム画面にCost and Usageウィジェットを追加して、月初からの実績コスト（month-to-date）、予測コスト、サービス別の支出推移、Cost Optimization Hubによる節約候補などを一目で確認できるようになります。ウィジェットはCost ExplorerとCost Optimization HubのAPIを参照してデータを表示するため、事前にCost Explorerの有効化と必要な権限が必要です。追加方法はAWS Management Consoleにサインインして「Add widgets」を選択し、Cost and Usageウィジェットをダッシュボードにドラッグ＆ドロップするだけです。データはCost Explorer由来のため通常24時間程度の遅延がある点、予測値は推定である点に注意してください。コンソリデーティッドビリング（組織/請求管理）環境では、表示される範囲は表示権限や管理アカウントの設定によります。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドコスト管理者、FinOpsチーム、SRE/運用チーム、組織の請求担当者
- **利用シーン**: 日次／月次のコスト監視、予算超過の早期検知、サービス別コスト分析、Cost Optimization Hubの節約候補の可視化
- **運用効果**: コンソールホーム上で主要コスト指標を素早く把握でき、意思決定やコスト最適化アクションの速度が向上する
- **組織対応**: マネージメントアカウントやIAM権限に応じて、マルチアカウントの集計表示や個別アカウント表示が可能（権限設定による）

### 技術的な注意点

- **IAM権限**: Cost ExplorerとCost Optimization Hubの参照API（例: ce:GetCostAndUsage, ce:GetCostForecast等）および請求情報へのアクセス権が必要です。組織環境ではマネージメントアカウント側での権限付与を確認してください。
- **リージョン制限**: 本リリースはAWS European Sovereign Cloud (Germany) リージョン向けのサポート追加です。他のリージョンでの挙動は従来どおりです。リージョンごとのサービス可用性は公式ドキュメントで確認してください。
- **コスト**: ウィジェット自体に追加料金は通常発生しませんが、基盤となるCost ExplorerやCost and Usage Report（CUR）を利用する場合のS3保存やデータ転送等の料金、また高度なレポートや外部ツールの利用に関するコストは別途発生する可能性があります。
- **前提条件**: Cost Explorerが有効化されていること、該当アカウント/組織でCost Optimization Hubが利用可能であることが必要です。
- **データ遅延/精度**: 表示されるコストデータには一般的に最大24時間程度の遅延があり、予測は推定値です。請求確定値は別途請求書やCURで確認してください。

- https://docs.aws.amazon.com/console/home/latest/userguide/console-home-widgets.html

## [Outposts] Second-generation AWS Outposts racks now supported in the AWS Asia Pacific (Mumbai) Region

- **公開日**: 2026-07-29 (JST)
- **カテゴリ**: Outposts
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/07/aws-outposts-asia-pacific-mumbai/

### 概要

第二世代の AWS Outposts ラックがアジアパシフィック（ムンバイ）リージョンでサポートされるようになりました。これにより、インド国内および周辺地域の顧客がムンバイをホームリージョンとして Outposts ラックを発注し、レイテンシやデータ主権要件を最適化できます。

### 変更内容・新機能の詳細

AWS Outposts は AWS のインフラ、サービス、API、ツールをオンプレミスやコロケーションに延長し、ハイブリッド環境を一貫性ある形で提供します。第二世代 Outposts ラックはムンバイ（ap-south-1）リージョンでサポートされるようになり、これにより対象顧客はムンバイをホームリージョンとしてラックを注文して運用できます。Outposts はローカルでの低レイテンシ処理（例：オンプレのシステムとの高速な相互接続が必要なワークロード）を実行しつつ、管理プレーンやAPI呼び出しは選択したホームリージョンへ接続して行われます。データレジデンシー要件のあるデータをオンプレで保持・処理する用途や、ネットワーク遅延を抑える必要があるアプリケーションに適しています。導入にあたっては、ラック設置のための物理スペース、電源、冷却容量、現地ネットワーク接続要件（ホームリージョンとの安定した接続）を満たす必要があります。対応サービスやインスタンスタイプ、国・地域ごとのサポート状況は随時更新されるため、第二世代の詳しい仕様は公式のブログおよびユーザーガイド、Outposts rack FAQ を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: エンタープライズ、スタートアップ、公共部門、オンプレミスで低レイテンシまたはデータ主権が必要なシステムを持つクラウド/インフラ担当者
- **利用シーン**: 金融取引やリアルタイム制御、医療・政府データのオンプレ処理、データ主権要件を満たすためのローカル処理
- **運用効果**: ムンバイをホームリージョンに選択することでリージョン間通信の遅延・帯域の影響を低減し、データレジデンシー方針の順守やユーザー体験の向上が可能

### 技術的な注意点

- **IAM権限**: Outposts の注文・管理には専用の IAM 権限が必要です（Outposts 関連の管理ポリシーやコンソール操作権限を確認してください）
- **リージョン制限**: 第二世代 Outposts ラックはムンバイで新たにサポートされましたが、利用可能な国・地域および接続先リージョンは FAQ で確認してください（すべてのリージョン/国で即時利用可能とは限りません）
- **ネットワーク要件**: 管理プレーンとデータ同期のためにホームリージョンへの安定した接続が必要です。ファイアウォールやプロキシの設定、必要ポートの開放等を事前に確認してください
- **サービス互換性**: すべての AWS サービスやインスタンスタイプが Outposts 上で利用できるわけではありません。ユーザーガイドでサポート一覧を確認してください
- **物理要件**: ラック設置には十分な床面積、電力（冗長電源要件含む）、冷却能力、重量・搬入経路の確認が必要です。設置前に AWS の事前調査を受けてください
- **コスト**: ハードウェア/サービスの注文費用と運用料金、データ転送コストなどが発生します。価格モデルはリージョンや構成により異なるため見積もりを取得してください
