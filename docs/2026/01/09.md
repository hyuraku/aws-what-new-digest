## [Lightsail] Announcing larger managed database bundles for Amazon Lightsail

- **公開日**: 2026-01-09
- **カテゴリ**: Lightsail
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/larger-managed-database-bundles-lightsail/

### 概要

Amazon Lightsailに8 vCPU／32GBメモリ／960GB SSDの大容量マネージドデータベースバンドルが追加されました。標準プランと高可用性(HA)プランの両方でMySQLとPostgreSQLが利用可能になり、よりデータ集約型・本番負荷向けのワークロードに対応します。

### 変更内容・新機能の詳細

新しいLightsailのデータベースバンドルは最大8 vCPU、32GBメモリ、960GBのSSDストレージを提供します。これらは標準（単一AZ）と高可用性（フェイルオーバー対応／複数AZ相当の冗長構成）両方のプランで選択可能で、対応DBエンジンはMySQLとPostgreSQLです。Lightsailのマネージドデータベース機能（自動バックアップ/スナップショット、簡易監視、パッチ適用、接続エンドポイント管理、HAプランでの自動フェイルオーバー等）は引き続き利用でき、より大規模なデータセットや同時接続数の多いアプリケーションがLightsail上で実行しやすくなります。これにより、eコマース、CMS、BI、SaaSなどの本番用途における処理能力とストレージ要件を満たせるようになります。新バンドルはLightsailが提供されている全リージョンで利用可能です（料金や無料トライアル情報は別途確認）。

### 影響範囲・利用シーン

- **対象ユーザー**: 小〜中規模のSaaS事業者、スタートアップ、ウェブ/アプリ開発者、運用チーム
- **利用シーンまたは効果**: eコマースやCMSなど読み書き・同時接続が増える本番データベースの処理能力向上、BIや分析用途での大容量データ格納
- **運用効果**: より高いCPU/メモリ/ストレージによりクエリ応答改善と同時接続の耐性向上、HAプランでのダウンタイム低減
- **利用可能DB**: MySQLおよびPostgreSQLをLightsailマネージドで利用可能
- **リージョン**: Lightsail提供リージョン全域で利用可能（個別リージョンの可用性は確認要）
- **コスト影響**: 高スペックバンドルは料金が上昇するため、コストと性能のバランスを評価する必要あり

### 技術的な注意点

- **IAM権限**: Lightsailのマネージドデータベース作成/管理には適切なIAMポリシー（lightsail:GetInstance、lightsail:CreateRelationalDatabase 等）が必要
- **リージョン制限**: 記事時点ではLightsail提供リージョンで利用可能とされるが、個別リージョンでの即時提供状況はコンソールで確認してください
- **コスト**: 高性能バンドルは月額/時間課金が増加します。バックアップやHA構成は追加コストが発生する場合があります
- **バックアップ/HA**: HAプランはフェイルオーバーとレプリケーションを提供するが、RPO/RTO要件に応じて設定とテストが必要
- **バージョン/互換性**: サポートされるMySQL/PostgreSQLのバージョンはドキュメントで確認し、アプリ互換性（拡張や設定）を事前検証してください
- **スケーリング**: 上位バンドルへのスケールアップやダウンのオペレーション（ダウンタイムや接続再設定の有無）を事前に確認すること
- **移行**: 既存のRDSやセルフホストDBからの移行はスキーマ/データ転送方法（ダンプ、レプリケーション等）とダウンタイム計画を検討すること

## [Emr] Amazon EMR Serverless adds support for job run level cost allocation

- **公開日**: 2026-01-09
- **カテゴリ**: Emr
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-emr-serverless-adds-job-run-level

### 概要

Amazon EMR Serverlessがジョブ実行単位（job run level）でのコスト配分（cost allocation）をサポートしました。これにより、個々のジョブ実行ごとにコスト配分タグを付与して、Cost ExplorerやCost and Usage Reportsで詳細な課金可視化が可能になります。

### 変更内容・新機能の詳細

従来はEMR Serverlessアプリケーション単位でのみコスト配分タグを設定できましたが、今回の更新で各ジョブ実行（job run）に対してコスト配分タグを割り当てられるようになりました。ジョブ実行IDやジョブ実行に付与したコスト配分タグでフィルタリングすることで、Cost ExplorerやCost and Usage Reports（CUR）上でジョブ実行単位のコストを追跡・分析できます。これにより、同一アプリケーション内で複数ドメイン（例：ファイナンス、マーケティング）のコストを分離して集計したり、個別ジョブのベンチマークやコスト最適化の評価をより細かく行えるようになります。機能はAmazon EMR Serverlessが利用可能なすべてのリージョン（AWS GovCloud (US)、中国リージョン含む）で利用可能です。ジョブ実行時にタグを付与する方法はコンソール、CLI、SDKなどから行い、タグを課金レポートに反映させるためには請求側でのコスト配分タグの有効化が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、データサイエンティスト、クラウド財務（FinOps）チーム、SRE/運用チーム
- **利用シーンまたは効果**: 個別ジョブのコスト追跡（ジョブ別の費用算出）、ドメイン別コスト分離（同一アプリ内での部門別集計）、ジョブ単位のベンチマークによるコスト最適化
- **運用効果**: コスト分析の粒度が向上し、無駄なリソース使用や高コストジョブの特定、課金の内部負担配分（showback/chargeback）が容易になる

### 技術的な注意点

- **IAM権限**: ジョブ実行にタグを付与・編集するためのEMR Serverless関連の権限と、Cost Explorer/CURを参照するための請求関連権限が必要です（Billing関連の閲覧権限やCost Explorer権限など）。
- **タグの有効化**: Cost ExplorerおよびCost and Usage Reportsにタグを表示するには、AWS請求の「コスト配分タグ」を請求コンソールで有効化する必要があります。タグを有効化してからレポートに反映されるまで時間がかかる場合があります。
- **リージョン制限**: 本機能はEMR Serverlessが利用可能な全リージョンで有効（AWS GovCloud (US)、中国リージョンを含む）とされていますが、利用前に対象リージョンでのドキュメント確認を推奨します。
- **コスト**: 機能自体に追加料金は発生しませんが、Cost and Usage ReportsのS3配信設定や大量の詳細データ保存・分析によりストレージやクエリ費用が増える可能性があります。
- **運用上の注意**: ジョブ実行時にタグを確実に付与する運用パターン（CI/CDやジョブテンプレートへの組み込み）を整備してください。タグ命名規約やタグ数制限にも注意が必要です（アカウント／サービスごとのタグ制限はAWSドキュメント参照）。

- https://docs.aws.amazon.com/emr-serverless/latest/ug/job-level-cost-allocation.html

## [Rds For Sql Server] Amazon RDS for SQL Server now supports cross-region read replica in additional AWS Regions

- **公開日**: 2026-01-09
- **カテゴリ**: Rds For Sql Server
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-rds-sql-server-cross-region-read-replica-in-additional-aws-regions/

### 概要

Amazon RDS for SQL Server が追加の16リージョンでクロスリージョン読み取りレプリカをサポートしました。これにより、他リージョンのユーザーに近い場所で読み取り専用レプリカを作成し、読み取りスケールアウトや障害時のディザスタリカバリに活用できます。

### 変更内容・新機能の詳細

今回の拡張により、RDS for SQL Server はプライマリ DB インスタンスに対して同一または別リージョンに最大15台までの読み取りレプリカを作成可能です。読み取りレプリカは読み取り専用ワークロードのスケールアウトや、レプリカを 'プロモート' してスタンドアロンの本番データベースとして使用することでディザスタリカバリ用途にも利用できます。今回サポートが追加されたリージョンは以下の16箇所です: Africa (Cape Town)、Asia Pacific (Hong Kong)、Asia Pacific (Hyderabad)、Asia Pacific (Jakarta)、Asia Pacific (Malaysia)、Asia Pacific (Melbourne)、Asia Pacific (Taipei)、Asia Pacific (Thailand)、Canada West (Calgary)、Europe (Milan)、Europe (Spain)、Europe (Zurich)、Israel (Tel Aviv)、Mexico (Central)、Middle East (Bahrain)、Middle East (UAE)。開始方法やバージョン/エディションの対応状況、細かい設定手順は Amazon RDS SQL Server User Guide を参照してください。一般にクロスリージョンの読み取りレプリカは非同期レプリケーションとなるため、レプリケーション遅延の可能性がある点に留意してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者、アプリケーション開発者、SRE/運用チーム
- **利用シーン**: グローバルユーザー向けに読み取りレイテンシを低減するための読み取り専用レプリカ配置、読み取り負荷のスケールアウト
- **運用効果**: リージョン間での読み取り性能向上、読み取り負荷の分散、レプリカをプロモートすることで地域障害時の復旧手段を確保

### 技術的な注意点

- **IAM権限**: レプリカ作成・プロモーションには適切なRDS関連のIAM権限が必要です。事前に権限を確認してください。
- **リージョン制限**: 今回は上記16リージョンにサポート追加。その他リージョンは未対応の可能性があるため、使用予定リージョンが対応済みか公式ドキュメントで確認してください。
- **コスト**: レプリカインスタンスのインスタンス料金とストレージ料金、リージョン間データ転送（アウトバウンド）に対する追加コストが発生します。コスト試算を行ってください。
- **レプリケーション特性**: クロスリージョンレプリケーションは非同期で動作するため、レプリケーション遅延（レプリカのデータがプライマリより遅れる）が発生する可能性があります。整合性要件を確認してください。
- **レプリカ数制限**: プライマリあたり最大15台の読み取りレプリカを作成可能です。
- **プロモーション**: レプリカのプロモートはワンウェイ操作で、プロモート後は元に戻せない場合があります。プロモーション時にアプリケーションの切替/ダウンタイムが必要となる場合があるため手順を確認してください。
- **バージョン/エディション互換性**: SQL Server のバージョンやエディションによって機能制約がある場合があります。対応表は User Guide を参照してください。
- **ネットワーク/セキュリティ**: レプリカを作成するリージョンの VPC、サブネットグループ、セキュリティグループ、エンドポイント設定を適切に構成する必要があります。
- **Multi-AZ との違い**: Multi-AZ は高可用性目的の同期レプリケーション（フェイルオーバー）であり、読み取り専用のスケーリングや地理的分散を目的とする場合は読み取りレプリカが適切です。
