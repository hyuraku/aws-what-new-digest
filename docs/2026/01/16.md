## [Mwaa] Amazon MWAA now available in additional Region

- **公開日**: 2026-01-16
- **カテゴリ**: Mwaa
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-mwaa-additional-region

### 概要

Amazon Managed Workflows for Apache Airflow (MWAA) が AWS リージョン Asia Pacific (Thailand) で利用可能になりました。MWAA は Apache Airflow をマネージドで提供し、ワークフローのオーケストレーションを簡素化します。

### 変更内容・新機能の詳細

今回の更新により、MWAA のサービスが新たに Asia Pacific (Thailand) リージョンで利用可能になりました。MWAA は Apache Airflow のプラットフォームをマネージドサービスとして提供し、スケーラビリティや可用性、セキュリティを向上させつつ、基盤インフラの運用負荷を軽減します。一般的に MWAA 環境では、DAG やプラグインを格納する Amazon S3、環境を配置する VPC・サブネット設定、環境実行に必要な IAM ロール、CloudWatch によるログ・メトリクス収集などの構成要素が必要となります。新リージョンでの提供により、タイ拠点や近接するユーザーに対して低遅延・データ主権の要件を満たしやすくなります。利用前にリージョンごとの対応状況やサポートされる Airflow バージョン、サービス連携（S3、CloudWatch、ECR など）を公式ドキュメントで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、ETL/ワークフロー開発者、SRE/クラウド運用チーム
- **利用シーン**: タイ国内や近接リージョンでのバッチ処理／ワークフロー実行、データパイプラインのローカル化、リージョン固有のコンプライアンス要件対応
- **運用効果**: 管理対象インフラの削減により運用工数を低減し、リージョン近接による遅延低減と可用性向上が期待できる
- **コスト影響**: 新リージョンでの MWAA 利用は通常の MWAA 課金（環境の時間課金、リソース利用、関連サービスの利用料）に従うため、配置リージョンに応じた料金確認が必要

### 技術的な注意点

- **IAM権限**: MWAA 環境作成・操作には専用の IAM ロールとポリシーが必要です。事前に最小権限を設計してください
- **リージョン制限**: この更新は Asia Pacific (Thailand) リージョン追加のみです。他リージョンでの機能差異（対応 Airflow バージョンや統合サービス）はドキュメントで確認してください
- **ネットワーク要件**: MWAA は VPC・サブネット設定や NAT ゲートウェイ／API エンドポイントへのアクセスを必要とする場合があります。プライベートサブネット配置やセキュリティグループの要件を確認してください
- **コスト**: MWAA は環境実行時間やバックエンドリソースに基づく課金があります。S3、CloudWatch、ECR などの連携サービス利用分も別途発生します
- **Airflow バージョン互換性**: 利用可能な Airflow バージョンはリージョン・タイミングにより異なる可能性があります。移行や新規構築時はサポートされるバージョンを確認してください
- **既存環境移行**: 他リージョンの MWAA から移行する場合、DAG・プラグイン・依存イメージの移行、IAM ロールやネットワーク設定の再構築が必要です

## [General] AWS Outposts racks support multiple LGW routing domains

- **公開日**: 2026-01-16
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-outposts-multiple-lgw-routing-domain

### 概要

AWS Outpostsラックで複数のローカルゲートウェイ（LGW）ルーティングドメインをサポートするようになりました。1つのOutpostあたり最大10個の分離されたルーティングドメインを作成でき、それぞれ独立したルートテーブルとBGPセッションを持てます。

### 変更内容・新機能の詳細

新機能により、Outpostsラック上で最大10個のLGWルーティングドメインを作成可能です。各ルーティングドメインは独自のLGW VIFグループ、LGWルートテーブル、VPC関連付け、およびオンプレミスとの個別BGPセッションを持ち、ドメイン間でトラフィックが交差しないように分離されます。これにより、同一Outpost上でCustomer-owned IP（CoIP）モードとDirect VPC Routing（DVR）モードを共存させることが可能になり、部門別や事業部別などでオンプレミス接続を論理的にセグメント化できます。設定はAWS Management ConsoleまたはAWS CLIで行えます。利用可能なのは第2世代（second-generation）Outpostsラックで、追加料金は発生しません。リージョン対応状況はOutpostsのFAQで確認してください。実装の詳細やベストプラクティスは公式ドキュメントや関連ブログ記事を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Outpostsを利用するクラウド/ネットワークエンジニア、オンプレとクラウドを統合するSREやネットワーク担当者
- **利用シーンまたは効果**: 部門別ネットワーク分離、マルチテナント運用、CoIPとDVRを同一Outpostで共存させる設計、異なるBGPポリシーや経路制御をドメイン単位で適用
- **運用効果**: ルーティングの分離によりネットワーク障害の影響範囲を限定できるほか、オンプレ側の課金/監査単位やセキュリティ境界を明確化できる
- **制約・留意点**: ドメイン数はOutpostごとに最大10、対応は第2世代Outpostsに限られるため事前確認が必要

### 技術的な注意点

- **IAM権限**: Outposts、VPC（LGW関連）、EC2、Direct Connect/VPN等のリソースを変更できる権限が必要（具体的にはOutposts関連とVPCの作成・更新権限、BGP/VIF管理権限を確認してください）
- **リージョン制限**: 第2世代Outpostsが利用可能なリージョンのみ対応。詳細はOutposts FAQで確認してください
- **制限事項**: 1 Outpostあたり最大10ルーティングドメイン。各ドメインは独立したLGW VIFグループとBGPセッションを持つため、BGPやVIFの管理数が増える点に注意
- **運用上の注意**: ドメイン間でルートが交差しないようにプレフィックス計画を行うこと、セキュリティグループやNACLはVPCレイヤの制御なのでルーティング分離だけでは不十分な場合があることを考慮すること
- **コスト**: 本機能自体に追加料金は発生しないと明記されているが、関連するVIF/Direct Connectやデータ転送コストは通常の料金が適用されるため見積りが必要

- https://aws.amazon.com/outposts/faqs/

## [Outposts] Second-generation AWS Outposts racks are now supported in additional AWS Regions

- **公開日**: 2026-01-16
- **カテゴリ**: Outposts
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/second-generation-aws-outposts-racks-additional-aws-regions

### 概要

第二世代（Second-generation）のAWS Outpostsラックが、南米（サンパウロ）および欧州（ストックホルム）リージョンでサポートされるようになりました。これにより、これらのリージョンをホームリージョンとしてOutpostsラックを発注でき、低遅延やデータレジデンシー要件に最適化できます。

### 変更内容・新機能の詳細

AWS Outpostsラックは、AWSのインフラストラクチャ、サービス、API、ツールをオンプレミスのデータセンターやコロケーションスペースに拡張し、一貫したハイブリッド環境を提供します。今回の発表ではSecond-generation Outpostsラックがサンパウロ（South America）とストックホルム（Europe）リージョンで利用可能になり、これらのリージョンを“ホームリージョン”としてOutpostsラックを注文・接続できます。Outpostsはローカルで低遅延が要求されるワークロード（オンプレシステムとの高速連携やリアルタイム処理）を実行しつつ、管理やメタデータのためにホームリージョンと安全に接続します。また、データレジデンシーの要件に応じてデータをオンプレミスで処理・保持することが可能です。地域拡張により、顧客はレイテンシー、法規制、運用拠点に合わせた接続先リージョンの選択肢が増えます。詳細や国・地域の対応状況、導入手順については公式ブログ、ユーザーガイド、OutpostsラックのFAQで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: ハイブリッド構成を必要とする企業（エンタープライズ、スタートアップ、公共セクター）、オンプレミスでの低遅延処理やデータレジデンシーが求められるシステム担当者
- **利用シーン**: ローカルでのリアルタイム処理、工場・医療・金融などの低遅延アクセス、法令でデータの域内滞在が必要なデータ処理、オンプレミス資源とクラウドサービスの統合運用
- **運用効果**: ホームリージョンを近隣のリージョンにすることでネットワーク遅延削減やデータ主権遵守が容易になり、運用・監視をクラウド側で一元化できる
- **リージョン影響**: サンパウロ（South America）とストックホルム（Europe）を新たにサポート対象に追加したことで、南米・北欧拠点の顧客がより最適なホームリージョンを選択可能
- **法令・コンプライアンス**: データレジデンシーや地域ごとの法規制に対応しやすくなる（ただし最終的な法的適合性は顧客側で確認が必要）

### 技術的な注意点

- **IAM権限**: Outpostsの作成・管理には適切なIAM権限が必要（Outposts関連のサービスロールやAPI権限を事前に確認してください）
- **リージョン制限**: 今回はサンパウロとストックホルムが追加されたが、全ての国・地域で即時注文可能とは限らないため、対応国・地域リストはOutpostsラックFAQで最新情報を確認してください
- **ネットワーク接続**: Outpostsはホームリージョンとのサービスリンクを必要とするため、十分な帯域、ルーティング、ファイアウォール設定、そして必要に応じたDR/冗長回線設計を検討してください
- **物理要件・設置**: ラック設置に伴う電源、冷却、床荷重、現地の設置スペースやコロケーション要件（アクセス、搬入経路等）を事前に確認・準備する必要があります
- **サービス互換性**: 全てのAWSサービス/インスタンスタイプがOutposts上で利用できるわけではないため、利用予定のサービスのOutposts対応状況をユーザーガイドで確認してください
- **コスト**: Outpostsはラックのインフラ費用（ハードウェア/管理料）に加え、利用するAWSサービス（EC2/EBS等）の料金が発生します。リージョンや構成によってコストが異なるため見積もりが必要です
- **導入期間・サポート**: ラックの発注から設置、検証までにリードタイムがあり、オンサイト作業やAWSとパートナーの調整が必要です。事前に導入スケジュールとサポート体制を確認してください

- https://docs.aws.amazon.com/outposts/latest/userguide/

## [Govcloud Us] Amazon S3 Storage Lens is now available in AWS GovCloud (US) Regions

- **公開日**: 2026-01-16
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/s3-storage-lens-aws-govcloud-us-regions/

### 概要

Amazon S3 Storage LensがAWS GovCloud (US) リージョンで利用可能になりました。これにより、GovCloud環境でも組織横断のストレージ使用状況・アクティビティの可視化と最適化が行えます。

### 変更内容・新機能の詳細

S3 Storage Lensは、組織内の複数アカウント・複数バケットにまたがるオブジェクトストレージの使用状況とアクティビティを単一ビューで提供します。今回のリリースでAWS GovCloud (US) リージョンでも利用可能となり、コスト最適化（未完了のマルチパートアップロードや非現行バージョンの蓄積検出など）、データ保護ギャップの特定（S3 Versioning や Cross-Region Replication の未設定バケットの検出など）、およびアプリケーション性能のボトルネック検出（リクエスト分布やオブジェクトサイズ分布、リージョン間転送の追跡など）に役立つメトリクスが利用できます。Storage Lensは組織階層やプレフィックス単位など複数の集約レベルでドリルダウン可能で、デフォルトで全顧客に無料メトリクス（14日分の履歴）が有効になります。より詳細な可視化（最長15か月の保持）を行うにはS3 Storage Lens Advanced（有償）にアップグレードします。高度なメトリクスの取得やメトリクスエクスポート設定、保持期間などの詳細は公式ドキュメントと料金ページを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: GovCloud (US) を利用する政府機関・機密ワークロードのクラウド運用者、セキュリティ/コンプライアンス担当、ストレージコスト管理者
- **利用シーン**: 組織横断でのストレージ利用状況監視、不要データや古いバージョンの検出によるコスト削減、クロスリージョンレプリケーションやバージョニング未設定のバケット検出によるデータ保護強化、リクエスト/オブジェクトサイズ分析によるアプリ性能改善
- **運用効果**: ストレージコスト最適化、データ保護遵守の可視化、性能ボトルネックの早期検出と改善によるユーザ体験/運用負荷の低減

### 技術的な注意点

- **IAM権限**: 組織全体でStorage Lensを利用する場合は AWS Organizations と S3 Storage Lens を作成・表示・管理するためのIAM権限が必要です。詳細な権限は公式ドキュメントで確認してください。
- **リージョン制限**: 本リリースにより AWS GovCloud (US) リージョンでも利用可能になりましたが、GovCloudは専用パーティションで動作するため、標準（commercial）アカウントとのアカウント管理やデータ連携の設計に注意が必要です。リージョン間/パーティション間の可視化要件がある場合は事前に挙動を確認してください。
- **コスト**: デフォルトで無料メトリクス（14日分）が提供されます。詳細な分析や最長15か月の保持が必要な場合は S3 Storage Lens Advanced（有償）にアップグレードする必要があり、追加料金が発生します。メトリクスのエクスポート先（S3等）や保持設定によるストレージコストも考慮してください。
- **データ保護/コンプライアンス**: GovCloud環境での運用のため、メトリクスの保存先や暗号化、アクセス制御（KMS キーの管理など）を適切に設定してください。
- **設定/出力**: Storage Lensは組織レベルやアカウント/バケット/プレフィックス単位での集約やドリルダウンをサポートします。初期設定やエクスポート設定（エクスポート先バケット、形式、暗号化）を適切に構成してください。
