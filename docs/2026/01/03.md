## [Clean Rooms,marketing:marchitecture/analytics] AWS Clean Rooms now supports detailed monitoring for collaboration queries

- **公開日**: 2026-01-03
- **カテゴリ**: Clean Rooms,marketing:marchitecture/analytics
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/clean-rooms-detailed-monitoring-collaboration-queries

### 概要

AWS Clean Roomsがコラボレーション内のSQLクエリに対する詳細モニタリングをサポートしました。クエリのパフォーマンスやリソース利用に関する詳細なメトリクスをCloudWatchに公開できます。

### 変更内容・新機能の詳細

今回の機能により、Clean Roomsのコラボレーションで実行されるSQLクエリについて、詳細モニタリング用のメトリクスをCloudWatchへ送信できるようになりました。公開されるメトリクスは運用監視とスケール時の可観測性向上を目的としており、クエリのパフォーマンスやリソース使用量（例：クエリの実行時間、ステータス、スキャンされたデータ量やリソース消費の指標などの運用上重要なメトリクス）をCloudWatchで可視化・アラート化できます。コラボレーションの作成者（collaboration creator）は該当コラボレーションで詳細モニタリングを有効化でき、また分析を実行する側（analysis runner）や設定された支払者（configured payor）もメンバーシップ設定時に有効化できます。これにより、広告主がキャンペーンリフト分析のクエリをCloudWatchで監視して性能問題の検出やコスト最適化を行う、といったユースケースが想定されます。詳しいリージョン対応状況はAWSのリージョン表を確認してください。

### 影響範囲・利用シーン

影響を受けるのはClean Roomsを使ってSQL分析を実行する組織・チーム（広告主、データ分析チーム、パートナー企業など）です。大規模なコラボレーションやバッチ／インタラクティブ分析を行う環境で、クエリ性能問題の早期検知、リソース最適化、コスト管理が必要なユーザーに特に有用です。CloudWatchへメトリクスを送ることで既存の監視・アラート基盤やダッシュボードに統合できます。

### 技術的な注意点

・有効化権限: コラボレーション作成者は詳細モニタリングを有効化可能。分析実行者や設定された支払者もメンバーシップ設定時に有効化できるため、権限と運用フローを事前に設計してください。\n・CloudWatchコスト: 詳細メトリクスを送信するとCloudWatchのメトリクス、API呼び出し、ダッシュボード、アラートに対する課金が増える可能性があります。メトリクス量と保持期間を検討し、コスト見積もりを行ってください。\n・データ公開範囲: この機能は運用メトリクスを公開するものであり、Clean Roomsの主旨である生データ非公開／合意に基づく集計制約は維持されるはずですが、監視メトリクスに含まれる情報がコラボレーションポリシーに沿っているかを確認してください。\n・リージョン制限: Clean Rooms自体の提供リージョンに依存します。利用可能リージョンはAWSのリージョン表で確認してください。\n・実装注意: 記事では「クエリ性能とリソース利用に関する詳細メトリクス」とのみ記載されており、公開される個々のメトリクス名称・スキーマはドキュメントで確認する必要があります。監視設定（アラーム閾値、ダッシュボード）やログ連携の要否を事前に設計してください。\n・請求・コスト分担: 支払者(payor)が有効化できる設計のため、どのアカウントがCloudWatch課金を負担するかを契約や設定で明確にしてください。\n・権限とIAM: CloudWatchへメトリクスを送信するためのIAM権限や、Clean Roomsでのコラボレーション管理権限を確認してください。

## [Connect,marketing:marchitecture/customer Enablement,marketing:marchitecture/business Productivity,general:products/aws Govcloud Us] Amazon Connect now provides the capability to store nested JSON object and looping arrays

- **公開日**: 2026-01-03
- **カテゴリ**: Connect,marketing:marchitecture/customer Enablement,marketing:marchitecture/business Productivity,general:products/aws Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-connect-nested-json-object-looping-arrays

### 概要

Amazon ConnectのフローでネストしたJSONオブジェクトや配列（ループするリスト）をそのまま保存・参照できるようになり、1回のバックエンド呼び出しで取得した複雑なデータをフロー内で順次処理できる機能が追加されました。これにより、繰り返しのAPI呼び出しを減らし、より動的で実用的な自動化体験が構築しやすくなります。

### 変更内容・新機能の詳細

フロー内で完全なデータレコード（ネストされたJSONオブジェクトやリスト）を保存でき、特定の要素（例：注文リストから特定の注文）へ直接参照できます。加えて、配列の各項目を自動的に順に処理するループ機能が提供され、現在のループ位置（インデックス）をトラックしながら項目レベルの情報へアクセス・提示できます。結果として、旅行代理店が顧客の全行程を1回のリクエストで取得して各予約を順に確認・更新したり、銀行が直近の取引を1件ずつ案内したりするようなユースケースが容易になります。これらはフロー設計のシンプル化、バックエンドへの呼び出し回数削減（レイテンシーとコスト低減につながる可能性）に寄与します。詳細な使用方法、参照式や制御要素の仕様はAmazon Connect Administrator Guideに記載されています。この記事によれば、本機能はAmazon Connectが利用可能なすべてのAWSリージョンで利用可能です。

### 影響範囲・利用シーン

影響を受けるユーザー: コンタクトセンターのフロービルダー、システム統合エンジニア、CRMやバックエンドAPIと連携する開発チーム。主な利用シーンは、複数件のレコードを一括取得してユーザーに順次提示・編集するワークフロー（行程、注文一覧、取引履歴など）。メリットとして、API呼び出し回数と総レイテンシーの低減、フローの可読性・保守性向上、よりリッチで動的な自動応答の実現が期待できます。コスト面ではバックエンドAPIコール数が減ることで間接的な費用削減が見込めますが、フロー内で保存するデータ量の増加がパフォーマンスに与える影響は検証が必要です。リージョン制限: 記事では「Amazon Connectが利用可能なすべてのAWSリージョン」で提供と明記されています（GovCloud含むかは利用リージョンの該当状況を確認してください）。

### 技術的な注意点

・保存場所と有効期間: 記事はフロー内でデータを保存・参照できると述べていますが、実際の保存スコープ（コンタクト属性／セッション状態の寿命）や永続化の可否・方法についてはAdministrator Guideの仕様を確認してください。\n・サイズ・数の制限: ネスト深度やJSONの総サイズ、配列長に関する制限は記事に明示されていません。実運用前に管理ガイドでの属性サイズ制限やフロー実行あたりのメモリ制限・タイムアウトを確認し、負荷テストを行ってください。\n・参照方法と構文: ネスト要素や配列アイテムの参照方法（パス表現、インデックス指定など）は管理ガイドの記法に従って実装してください。\n・ループ制御: 無限ループや想定外の長大配列処理を防ぐため、ループ終了条件・最大反復回数・タイムアウトを設計時に明示してください。\n・エラー処理とリトライ: バックエンドからの不正なJSONや部分欠損、ネットワーク障害時のフォールバック処理を組み込んでください。\n・セキュリティとコンプライアンス: 取得・保存するデータに個人情報(PII)や機密情報が含まれる場合の暗号化、アクセス制御、ログ出力の扱いを確認し、必要に応じてKMSやIAMロールで保護してください。\n・パフォーマンスとコスト: API呼び出し削減により外部サービス側のコストが下がる可能性がありますが、フロー内での大きなデータ保持はフロー実行のリソース消費を増やすため、レスポンス時間や同時実行性に与える影響を評価してください。\n・リージョンと互換性: 記事は全てのAmazon Connect対応リージョンで提供としていますが、特定リージョン（例えばGovCloud）のポリシーやリージョン間差異は事前確認を推奨します。
