## [Ec2] Amazon EC2 G5 instances are now available in Asia Pacific (Hong Kong) Region

- **公開日**: 2026-01-05
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-ec2-g5-now-available-asia-pacific-hong-kong

### 概要

Amazon EC2のG5インスタンス（NVIDIA A10G Tensor Core GPU搭載）がアジアパシフィック（香港）リージョンで利用可能になりました。グラフィックス集約型や機械学習ワークロード向けの高性能GPUインスタンスです。

### 変更内容・新機能の詳細

G5インスタンスはNVIDIA A10G Tensor Core GPU（最大8GPU）と第2世代AMD EPYCプロセッサを組み合わせたインスタンスファミリーです。最大構成は192 vCPU、最大100 Gbpsのネットワーク帯域、最大7.6 TBのローカルNVMe SSDをサポートします。8つのインスタンスサイズが用意されており、単一GPUからマルチGPU構成まで選択可能です。用途別に最適化されたNVIDIAドライバ（compute、gaming、workstation）が利用でき、リモートワークステーション、ビデオレンダリング、クラウドゲーム、高速な機械学習（NLP、コンピュータビジョン、レコメンダ）でのトレーニングおよび推論に向きます。購入はオンデマンドおよびリザーブドインスタンスで可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: グラフィックス開発者、CG/映像制作チーム、ゲーム開発者、機械学習エンジニア、SRE/クラウドインフラ担当者
- **利用シーン**: リモートワークステーションによる高精細グラフィック編集、リアルタイムレンダリング／クラウドゲーミング、NLP/CV/レコメンダの大規模トレーニングおよび低レイテンシ推論
- **運用効果**: GPUアクセラレーションによる処理時間短縮と高品質レンダリングの実現。インスタンスサイズの柔軟性によりコスト対性能の最適化が可能

### 技術的な注意点

- **IAM権限**: EC2起動・管理に必要な標準IAM権限（RunInstances等）を用意してください。イメージやカスタムAMIを使う場合は追加のS3/ECRアクセス権が必要となる場合があります。
- **リージョン制限**: 本リリースはアジアパシフィック（香港）リージョンでの提供開始を示します。他リージョンでの利用状況はリージョンごとに異なります。
- **ドライバ/AMI**: NVIDIAのワークロード別ドライバ（compute/gaming/workstation）を選択してインストールしてください。最適なパフォーマンスのために対応カーネルやENABLED NVMeドライバを含む公式/最適化済みAMIの利用を推奨します。
- **インスタンス仕様**: 最大8 GPU、192 vCPU、最大100 Gbpsネットワーク、最大7.6 TB NVMeというハードウェア上限を確認の上でサイズを選択してください。
- **コスト**: GPUインスタンスは一般的に高額です。オンデマンド、リザーブド（RI）を比較し、長期利用はRIやSavings Plansでの割引を検討してください。ネットワーク転送や大容量NVMe利用によるストレージ/IOコストも考慮が必要です。
- **クォータ/上限**: 新しいGPUインスタンスはアカウントのクォータ（GPUインスタンス数やvCPU上限）に影響します。上限引き上げが必要な場合はサポートへ申請してください。

## [Resource Explorer] AWS Resource Explorer is now available in AWS Asia Pacific (New Zealand) Region.

- **公開日**: 2026-01-05
- **カテゴリ**: Resource Explorer
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-resource-explorer-aws-asia-pacific-new-zealand/

### 概要

AWS Resource Explorerがアジアパシフィック（ニュージーランド）リージョン（ap-nz-1）で利用可能になりました。これにより、コンソール、CLI、SDK、または統一検索バーからリージョンやアカウントを跨いだリソース検索・発見が可能になります。

### 変更内容・新機能の詳細

今回の拡張により、Asia Pacific (New Zealand) リージョンでもAWS Resource Explorerのリソース検索機能が利用できるようになりました。Resource Explorerは、複数のAWSリージョンや組織内アカウントにまたがるリソースをインデックス化して検索できるサービスで、検索はAWS Management Consoleの統一検索バー、専用コンソール、AWS CLI、AWS SDKから実行できます。導入時はコンソールでResource Explorerを有効化し（インデックス作成）、必要に応じてAWS Organizationsと連携して組織内での共有設定を行います。リージョン対応状況はAWSのリージョン製品一覧で確認できます。詳細や開始手順は公式ドキュメントとプロダクトページを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドエンジニア、SRE、運用チーム、クラウド資産管理者
- **利用シーン**: マルチリージョン／マルチアカウント環境でのリソース検出、インベントリ作成、トラブルシューティング（例：どのリージョンに特定のEC2/ RDS/ S3リソースがあるかを即時検索）
- **運用効果**: リソース探索の工数削減、インシデント時の迅速な影響範囲把握、ガバナンス／監査の効率化
- **地理的影響**: ap-nz-1（Asia Pacific — New Zealand）リージョンにデプロイしている組織で遅延低減やデータ所在地要件への対応が可能

### 技術的な注意点

- **IAM権限**: Resource Explorerの有効化・設定や検索実行には専用の権限が必要（Resource Explorer関連のAPI操作権限と、参照対象サービスのRead/Describe権限を確認してください）
- **リージョン制限**: 本発表は ap-nz-1 の対応追加。利用可能リージョンはAWSのリージョン製品一覧で随時確認してください
- **インデックス／データ整合性**: リソースのインデックス作成には時間がかかる場合があり（数分程度）、最新の状態反映に遅延が生じる可能性があります
- **組織連携**: 組織（AWS Organizations）で横断検索を行う場合は、インデックスの共有設定や信頼設定を正しく構成する必要があります
- **コスト**: Resource Explorer自体は追加の利用開始手順が必要ですが、関連するAPI呼び出しやログ保存、その他連携サービスに対して課金が発生する可能性があるため、公式ドキュメントの料金情報を確認してください

## [Transfer Family] AWS Transfer Family is now available in AWS Asia Pacific (New Zealand) region

- **公開日**: 2026-01-05
- **カテゴリ**: Transfer Family
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-transfer-family-asia-pacific-new-zealand-region

### 概要

AWS Transfer FamilyがAWS Asia Pacific (New Zealand) リージョンで利用可能になりました。SFTP、FTP、FTPS、AS2 を使ったマネージドなファイル転送が同リージョン内で直接行えます。

### 変更内容・新機能の詳細

今回の拡張で、Asia Pacific (New Zealand) リージョンの顧客はAWS Transfer Familyを使って、SFTP、FTP、FTPS、AS2プロトコルによるファイル転送をAmazon S3およびAmazon EFSへ/から実行できます。Transfer FamilyはマネージドMFT（Managed File Transfer）サービスで、以下の点が技術的に重要です。
- 対応プロトコル: SFTP（SSHベース）、FTP、FTPS（TLS/SSL）、AS2（B2B向けメッセージング／MDN対応）。
- ストレージ統合: Amazon S3とAmazon EFSをネイティブサポートし、ユーザごとにホームディレクトリやアクセスロールを紐づけ可能。
- 認証・ID連携: サービス管理ユーザーの他、カスタムIDプロバイダー（APIベース）を用いた外部認証連携が可能で、既存のID/パスワードや鍵、ディレクトリサービスとの統合をサポートします。
- ネットワークとエンドポイント: パブリック接続とVPC内でのプライベート接続（VPC接続オプション）を選べ、セキュリティグループやVPCルーティングによりアクセス制御できます。
- イベント／自動化: Transfer FamilyはAmazon EventBridgeやCloudWatch Logsと連携でき、ファイル到着時のLambdaトリガー等を使ったワークフロー自動化や処理パイプライン構築が容易です。
- B2B移行支援: AS2サポートや証明書管理、ログ・監査機能により既存の企業間ファイル転送（EDIなど）のクラウド移行を支援します。
これらにより、リージョン内で遅延を低減し、オンプレミスのMFT基盤からの移行や新規構築が容易になります。詳細は製品ページとユーザーガイドを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: ファイル転送/連携を扱うシステム管理者、SRE、B2B統合担当者、データ連携チーム
- **利用シーン**: 既存のSFTP/FTPS/FTP/AS2ベースのB2B受発注やログ受取のクラウド移行、S3/EFSを使ったデータレイクへの取り込み、イベント駆動のファイル処理パイプライン構築
- **運用効果**: リージョン内での低遅延転送とマネージド運用によりインフラ運用負荷を削減し、EventBridge/Lambda連携で自動処理を実現できる
- **リージョン制限**: 本発表によりNew Zealandリージョンで利用可能になったが、利用前に対象リージョンの完全サポート状況をAWS Region Tableで確認する必要あり

### 技術的な注意点

- **IAM権限**: Transfer Familyのリソース作成、S3/EFSアクセスには適切なIAMロールとポリシー（サーバー作成権限、ポリシーでのS3/EFSアクセス許可等）が必要です
- **リージョン制限**: 機能のリージョン提供状況は逐次追加されるため、他リージョンでの利用や特定機能（例: 一部の認証方式やエンドポイントタイプ）がまだ未対応の可能性があるため事前確認を推奨します
- **コスト**: サーバー（エンドポイント）稼働時間、転送データ量、関連するS3/EFSストレージとデータ転送料金が発生します。設計時に課金モデルを確認してください
- **認証方式**: サービス管理ユーザーのほかカスタムIDプロバイダー（API）による認証連携が可能。既存のディレクトリや鍵管理との統合方法を事前に検討してください
- **ログ/監査**: CloudWatch Logs、S3へのアクセスログ、EventBridge連携を使った監査・自動化が可能。ログ保持ポリシーとアクセス監査の要件を設定してください

## [Ec2] EC2 Capacity Manager now includes Spot interruption metrics

- **公開日**: 2026-01-05
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/ec2-capacity-manager-spot-interruption-metrics/

### 概要

Amazon EC2 Capacity Managerにスポットインスタンスの割り込み（interruption）に関する新しいメトリクスが追加され、組織全体でスポットキャパシティの稼働数・割り込み数・割り込み率を可視化できるようになりました。これによりスポット戦略をデータに基づいて最適化できます。

### 変更内容・新機能の詳細

追加されたメトリクスは3つです：
- Spot Total Count: 選択した期間において稼働した“異なる”SpotインスタンスまたはvCPUの合計（期間内に起動していたユニークなインスタンス/ vCPUをカウント）。
- Spot Total Interruptions: 期間内に割り込み（AWSによる回収・終了通知を受けた）と記録されたインスタンス数の合計。
- Spot Interruption Rate: 期間中に割り込みを経験した割合（Spot Total Interruptions ÷ Spot Total Count）。
これらはリージョン、アベイラビリティゾーン、アカウント単位で集計可能で、パターン分析やリージョン／AZ間比較に使えます。実務的には、割り込み率が高いプールを特定してインスタンスタイプ多様化、AZ分散、あるいはSpot Placement Scoreを利用して入手可能性の高いキャパシティプールにシフトする判断に役立ちます。なお、本機能は全ての商用AWSリージョンでデフォルト有効、追加料金は発生しません。始め方はEC2コンソール内の EC2 Capacity Manager を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド運用者、SRE、コスト最適化担当、データプラットフォーム／バッチ処理チーム
- **利用シーン**: スポットインスタンスを使ったバッチ処理や分散コンピューティングで割り込みリスクの可視化と比較分析を行う場面
- **運用効果**: 割り込みの多いリージョン／AZ／インスタンスタイプを特定して再配置や多様化を行うことで、ジョブ中断の低減やコスト最適化が図れる

### 技術的な注意点

- **IAM権限**: EC2 Capacity Managerの表示にはEC2リソースの読み取り権限が必要（例: ec2:DescribeInstances等）。組織横断で可視化する場合はAWS Organizationsやクロスアカウントアクセス設定が必要になる場合があります
- **リージョン制限**: 全ての商用AWSリージョンでデフォルト有効（パートナー/特殊リージョンの対応は要確認）
- **コスト**: EC2 Capacity Manager内のスポット割り込みメトリクスは追加料金なしで利用可能。ただし、メトリクスを外部にエクスポートして可視化・保存（例: CloudWatch LogsやS3へのエクスポート）すると別途コストが発生する可能性があります
- **データ解釈**: 'Spot Total Count'は期間内のユニークなインスタンス／vCPUをカウントするため、短時間での再起動や入れ替わりがあるワークロードではカウントの扱いに注意が必要です。割り込みはAWSによる回収（通常2分の通知）を基に計測されます
- **統合注意**: メトリクスを運用監視ツールやレポートに組み込む場合、アカウントやタグでのフィルタリングポリシーを事前に設計してください
