## [Ec2] Amazon EC2 G5 instances are now available in Asia Pacific (Hong Kong) Region

- **公開日**: 2026-01-05
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-ec2-g5-now-available-asia-pacific-hong-kong

### 概要

Amazon EC2 G5（NVIDIA A10G Tensor Core GPU搭載）インスタンスが、アジアパシフィック（香港）リージョンで利用可能になりました。グラフィックス重視のワークロードや機械学習のトレーニング／推論向けに設計されたGPUインスタンスです。

### 変更内容・新機能の詳細

G5インスタンスはNVIDIA A10G Tensor Core GPU（最大8 GPU）と第2世代AMD EPYCプロセッサを組み合わせたGPUインスタンスファミリーです。インスタンスは最大192 vCPU、最大100 Gbpsのネットワーク帯域、最大7.6 TBのローカルNVMe SSDストレージをサポートし、シングルGPU〜マルチGPUをカバーする8つのサイズが提供されます。用途に応じて計算（CUDA/cuDNN等）／ゲーミング／ワークステーション向けのNVIDIAドライバー（プロファイル）を選択でき、これによりレンダリング、リモートワークステーション、クラウドゲーム、高精度なリアルタイムグラフィックス出力だけでなく、NLP、コンピュータビジョン、レコメンダーなどの機械学習トレーニングおよび推論でも高い性能対コスト比を発揮します。購入モデルはオンデマンドとリザーブドインスタンス（Reserved）に対応しています。運用面では適切なAMI（例：AWS Deep Learning AMI）やNVIDIAのドライバー/ツールキットの導入により、GPU最適化されたソフトウェア環境を簡単に構築できます。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、モデル／推論運用チーム、レンダリング／映像制作チーム、クラウドゲーム／リモートワークステーションを提供する事業者
- **利用シーン**: 高精度なトレーニングや大規模推論、リアルタイムレンダリング、クラウドベースのワークステーション、ゲームストリーミング等のGPU集約型ワークロード（NLP、CV、レコメンドなど）
- **運用効果**: ローカルNVMeと高帯域ネットワークによりI/O/通信ボトルネックを軽減し、マルチGPU構成で短時間でのトレーニングや低レイテンシ推論が可能になる

### 技術的な注意点

- **IAM権限**: EC2起動（ec2:RunInstances 等）、関連ネットワーク/ストレージ操作の権限を持つことを確認してください
- **リージョン制限**: 本アップデートはアジアパシフィック（香港）リージョンでの提供開始を示しています。他リージョンではすでに提供済みか未提供の可能性があります
- **ドライバー／ソフトウェア**: 適切なNVIDIAドライバー（compute/gaming/workstationプロファイル）、CUDA、cuDNNなどを選択・インストールしてください。AWS提供のDeep Learning AMIやNVIDIAのプリビルトドライバーを利用すると導入が容易です
- **ストレージ**: 最大7.6 TBはインスタンスストア（ローカルNVMe）であり、インスタンス停止や終了でデータが消失します。永続化が必要なデータはEBSやS3を使用してください
- **サービスクォータ**: GPUインスタンスはアカウント初期上限が低いことがあるため、必要に応じてサービスクォータ（上限）引き上げを申請してください
- **コスト**: GPUインスタンスは高コストになり得ます。長期利用はリザーブドインスタンスやSavings Plansの検討、スポットインスタンス活用でコスト最適化を行ってください

## [Resource Explorer] AWS Resource Explorer is now available in AWS Asia Pacific (New Zealand) Region.

- **公開日**: 2026-01-05
- **カテゴリ**: Resource Explorer
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-resource-explorer-aws-asia-pacific-new-zealand/

### 概要

AWS Resource Explorerがアジアパシフィック（ニュージーランド）リージョンで利用可能になりました。これにより同サービスを使って同リージョン内のリソース検索・発見ができるようになります。

### 変更内容・新機能の詳細

AWS Resource Explorerは、AWSアカウントとリージョンを横断してリソースの検索・発見を行うサービスです。コンソールの専用画面、AWS Management Consoleの統一検索バー、AWS CLI、またはAWS SDKを通じて検索できます。今回の拡張で、Asia Pacific (New Zealand) リージョンでもResource Explorerのインデックス作成と検索機能が利用可能になりました。設定はResource Explorerコンソールから有効化でき、組織（AWS Organizations）単位での集約や各リージョンのインデックス管理が可能です。初回インデックス作成時は既存リソースの走査（population）に時間がかかる場合があり、以降は増分更新で同期されます。詳細な対応リージョンは公式のリージョン表を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド運用者（SRE/DevOps）、クラウドアーキテクト、セキュリティ／ガバナンス担当者、資産管理者
- **利用シーンまたは効果**: マルチリージョン／マルチアカウント環境でのリソース在庫管理、インシデント対応時の関連リソース特定、準拠性／監査用の資産把握、コスト最適化のための不要リソース発見
- **運用効果**: 各リージョンに散在するリソースを統一的に検索できるためトラブルシューティングや監査に要する時間を短縮できる
- **リージョン追加の効果**: Asia Pacific (New Zealand) のワークロードも同機能で一元検索可能になり、同リージョンを利用する組織の可視性が向上する

### 技術的な注意点

- **IAM権限**: Resource Explorerの設定（インデックスの有効化）と検索には適切なIAMポリシーが必要です。具体的なアクションや最小権限ポリシーは公式ドキュメントで確認してください。
- **リージョン制限**: 本リリースでAsia Pacific (New Zealand) が追加されましたが、サービス対応リージョンは随時更新されるため最新のリージョン表を確認してください（リージョン未対応の場合は利用不可）。
- **初期同期時間**: 初回インデックス作成時は既存リソースの走査に時間がかかることがあります。大規模環境では完了までの時間を考慮してください。
- **組織対応**: AWS Organizationsとの連携により組織単位での検索が可能ですが、組織レベルでの有効化/委任設定やアクセス許可の構成が必要です。
- **コスト**: Resource Explorer自体に目立った追加料金は発生しない場合が多いですが、クロスリージョン通信や関連サービス（例: AWS Config、CloudTrail、ログ保管）による課金は別途発生する可能性があります。必要に応じて請求への影響を確認してください。

## [Transfer Family] AWS Transfer Family is now available in AWS Asia Pacific (New Zealand) region

- **公開日**: 2026-01-05
- **カテゴリ**: Transfer Family
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/aws-transfer-family-asia-pacific-new-zealand-region

### 概要

AWS Transfer Family が AWS Asia Pacific (New Zealand) リージョンで利用可能になりました。SFTP、FTP、FTPS、AS2 によるフルマネージドなファイル転送が、Amazon S3 と Amazon EFS をバックエンドに利用して行えます。

### 変更内容・新機能の詳細

今回のリリースにより、Asia Pacific (New Zealand) リージョンの顧客は AWS Transfer Family を使って次のプロトコルでファイル転送を行えます：SFTP、FTP、FTPS、AS2。Transfer Family は Amazon S3 または Amazon EFS をネイティブなストレージバックエンドとしてサポートし、エンドポイント（パブリック / VPC / VPC エンドポイント構成）を通じて接続可能です。サービスはユーザー認証（サービス管理型 ID、カスタム ID プロバイダ(API 経由)、AWS Directory Service 連携など）を提供し、鍵ベースの SFTP 認証や証明書ベースの AS2 構成をサポートします。さらに、S3 イベントや Lambda との連携で、受信したファイルに対するイベント駆動の処理（ウイルススキャン、ファイル検証、ETL トリガー等）や、MFT（Managed File Transfer）ワークフローのモダナイズ・自動化が行えます。監査・運用面では CloudWatch Logs / CloudTrail による操作ログや転送ログの収集、S3/EFS の暗号化（SSE、EFS 暗号化）や TLS/SSH による転送時の保護が利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: B2B/B2C のファイル連携を行うアプリケーション開発者、SRE、運用チーム、EDI/パートナ連携担当者
- **利用シーン**: 取引先とのEDI（AS2）やSFTPベースのバッチ受け渡し、FTPS/FTP によるレガシーシステムのクラウド移行、受信ファイルに対するイベント駆動処理（Lambda トリガーでの変換・検証・転送）
- **運用効果**: リージョン内での転送によりレイテンシやデータ主権の懸念を低減し、フルマネージドによりサーバ管理負荷を軽減。イベント連携で自動処理を実現し、B2B ファイル連携のモダナイズと移行が容易になる

### 技術的な注意点

- **IAM権限**: Transfer Family の操作（サーバ作成、ユーザー管理、ログ設定）には専用の IAM 権限が必要です。S3/EFS へアクセスするロール/ポリシーも事前に設定してください。
- **VPC/EFS**: Amazon EFS をバックエンドにする場合、Transfer サーバは VPC 内に配置する必要があり、適切なセキュリティグループとマウントターゲット設定が必要です。S3 を使う場合でも VPC エンドポイント（Gateway/Interface）を利用したプライベート接続を検討してください。
- **認証方式**: サービス管理型 ID、カスタム ID プロバイダ（API Gateway + Lambda 等）、Directory Service の選択肢があり、SFTP は SSH 鍵、AS2 は証明書と MDN 設定が必要です。事前にパートナー側との証明書交換などを準備してください。
- **暗号化/セキュリティ**: 転送時は SFTP/FTPS/AS2 のプロトコルに応じた TLS/SSH、保存時は S3 SSE や EFS 暗号化を利用可能です。CloudTrail/CloudWatch で監査ログを有効化してください。
- **コスト**: エンドポイントの時間料金、データ転送量（リージョン内外のデータ転送料金）、S3/EFS ストレージ料金、ログ保存コストなどが発生します。利用前に Transfer Family と関連サービスの料金表を確認してください。
- **リージョン制限**: 本アップデートは Asia Pacific (New Zealand) リージョンでの提供開始を示します。他リージョンでの有無やサービス差異は AWS Region Table を参照してください。
- **運用注意**: AS2 の MDN 処理や再送、FTP/FTPS のパッシブ/アクティブ設定など運用仕様は取引先と合意したパラメータに合わせてテストを行ってください。

## [Ec2] EC2 Capacity Manager now includes Spot interruption metrics

- **公開日**: 2026-01-05
- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/ec2-capacity-manager-spot-interruption-metrics/

### 概要

Amazon EC2 Capacity ManagerにSpot割り込み（interruptions）に関する新しいメトリクスが追加され、組織全体でのSpotキャパシティの稼働数・割り込み数・割り込み率を地域／AZ／アカウント単位で把握できるようになりました。これによりSpot運用の意思決定をデータ駆動で行いやすくなります。

### 変更内容・新機能の詳細

追加された3つのメトリクスは以下です。
・Spot Total Count: 選択した期間内に稼働した「ユニークな」SpotインスタンスまたはvCPUの合計数を表示します（短時間で入れ替わったインスタンスは期間の集計方法により影響します）。
・Spot Total Interruptions: 期間内に発生したSpot割り込み（AWS側による取り上げ・終了）の総件数をカウントします。
・Spot Interruption Rate: 指定期間に稼働したインスタンス（またはvCPU）に対する割り込みの割合（Spot Total Interruptions ÷ Spot Total Count × 100%）を算出します。
これらはリージョン、アベイラビリティゾーン、アカウント単位で閲覧・比較できるため、割り込みパターンの可視化、地域やAZ間での可用性比較、インスタンスタイプ分散やAZ分散、Spot Placement Scoreを用いた最適プール選定といったSpot戦略の最適化に役立ちます。EC2 Capacity Manager上でデフォルト有効・追加料金なしで利用可能（商用リージョン）。AWSコンソールのEC2 Capacity Managerから確認できます。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド運用者、SRE、プラットフォーム／インフラ担当、コスト最適化担当
- **利用シーンまたは効果**: Spot利用の安定化（割り込み率の可視化によるインスタンスタイプやAZの分散判断）、リージョン／アカウント間比較による容量計画
- **運用効果**: 割り込みが多いプールを検出して配置戦略を変更することで、ワークロード中断の低減やコスト効率の向上が期待できる
- **コスト最適化**: Spotの利用を安全に拡大するための根拠が得られ、オンデマンドへの切替やリザーブド容量との組合せ判断がしやすくなる

### 技術的な注意点

- **IAM権限**: EC2 Capacity Manager表示・参照に必要なIAM権限（コンソールアクセスとec2の閲覧系権限が必要）。具体的なポリシーは環境に合わせて確認してください。
- **リージョン制限**: 商用のAWSリージョンではデフォルトで有効。AWS GovCloudや中国リージョンなど特殊リージョンでの対応状況は別途確認してください。
- **コスト**: 本機能自体は追加料金なしで提供されますが、関連する監視・ログ保存（CloudWatchダッシュボードや長期保存）や追加の分析処理には別途コストが発生する可能性があります。
- **データ粒度／計算式**: メトリクスは「選択期間」に基づく集計です。短い期間や高頻度でのインスタンス入れ替わりがあると数値の解釈に注意が必要です。Spot Interruption Rate = Spot Total Interruptions / Spot Total Count × 100% で算出されます。
- **アクセス方法**: 現時点で確認はEC2 Capacity ManagerのAWSコンソールから行えます。API/CLIでの取得可否やエクスポート機能は公式ドキュメントで確認してください。
