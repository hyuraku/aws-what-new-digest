# 2026年03月23日

## [General] AWS HealthImaging is now available in Europe (London)

- **公開日**: 2026-03-23 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/03/aws-healthimaging-europe-london/

### 概要

AWS HealthImagingがAWS Europe (London) リージョンで利用可能になりました。医療画像（DICOM）をペタバイト規模で管理・共有・解析できるHIPAA適合（※BAA必要）なフルマネージドサービスです。

### 変更内容・新機能の詳細

AWS HealthImagingは、医療機関・ライフサイエンス組織・ソフトウェアパートナー向けに設計された医療画像管理プラットフォームです。主な技術要素は以下の通りです。
- ストレージと管理: ペタバイト規模の医療画像をフルマネージドで保存・管理。運用負荷や自己構築のストレージ管理を削減します。
- API互換性: DICOMweb（医療画像の既存アプリケーションとの互換性確保）と、クラウドネイティブな操作を可能にするAWSネイティブAPIの両方を提供。既存のPACSやビューワーとの統合／クラウドファースト設計の双方をサポートします。
- コスト最適化: AWS側のマネージド設計により、DIY（独自構築）ソリューションと比較して最大約40%のストレージコスト削減が見込めるとしています（利用パターンに依存）。
- 臨床ワークフローとAI: 画像アクセスの高速化により臨床ワークフローを改善し、Amazon SageMakerなどのAWS MLサービスと組み合わせることでAI診断アプリ開発を加速できます（統合は設計により実施）。
- セキュリティとコンプライアンス: HIPAA適合（HIPAA-eligible）であり、厳格なアクセス制御・暗号化による機密データ保護をサポートします（※HIPAA対応にはAWSとのBAA締結および顧客側の運用要件遵守が必要）。
本リリースでEurope (London) が追加され、現時点での一般提供リージョンは US East (N. Virginia), US West (Oregon), Asia Pacific (Sydney), Europe (Ireland), Europe (London) です。詳細はAWS HealthImaging Developer Guideを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 医療機関、放射線部門、医療画像ソフトウェアベンダー、ライフサイエンス研究チーム
- **利用シーン**: PACSデータのクラウド移行・長期保管、臨床画像の高速配信、AIモデル学習・推論用データ基盤、画像共有ワークフローの標準化
- **運用効果**: ストレージ運用負荷の低減、最大約40%のストレージコスト削減（ケースによる）、臨床ワークフローでの画像アクセス高速化による診療効率向上
- **データ主権**: Londonリージョンでの提供により英国/欧州内でのデータレジデンシー要件への対応が容易に（リージョン選択によりデータ常駐が可能）

### 技術的な注意点

- **HIPAA/BAA**: サービスはHIPAA-eligibleですが、HIPAA準拠での運用にはAWSとのBusiness Associate Agreement(BAA)締結と顧客側の適切な設定・運用が必要です
- **IAM権限**: アクセスには適切なIAMポリシー設計が必要です。最小権限の原則に従い、API操作やデータアクセス権限を細かく制御してください
- **暗号化/KMS**: 保管時の暗号化（KMSによる管理）や転送時のTLSを利用して機密性を確保することを推奨します（顧客側のKMSキー管理ポリシー設計が必要）
- **リージョン制限**: 現在一般提供されているリージョンは US East (N. Virginia), US West (Oregon), Asia Pacific (Sydney), Europe (Ireland), Europe (London) です。利用前に利用予定リージョンでの提供状況を確認してください
- **コスト**: AWS側の案内では最大約40%のストレージコスト削減が期待できますが、実際のコストは保存容量、IOパターン、データ転送、アクセス頻度、追加サービス（例: ML、ログ保存）により変動します。データ転送（リージョン間やアウトバウンド）コストにも注意してください
- **API互換性**: DICOMwebをサポートするため既存の医療画像ツールと統合しやすい一方、AWSネイティブAPIを使う設計ではアプリケーション側の改修が必要になることがあります。既存PACSとの相互運用性検証を実施してください
- **統合/運用**: AIや解析ワークフローに統合する場合は、データ前処理、匿名化（必要に応じたPHI除去）、アクセス監査ログの設計を事前に計画してください
