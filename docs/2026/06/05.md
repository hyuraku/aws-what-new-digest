## [SageMaker] Amazon SageMaker Data Agent integrates business context into conversations

- **公開日**: 2026-06-05 (JST)
- **カテゴリ**: SageMaker
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-sagemaker-data-agent-bdc/

### 概要

Amazon SageMaker Data AgentがSageMaker Catalogのビジネスコンテキストとメタデータと統合され、業務用語でデータ発見やSQL/Pythonコード生成ができるようになりました。これにより、技術的なテーブル名を解読することなく、業務用語で問い合わせて正しいテーブル・カラムを特定できるようになります。

### 変更内容・新機能の詳細

SageMaker Data AgentはSageMaker Catalogに保存されたビジネス用語（グロッサリ）、カスタムメタデータフォーム、アセットのサマリ、READMEなどのメタデータを参照して、自然言語での問い合わせを業務コンテキストに基づいて解釈します。Collibra、Atlan、Alationなどと同期されたカタログ項目も活用可能で、既存のカタログ投資をそのまま利用します。主な機能は以下の通りです。
- 業務用語に基づくデータ探索: 「顧客離脱に関するデータは？」や「顧客維持率を算出して」といった業務言語で検索し、該当するテーブル／カラムを特定します。
- 正確なコード生成: ビジネスコンテキストを理解することで、初回からより正確なSQLやPythonコードを生成します（例：適切なジョイン順序、フィルタ、カラム選択）。
- マルチステップワークフローの計画: 必要なテーブルと変換の順序を考慮した複数ステップの処理プランを作成します。
- ガバナンスの尊重: データの購読状況（subscription status）を確認し、アクセス権がない場合はアクセス要求リンクを提示します。
- 利用場所: SageMaker Unified StudioのノートブックとQuery Editorで利用可能（Amazon SageMaker Unified Studioが利用可能なリージョンで提供）。
この統合により、既存のデータワークフローを変更せずにインサイト獲得までの時間を短縮し、データチームが業務用語で作業できるようになります。

### 影響範囲・利用シーン

- **対象ユーザー**: データサイエンティスト、データエンジニア、アナリスト、SRE/運用チーム
- **利用シーンまたは効果**: 業務用語でのデータ探索、より正確なSQL/Pythonコード生成、マルチステップのデータ変換フローの自動計画、アクセス管理フローの簡素化
- **運用効果**: カタログ投資を活用して分析準備時間を短縮、初回からのコード精度向上により反復作業を削減、データガバナンスを維持しつつ迅速に分析を開始可能

### 技術的な注意点

- **IAM権限**: SageMaker Unified Studio、Data Agent、SageMaker Catalogへの参照権限（および必要に応じたアクセスリクエスト用のIAM設定）が必要です。
- **リージョン制限**: SageMaker Unified Studioが利用可能な全リージョンで提供されていますが、利用可能リージョンを事前に確認してください。
- **依存サービス**: SageMaker Unified Studio（ノートブック/Query Editor）、SageMaker Catalog、および（必要に応じて）Collibra/Atlan/Alation等のカタログ同期設定が必要です。
- **カタログ品質**: Data Agentの精度はカタログ内のグロッサリやメタデータの品質に依存します。用語定義やREADME、カスタムメタデータを適切に整備してください。
- **アクセス制御／ガバナンス**: Data Agentは購読状況を確認し、アクセス権がない場合はアクセス要求リンクを提示しますが、実際のアクセス制御は既存のガバナンス機構（IAM、データアクセス許可）に従います。
- **コスト**: Data Agent自体の利用が追加料金になる可能性や、SageMaker/Unified Studioの実行に伴う通常のSageMakerリソース料金（ノートブック／クエリエディタ／推論等）が発生する点に注意してください。
- **制限事項**: カタログに該当するメタデータが存在しない場合や不完全な場合は推奨が限定的になる可能性があります。特定の外部カタログ統合の設定状態によっては同期遅延やメタデータ不足が発生します。

## [Cognito] Amazon Cognito now supports multi-Region replication

- **公開日**: 2026-06-05 (JST)
- **カテゴリ**: Cognito
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-cognito-multi-region/

### 概要

Amazon Cognitoがマルチリージョンレプリケーションをサポートしました。ユーザープールの資格情報、プール設定、フェデレーション構成などを指定したスタンバイリージョンにほぼリアルタイムで同期し、リージョン障害時の認証システムの耐障害性を向上させます。

### 変更内容・新機能の詳細

本機能は、プライマリのユーザープールから指定したセカンダリ（スタンバイ）リージョンのレプリカユーザープールへユーザーおよびマシンIDデータをほぼリアルタイムで同期します。同期対象にはユーザー資格情報（パスワードなど）、ユーザープールの設定、ソーシャル認証やSAML/OIDCなどのフェデレーション設定、機械間認証フローの構成が含まれます。リージョン障害発生時にはトラフィックをセカンダリのレプリカに切り替えることで継続的な認証を提供できます。サインイン済みユーザーは再認証なしにアプリへアクセスを継続でき、登録済みユーザーは既存の資格情報でサインイン可能です。サポートされる認証方式はユーザー名/パスワード、ソーシャル・SAML/OIDCフェデレーション、マシンツーマシンの認可フロー等です。マルチリージョンレプリケーションはEssentialsまたはPlus機能階層向けのアドオンとして提供され、管理コンソール、AWS CLI、SDKからレプリカユーザープールを追加して設定します。現在の利用可能リージョンには米国（オハイオ、バージニア北部、北カリフォルニア、オレゴン）、アジア太平洋（ムンバイ、ソウル、シンガポール、シドニー、東京）、カナダ（セントラル）、欧州（フランクフルト、アイルランド、ロンドン、パリ、ストックホルム）、南米（サンパウロ）が含まれます。料金は別途アドオンとして課金されるため、利用前に価格ページを確認してください。詳細な設定手順や運用上の推奨は開発者ガイドを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 認証可用性を重視するクラウドアーキテクト、SRE、セキュリティエンジニア、およびアプリ開発者
- **利用シーン**: リージョン障害発生時のフェイルオーバー／災対（DR）構成、グローバルユーザーベース向けの耐障害性強化
- **運用効果**: リージョン単位のサービス障害時でも認証サービスの継続利用が可能になり、ユーザーの再認証を不要にしてダウンタイムを短縮
- **可用性向上**: スタンバイリージョンがトラフィックを受けられるためRTO（復旧時間目標）を短縮できる
- **コスト影響**: アドオン料金が発生するためコスト増が見込まれる（詳細は価格ページを確認）
- **開発/テストへの影響**: フェイルオーバーやレプリケーション整合性を事前に検証する必要あり

### 技術的な注意点

- **IAM権限**: レプリカ作成や設定変更にはCognito Identity Provider関連の権限（例: cognito-idp:CreateUserPool、UpdateUserPool など）が必要。事前に最小権限を設計してください
- **リージョン制限**: 対応リージョンは限定されているため（記事記載のリージョン一覧を参照）東京など一部リージョンはサポート済だが、利用前にターゲットリージョンの対応状況を確認してください
- **コスト**: Essentials/Plusのアドオンとして追加課金。レプリケーション対象のユーザープールごとに料金が発生する可能性があるため予算設計が必要
- **フェイルオーバー方式**: 記事では「トラフィックをリダイレクトできる」としており、完全自動フェイルオーバーの挙動は明示されていないため、DNS（Route53）やロードバランサ/アプリ側の切替手順を設計・自動化する必要があります
- **レプリケーション整合性**: 「ほぼリアルタイム」とあるためレプリケーション遅延（短時間のラグ）が発生する可能性がある。セッションやトークンの有効性、整合性要件を確認の上、テストを行ってください
- **データ所在地/コンプライアンス**: レプリケーションによりユーザーデータが別リージョンに複製されるため、データ保護や規制（データローカライゼーション）への影響を確認してください
- **検証/運用**: フェイルオーバー時のユーザー体験（既存トークンでの継続利用、フェデレーションプロバイダの動作）を事前に検証し、運用Runbookや監視アラートを整備してください
- **SDK/CLI/Console**: 管理コンソールのほかAWS CLI/SDKでレプリカ作成が可能。自動化やIaC（Infrastructure as Code）との統合を検討してください

## [Aurora] AWS Databases on Vercel now available in additional AWS Regions

- **公開日**: 2026-06-05 (JST)
- **カテゴリ**: Aurora
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/06/aws-databases-vercel-aws-regions/

### 概要

Vercel Marketplaceおよびv0からAmazon Aurora PostgreSQL、Amazon Aurora DSQL、Amazon DynamoDB serverlessを追加のAWSリージョンでプロビジョニングできるようになりました。Vercel上でデータベース作成・管理を完結でき、新規Vercel発行のAWSアカウントには$100 USDのクレジットが付与されます。

### 変更内容・新機能の詳細

主な変更点と機能：
- 対応DB: Amazon Aurora (PostgreSQL)、Amazon Aurora DSQL、Amazon DynamoDB (serverless)。
- Vercel統合: Vercel Marketplaceおよびv0のUI/ワークフローから、既存のAWSアカウントへリンクするか、新規AWSアカウントを作成してデータベースを秒単位で作成可能。手動でのコード記述やインフラプロビジョニング不要（v0は自然言語でアイデアを記述すると仕様設計・コード・インフラを自動生成してデプロイ）。
- 管理: VercelダッシュボードのAWS設定からプラン管理、支払い情報追加、利用状況の確認が可能。作成されたリソースは指定したAWSリージョン上に配置されるため、データ主権やレイテンシ要件に応じた配備ができる。
- 新規アカウント特典: Vercelから作成した新しいAWSアカウントでは3つのデータベースにアクセスでき、最大6か月間有効な$100 USDクレジットが付与される（適用範囲は記事記載のDBオプションに準拠）。
- リージョン: Aurora PostgreSQLおよびDynamoDBはデフォルトで17リージョン、Aurora DSQLは16リージョンで利用可能。記事で明示されたリージョンには以下が含まれる：US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Mumbai), Asia Pacific (Osaka), Asia Pacific (Seoul), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (Ireland), Europe (London), Europe (Paris), Europe (Stockholm), South America (São Paulo)。
- 運用面: AWS側のマネージドDB（Aurora/DynamoDB）のセキュリティ、可用性、コストパフォーマンスを活用でき、プロトタイプからAI/データ駆動型の本番アプリケーションまで適用可能。

### 影響範囲・利用シーン

- **対象ユーザー**: Vercelを使うフロントエンド/フルスタック開発者、SaaSスタートアップ、プロトタイピングを行うチーム、AI／データ駆動アプリケーション担当者
- **利用シーン**: 低レイテンシが必要なエッジに近いデータ配置、短時間でのDBプロトタイピング、Vercel上からの本番データベース作成・運用、既存AWSアカウントと連携したアプリ移行
- **運用効果**: DB作成のオーバーヘッド削減と時間短縮（秒〜分単位で作成可能）、データレジデンシーを選べることでレイテンシとコンプライアンス要件を最適化、初期コストをクレジットで軽減

### 技術的な注意点

- **IAM権限**: VercelがAWSリソースを作成するためのクロスアカウントロールまたは一時的なIAM権限が必要。CloudFormation、RDS、DynamoDB、IAM、Secrets Manager等のリソース作成権限が関係します。事前に必要権限を確認してください。
- **リージョン制限**: Aurora PostgreSQL／DynamoDBはデフォルトで17リージョン、Aurora DSQLは16リージョンで利用可能。利用可能リージョンは記事に記載のリージョン一覧を確認してください。リージョン未対応の場合はVercel経由での作成ができません。
- **ネットワーク**: AuroraをVPC内に配置する場合のサブネット、セキュリティグループ、VPCピアリング/エンドポイント設計は考慮が必要。Vercel側とアプリ間の接続要件（パブリックアクセス／プライベート接続）を事前に検討してください。
- **コスト**: 新規Vercel経由のAWSアカウントに$100 USD（6か月有効）クレジットが付与されますが、それを超えると通常のAWS料金が発生します。Aurora（インスタンス/ストレージ/IO）やDynamoDB（キャパシティ/オンデマンド/ストレージ）の料金構造を確認してください。
- **運用管理**: リソースはAWS上に作成されるため、本番運用時のバックアップ、監視（CloudWatch等）、スケーリングポリシーはAWS側で設定・確認する必要があります。Vercelダッシュボードは作成・請求・基本的な使用状況確認を提供しますが、詳細なDB運用はAWSコンソールで管理する場合があります。
- **セキュリティ/コンプライアンス**: データが置かれるリージョンとアカウントが重要です。ログ保管、暗号化、アクセス制御、監査要件を満たすためにAWS側の設定を確認してください。

## [EKS] Amazon EKS Capabilities now supports Amazon CloudWatch Vended Logs  

- **公開日**: 2026-06-05 (JST)
- **カテゴリ**: EKS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-eks-capabilities-logging

### 概要

Amazon EKS Capabilities が Amazon CloudWatch Vended Logs をログ配信ソースとしてサポートするようになりました。これにより Argo CD、AWS Controllers for Kubernetes (ACK)、kro のマネージドコントローラのログを CloudWatch（および S3 / Kinesis Data Firehose）へ確実に送り、監視やトラブルシューティングを行えます。

### 変更内容・新機能の詳細

EKS Capabilities の各機能（Argo CD、ACK、kro）から出力されるマネージドコントローラのログを、CloudWatch Vended Logs の配信ソースとして有効化できるようになりました。設定は AWS コンソールまたは CloudWatch の API を通じて個別の Capability 毎に行えます。配信先は CloudWatch Logs、Amazon S3、Amazon Kinesis Data Firehose が選択可能で、CloudWatch Vended Logs の仕組みによる信頼性の高い配信（セキュアな転送・再試行等）が利用されます。料金は選択した配信先と標準の CloudWatch Vended Logs 課金に準じ、EKS 固有の追加料金は発生しません。機能は EKS Capabilities がサポートされる全リージョンで利用可能です（個別リージョンの対応状況は事前確認推奨）。

### 影響範囲・利用シーン

- **対象ユーザー**: EKS を利用するクラウドエンジニア、プラットフォーム/SRE チーム、Argo CD/ACK/kro を活用する開発チーム
- **利用シーン**: マネージドコントローラの動作監視とトラブルシューティング、コントローラのログを SIEM/分析基盤 に送って可観測性を向上させる場合
- **運用効果**: マネージドインフラ側のコントローラログを集中管理できるため障害原因の切り分けが容易になり、監査・長期保存・アラート連携が行いやすくなる

### 技術的な注意点

- **IAM権限**: CloudWatch の Vended Logs 関連 API と、選択したデスティネーション（S3 バケットや Firehose）への操作権限が必要です。設定を行う IAM ロール/ユーザに必要な権限を付与してください。
- **リージョン制限**: EKS Capabilities がサポートされるリージョンで利用可能です。EKS Capabilities 自体が未対応のリージョンでは利用できないため事前に確認してください。
- **コスト**: CloudWatch Vended Logs の標準課金が適用されます。S3 への保存、Kinesis Data Firehose 経由配信など、デスティネーション側のストレージ/転送コストも発生します。EKS 側の追加料金はありません。
- **ログの種類と範囲**: 収集対象は AWS 管理下で稼働するマネージドコントローラの運用ログ（コントローラ stdout/stderr 等）であり、ユーザーアプリケーションログとは別です。
- **運用上の注意**: 大量ログの長期保存やリアルタイム分析を行う場合は、デスティネーション側のスループット・保持ポリシー・暗号化設定を確認し、必要に応じてライフサイクルやフィルタリングを適用してください。

- https://docs.aws.amazon.com/eks/latest/userguide/
