# 2026年09月17日

## [Corretto] Amazon Corretto 27 is now generally available

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: Corretto
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-corretto-27-generally-available/

### 概要

Amazon Corretto 27（Feature Release）が一般提供開始されました。OpenJDK 27 をベースにした無償のマルチプラットフォームな商用対応JVMで、Linux／Windows／macOS向けにダウンロード可能です（サポート期限: 2027年4月まで）。

### 変更内容・新機能の詳細

主な技術的変更点は以下のとおりです。
- G1を全環境のデフォルトGCに設定（JEP 523）: サーバー／クライアント／コンテナ等の実行環境にかかわらずG1が既定になり、より一貫したスループットと予測可能な一時停止時間を目指します。従来のデフォルト（例えばZGCなど）との挙動差を考慮した検証が必要です。
- TLS 1.3向けポスト量子ハイブリッド鍵交換（JEP 527）: 古典的アルゴリズムとポスト量子アルゴリズムを組み合わせたハイブリッド鍵交換をサポートし、将来の量子耐性を高めます（ハンドシェイクサイズやCPUコストの増加に注意）。
- Compact Object Headersをデフォルト化（JEP 534）: Javaオブジェクトヘッダを小さくすることでメモリ使用量とキャッシュ効率を改善します。オブジェクトレイアウトに依存するネイティブコードやUnsafe利用箇所は影響を受ける可能性があります。
- JFRのプロセス内データマスキング（JEP 536）: Java Flight Recorder記録からJVMの外部に出す前に機微データをマスク／削除できる仕組みを導入し、プロファイリング時の情報漏洩リスクを低減します。
- パターンマッチングの強化（継続プレビュー、JEP 532）: プリミティブ型（int、boolean等）に対するパターンやinstanceof、switchのサポートが拡張され、型／値チェックがより簡潔に記述できます（利用にはプレビュー有効化が必要な場合があります）。
- 構造化コンカレンシー（継続プレビュー、JEP 533）: 複数スレッドで実行される関連タスク群を単一の論理ユニットとして扱うAPIを改善し、エラー処理・キャンセルやオブザーバビリティの向上を図ります（プレビューAPI）。
- Lazy Constants（継続プレビュー、JEP 531）: 不変値の初期化を実際に必要になるまで遅延させるAPIで、finalフィールドの性能利点と遅延初期化の柔軟性をあわせ持ちます。
- Vector API（継続インキュベータ、JEP 537）: CPUのベクトル命令を活用した高性能数学処理をサポートするAPIを改善。数値計算やデータ処理の高速化に寄与します。
その他: Corretto 27はオープンソースライセンスで配布され、AWSのダウンロードページから各OS用バイナリを入手可能です。サポート期間や各プレビュー／インキュベータ機能の有効化方法（--enable-preview やモジュール追加など）はリリースノート／OpenJDKページで確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: Javaアプリケーション開発者、SRE／運用チーム、パフォーマンスエンジニア
- **利用シーン**: コンテナ化されたマイクロサービスやクラウド環境での一貫したGC挙動が必要な運用、TLS通信の長期的な量子耐性を検討するセキュリティ要件、メモリ最適化が重要な大規模ヒープ環境
- **運用効果**: G1デフォルト化により環境間でのGC調整負荷が低減される可能性、Compact Object Headersでメモリ使用効率とキャッシュヒット率が改善、JFRのデータマスキングでプロファイリング時の情報漏洩リスクを低減

### 技術的な注意点

- **互換性／テスト**: G1がデフォルトとなるためGC挙動（スループット、停止時間）に影響が出る可能性があり、既存アプリは事前検証が必要です
- **プレビュー／インキュベータ機能**: パターンマッチング、構造化コンカレンシー、Lazy Constants、Vector APIなどは継続プレビュー／インキュベータ扱いであり、使用時はコンパイル／実行フラグ（例: --enable-preview）やモジュール追加（例: --add-modules jdk.incubator.vector）を確認してください
- **セキュリティ設定**: ポスト量子ハイブリッド鍵交換はTLS 1.3の拡張であり、デフォルトで有効化されていない場合や設定項目がある可能性があるため、運用環境での有効化手順と性能影響を確認してください
- **ネイティブ依存**: Compact Object Headersやオブジェクトレイアウトの変更はUnsafeやJNI、シリアライズ形式に影響する可能性があるため、ネイティブ連携部分の検証を推奨します
- **サポート期間**: Corretto 27は2027年4月までサポートされます。長期運用の場合はサポート期限の計画を考慮してください
- **コスト**: Corretto自体は無償配布ですが、新機能のテストやチューニング、TLS設定変更によるCPU/帯域の増加など運用コスト増の可能性があります
- **リージョン制限**: JVM配布としてリージョン制限は基本的にありません。ダウンロードはAWS Correttoの公式サイト経由で行ってください

### 参考情報

## [Aiml] Amazon SageMaker AI now supports serverless model customization for NVIDIA Nemotron 3.5 Lightning 

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-sagemaker-ft-nemotron-3-5-lightning/

### 概要

Amazon SageMaker AIは、NVIDIAのオープンウェイトモデル「Nemotron 3.5 Lightning」に対するサーバーレスなモデルカスタマイズ（SFT・DPO・RFT）をサポートしました。インフラ管理不要でドメイン特化の微調整が行え、低コスト・低レイテンシな運用を実現します。

### 変更内容・新機能の詳細

本アップデートにより、SageMaker AIでNVIDIA Nemotron 3.5 Lightning（ハイブリッドMixture-of-Expertsアーキテクチャ、アクティブパラメータ約3B、総パラメータ約30B）をサーバーレスでカスタマイズ可能になりました。サポートされる調整手法は以下の通りです：
- SFT（Supervised Fine-Tuning）: ラベル付きデータでドメイン特化タスクの精度向上。
- DPO（Direct Preference Optimization）: 人間や組織の好みに応じた出力整合性の強化（好みデータ／比較データを利用）。
- RFT（Reinforcement Fine-Tuning）: 報酬信号に基づく強化学習的な微調整で新しいタスク性能を向上。
サーバーレスカスタマイズでは、SageMakerがインフラプロビジョニング・トレーニングオーケストレーションを管理するため、ユーザーはデータ準備と評価に集中でき、使用時間に応じた課金のみ発生します。カスタマイズ後は同一環境でのデプロイが可能で、SageMaker StudioのModelsページまたはSageMaker Python SDKを通じてジョブを開始できます。対応リージョンは US East (N. Virginia)、US West (Oregon)、Asia Pacific (Tokyo)、Europe (Ireland) です。

### 影響範囲・利用シーン

- **対象ユーザー**: MLエンジニア、データサイエンティスト、プロダクトチーム（特にドメイン固有のNLPアプリケーションを持つチーム）
- **利用シーン**: カスタムFAQ/チャットボット、業界特化型文書生成、トーンやコンプライアンスに沿った出力整形、専門用語を扱う分類/抽出タスク
- **運用効果**: 小さめに調整したモデルでフロントランクの品質を目指すことで推論コストとレイテンシを削減可能
- **コスト影響**: サーバーレスのため初期クラスタ管理コストは不要。トレーニングと実行は使用量に応じて課金されるため、従来の常時プロビジョニングよりコスト最適化が期待できる

### 技術的な注意点

- **リージョン制限**: 現時点で利用可能なリージョンは US East (N. Virginia)、US West (Oregon)、Asia Pacific (Tokyo)、Europe (Ireland) のみ。その他リージョンは今後対応の可能性あり。
- **IAM権限**: SageMaker上でカスタマイズを行う権限（モデル読み取り/書き込み、ジョブ作成、S3アクセス、ECRやLogsへのアクセスなど）を事前に付与する必要あり。
- **データ要件**: SFTは高品質なラベルデータ、DPOは比較／選好データ、RFTは報酬関数と報酬データが必要。データ前処理（トークナイズやフォーマット整備）を行ってからジョブをキックすること。
- **モデル特性**: Nemotron 3.5 LightningはMoE（Mixture-of-Experts）でアクティブパラメータが小さくても総パラメータが大きい設計。MoE特有のルーティングや専門家活性化の挙動が推論コストや性能に影響するため評価が必要。
- **互換性/利用方法**: SageMaker StudioのModelsページからGUIで開始、またはSageMaker Python SDKでプログラム的にジョブを作成可能。SDKバージョンやAPI変更に注意。
- **コスト**: サーバーレスは実行時間課金だが、トレーニングデータ量や反復回数により費用は増加。トラフィック・推論コストも別途発生。
- **セキュリティ/コンプライアンス**: 機密データを使用する場合はS3暗号化、VPCエンドポイント、KMSキー、ログ管理などを適切に設定すること。
- **制限事項**: サーバーレス実行にはジョブ時間や同時実行数のクォータがある可能性があるため、想定負荷に対して事前に制限を確認/申請すること。
- **追加注意**: 最新のドキュメントとリージョン対応状況を公式コンソールまたはAWSドキュメントで都度確認すること。

## [Client Vpn] AWS Client VPN is now supporting MacOS 27 Golden Gate

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: Client Vpn
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-client-vpn-macos-golden-gate/

### 概要

AWS Client VPNの公式デスクトップクライアントがMacOS 27（Golden Gate）をサポートしました。クライアントバージョン6.0以降で最新のMacOS上でAWS提供のVPNクライアントが動作します。

### 変更内容・新機能の詳細

今回の更新で、AWS Client VPNのデスクトップクライアント（バージョン6.0以降）がMacOS 27.0（Golden Gate）に対応しました。これにより、既存のサポート済みOS（macOS 13/14/15/26、Windows 10(x64)、Windows 11(x64/Arm64)、Ubuntu 22.04/24.04 LTS）に加えて、最新のmacOS上でもAWS公式クライアントを利用して安全にAWSやオンプレミスネットワークへリモート接続できます。クライアントソフト自体は無償で配布されており、AWS Client VPNはマネージドサービスとして、クライアント認証（証明書、Active Directory、SAMLフェデレーション等）やルート/アクセスルール、分割トンネル設定、VPCルーティング等の管理を提供します。導入・運用にあたっては、クライアントのバージョン確認、認証方式・証明書の整備、エンドポイント設定（サーバー証明書、認可ルール、ルート付与）の確認が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: リモートワーカー、セキュアなVPN接続を必要とする開発者/運用担当者、MacOS 27へアップグレード予定のエンドユーザー
- **利用シーン**: 最新のMac環境からAWSリソースやオンプレミスネットワークへ安全にアクセスするリモート接続
- **運用効果**: MacOSアップデート後も公式クライアントで接続が維持できるため、クライアント互換性対応の負荷低減と運用の安定化が期待できる

### 技術的な注意点

- **クライアント要件**: クライアントはバージョン6.0以上が必要。MacOSは27.0（Golden Gate）で動作確認済み。既存MacOSサポートは13/14/15/26も継続。
- **認証方式**: Client VPNは証明書ベース、Active Directory、SAMLフェデレーション等をサポート。各認証方式の設定（ACMやディレクトリサービス、IdP設定）は事前に確認が必要。
- **IAM権限**: Client VPNエンドポイントや認可ルールの作成・変更には適切なIAM権限（ec2:CreateClientVpnEndpoint等）を付与してください。クライアントのダウンロード自体は通常追加権限不要。
- **リージョン制限**: Client VPNサービスはすべてのリージョンで同等に提供されているとは限りません。使用予定リージョンでサービス提供状況を確認してください。
- **ネットワーク設定**: エンドポイントに割り当てるサブネット、ルート、セキュリティグループ、VPC側のルーティング（ターゲットの確認）を適切に設定する必要があります。分割トンネルやDNS設定の影響も確認してください。
- **クライアントアーキテクチャ**: macOS上でのIntel/Apple Siliconサポート状況はクライアント配布ページで確認してください（アーキテクチャ依存のバイナリがある場合あり）。
- **互換性テスト**: 大規模導入前に代表ユーザーで接続・認証・ルーティング・パフォーマンスを検証してください。
- **コスト**: クライアントソフトは無償ですが、AWS Client VPNの利用にはエンドポイント時間課金やデータ転送等の料金が発生します。予想接続数・稼働時間に基づきコスト見積りを行ってください。

## [IAM] New AWS experience helps builders get started and ship faster

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: IAM
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/New-AWS-Builder-Experience

### 概要

新しい「Builder experience」は、サインアップと初期プロジェクト構成を自動化して、アイデアから実装までの時間を短縮する開発者向けの簡易体験です。既存のGoogle/GitHub/Apple/Amazonアカウントで始められ、無料クレジットやプロジェクトごとの支出上限などコスト制御機能を備えます。

### 変更内容・新機能の詳細

主な機能と技術的内容：
- 簡易サインアップ: Google、GitHub、Apple、Amazon の既存認証情報で新しい開発体験にサインアップ可能。多くの新規ユーザーはクレジットカード不要で、AWS Free Tierの一部として最大$200の無料クレジットが付与される場合がある。
- 初期プロジェクトの自動設定: サインアップ時に「妥当なデフォルト」で初期プロジェクトが自動作成され、複雑な前提設定を省略してすぐにコーディング／デプロイを開始できる。
- コーディングエージェント統合: 単一プロンプトでAWS CLIとAgent Toolkit for AWSを自動インストールし、開発者の“コーディングエージェント”がプロジェクトに接続。組み込みガイダンスに従いベストプラクティスでリソースをデプロイできる（エージェント側の実行権限と認証情報管理が必要）。
- チームコラボレーション: メール招待でチームメンバーを追加すると、受諾時にプロジェクトアクセスが自動構成されるため、手動でIAMロールを細かく作成する手間を削減。
- IAM Role Manager: プロジェクト向けにIAMロール管理機能が有効化され、多くの作成リソースが他サービスへアクセスできるよう自動でロールを構成することでリソース間連携を簡素化。
- コスト管理: プロジェクトごとに月次支出上限を設定可能。上限に到達するとその月はプロジェクトが一時停止される（支出超過を防止）。複数プロジェクトをワンクリックで作成でき、それぞれ独立した上限・メンバー設定を持つ。
- スケールアップと高機能化: いつでもダウンタイムなしに「上位プラン」や高度機能（複数リージョン、カスタムガバナンス制御など）を有効化できるため、PoCから本番へ移行する際の移行コストを軽減。
- 利用開始: 試すには新規AWSアカウントを作成することが案内されている（既存アカウントでの有無・移行方法はコンソールで要確認）。

### 影響範囲・利用シーン

- **対象ユーザー**: 個人開発者、スタートアップ、プロダクトのPoC/ハッカソン参加者、SRE/DevOpsチーム
- **利用シーン**: 迅速なプロトタイピングやPoC作成、教育・ラボ環境、コーディングエージェントを用いた自動デプロイワークフローの導入
- **運用効果**: 初期設定工数の大幅削減により「アイデア→動作するコード」までの時間短縮、チーム招待と自動設定により導入障壁と人的ミスを低減、プロジェクト単位の支出上限で予算超過リスクを抑制

### 技術的な注意点

- **IAM権限**: 自動でIAMロールが作成・付与されるため、権限範囲（最小権限）のレビューが必要。Role Managerの構成を確認し、不要な横断アクセスを防いでください。
- **認証/セキュリティ**: Google/GitHub/Apple/Amazonログインを利用するが、アカウント連携時のIDプロバイダ設定やMFAポリシーは事前に検討すること。コーディングエージェントがアクセスする認証情報の保護（シークレット管理）も重要です。
- **コスト**: 多くの新規ユーザーはクレジットカード不要で最大$200の無料クレジットが付与されるケースがあるが、無料枠やクレジットの適用条件を確認してください。プロジェクト単位の支出上限は到達時にその月のプロジェクトを一時停止する挙動があるため、運用への影響を考慮して上限を設定してください。
- **既存アカウントとの互換性**: 公式の案内では「新規アカウントで試す」と記載されているため、既存アカウントでの利用可否やプロジェクト移行手順はコンソールの最新情報を確認してください。
- **リージョン制限**: 提供リージョンの可用性は明示されていないため、利用前に対象リージョンでこの体験が提供されているかを確認してください。
- **エージェント/ローカル環境**: 単一プロンプトでAWS CLIやAgent Toolkitがインストールされるため、開発端末のセキュリティポリシーやネットワーク環境（プロキシ、ファイアウォール）を事前に確認してください。
- **監査/ガバナンス**: 自動設定が便利だが、企業ガバナンス（組織単位のポリシー、Service Control Policies等）に適合させるための追加設定が必要になる場合があります。

## [Workspaces] Amazon WorkSpaces adds support for NVIDIA Blackwell GPU instances

- **カテゴリ**: Workspaces
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-workspaces-nvidia-blackwell-gpu-instances/

### 概要

### 変更内容・新機能の詳細

各カスタムメトリクスにタグを付与し、そのタグを条件にしたアクセス制御を適用できる機能です。タグに基づくポリシーにより、チーム単位で「フルコントロール」「閲覧のみ」「非表示（アクセス不可）」といった権限を付与できます。検索や一覧表示などUI/検索の結果も同じアクセスルールに従うため、許可されていないメトリクスはユーザーに表示されません。これにより、従来のように限られた管理者だけが操作できる運用に頼らず、各チームへ委譲しつつガバナンスを維持できます。実装上はタグをポリシー条件（例：aws:ResourceTag/&lt;タグキー&gt;、aws:RequestTag など）で参照する形になるため、IAMポリシーの更新が必要になります。また、既存メトリクスへのタグ付与やタグ変更により即時にアクセス範囲が変わる点に注意してください。

### 影響範囲・利用シーン

- **運用効果**: メトリクスの競合や意図しない変更を防ぎつつ、各チームへ安全に運用権限を委譲できるため、開発スピードとガバナンスの両立が可能

### 技術的な注意点

- **IAM権限**: タグベースの条件を使うため、IAMポリシーで aws:ResourceTag/&lt;タグキー&gt;、aws:RequestTag、aws:TagKeys 等の条件キーを利用する必要があります。タグ操作用の権限（TagResource/ UntagResource相当）やカスタムメトリクスの管理権限を付与してください。
- **既存ポリシーの更新**: 既存の接続/メトリクス関連ポリシーにタグ条件を追加することで制御します。誤った条件設定はアクセス不能を招くため段階的に適用・検証してください。
- **タグ運用**: 一貫したタグキー/値の命名規約（例: team, environment, owner）を定め、ライフサイクル（作成時付与・変更時の手順）を運用ドキュメントに組み込んでください。
- **リージョン制限**: 本機能の展開状況はリージョンによって異なる可能性があります。利用前に対応リージョンを公式ドキュメントで確認してください。
- **コスト**: タグベースアクセス制御自体に追加料金は通常発生しませんが、ポリシー管理や運用プロセス整備に工数がかかります。
- **互換性/検索挙動**: UIおよび検索はタグに基づくアクセス制御に従って結果がフィルタされます。タグ変更は即時にアクセス挙動に影響します。

## [Elemental Mediatailor] AWS Elemental MediaTailor Monetization Functions adds ad response hooks

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: Elemental Mediatailor
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-elemental-mediatailor-functions-ad-response-hooks

### 概要

AWS Elemental MediaTailor の Monetization Functions に、広告配信ライフサイクルの2つの新しいフック（post ADS response と pre manifest insertion）が追加されました。これにより、MediaTailor と広告決定サーバー（ADS）間のミドルウェア不要で、配信直前やADS応答後にカスタムロジックを実行できます。

### 変更内容・新機能の詳細

追加された2つのフックは次の通りです。

・post ADS response フック: MediaTailor が ADS のレスポンスを解析し、VAST のラッパー解決を完了した直後、広告の選択とトランスコード処理が始まる前に呼び出されます。このフックは、プライマリ ADS がブレイクを埋められないときにセカンダリ ADS を呼び出す、コンテンツやブランドポリシーに反する広告を除外する、ハウス広告や自社プロモーションを追加するといった処理に利用できます。

・pre manifest insertion フック: MediaTailor が視聴者へ返す直前に一度だけ呼び出され、個々のパーソナライズ済み広告ブレイク（ad pod）全体を単一の呼び出しで受け取ります。再生前の最終チェックや、他に充填手段がない場合にパーソナライズされたスレートを挿入する用途に適しています。

両フックにはコンソール上のプリビルト・レシピが用意されており、導入の出発点になります。動作は fail-open で設計されており、タイムアウト、式評価エラー、リソース制限等で関数の出力が利用できない場合は、MediaTailor は関数出力を破棄してデフォルトの広告挿入へフォールバックし、視聴体験に影響を与えません。新機能は MediaTailor が提供されているすべての AWS リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: 動画配信プラットフォームのエンジニア、広告運用（Ad Ops）、SSAI/マネタイズ担当者、配信システムをカスタマイズする開発者
- **利用シーン**: プライマリ ADS の不足時にセカンダリソースを動的に呼ぶ、ブランドセーフティに基づく広告フィルタリング、ハウス広告挿入、再生直前の最終チェックやパーソナライズスレート挿入
- **運用効果**: ミドルウェア層を減らしてアーキテクチャを簡素化できる／広告のフィル率とブランド整合性を向上できる／最終局面での差し替えにより視聴者体験を保護できる

### 技術的な注意点

- **IAM権限**: Monetization Functions の作成・更新や MediaTailor が関数を呼び出すための適切な IAM 権限が必要です。具体的なポリシーは公式ドキュメントを参照してください。
- **リージョン制限**: 記事によれば、MediaTailor が提供されている全リージョンで利用可能です。利用前に対象リージョンでの提供状況を確認してください。
- **コスト**: MediaTailor および関連するリクエスト/データ転送に対する課金が発生する可能性があります。追加の API 呼び出しや外部 ADS の利用が増えるとコスト増となるため、料金ページで確認してください。
- **タイムアウト／フォールバック**: フックは fail-open 動作（タイムアウト、式エラー、リソース制限時に出力を無視して既定動作へ継続）です。関数は低遅延で確実に応答するよう設計し、冗長な外部呼び出しはバウンダリ設定を行ってください。
- **デバッグとロギング**: 実行失敗やタイムアウトは MediaTailor のログ／コンソールから確認できるはずです。CloudWatch 等で関数側のログを集約する設計を推奨します。
- **VAST／ADS の扱い**: post ADS response フックには VAST ラッパーが解決された後の結果が渡されます。ラッパー解決をフック側で再実装する必要はありませんが、受け取るデータ構造に依存した処理を行う際はドキュメントの仕様を確認してください。
- **セキュリティ**: 外部 ADS への呼び出しや機密情報の取り扱い時は、認証情報の安全な保管（Secrets Manager 等）や暗号化を適用してください。
- **スケーリング／レート制限**: 高頻度の広告リクエストに応答するため、フック実装はスケーラブルかつ短時間で完了するように設計してください。長時間処理はフォールバックを誘発します。
- **既成レシピ**: コンソールに用意されたプリビルトレシピをカスタマイズして導入を短縮できます。

## [Connect] Amazon Connect Customer now lets you create, manage, and search custom metrics through APIs 

- **公開日**: 2026-09-17 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/connect-customer-custom-metrics-apis/

### 概要

Amazon Connect Customer がカスタムメトリクスの作成・管理・検索をAPIで行えるようになりました。これによりメトリクス定義をコードで一元管理し、環境間の定義ズレ（definition drift）を防げます。

### 変更内容・新機能の詳細

Amazon Connect Customer は従来の標準メトリクスに加え、独自指標（カスタムメトリクス）をプログラム的に管理するための7つの新しいAPI操作を提供します。追加されたAPIは CreateMetric, DeleteMetric, DescribeMetric, ListMetrics, SearchMetrics, UpdateMetricContent, UpdateMetricMetadata です。UpdateMetricContent は実際の計測ロジック（メトリクス定義／計算式）を変更する用途、UpdateMetricMetadata は名前・説明・タグ等の記述情報を更新する用途と分かれています。SearchMetrics と ListMetrics により多数のインスタンスやキューにまたがるメトリクスを効率的に検索・列挙できます。すべての変更は AWS CloudTrail に記録され、監査トレイルが取得可能です。結果として、AI運用アシスタントやCI/CDパイプラインからメトリクスを自動作成してダッシュボードに公開する、といった自動化が可能になり、手動コンソール操作による定義ズレの発生を抑制できます。記事の例では「顧客が90秒以内に切り替えて有人対応を要求した割合」を追うカスタムメトリクスを自動で作成して監視するユースケースが示されています。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンター管理者、データエンジニア、SRE/運用チーム、CX（顧客体験）リーダー、開発者
- **利用シーンまたは効果**: カスタムKPIの一元管理（例: 自動化されたセルフサービ ス完了率や90秒以内の有人切替率の追跡）、AI/Automationによるメトリクス自動作成とダッシュボード公開、環境間での定義整合性維持
- **運用効果**: 手動設定の削減による人的ミス低減、定義ドリフトの防止による指標信頼性向上、監査ログ（CloudTrail）による変更トレーサビリティ確保

### 技術的な注意点

- **IAM権限**: 新しいAPI呼び出し（CreateMetric 等）を許可するIAMポリシーが必要です。サービスアクション名はドキュメントで確認してください。
- **リージョン制限**: 利用可能リージョンは公式ドキュメントで確認してください（What's New記事にリージョン情報の明記がないため事前確認推奨）。
- **コスト**: API呼び出し自体は小額だが、CloudTrailログ保存・ダッシュボード表示・関連するメトリクス保持には追加コストが発生する場合があります。料金影響を事前に評価してください。
- **APIクォータ/レート制限**: 大量の自動化で呼び出す場合はAPIレート制限・サービスクォータを確認し、必要なら引き上げ申請を行ってください。
- **変更管理**: UpdateMetricContent により計測ロジックが変更されうるため、CI/CDやレビュー・テストプロセスでバージョン管理・検証を行ってください。CloudTrailでの監査ログは有効ですが、メトリクス定義の意図を残すためにソース管理（例: Git）を推奨します。
- **既存メトリクスとの互換性**: 標準メトリクスは引き続き利用可能。カスタムメトリクスの命名規約やタグ付けルールを定め、環境間での一意性と再利用性を設計してください。
