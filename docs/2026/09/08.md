## [CloudFront] Dynamic Image Transformation for Amazon CloudFront adds four new features

- **公開日**: 2026-09-08 (JST)
- **カテゴリ**: CloudFront
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/08/dynamic-image-transfromation-adds-new-features/

### 概要

Amazon CloudFront の Dynamic Image Transformation (DIT) が4つの新機能を追加しました。スマートクロップの強化（カスタムラベル検出と高度な構図制御）、自動画像最適化の拡張、インタラクティブな変換プレイグラウンド、ECS と Lambda アーキテクチャ間での機能差解消が主なポイントです。

### 変更内容・新機能の詳細

主な追加・強化点は次の通りです。
- 拡張スマートクロップ: 顔検出、ラベル、テキスト、ロゴ、そして Amazon Rekognition のカスタムモデルを組み合わせて単一リクエストで検出可能。アスペクト比、パディング、重心（gravity）制約やビジネス優先度に基づく優先順位付けを設定でき、商品、テキスト、ロゴ、カスタムオブジェクトを切り抜き後も保持する高度なコンポジション制御を提供します。検出結果（バウンディングボックス等）に基づいてクロップ領域を調整するため、重要領域が切り落とされにくくなります。
- 強化された自動最適化: ブラウザの Client Hints を第一に利用し、CloudFront のマルチティア（段階的）デバイス検出ヘッダーと設定可能なフォールバックを組み合わせることで、従来は最適化が適用されなかった約30%のトラフィックギャップを埋めます。これにより、スマートフォンやタブレットに加えスマートTVなどブラウザ外デバイスにも適切なサイズ・フォーマットの画像配信を拡張します。
- 変換プレイグラウンド: インタラクティブな UI で変換結果をプレビューし、オリジナル/出力の寸法、フォーマット、ファイルサイズ、圧縮率、処理時間など拡張メトリクスを確認可能。変換ポリシーの検証やパフォーマンス評価に利用できます。
- アーキテクチャ間の完全な機能差解消: DIT の機能が ECS ベース実装と Lambda（おそらく Lambda@Edge 等）実装で同等になり、利用するアーキテクチャに依らず機能を選べるようになりました。
運用面では、これらの機能は CloudFront のリクエスト処理パイプラインに統合され、変換パラメータはキャッシュキー／キャッシュポリシーに影響します。Rekognition のカスタムモデルを利用する場合はそのモデルのデプロイ済リージョンやアクセス権が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: ウェブ/モバイル開発者、Eコマース事業者、メディア配信チーム、SRE/運用担当者
- **利用シーン**: 商品画像の自動トリミングで重要領域（商品/ロゴ/テキスト）を保持する表示、レスポンシブ画像配信でデバイスごとに最適サイズを配信、広告クリエイティブやニュースメディアでの自動レイアウト調整の検証
- **運用効果**: UX 向上（重要領域の欠落削減）、帯域/レイテンシ削減（適切サイズ配信による転送量削減）、画像アセットの前処理工数削減、変換ポリシーを本番前に検証できることでミスによる表示障害を低減

### 技術的な注意点

- **IAM権限**: CloudFront の DIT を利用するための権限に加え、Rekognition のカスタムモデルを利用する場合は Rekognition へのアクセス権が必要です（モデルを配置したリージョンの権限確認を含む）。
- **リージョン制限**: CloudFront はグローバルサービスですが、Rekognition のカスタムラベルなどはリージョン依存です。カスタムモデルがデプロイされているリージョンと連携方法を確認してください。
- **コスト**: 画像処理（DIT）のリクエスト/処理コスト、CloudFront リクエスト増加、Rekognition の検出 API 利用料、かつ最適化によりオリジン転送量は減少する可能性があるため総合的なコスト差分を試算してください。
- **キャッシュ設計**: 変換パラメータはキャッシュキーに影響します。パフォーマンスとキャッシュ効率を両立するためにキャッシュポリシー／レスポンスヘッダーの設計を見直してください。
- **Client Hints / フォールバック**: 一部クライアントは Client Hints を送信しないため、CloudFront の段階的デバイス検出とフォールバック設定を適切に構成する必要があります。
- **プレイグラウンド注意**: プレイグラウンドのメトリクスは検証用であり、本番のエッジノード負荷やネットワーク条件と差が出る場合があります。大量トラフィック下での挙動は本番で検証してください。
- **アーキテクチャ移行**: ECS と Lambda の機能差は解消されましたが、既存設定の移行時は挙動・パフォーマンスをテストしてください。

## [Iam Identity Center] AWS Builder ID adds recovery options and multi-factor authentication for third-party logins

- **公開日**: 2026-09-08 (JST)
- **カテゴリ**: Iam Identity Center
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-builder-id-recovery-mfa-third-party/

### 概要

AWS Builder IDに復旧用メールアドレスとサードパーティログイン向けの多要素認証（MFA）登録機能が追加され、自己復旧フローとアカウント保護が強化されました。これによりGoogle/Apple/GitHub/Amazonなどの外部ログインでもMFAを利用でき、パスワード忘れやMFA紛失時のセルフサービスでの回復が容易になります。

### 変更内容・新機能の詳細

今回のアップデートでは、個人用プロファイルであるAWS Builder IDに対して以下の機能が追加・強化されました。1) 復旧用メール（recovery email）の登録が可能になり、プライマリメールと復旧メールのいずれかに送信されるリンクでパスワードリセットができるようになったため、AWSサポートへの問い合わせなしで自己復旧が可能なケースが増えます。2) MFAデバイスの自己登録が全サインイン方式（メール/パスワードだけでなくGoogle、Apple、GitHub、Amazon等のサードパーティログイン）で可能になりました。これにより外部プロバイダを使っているユーザーもTOTPやハードウェアキーなどのMFAでアカウントを強化できます。3) MFAを紛失した場合の復旧フローとして、プライマリと復旧メールの両方を検証することでアクセス回復が可能です。4) サードパーティログイン用の外部アカウントにアクセスできなくなった場合、Builder ID側でメールアドレス＋パスワードに恒久的にサインイン方式を切り替えることができ、外部プロバイダ障害からの救済手段が用意されます。これらの変更はBuilder IDを利用するAWS Builder Center、AWS Training and Certification、Amazon Quick and Kiroなどの関連サービスへのサインイン体験とセキュリティに直接影響します。具体的な設定手順やサポートされるMFAデバイスの種類、アカウント移行の詳細は公式ドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Builder IDを使用する開発者、学習者、トレーニング受講者、個人利用者およびSRE/運用担当者
- **利用シーン**: パスワード忘れ時の自己回復、MFA紛失時のアクセス回復、サードパーティ認証を利用するユーザーのアカウント保護強化
- **運用効果**: サポートへの問い合わせを減らし、復旧時間を短縮。第三者ログインを利用するユーザーにも一貫したMFAポリシーを適用できるためセキュリティ向上
- **セキュリティ影響**: 復旧用メールを追加することで二要素的な検証が可能になり、総合的な不正アクセスリスクが低下。だたし復旧メール自体の保護が重要（メールアカウントのセキュリティが新たな攻撃対象になる）
- **移行・運用影響**: サードパーティアカウント喪失時にメール/パスワードへ切替える運用設計が可能。組織でSSO/SAMLを使う場合は既存の認証フローとの整合を確認する必要あり

### 技術的な注意点

- **IAM権限**: Builder IDは個人プロファイルの管理機能のため、AWSアカウント内のIAMポリシーは不要。ただし組織でのSSO連携や組織ポリシーがある場合は管理者による設定確認が必要
- **リージョン制限**: Builder IDはグローバル（リージョン非依存）のサービス/プロファイルで提供されるため、リージョン制限は基本的に無し。ただし関連サービスの挙動はサービスごとに異なる可能性あり
- **コスト**: Builder IDの復旧メール登録やMFA設定自体に追加料金はかかりません。ただしハードウェアMFAトークンを用いる場合は別途デバイス購入が必要になる可能性があります
- **互換性・制限**: サードパーティログインはGoogle、Apple、GitHub、Amazon等に対応（記事内容）。各外部プロバイダ側のアカウント復旧ポリシーや制限は別途影響するため注意
- **MFA/復旧フローの注意**: MFA紛失時はプライマリと復旧メールの両方の検証が復旧条件になる点に留意。サードパーティアカウントを失った場合に備え、事前に復旧メールやMFAの設定を行っておくことを推奨
- **その他**: 詳細な設定手順、サポートされるMFA種別（TOTPアプリ、セキュリティキー等）の対応状況やUIは公式ドキュメントを確認してください

### 参考情報

- https://aws.amazon.com/builder-id/

## [Cloud Development Kit] AWS announces Nx Plugin for AWS for scaffolding full-stack applications

- **公開日**: 2026-09-08 (JST)
- **カテゴリ**: Cloud Development Kit
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/nx-plugin-for-aws/

### 概要

Nx Plugin for AWS v1.0が公開されました。Nx（モノレポ用ビルドシステム）を拡張し、AIエージェントやAPI、Web、DBなどのフルスタック部品とそれを動かすインフラ（AWS CDKまたはTerraform）をスキャフォールドするオープンソースツールキットです。

### 変更内容・新機能の詳細

このプラグインはNxに対して「ジェネレーター」を提供し、各ジェネレーターが要求に応じてアプリケーションの一部（例：Amazon Bedrock AgentCore上のAIエージェントやModel Context Protocolサーバ、API、ウェブサイト、データベース）とその実行に必要なインフラを生成します。生成されるコードはTypeScript/Pythonの実践的なフレームワークをベースに作られ、インフラはAWS CDKのConstructまたはTerraformモジュールとして定義されます。セキュリティや可観測性の推奨設定（AWS WAFによる保護、Amazon CloudWatchへのアクセスログ、AWS X-Rayトレーシングなど）があらかじめ組み込まれています。プロジェクト間の接続は型安全なクライアントでワイヤリングされるため、APIの破壊的変更はランタイムエラーではなくビルドエラーとして検出できます。各ジェネレーターは決定論的に同じ結果を出力し、生成後のコードはユーザーの所有物でプラグインへのランタイム依存はありません。Nxのマイグレーション機能で、ワークスペースのカスタマイズに対して後続の改善を適用できます。ライセンスはApache 2.0で無償提供（ただし実際のAWSリソース使用に伴う料金は別途発生）。

### 影響範囲・利用シーン

- **対象ユーザー**: フルスタック開発者、クラウドエンジニア、AI/MLエンジニア、SRE/プラットフォームチーム
- **利用シーンまたは効果**: AIアシスタントや開発者が数分で本番に近いセキュリティ・可観測性を備えたアプリケーション骨子を生成し、インフラ（CDK/Terraform）定義とアプリ実装を同時に得られることで開発初期の手戻りを削減
- **運用効果**: 型安全な接続と標準化された推奨設定により本番での障害やセキュリティ設定漏れを減らし、CI/CDへの組み込みや自動化が容易になる（ビルド段階で不整合を検知）

### 技術的な注意点

- **IAM権限**: CDK/Terraformでデプロイする際はリソース作成に必要なIAM権限（WAF、CloudWatch Logs、X-Ray、Bedrock関連リソース等）を事前に付与する必要があります
- **リージョン制限**: Amazon BedrockやAgentCoreは一部リージョンでのみ提供されている可能性があるため、利用前に対象リージョンの対応状況を公式ドキュメントで確認してください
- **コスト**: プラグイン自体はApache 2.0で無償だが、生成したリソース（Compute、S3、CloudWatchログ、WAF、X-Ray、Bedrockの推論料金等）には通常のAWS料金が発生します。特にBedrock等のAIサービスはコストが高くなる可能性があります
- **依存関係**: 生成コードはTypeScript/PythonやNx、AWS CDKあるいはTerraformのバージョンに依存します。プロジェクトの既存依存関係と互換性を確認してください
- **ランタイム依存**: 生成後のアプリケーションはプラグインにランタイム依存しませんが、CI/CDやマイグレーション適用にはNxのツールチェーンが必要です
- **アップデート/マイグレーション**: Nxのマイグレーターを介してワークスペースに後続の改善を取り込めますが、カスタム変更がある場合はマイグレーションの衝突を検証してください
- **セキュリティベストプラクティス**: プラグインが推奨するWAFやログ、トレーシング設定は有効ですが、組織固有のコンプライアンス要件（ネットワーク分離、鍵管理、ログ保管ポリシー等）は個別対応が必要です
- **ライセンス**: Apache License 2.0。生成コードはユーザーの所有物です

## [Rds For Sql Server] Amazon RDS now supports the latest CU and GDR updates for Microsoft SQL Server

- **公開日**: 2026-09-08 (JST)
- **カテゴリ**: Rds For Sql Server
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-rds-supports-latest-cu-gdr-microsoft-sql-server/

### 概要

Amazon RDS for SQL Server が Microsoft の最新 Cumulative Updates (CU) と General Distribution Release (GDR) をサポートしました。複数の SQL Server バージョンに対しセキュリティ修正（CVE）が適用可能になっています。

### 変更内容・新機能の詳細

今回のリリースでサポートされたエンジン／RDSバージョンは以下の通りです：
- Microsoft SQL Server 2016 SP3 + GDR KB5102340 (RDS 13.00.6500.1.v1)
- Microsoft SQL Server 2017 CU31 + GDR KB5102337 (RDS 14.00.3540.1.v1)
- Microsoft SQL Server 2019 CU32 + GDR KB5102335 (RDS 15.09.4480.2.v1)
- Microsoft SQL Server 2022 CU26 KB5093420 (RDS 16.00.4265.3.v1)
- Microsoft SQL Server 2025 CU7 KB5096981 (RDS 17.00.4065.4.v1)
これらの GDR（および CU）アップデートには CVE-2026-47295、CVE-2026-47296、CVE-2026-54118、CVE-2026-55002 に関連する脆弱性修正が含まれます。詳細な修正点・改善内容は各 Microsoft の KB（KB5102340、KB5102337、KB5102335、KB5093420、KB5096981）を参照してください。RDS 上でこれらの更新を適用するには、管理コンソール、AWS CLI、または SDK を用いて DB インスタンスのエンジンバージョンをアップグレードします。アップグレード手順や影響については Amazon RDS SQL Server のユーザーガイド（アップグレード手順）を参照し、事前にスナップショット取得や互換性確認を行うことを推奨します。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon RDS for SQL Server を利用しているデータベース管理者、アプリケーション開発者、SRE/運用チーム
- **利用シーン**: セキュリティパッチ適用（脆弱性修正）、定期メンテナンス、法令・コンプライアンス対応のためのエンジン更新
- **運用効果**: CVE に対する修正が適用されることでセキュリティリスク低減が期待できる。最新 CU/GDR を利用することで既知のバグ修正や安定性改善も享受可能
- **互換性・テスト要件**: アプリケーション互換性の確認が必要（特にメジャーな機能/動作が影響を受ける可能性があるためステージング環境での検証推奨）

### 技術的な注意点

- **IAM権限**: DB インスタンスのアップグレードには rds:ModifyDBInstance 等の適切な RDS 権限が必要です（rds:RebootDBInstance / rds:DescribeDBInstances も併せて確認）
- **メンテナンス/ダウンタイム**: エンジンバージョンの変更は再起動が必要になることがあり、短時間のダウンタイムが発生する可能性があります。メンテナンスウィンドウの利用やスケジュール適用を検討してください
- **バックアップ**: アップグレード前にスナップショットを取得し、復旧手順を確認してください
- **互換性テスト**: アプリケーションのクエリ実行計画や互換性レベル、拡張機能の振る舞いが変わることがあるため、ステージング環境での検証を推奨します
- **リージョン制限**: 記事で明示されたリージョン制限はありませんが、RDS の機能や新しいエンジンバージョンの提供状況はリージョンごとに異なる場合があるため、利用リージョンでの提供状況を事前確認してください
- **コスト**: アップグレード自体に追加料金は発生しませんが、アップグレード作業中のダウンタイムやリカバリ作業による影響（運用コスト）は考慮してください
- **セキュリティ優先度**: 修正対象の CVE を含むため、優先度は高めです。可能な限り早期の適用を推奨します
- **実施方法**: AWS マネジメントコンソール、AWS CLI、または SDK を使用して DB エンジンのバージョンを指定してアップグレードします。アップグレード手順は RDS のドキュメントを参照してください
