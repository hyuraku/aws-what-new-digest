## [DynamoDB] Amazon DynamoDB global tables with multi-Region strong consistency now supports additional AWS Regions and cross-continent configurations

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: DynamoDB
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/dynamodb-mrsc-additional-regions/

### 概要

Amazon DynamoDB のマルチリージョン強整合性（MRSC）対応グローバルテーブルが、カナダ（Central）、欧州（Stockholm、Spain）、アジア太平洋（Mumbai、Singapore）の5リージョンを追加して合計15リージョンで利用可能になりました。これにより、サポートされる15リージョンの任意の3リージョン構成（3レプリカ、または2レプリカ＋1ウィットネス）でクロス大陸のMRSCグローバルテーブルを作成できます。

### 変更内容・新機能の詳細

MRSC（Multi-Region Strong Consistency）は、複数リージョン間で強い一貫性（strong consistency）を維持しつつ、可用性とゼロRPO（リカバリポイント目標）を実現するための DynamoDB のグローバルテーブル設定です。今回の拡張で、Canada (Central)、Europe (Stockholm)、Europe (Spain)、Asia Pacific (Mumbai)、Asia Pacific (Singapore) が新たにサポート地域に加わり、サポートリージョンは合計15になりました。MRSC で作成できる構成は「3つのフルレプリカ」または「2つのフルレプリカ＋1つのウィットネス（witness）リージョン」のいずれかで、3リージョン構成を横断的（北米・欧州・アジア太平洋など）に組むことができます。

技術的には、MRSC はリージョン間でコンセンサス（過半数）を取りながら書き込みを確定させる仕組みを使うため、書き込みはグローバルな合意が必要になり、レイテンシは単一リージョンの整合性設定より高くなる可能性があります。一方で、RPO が 0 になるため、リージョン障害時にもデータが欠落することなく別リージョンへ切り替え可能です。ウィットネスリージョンはフルデータの保持を行わず、コンセンサスに参加する軽量ノードとして動作し、ストレージ・レプリケーションコストを抑える選択肢を提供します。

推奨ユースケースは、グローバルに展開するアプリで厳格な整合性が必要なもの（ユーザープロファイル管理、在庫管理、注文状態管理、権利（entitlement）管理など）です。設定可能なリージョンや詳細な構成オプションは DynamoDB Developer Guide の Global Tables セクションを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: グローバルに展開するアプリケーション開発者、SRE/運用チーム、データ整合性が重要なサービスオーナー
- **利用シーン**: ユーザープロファイルの同期、在庫・注文状態の厳密なトラッキング、ライセンスや権利情報の一貫性保持、クロス大陸フェイルオーバーの実装
- **運用効果**: RPO=0 によりリージョン障害時のデータ欠落を防止し、ユーザーに近いリージョンで強整合性読み取りを提供できるためユーザー体験と信頼性が向上する

### 技術的な注意点

- **IAM権限**: グローバルテーブル作成・変更には dynamodb:CreateTable / UpdateGlobalTable などの適切な DynamoDB 権限が必要です。KMS を利用する場合は各リージョンの CMK に対する kms:Encrypt/kms:Decrypt 等の権限も確認してください。
- **リージョン制限**: MRSC は記事で列挙された15リージョンのみサポートされます。利用前に Developer Guide のサポートリージョン一覧を必ず確認してください。
- **構成制約**: 現在 MRSC は任意の“3リージョン構成”（3 レプリカ、または 2 レプリカ + 1 ウィットネス）をサポートします。2リージョンや4+リージョンの MRSC 構成はサポート対象外です（将来変更される可能性あり）。
- **レイテンシ/パフォーマンス**: 強整合性の保証のためにリージョン間で合意が行われるため、書き込みレイテンシが増大する可能性があります。読み取りは各レプリカの強整合性エンドポイントを利用できますが、内部的な同期とフォールトトレランスの影響を評価してください。
- **コスト**: 各レプリカのストレージ、書き込みレプリケーション（リージョン間データ転送）、およびウィットネスの運用に伴う費用が発生します。ウィットネスはフルレプリカより低コストですが、全体のコスト影響は設計次第です。
- **暗号化と鍵管理**: CMK を使う場合、リージョンごとに鍵ポリシーやキーの配置・許可を整備する必要があります（リージョンを跨いだ CMK の直接共有は不可）。
- **モニタリング/運用**: CloudWatch メトリクス、DynamoDB Streams、AWS X-Ray 等でレイテンシ・エラー・レプリケーションの健全性を監視してください。
- **マイグレーション**: 既存のグローバルテーブルから MRSC へ移行する場合、ダウンタイム要件やデータ同期手順を事前に検証してください。

## [CloudWatch] Amazon CloudWatch Omni: AI-first observability for agents and applications

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: CloudWatch
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-cloudwatch-omni-ai/

### 概要

Amazon CloudWatch Omniが一般提供を開始しました。OpenTelemetry互換のテレメトリ統合とAI駆動の操作性を組み合わせ、チームやアプリケーション単位での可観測性（ログ・メトリクス・トレース・エージェント観測）を単一の体験で提供します。

### 変更内容・新機能の詳細

CloudWatch OmniはAI-firstな可観測性プラットフォームで、以下を特徴とします。
- スペース（Spaces）: 中央アカウントでスペースを作成し、複数AWSアカウント／リージョンだけでなく、Azureなど他クラウドのテレメトリも集約して可視化・分析できる設計。
- OpenTelemetry互換性: OpenTelemetry経由の信号受け取りと相互運用性を備え、既存のOTelインストルメンテーションをそのまま活用可能。
- 自動検出と依存関係マッピング: サービスの自動検出、依存関係の可視化、いわゆる“golden metrics”（主要指標）の抽出で運用フローを効率化。
- 多様な操作インターフェース: 単体のWeb体験（SSOサポート）や、コンソールのポイント＆クリック、自然言語による問い合わせ（チャット）で動的に関連テレメトリを探し表示。
- Agent Toolkit & DevOps Agent連携: Agent Toolkit for AWSから任意のツールで操作可能。AWS DevOps Agentと連携し、根本原因探索を支援。
- エージェント／AIワークロード向け評価ワークフロー: LangGraph、CrewAI、OpenAI Agents SDK、Vercel AI SDK、Strands等のフレームワークに対応した、プロンプト／モデルコール／ツール呼び出しごとの品質評価と実験（A/B的検証）を実施可能。
- 開発者向けIDE拡張: VS Code、Cursor、Kiro向けのCloudWatch Omni拡張を無償で提供（ローカルでの計測・デバッグ・評価が可能、AWSアカウント不要でのローカル操作をサポート）。
- GAリージョン: 米東（バージニア北部）、米西（オレゴン）、欧州（アイルランド）で一般提供。価格は専用の料金ページで確認可能。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド/サイト信頼性エンジニア（SRE）、運用チーム、アプリ/エージェント開発者、AIエージェント運用担当者
- **利用シーン**: マルチアカウント／マルチリージョンや他クラウドを跨いだテレメトリの一元観測、AIエージェントやLLM呼び出しの品質評価・実験、障害時の根本原因解析
- **運用効果**: テレメトリ探索の工数削減（自然言語検索や動的ビュー）、依存関係可視化による障害影響範囲の短縮、AIワークロードのプロンプト/モデル品質改善サイクルの短縮

### 技術的な注意点

- **IAM権限**: スペース作成やクロスアカウント／クロスリージョン集約には適切なクロスアカウントロール（AssumeRole）とCloudWatch関連権限が必要です。SSO設定やAgentの権限付与も事前に設計してください。
- **リージョン制限**: GA時点では US East (N. Virginia), US West (Oregon), Europe (Ireland) のみ。その他リージョンは順次対応予定の可能性あり。利用前にリージョン対応状況を確認してください。
- **コスト**: Omni自体の料金に加え、受信されるログ／メトリクス／トレースのインジェスト・保管・クエリに対するCloudWatchの既存課金が発生します。Agent Toolkitの拡張は無償でも、テレメトリ送信量に基づく課金を考慮してください。
- **データ保護・レイテンシ**: マルチクラウド／他リージョンのテレメトリを中央に集約する場合、データ越境やレイテンシ、コンプライアンス（データ所在地）要件を確認してください。
- **インストルメンテーション**: OpenTelemetry互換とはいえ、フレームワーク固有の追加メトリクス／イベント（特にAIエージェント関連のプロンプトやツール呼び出し）を収集するには追加のインストルメンテーションやSDK設定が必要です。
- **IDE拡張とローカルワークフロー**: VS Code／Cursor／Kiroの拡張はローカルでの計測・評価をサポートしますが、本番データの送信やスペースへの接続は追加設定（認証／ネットワーク）を要します。
- **互換性とサポートされるフレームワーク**: 記載のLangGraph等は対応フレームワークの一部。実際のサポート範囲やバージョン要件はドキュメントで確認してください。

## [Cloud Financial Management] Billing Transfer now supports automatic billing group creation for two-level transfers

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: Cloud Financial Management
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-billing-transfer-supports-automatic-billing-group-creation/

### 概要

AWS Billing Transferに「Auto-Billing Transfer Billing Group Creation」設定が追加され、二段階（two-level）の請求転送で下流パートナー→エンド顧客の承諾時に自動でBilling Conductorの請求グループを作成できるようになりました。これにより手動設定を省き、プロフォーマのコスト情報を即時にパートナーへ提供できます。

### 変更内容・新機能の詳細

新機能はAWS Billing Conductorの「Auto-Billing Transfer Billing Group Creation」というプリファレンスで、受信する（inbound）請求転送リレーションシップごとに一度設定します。設定を有効にすると、下流のセラー・パートナーがエンド顧客からの請求転送を受け入れた時点で、Billing Conductor上に請求グループ（billing group）を自動作成します。自動作成時に、作成される請求グループに対してあらかじめ指定したBilling Conductorのプライシングプランを割り当てることが可能です。これにより、パートナーは手動でグループを作成・紐付けすることなく、プロフォーマ（概算）コストデータを即時に参照・共有できます。プリファレンスの設定／変更は、Billing Transfer詳細ページのAWS Management Consoleから行えるほか、2つの新しいAPIオペレーション（コンソール操作と同等のAPI）でも制御できます。なお、この自動作成は新規の間接転送（indirect transfer）に対して適用され、既存の転送や既存グループに対して遡及的に適用されるわけではありません。

### 影響範囲・利用シーン

- **対象ユーザー**: AWSディストリビュータ、下流セラーパートナー、パートナー向けの請求管理を行うクラウド／ファイナンスチーム
- **利用シーン**: 下流パートナーがエンドカスタマーの請求を転送する二段階のビリングフローで、転送承諾時に自動で請求グループを作成してコスト可視化を即時提供する場面
- **運用効果**: 手動設定の削減によりオンボーディング時間短縮、設定ミス低減、パートナーへのプロフォーマコスト提示を迅速化
- **セキュリティ／ガバナンス影響**: 自動作成を許可するプリファレンスは受信側で設定するため、権限管理（誰がプリファレンスを変更できるか）と監査が重要
- **コスト影響**: 機能自体の有料／無料は明記されていないが、Billing Conductorの利用や適用するプライシングプランに伴う料金が発生する可能性があるため事前確認が必要

### 技術的な注意点

- **IAM権限**: プリファレンス変更・API実行にはBilling TransferおよびBilling Conductor関連の適切なIAM権限が必要。CloudTrailでAPI呼び出しの監査を推奨
- **リージョン制限**: 記事で明示的なリージョン制限は記載されていません。利用前に対象リージョンでの対応状況を公式ドキュメントで確認してください
- **コスト**: Billing Conductorや選択するプライシングプランの適用により課金影響が発生する可能性があります。料金モデルを確認してください
- **適用範囲**: プリファレンスは「inbound transfer relationship」ごとに一度設定する方式で、新規の間接転送に対して自動作成が適用されます。既存の転送や既存の請求グループには遡及適用されません
- **操作方法**: 設定はAWS Management ConsoleのBilling Transfer詳細ページか、記事で言及されている2つのAPIオペレーションで行えます。API名はドキュメント参照してください
- **動作確認**: 本番適用前にテスト環境で受け入れフロー（エンド顧客の承諾→請求グループ自動作成）が期待通り動作するか確認することを推奨します

- https://docs.aws.amazon.com/billingconductor/latest/userguide/

## [Bedrock] OpenAI GPT-6 Sol and GPT-6 Luna are now generally available on Amazon Bedrock

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/openai-gpt-6-sol-luna-on-amazon-bedrock/

### 概要

OpenAIのGPT-6ファミリーからGPT-6 SolおよびGPT-6 LunaがAmazon Bedrockで一般利用（GA）になりました。両モデルは最大1Mトークンのコンテキストをサポートし、性能・速度・コストのトレードオフを選べる選択肢を提供します。

### 変更内容・新機能の詳細

GPT-6 Solは複雑で反復的なタスクやソフトウェア開発向けに設計された汎用モデルで、OpenAIの内部事実性評価でGPT-5.6 Solに比べ誤り率が概ね半分になっているとされています。コードの実装・デバッグ・レビュー・リファクタリング、データ解析、マルチステップのワークフロー実行（ツール連携を含む）を高い精度でこなせます。GPT-6 Lunaは要約、抽出、分類、ルーティング等の高頻度・高スループット処理に最適化された効率重視モデルで、推論時の「推論努力（reasoning effort）」を調整して品質・速度・コストのバランスを制御できます。両モデルとも1,000,000トークンまでのコンテキストをサポートします。Amazon Bedrockの推論エンジンはプロダクション運用に必要な性能・セキュリティ・スケールを提供し、既存のAWSのアクセス制御・監査機能と連携してモデル呼び出しのガバナンスを行えます。利用はBedrockコンソールまたはBedrock API経由で可能で、リージョン、エンドポイント、推論プロファイル、価格などの詳細はBedrockドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習/AIプロダクト開発者、ソフトウェア開発チーム、SRE/運用チーム、データエンジニア
- **利用シーン**: 複雑なコード作成やレビュー、デバッグ、自動化されたマルチステップワークフローの実行（GPT-6 Sol）；大量の要約・抽出・分類・ルーティング処理（GPT-6 Luna）
- **運用効果**: 精度向上により手動レビューや修正コストが削減される可能性。Lunaを使った高並列処理でレイテンシとコスト効率を改善できる
- **コスト/性能の選択肢**: Solは高精度だがコストは高め、Lunaは高効率でコスト最適化に有利。推論時の「reasoning effort」を調整して1リクエストあたりのコストと品質をトレードオフ可能

### 技術的な注意点

- **IAM権限**: Bedrockのモデル呼び出しには適切なIAM権限が必要です（最小権限でのロール設計を推奨）
- **リージョン制限**: モデルの提供リージョンは限定される場合があります。利用前にBedrockドキュメントで対応リージョンを確認してください
- **コスト**: Solは高精度モデルのためコストが高くなる可能性があります。Lunaは高スループット向けにコスト効率が良い設計です。推論プロファイルやreasoning effortが料金に影響します
- **トークン制限**: 両モデルとも最大1,000,000トークンのコンテキストをサポートしますが、長コンテキストを使う際はレイテンシとコストの増加を考慮してください
- **互換性/API**: BedrockコンソールまたはBedrockのサポートAPI経由で利用可能です。既存のBedrockワークフロー・プロファイルと統合する形で運用できます
- **セキュリティ/ガバナンス**: AWS IAM、AWS KMS（キー管理）、CloudTrail（監査ログ）などの既存AWSコントロールと連携してアクセス管理・監査・暗号化を行ってください
- **評価注意**: 「誤り率が半分」といった性能比較はOpenAIの内部評価に基づくものであり、実運用での結果はユースケースやプロンプト設計に依存します

## [Bedrock] Claude Opus 5.5 is now available on AWS GovCloud (US)

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/claude-opus-5-5-aws-govcloud/

### 概要

AWS GovCloud (US) で Anthropic の最新 Opus ファミリ最初のモデル「Claude Opus 5.5」が利用可能になりました。Amazon Bedrock 経由で提供され、ZDR（Zero Data Retention）をデフォルトでサポートします。

### 変更内容・新機能の詳細

Claude Opus 5.5 は Opus 5 より少ないトークンでタスクを完了できるよう設計された、長時間のコーディングやナレッジワーク向けの高性能モデルです。Anthropic によれば、トークン使用効率の改善に加えトークン単価も低く設定されており、さらにキャッシュ読み取りコストが安価であるため総合的なコスト効率が向上します。モデルは「何をしたか・何を見つけたか・次に何が必要か」を明確に報告する共同作業的な振る舞いを重視しており、各リクエストごとに必要な作業量を適応的に判断します。Amazon Bedrock 経由での提供により、データは AWS インフラ内に保持され（リージョナルなデータ居住性）、Bedrock のガードレールやナレッジベースなど AWS 管理の機能と統合された形で利用できます。なお、本リリースは AWS GovCloud (US) における利用開始の情報であり、他リージョンでの提供状況は別途確認が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: 米国政府機関やその契約業者、規制下で運用するエンタープライズ、AWS GovCloud (US) アカウントを利用する開発者・SRE・データサイエンティスト
- **利用シーン**: 長時間にわたるコード作成・リファクタリング、複雑なナレッジワーク（リサーチ要約、ドキュメント生成、コンプライアンス調査）、インタラクティブなコラボレーティブアシスタント
- **運用効果**: トークン効率と低価格により実行コストを削減しやすく、ZDR とリージョナルデータ居住性によりコンプライアンス要件を満たしやすくなる。出力が「何をしたか/見つけたか/次に何が必要か」を明示するためレビュー負荷が軽減され、長時間タスクの自動化や人間との協調が向上する

### 技術的な注意点

- **IAM権限**: Bedrock の呼び出し権限（モデル呼び出しに関する権限）や、入力データを格納する S3、Secrets Manager、CloudWatch 等へのアクセス権を事前に確認・最小権限で付与してください
- **リージョン制限**: 本リリースは AWS GovCloud (US) 向けの提供です。パブリックリージョン（例: us-east-1 等）での可用性は別途確認が必要です。GovCloud アカウントと適切な資格情報が必要です
- **データ保持（ZDR）**: Amazon Bedrock はデフォルトで Zero Data Retention をサポートしますが、CloudWatch ログ、S3 バケット、アプリケーション側のログ出力などによりデータが残る可能性があるためログ設定・ライフサイクルポリシーを確認してください
- **コスト**: Opus 5.5 はトークン効率が高くトークン単価も低く設定されていますが、最終的なコストは Bedrock の利用料金、API 呼び出し頻度、キャッシュ利用やストレージなどの周辺サービスによって変動します。料金ページで具体的な単価を確認してください
- **SDK/エンドポイント**: GovCloud 用の Bedrock エンドポイントと認証設定（GovCloud アカウント）を使用する必要があります。使用する AWS SDK/CLI が Bedrock と GovCloud エンドポイントに対応しているか確認してください
- **コンプライアンス**: GovCloud は規制対応ワークロード向けですが、必要な認証（例: FedRAMP、ITAR 等）はワークロード次第で異なるため、自組織のコンプライアンス要件を確認のうえ評価してください

## [Bedrock] Claude Opus 5.5 is now available on AWS

- **公開日**: 2026-09-23 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/claude-opus-5-5-aws/

### 概要

Anthropicの最新OpusファミリーであるClaude Opus 5.5がAWSで利用可能になりました。長時間のコーディングやナレッジワークに強く、低トークン消費・低コストで効率的にタスクを完遂するエンタープライズ向けモデルです。

### 変更内容・新機能の詳細

Claude Opus 5.5は、従来のOpus 5に比べて同じタスクをより少ないトークンで完了し、トークン単価が下がっているほか、キャッシュ読み取りのコスト削減が積み重なって総コスト効率が向上しています。モデルは“各リクエストで適応的に考える”設計になっており、長時間にわたるコーディング作業やドキュメント調査・要約などのナレッジワークを継続的に扱うのに適しています。出力時に「何をしたか」「何を発見したか」「次に何が必要か」を明確に報告するため、チームでの共同作業やレビューに向いています。AWS上での提供方法は2通りです。1) Amazon Bedrock経由：デフォルトでZero Data Retention（ZDR、データ非保持）をサポートし、AWSインフラ内でのリージョナルデータレジデンシーとBedrockのガードレール／Knowledge Basesなどの管理機能を利用できます。2) Claude Platform on AWS：Anthropicが提供するネイティブなプラットフォーム体験（同一API／コンソール操作）をAWSコンソール経由で直接利用でき、AWS請求・認証と統合して運用できます。導入時は既存のAPI呼び出し設計（コンテキスト長、ストリーミング、リトライ、キャッシュ戦略）やコストモデルを見直すと効果的です。

### 影響範囲・利用シーン

- **対象ユーザー**: AI開発者、SRE/運用チーム、データサイエンティスト、ソフトウェア開発チーム
- **利用シーンまたは効果**: 長時間のコーディング（リファクタリング・デバッグの継続作業）、大規模ドキュメントの要約・検索・ナレッジワーク、RAG（Retrieval-Augmented Generation）を用いた業務支援、レビュー付き自動化ワークフロー
- **運用効果**: トークン効率とキャッシュコスト削減によりランニングコストが下がる可能性、モデル出力がより説明的になることでヒト側のレビュー時間が短縮
- **コスト影響**: Opus 5に比べ単価やキャッシュコストが低く設計されているが、長いコンテキストや高頻度呼び出しでは依然コスト要因となるため見積もりが必要
- **リージョン制限**: Bedrockでの提供はリージョン単位の可用性に依存するため、利用前に該当リージョンでの対応状況を確認する必要あり
- **アクセス経路**: Amazon Bedrock（ZDR、AWS管理機能と統合）またはClaude Platform on AWS（Anthropicネイティブ体験をAWS経由で利用）

### 技術的な注意点

- **IAM権限**: Amazon BedrockやClaude PlatformにアクセスするためのBedrock関連のIAMポリシー（bedrock:InvokeModelなど）など適切な権限が必要
- **リージョン制限**: Bedrock上の提供はリージョン依存。利用前にAWSのリージョン対応状況を確認してください
- **データ保持／プライバシー**: Bedrock経由ではデフォルトでZero Data Retention（ZDR）が有効。Claude PlatformではAnthropic側のデータ処理ポリシーも確認すること
- **コスト**: モデル自体はトークン効率が改善されているが、コンテキスト長、キャッシュ設計、呼び出し頻度によりコストが変動するため事前に想定ワークロードで試算を推奨
- **互換性**: Claude Opus 5.5はOpus 5から性能が向上しているが、プロンプト設計やハイパーパラメータ（温度、最大トークン、ストリーミング設定等）のチューニングが必要になる可能性あり
- **運用監視**: レイテンシ、エラー率、トークン消費をモニタリングし、ガードレールやリトライ戦略を整備すること
- **ガードレール／Knowledge Bases**: Bedrockの管理機能（ガードレール、Knowledge Bases）を利用する場合は追加設定と権限、メンテナンスが必要
