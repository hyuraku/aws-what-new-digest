## [Glue] AWS Glue zero-ETL now captures archived Salesforce records

- **公開日**: 2026-09-15 (JST)
- **カテゴリ**: Glue
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/glue-zero-etl-archived-salesforce/

### 概要

AWS Glue zero-ETL の Salesforce 統合が、Salesforce のアーカイブ済みレコードをターゲットテーブルに取り込めるようになり、isArchived フィールドでアーカイブ状態を正確に反映することで Salesforce の完全な複製を分析用に提供します。

### 変更内容・新機能の詳細

Glue zero-ETL の Salesforce 統合がアーカイブ済みレコードをキャプチャするようになりました。アーカイブされたレコードはターゲットテーブルに取り込まれ、isArchived フィールドでアーカイブ状態が明示されます。これにより、Salesforce が自動的にアーカイブする高ボリュームエンティティ（例: Events、Tasks、Activities）も分析対象に含められ、分析・レポートの完全性が向上します。新規統合では作成時から自動的にアーカイブレコードを取り込み、既存の統合については AWS Glue が isArchived 状態を自動でバックフィルします（再同期・再設定・スキーマ変更は不要）。既存のパイプラインは停止せず継続実行され、バックフィル中もターゲットテーブルへ順次反映されます。本機能は AWS Commercial および AWS GovCloud (US) の Glue zero-ETL for Salesforce 対応リージョンで利用可能です。利用開始は AWS Glue コンソール、CLI、SDK から統合を作成または継続利用してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データ分析者、BI/ETL エンジニア、SRE/運用チーム
- **利用シーン**: Salesforce の完全なデータ複製が必要な分析・ダッシュボード作成、アーカイブ対象エンティティ（Events/Tasks/Activities 等）の履歴分析や監査
- **運用効果**: 既存パイプラインを止めずに isArchived 情報が自動反映されるため、データ欠損や不整合のリスクを低減し、分析精度を向上できる
- **制限**: 利用可能リージョンは Glue zero-ETL for Salesforce をサポートするリージョンに準拠。リージョンごとのサポート状況を確認する必要がある

### 技術的な注意点

- **IAM権限**: Glue 統合の作成・管理や Data Catalog 更新に必要な IAM 権限（Glue の Create/Update 統合権限等）と、Glue が利用するサービスロールの設定が必要です
- **Salesforce権限**: アーカイブ済みレコードを参照できる Salesforce 側の API/ユーザー権限が必要。Salesforce の共有設定や保管ポリシーが結果に影響する可能性があります
- **リージョン制限**: 本機能は AWS Commercial および AWS GovCloud (US) の Glue zero-ETL for Salesforce 対応リージョンで利用可能です。利用前に対象リージョンの対応状況を確認してください
- **コスト**: AWS が本機能の個別課金を明示していませんが、ターゲットテーブルの保存（ストレージ）や、それらに対するクエリ実行（Athena、Redshift、EMR 等）には通常の料金が発生します
- **互換性/スキーマ**: AWS 側で isArchived フィールドを自動で反映・バックフィルするためスキーマ変更は不要とされていますが、下流のクエリ・ビュー・ETL ジョブでは isArchived を考慮するよう更新が必要になる場合があります
- **運用影響**: 既存パイプラインは継続して動作しますが、バックフィル処理によりターゲットテーブルに増分が発生します。バックフィルの進行状況やストレージ増加をモニタリングしてください
- **API/レイテンシ**: 既存統合のバックフィルは自動で行われますが非同期処理のため反映に時間がかかる場合があります。大量データや高頻度更新では Salesforce API のレート制限に注意してください

## [Aiml] Qwen3.6-35B-A3B-NVFP4 and Wan2.1-T2V-1.3B-Diffusers models now available on Amazon SageMaker JumpStart

- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/qwen3.6-35b-a3b-nvfp4-wan2.1-t2v-1.3B-diffusers-jumpstart/

### 概要

Amazon SageMaker JumpStartに、NVIDIA版Qwen3.6-35B-A3B-NVFP4とAlibabaのWan2.1-T2V-1.3B-Diffusersの2モデルが追加されました。これにより、長文コンテキスト対応のエージェント型コーディングや、低VRAMで動作するテキスト→動画生成がJumpStart上で簡単に利用可能になりました。

### 変更内容・新機能の詳細

・Qwen3.6-35B-A3B-NVFP4: NVIDIAがModelOptでNVFP4量子化したAlibabaのQwen3.6-35B-A3Bの派生版です。Mixture-of-Experts(MoE)アーキテクチャで総パラメータは35B、トークンあたり実際にアクティブになるのは約3B（256専門家中8専門家を選択）です。ネイティブで262kトークンのコンテキストウィンドウをサポートし、YaRNスケーリングにより約1Mトークンまで拡張可能とされています。NVFP4量子化によりメモリ使用量が大幅に削減され、会話の文脈保持（multi-turn reasoning）、マルチトークン予測、ツール呼び出しを含む複雑なエージェントパイプラインの実行が現実的になります。
・Wan2.1-T2V-1.3B-Diffusers: Diffusion Transformerと新しいVideo VAEを組み合わせたテキスト→動画生成モデル（1.3Bパラメータ）。8.19GBのVRAMで動作可能とされ、消費者向けGPU（例: RTX 4090）で約4分で5秒・480pの動画を生成できる性能を示します。物理的一貫性のある高品質な短尺動画生成に最適化されており、オープンソースのテキスト→動画モデルとしてはアクセスしやすい構成です。
・SageMaker JumpStart統合: これらのモデルはSageMaker JumpStartモデルカタログから数クリックでデプロイできます。コンソール操作のほか、SageMaker Python SDK経由でプログラム的にエンドポイント作成・デプロイ・推論が可能で、SageMakerのGPUインスタンス上でスケーラブルに運用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、アプリケーション開発者、研究者、メディア/クリエイティブチーム
- **利用シーン**: 長文コンテキストを必要とするエージェント型コーディングやマルチモーダル推論（Qwen）、短尺テキスト→動画コンテンツ生成やプロトタイピング（Wan2.1）
- **運用効果**: 高度な長期文脈保持やツール連携が可能になり複雑な自動化エージェントの構築が容易に。低VRAMで動く動画モデルにより、コストを抑えた動画生成ワークフローの実現が可能

### 技術的な注意点

- **IAM権限**: SageMakerのモデルデプロイ、エンドポイント作成、ECR/EFS/S3アクセス等の権限が必要です（例: AmazonSageMakerFullAccessや最小権限ポリシーの適切設定）。
- **リージョン制限**: JumpStartのモデル提供状況はリージョン依存です。利用前にSageMakerコンソールのJumpStartカタログで対象リージョンでの提供有無を確認してください。
- **コスト**: GPUインスタンス（推奨：g5, p4, p4dなど）の利用は時間課金です。MoEや長コンテキスト処理は計算・メモリ需要が高くなる可能性があるため、インスタンスタイプ選定でコストに大きな影響があります。量子化はメモリ/コスト削減に寄与しますが、スループット要件に応じたサイズ選定が必要です。
- **ハードウェア要件**: Qwen NVFP4はNVIDIA GPU上での最適化を前提としています。Wan2.1は研究値でRTX 4090 (≈8.19GB VRAMでの動作例)が挙げられていますが、SageMaker上では十分なGPUメモリを持つインスタンスを選択してください。
- **モデル互換性/ランタイム**: NVFP4量子化モデルはNVIDIAのModelOpt変換を使用しており、ランタイム依存（CUDA/NVIDIAドライバ・ライブラリ）があります。SageMakerでのデプロイ時は対応ランタイム/コンテナを使用してください。
- **コンテキスト/スケーリング**: YaRN等を用いた1Mトークン級のスケーリングは特殊な分散・メモリ戦略を必要とします。大規模コンテキスト利用時はレイテンシとコストのトレードオフを評価してください。
- **API/SDK**: JumpStartカタログまたはSageMaker Python SDKからのデプロイが可能です。バージョン互換性のためにSDKとコンテナのバージョンを確認してください。

Amazon SageMaker JumpStartに、BMのgranite-speech-4.1-2b、Kakaoのkanana-2-30b-a3b-instruct、OpenFold ConsortiumのOpenFold3が追加され、音声認識／翻訳、二言語エージェントAI、および生体分子構造予測の基盤モデルがJumpStartから簡単に利用可能になりました。

### 変更内容・新機能の詳細

今回追加された3モデルは用途が異なる専門特化型のファウンデーションモデルです。granite-speech-4.1-2bは約2Bパラメータの音声言語モデルで、英語・フランス語・ドイツ語・スペイン語・ポルトガル語・日本語の多言語ASR（自動音声認識）と双方向音声翻訳（AST）に最適化されています。記事では単語誤り率（WER）5.33%／リアルタイム係数（RTF）約231という効率性が示されており、Apache 2.0ライセンスで提供されるため企業ワークフローへの統合が容易です。kanana-2-30b-a3b-instructはKakao開発の30Bパラメータモデルで、Mixture-of-Experts（MoE）設計により1推論あたり約3Bパラメータ分のみを活性化することでスループットを向上させています。Multi-head Latent Attention（MLA）アーキテクチャを採用し、教師あり微調整（SFT）と強化学習（RL）で後処理され、最大128Kトークンの長文コンテキスト（YaRNスケーリング）をサポートします。二言語（韓国語⇄英語）での指示追従やエージェント的振る舞い（先読み・状況対応）に向いています。OpenFold3はOpenFold ConsortiumとAlQuraishi研究室による拡散（diffusion）ベースの構造予測モデルで、単一タンパク質を超えた多鎖複合体やタンパク質–DNA/RNA、低分子リガンドを含む全原子レベルの構造予測を目指します。コンピュータ支援創薬（CADD）や基礎研究での構造モデリングに適用でき、複雑な相互作用を扱える点が特徴です。これらはすべてSageMaker JumpStartのモデルカタログからワンクリックでデプロイ可能、あるいはSageMaker Python SDKを使ってプログラム的にデプロイできます。

### 影響範囲・利用シーン

- **対象ユーザー**: 音声処理/対話アプリ開発者、NLPエンジニア、SRE/運用チーム
- **利用シーン**: 多言語通話の自動文字起こし＆翻訳（granite-speech）／二言語コラボレーションAIやエージェントの構築（kanana）／タンパク質・核酸・リガンドの構造予測や創薬ワークフロー（OpenFold3）
- **運用効果**: JumpStart経由でのワンクリック展開によりPoCや製品化のスピードが向上し、専門モデルを素早く評価・導入できる
- **スケーラビリティ**: MoEや長文コンテキスト対応など、スループットや大コンテキスト処理を必要とするユースケースでコスト対性能を改善可能
- **研究/商用効果**: OpenFold3により構造予測をパイプラインに組み込むことで、創薬や分子設計の反復サイクルを短縮できる

### 技術的な注意点

- **IAM権限**: SageMakerモデルデプロイ用の関連IAM権限（SageMakerフルアクセスまたは必要な最小権限）を付与してください
- **リージョン制限**: モデルはJumpStartで提供されますが、リージョンによって未対応の場合があります。コンソールのJumpStartカタログで利用可能リージョンを確認してください
- **コスト**: 高性能GPUインスタンス（推論/バッチ処理ともに）を用いるとコストが高くなります。MoE構成のkananaは活性化パラメータが少ないとはいえ推論は大規模モデルに準じる計算資源を要します
- **ライセンス**: granite-speech-4.1-2bはApache 2.0で提供されています。kananaおよびOpenFold3のライセンス／利用条件は各モデルカード（JumpStartのモデルページ）で必ず確認してください
- **推論要件**: graniteは低レイテンシ音声ワークロード向けに効率的ですが、リアルタイム処理にはGPUや低遅延I/Oが望ましい。kananaの128Kトークン長やMoEは大量メモリ・特定のランタイムサポートを必要とする場合があります。OpenFold3は拡散ベースの全原子予測で計算負荷が高く、GPU（大容量メモリ）や分散推論の検討が必要です
- **実装注意**: MoEや長文コンテキストを最大限活用するには、対応する推論用コンテナ／最適化（モデル並列、カスタムランタイム）を利用すると良いです。JumpStartの推奨デプロイ設定に従ってください
- **データ保護**: 音声データやバイオ医療データを扱う場合は、暗号化・アクセス制御・ログ管理などのコンプライアンス要件を満たす設計を検討してください
- **互換性**: SageMaker Python SDKおよびJumpStartのテンプレートからデプロイ可能。追加のモデル固有ドキュメントやモデルカードを参照してAPI/入出力仕様を確認してください
