## [General] AWS Glue zero-ETL adds target table property ownership and conflict detection

- **公開日**: 2026-09-14 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/glue-zero-etl-ownership-conflicts/

### 概要

AWS Glue の zero-ETL 統合が、ターゲットテーブルのプロパティに対する所有権管理と競合検出をサポートするようになりました。これにより、複数の統合が意図せず同じターゲット表を上書き・参照するリスクを低減できます。

### 変更内容・新機能の詳細

Glue zero-ETL でソーステーブルとターゲットカタログを設定すると、生成されるテーブルプロパティに「どの統合が所有しているか」のメタ情報が紐づけられます。Amazon S3 Tables と SageMaker Lakehouse のカタログ双方に対応しており、既に別の統合が所有しているテーブルに対して新しい統合を作成・変更しようとすると、Glue が所有統合を特定して警告を出します。ユーザーは別のターゲットを選ぶか既存統合を更新するかを選択するガイダンスを得られるため、データパイプラインの孤立性が保たれ、データが意図した場所に確実に格納されます。機能は、Glue zero-ETL 統合がサポートされているすべての AWS Commercial および AWS GovCloud (US) リージョンで利用可能です。詳しい操作方法や API/コンソールでの挙動については Glue Developer Guide を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データプラットフォームエンジニア、ETL/データ統合チーム、SRE/運用チーム
- **利用シーン**: 複数チームが並行して zero-ETL 統合を作成する環境で、どのソースがどのターゲットテーブルにマッピングされるかを明確にしたい場合
- **運用効果**: 意図しないテーブル上書きやパイプライン干渉を未然に防ぎ、データ配置の予測可能性と隔離性が向上する
- **対象サービス**: Amazon S3 Tables、SageMaker Lakehouse カタログ、AWS Glue zero-ETL 統合
- **組織面の影響**: チーム間のターゲット設計ルールや命名規則の整備、ターゲット割当ての運用フロー整備が推奨される

### 技術的な注意点

- **IAM権限**: 統合作成/更新に必要な AWS Glue 権限（例: glue:CreateMLTransform/Update* は機能によるが、Glue の統合管理に関連する Create/Update/Get 権限）およびカタログ操作権限（glue:GetTable, glue:UpdateTable など）を確認してください。S3 や SageMaker に対する読み書き権限も必要です
- **リージョン制限**: Glue zero-ETL 統合がサポートされている AWS Commercial および AWS GovCloud (US) リージョンで利用可能です。利用前に対象リージョンで zero-ETL のサポート状況を確認してください
- **コスト**: 本機能自体に追加料金は明示されていませんが、Glue や関連サービスの通常料金が適用されます。統合の作成・実行に伴うストレージや処理コストは既存の課金体系に従います
- **互換性と移行**: 既存のテーブルに所有情報がない場合は、最初の統合が所有権を取得します。別統合へ所有権を移す場合は既存統合の更新や削除といった手順が必要になるため、事前に調整してください
- **API/コンソール**: 所有権表示と競合検出は Glue コンソールでガイド表示されます。自動化やスクリプトで扱う場合は Glue の API/CLI 出力や Developer Guide の仕様を確認して処理を組んでください

## [General] AWS End User Messaging now supports Dynamic Flows in WhatsApp

- **公開日**: 2026-09-14 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-end-user-messaging-whatsapp-dynamic-flows

### 概要

AWS End User Messaging が WhatsApp の動的フローをサポートしました。WhatsApp チャット内で予約、リード取得、サインアップ、アンケート、トランザクションなどの対話型体験をリアルタイムに実行できます。

### 変更内容・新機能の詳細

動的フローでは、Meta（WhatsApp）のスターターテンプレートやカスタムで定義した画面（テキスト入力、日付ピッカー、ドロップダウン、ボタンなど）を利用し、各画面ごとにユーザー操作に応じて AWS End User Messaging 側で定義した JSON スキーマに基づくフローを配信します。各画面はリアルタイムにお客様の HTTPS エンドポイントを呼び出せるため、空き状況や在庫などのライブデータを表示したり、ユーザーごとにパーソナライズした内容を返すことが可能です。フローの作成・管理は AWS End User Messaging Social コンソールまたは API で行い、作成したフローを WhatsApp 用メッセージテンプレートで配信してユーザーに到達させます。WhatsApp の動的フローは End User Messaging Social が利用可能な全リージョンで利用可能です（詳細は User Guide を参照）。

### 影響範囲・利用シーン

- **対象ユーザー**: チャットを介した顧客接点を作る開発者、プロダクト担当、SRE/運用チーム
- **利用シーンまたは効果**: 予約受付、リード獲得フォーム、アンケート、会員登録、簡易決済や在庫確認などをユーザーを外部サイトへ誘導せずチャット内で完結させ、コンバージョン向上やUX改善に寄与
- **運用効果**: ライブデータ連携により空き状況や在庫を即時反映できるためキャンセル/二重予約の削減、ユーザー体験の短縮化、問い合わせ工数の削減
- **対応リージョン**: End User Messaging Social が提供されているすべてのリージョンで利用可能（ただしリージョンごとの提供状況は公式ドキュメントで確認してください）

### 技術的な注意点

- **IAM権限**: End User Messaging のリソース作成・編集、API 呼び出しに必要な IAM ポリシーを付与してください（コンソール操作と API の両方で適切な権限が必要）
- **リージョン制限**: WhatsApp フローは End User Messaging Social が利用可能なリージョンで提供。利用前に対象リージョンでの利用可否を確認してください
- **メッセージテンプレート**: WhatsApp のテンプレートは Meta 側の承認が必要です。テンプレート承認待ちの間は配信できません
- **HTTPS エンドポイント**: フローの各画面から呼び出すエンドポイントはパブリックに到達可能で TLS（HTTPS）を使用する必要があります。認証ヘッダや署名検証の要件、期待するリクエスト/レスポンス JSON スキーマを事前に実装してください
- **レイテンシ/タイムアウト**: 各画面でのリアルタイム呼び出しはユーザー体験に直結します。エンドポイントの応答時間を短く保ち、適切なタイムアウト・リトライ設計を行ってください
- **スケーリング/レート制限**: 大量の同時フロー実行ではエンドポイント側のスケーリングと WhatsApp/API のレート制限を考慮してください
- **コスト**: End User Messaging の利用料金、WhatsApp（Meta）経由でのメッセージ送信費用やテンプレートメッセージの課金が発生する可能性があります。トラフィック増加に伴うバックエンド API のコストも考慮してください
- **セキュリティ/プライバシー**: 個人情報や決済情報を取り扱う場合は暗号化、アクセス制御、ログ管理、データ保持ポリシーを適用してください

- https://aws.amazon.com/end-user-messaging/

## [Pinpoint] AWS End User Messaging strengthens SMS deliverability with automatic failover

- **公開日**: 2026-09-14 (JST)
- **カテゴリ**: Pinpoint
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-end-user-messaging-improves-deliverability

### 概要

AWS End User Messaging（EUM）の電話番号プール（phone pools）において、SMS配信品質が低下した際に自動的に次に最適な番号へフェイルオーバーする機能が有効になりました。ユーザー側での操作は不要で、EUMを提供するリージョン全体で利用可能です。

### 変更内容・新機能の詳細

電話番号プールから送信されるSMSについて、EUMが配信遅延、配信失敗、コンバージョン低下などの指標を継続的に監視し、障害や下流の経路問題（AWS → メッセージプロバイダー → 携帯キャリア）によって配信が阻害された場合に、自動的にプール内の『次に最適な送信元番号』へトラフィックを切り替えます。これによりワンタイムパスコード（OTP）、配信通知、リマインダーなど時間制約のあるメッセージの到達性が向上します。顧客は電話番号プール経由で送信している限り追加設定は不要で、EUMが既定の監視とルーティングを行います。機能はEUMが利用可能なすべてのAWSリージョンで有効です。

### 影響範囲・利用シーン

- **対象ユーザー**: モバイル通知・SMSを利用するアプリ開発者、マーケティングチーム、SRE/運用チーム、セキュリティチーム（OTP発行担当）
- **利用シーン**: ワンタイムパスコード（認証）、配達/注文通知、定期リマインダー、時間限定キャンペーン通知など、到達性が重要なSMS送信
- **運用効果**: 自動フェイルオーバーにより配信失敗や遅延の影響を低減し、手動の切替や障害対応工数を削減可能
- **注意点（利用上）**: 本機能は電話番号プール経由の送信にのみ適用されるため、個別の固定番号やプールを利用していないワークフローは恩恵を受けません

### 技術的な注意点

- **IAM権限**: 電話番号プールの作成・管理やEUMの設定を行うためのEUM/Pinpoint関連の管理権限が必要（組織のIAMポリシーで許可を確認してください）
- **リージョン制限**: 記事の通り『EUMが利用可能なリージョン』で有効。リージョンごとにEUMの提供状況を確認してください
- **コスト**: フェイルオーバー自体で別料金が発生する旨の案内はないが、送信されるSMSは通常の送信課金の対象になります。複数番号への試行やキャリア経路の切替が追加請求に影響する可能性があるため料金表を確認してください
- **互換性／制限**: 本機能は“電話番号プール”の送信に限定。ショートコード、トールフリー、ロングコード等の番号種別や国ごとのA2P規制により挙動や利用可否が異なる場合があります（現地の送信規制や送信元表示の制約に注意）
- **運用上の注意**: フェイルオーバーで送信元番号が変わるため、受信者側での信頼性やOTPの検証フロー（送信元と受信側の期待）が影響を受ける可能性があります。送信元番号の変更がユーザー体験やキャリアフィルタリングに与える影響を事前に評価してください
- **監視・可視化**: EUMのコンソールや既存の配信指標（ログ/メトリクス）でフェイルオーバー状況や配信成功率を確認し、必要に応じてアラートを設定してください
