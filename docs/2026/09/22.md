## [Emr] Amazon EMR introduces Long Term Support with Apache Spark 4.1

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Emr
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-emr-long-term-support-spark-4-1/

### 概要

Amazon EMRがLong Term Support（LTS）を導入し、最初の対象リリースとしてemr-spark-8.1.0（Apache Spark 4.1）をサポート開始しました。指定されたSparkランタイムは36か月間の重要/高優先度の修正提供対象になります。

### 変更内容・新機能の詳細

LTS: emr-spark-8.1.0（Apache Spark 4.1）を対象に、36か月間のLTSサポートを提供します。LTS期間中は、重大／高優先度のセキュリティ修正、バグ修正、データ破損に関する修正が（該当する場合に）提供され、追加料金は発生しません。Apache Iceberg v3のフルサポートを追加し、ジオスペーシャル型、より高精度のタイムスタンプ、スキーマ進化（schema evolution）などの機能が利用可能になりました。Spark SQLでは、カタログを名前で参照できるようになり、クロスアカウントやAmazon S3 Tablesカタログを含めて、各カタログを事前にSpark設定に登録しなくてもApache Iceberg、Delta Lake、Apache Hudiのテーブル形式を自動検出します。細粒度アクセス制御（カラム/行レベルの権限）は、より多くのApache Iceberg操作とDelta LakeのVACUUM操作に拡張され、これら操作に対するアクセス制御を強化できます。Amazon EMR on EKSクラスターはSpark Connectエンドポイントをトークンベース認証でサポートします。emr-spark-8.1.0は、Amazon EMRが提供されるすべてのAWSリージョンで、EMR on EC2、EMR on EKS、EMR Serverlessの各実行形態にて利用可能です。導入はAWS Management Consoleでemr-spark-8.1.0を選択してクラスター／アプリケーションを作成するか、既存アプリケーションを移行する場合はApache Spark Upgrade Agent for Amazon EMRを利用してください。

### 影響範囲・利用シーン

- **対象ユーザー**: EMRで本番Sparkワークロードを運用するデータエンジニア、SRE、プラットフォームチーム
- **利用シーン**: 長期安定性が重要な本番環境でのSparkランタイム運用、Iceberg v3を利用した高度なテーブル機能（ジオスペーシャル、高精度タイムスタンプ、スキーマ進化）の活用、クロスアカウントやS3 Tablesカタログ参照を含むマルチカタログクエリ
- **運用効果**: ライフサイクルを延長できるためアップグレード運用の計画を立てやすくなり、重大なセキュリティやデータ破損問題に対する修正を受け取りやすくなる。Iceberg/Delta/Hudiの自動検出や細粒度アクセス制御拡張により、データガバナンスと互換性管理が容易になる。

### 技術的な注意点

- **IAM権限**: EMRクラスター／アプリケーション作成時やSpark Connectトークン認証利用時に必要なIAMロール／ポリシーの確認と付与が必要です（例えば、S3アクセス、カタログアクセス、EKS関連権限）。
- **リージョン制限**: emr-spark-8.1.0はAmazon EMRが提供されるすべてのリージョンで利用可能とアナウンスされていますが、個別リージョンでの機能差異や遅延配信がある可能性があるため、利用前に対象リージョンでの展開状況を確認してください。
- **互換性と移行**: Spark 4.1やIceberg v3の機能は既存アプリケーションの互換性に影響を与える場合があります。Spark APIの互換性、サードパーティライブラリやジョブの動作確認、Icebergメタデータの移行テストを事前に実施してください。
- **テストとバックアップ**: 本番移行前にステージング環境でジョブ実行／パフォーマンステストを行い、重要データはバックアップ（スナップショットやバケットのバージョニング）を取得してください。
- **コスト**: LTS自体に追加料金は発生しませんが、emr-spark-8.1.0の新機能（例: Iceberg操作、追加のメタストアアクセス、EKS上でのSpark Connectなど）を活用すると、ストレージ・データ転送・クラスター実行時間などのコストに影響する可能性があります。
- **運用監視**: 新しいフォーマット自動検出や追加のテーブル操作導入に伴い、ログ、メトリクス、アクセス監査（CloudTrailなど）の設定を見直してください。
- **Spark Connect**: EMR on EKSでのSpark Connectはトークン認証をサポートしますが、ネットワーク（VPC、セキュリティグループ）、証明書/シークレット管理の構成を確認してください。

## [Outposts] Amazon Route 53 Resolver is now generally available on second-generation AWS Outposts racks

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Outposts
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/route-53-resolver-gen2-outposts/

### 概要

Amazon Route 53 Resolverが第2世代AWS OutpostsラックでGAになりました。Outpost上のワークロードに対してローカルで管理された再帰的DNS解決を提供し、レイテンシ低減とService Link経由のトラフィック削減、切断時の継続的な名前解決を実現します。

### 変更内容・新機能の詳細

第2世代（second-generation）Outpostsラックに組み込まれたAWS管理インフラ上でRoute 53 Resolverが動作し、Outposts上のDNSクエリを親リージョンへ渡さずローカルで再帰的に解決します。Service Linkが断続的または完全に切断された場合でも、ResolverはキャッシュされたDNSレコードを保持しているため、キャッシュ有効期間内は継続して名前解決が可能です。サービスはマルチラックの第2世代Outpostsではデフォルトで有効化されており、顧客側で追加のコンピュート（EC2など）を用意する必要はありません。必要に応じてAWSサポートへ連絡することでオプトアウトできます。提供リージョンは第2世代OutpostsをサポートするすべてのAWSリージョンで利用可能です。全顧客（既にプレビューで利用中の顧客を含む）には2026-12-21までの91日間の無料試用が適用され、2026-12-22以降はラックあたり$0.65/時間で課金されます。

### 影響範囲・利用シーン

- **対象ユーザー**: Outpostsを使用するクラウドエンジニア、ネットワーク/インフラチーム、SRE、エッジ/低レイテンシアプリケーションの開発者
- **利用シーン**: Outpost上のマイクロサービスやデータベース、IoT/産業系エッジアプリケーションでの低レイテンシDNS解決、リージョン接続が断続する環境での継続的名前解決
- **運用効果**: Service Linkを跨いだDNSトラフィック削減によるレイテンシ低減とネットワーク負荷抑制、切断時のキャッシュ利用による可用性向上、顧客側でDNS基盤を構築・管理する手間の削減

### 技術的な注意点

- **世代依存**: 第2世代（second-generation）Outpostsラックが対象です。第1世代では利用できません
- **デフォルト設定**: マルチラック第2世代Outpostsではデフォルトで有効化されています。シングルラック環境や手動での無効化を希望する場合はAWSサポートへ連絡してください
- **キャッシュ挙動**: Service Link切断時はキャッシュされたエントリで解決しますが、DNS TTLに従ってキャッシュは期限切れになります。完全切断が長期間続く場合は名前解決失敗のリスクがあります
- **権限**: Route 53 ResolverおよびOutposts設定の変更には適切なIAM権限が必要です（Route 53 ResolverとOutpostsに関する管理権限を事前に確認してください）
- **リージョン制限**: 第2世代OutpostsをサポートするAWSリージョンでのみ利用可能です。リージョンごとの対応状況はOutpostsのドキュメントで確認してください
- **コスト**: 91日間の無料試用（〜2026-12-21）あり。2026-12-22以降は$0.65/ラック/時間で課金されます。利用規模（ラック数×稼働時間）に応じて運用コストを見積もってください
- **運用監視**: Query logやCloudWatch連携などの監視・ログ収集設定はドキュメントで確認し、監視要件に応じて設定してください

## [Security Hub] AWS Security Hub AI Inventory adds Azure self-hosted instance support

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Security Hub
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/security-hub-ai-inventory-azure-support/

### 概要

AWS Security HubのAI InventoryがMicrosoft Azure上のセルフホスト型インスタンスで稼働するAI資産の検出・カタログ化をサポートするようになりました。これにより、組織全体でAWSとAzureを横断したAI資産の継続的な可視化とセキュリティ評価が可能になります。

### 変更内容・新機能の詳細

Security HubのAI Inventoryは、Amazon Inspectorのソフトウェア部品表（SBOM）分析機能の拡張を利用して、Azure仮想マシン上にインストールされた推論エンドポイント、モデル、AIエージェントを識別します。識別対象にはOllama、vLLM、Hugging Face TGIなどのフレームワークが含まれます。検出された各AI資産は、その基盤となるインフラストラクチャ（該当VMなど）にマッピングされ、Security Hubのセキュリティ所見と相関付けされます。これにより、AIインベントリをAWS/Azureを跨いでフィルタ・グループ化・クエリでき、組織のセキュリティチームは資産ごとのリスクや所見を統合的に把握できます。なお、本機能はSecurity Hub Essentialsに含まれ、追加料金なしで利用可能です。利用可能リージョンは、Security Hubが提供されている全てのAWS商用リージョンです。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティチーム、クラウド/プラットフォーム運用者、SRE、AI/MLインフラ担当者
- **利用シーン**: AWSとAzureにまたがるAIサービス（セルフホストされた推論サーバやモデルホスト）の資産管理・セキュリティ評価・監査
- **運用効果**: マルチクラウド環境でのAI資産の一元可視化により、脆弱性や不正設定の関連所見を迅速に追跡・対応できる
- **コスト**: Security Hub側のAI Inventory機能はSecurity Hub Essentialsに含まれるため追加費用はないが、Amazon Inspectorやデータ転送、Azure側での接続設定に関連する費用は発生する可能性がある
- **リージョン**: Security Hubが提供されている全てのAWS商用リージョンで利用可能

### 技術的な注意点

- **IAM権限**: Security HubおよびAmazon Inspectorを有効化／連携するための管理権限（または必要最小限の権限セット）を事前に確認・付与してください
- **前提（Inspector）**: Amazon InspectorのSBOM分析が有効化され、Azure上のセルフホストインスタンスをスキャン可能な状態である必要があります。必要に応じてInspectorのドキュメントに従いエージェント／コネクタの導入や設定を行ってください
- **Azure側アクセス**: Azure仮想マシンやそのメタデータに対する読み取り/スキャン用のアクセス許可や認証情報（サービスプリンシパル等）の設定が必要となる場合があります。組織のクラウド接続方針に従って事前に手順を整備してください
- **データ連携とセキュリティ**: 検出・SBOM情報や所見はSecurity Hubに格納されます。機密性やデータ滞在場所に関する要件（コンプライアンス／ガバナンス）がある場合は事前に確認してください
- **サポートされるフレームワーク**: 記載例としてOllama、vLLM、Hugging Face TGI等が明示されていますが、その他フレームワークの検出対応はAmazon InspectorのSBOM解析能力に依存します
- **コスト**: Security Hub側は追加料金不要（Security Hub Essentialsに含まれる）が、Amazon InspectorのスキャンやAzureとの接続設定に関連する費用は別途発生する可能性があります。コスト影響を事前に評価してください

## [Emr] Amazon EMR 7.14 is now available

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Emr
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-emr-7-14-available/

### 概要

Amazon EMR 7.14 が利用可能になりました。Spark と Iceberg のバージョンアップに加え、EMR on EKS と EMR Serverless 向けの機能強化（Spark Connect、IPv6対応、Serverlessの一時ストレージ増加など）が含まれます。

### 変更内容・新機能の詳細

主な変更点:
- Apache Spark を 3.5.8 にアップグレード。
- Apache Iceberg を 1.10.1 にアップグレード。
- Iceberg のマテリアライズドビューのリフレッシュ速度改善: 更新・削除のあるテーブルに対し、変更データキャプチャ（CDC）を利用して変更があったデータファイルのみを読み取り、リフレッシュの処理を高速化。
- Amazon EMR on EKS: Spark Connect エンドポイントのサポート（対話的な Spark セッションをトークンベース認証で利用可能）および IPv6 対応クラスター上でのワークロード実行サポート。
- Amazon EMR Serverless: Spark ジョブ向けの一時ストレージ（シャッフル領域）上限が 200 GiB から 1 TiB に拡大。大規模シャッフルを伴うジョブでのディスク不足を緩和。
- その他アプリケーションのバージョンアップや細かな改善が含まれ、Amazon EMR が利用可能なすべてのリージョンで提供開始。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、データサイエンティスト、プラットフォーム/インフラチーム
- **利用シーン**: 大規模な Spark バッチ/ストリーミング処理、Iceberg テーブルの頻繁な更新を伴う OLAP ワークロード、対話的な Spark 開発・デバッグ（EMR on EKS + Spark Connect）
- **運用効果**: Iceberg マテリアライズドビューのリフレッシュ時間短縮により遅延が低減され、EMR Serverless のストレージ増加でシャッフル失敗が減少。Spark Connect により開発・トラブルシューティングの生産性が向上。IPv6 サポートで IPv6 ネットワーク要件を持つ環境へデプロイ可能となる。

### 技術的な注意点

- **互換性/テスト**: Spark 3.5.8 および Iceberg 1.10.1 へ移行する際は既存ジョブの互換性テストを実施してください（API/最適化や挙動変更の可能性）。
- **Iceberg CDC 要件**: マテリアライズドビューの高速リフレッシュは、テーブルとカタログの設定によって動作が異なるため、対象テーブルが CDC を活用できる構成であるか確認してください（使用カタログ/ファイルレイアウト依存）。
- **EMR on EKS 要件**: Spark Connect とトークン認証を利用するには、EKS クラスター側のバージョン・CNI 設定や Pod セキュリティ、サービスアカウントの設定が必要です。管理者は RBAC や IAM Role for Service Accounts の設定を確認してください。
- **IPv6**: IPv6 を利用するには Amazon EKS の IPv6 構成や VPC サブネット設定が適切に行われている必要があります。既存クラスターの再設定やネットワーク設計見直しが必要になる場合があります。
- **EMR Serverless ストレージ**: 一時ストレージ上限が 1 TiB に増加しましたが、大きなシャッフルはコストやジョブ遅延に影響するため、ジョブ設定（メモリ/コア配分、パーティション数、shuffle 圧縮設定など）を最適化してください。
- **IAM 権限**: EMR（on EC2/on EKS/Serverless）で新機能を使うために必要な IAM ポリシーや EKS の ServiceAccount の権限を確認・付与してください。
- **コスト**: ストレージ増加や大規模ジョブの稼働はコスト増加につながる可能性があります。EMR/Serverless の課金モデルを確認し、コスト監視と予算管理を行ってください。
- **リージョン制限**: 記事では "すべての Amazon EMR が利用可能なリージョンで提供" とありますが、実運用前に利用リージョンで Release Guide とコンソール上での提供状況を確認してください。

## [Glue] AWS Glue Data Quality delivers context-specific rule recommendations in seconds

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Glue
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/glue-data-quality-rule-recommendations/

### 概要

AWS Glue Data Qualityが新たに提供する「Advanced mode」により、ジェネレーティブAIを使ってテーブルの各カラムに対する業務に即したデータ品質ルールを数秒で自動生成できるようになりました。手作業でルールを書くことなく、即時にルールセットを作成して監視を開始できます。

### 変更内容・新機能の詳細

Advanced modeはGlue Data Qualityのルール推奨機能の拡張で、データのスキーマやサンプル、利用目的（意図）をAIが解析してビジネスに関連するルール（列ごとの完全カバレッジ）を自動生成します。主な挙動は以下の通りです。1) 数秒でテーブル全カラムに対する推奨ルールを生成、2) 生成されたルールはレビュー・編集可能で、ルールセットとして保存すれば即座にモニタリングを開始、3) 新規データセットのブートストラップや大規模データレイクのベースラインチェック作成を手作業を大幅に削減して支援します。これにより、データの取り込みから信頼できるデータへの移行が早くなり、パイプライン作成時に品質担保を組み込めます。Advanced modeはジェネレーティブAI（AWSのAI技術）を用いてデータの“意図”を検出するため、単純な統計的チェックにとどまらないビジネス・ルール（例：特定IDの一意性、業務で期待される値範囲、参照整合性の推奨など）を提案します。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、データアナリスト、SRE/運用チーム、データガバナンス担当者
- **利用シーン**: 新規にオンボードするデータセットの初期ルール作成、大規模データレイクのベースラインチェック整備、パイプライン作成時の即時品質担保
- **運用効果**: ルール作成工数の大幅削減（数秒で初期ルールが生成）、レビュー後即時監視開始により品質の立ち上げ時間短縮と早期問題検出が可能

### 技術的な注意点

- **IAM権限**: Glue Data Catalog への読み書き権限、対象データストア（例: S3）への読み取り権限、Glue Data Quality の操作権限が必要です。具体的な最小権限はドキュメントで確認してください。
- **リージョン制限**: Advanced modeは以下のリージョンで利用可能です — Asia Pacific (Melbourne, Osaka, Sydney, Tokyo)、Canada (Central)、Europe (Frankfurt, Ireland, London, Milan, Paris, Spain, Stockholm, Zurich)、US East (N. Virginia, Ohio)、US West (N. California, Oregon)。他リージョンでは未対応の可能性があります。
- **コスト**: 新機能の利用に伴う追加料金が発生する可能性があります。Glue Data Qualityのルール評価・監視、ルール推奨機能の処理コスト（生成や評価のジョブ実行）については料金ページを確認してください。
- **データ/プライバシー**: ジェネレーティブAIはスキーマやサンプルデータ（メタデータ）を解析してルールを生成します。機密データを含む場合はサンプリング・マスキングやポリシー確認を行い、コンプライアンスに配慮してください。
- **品質保証**: 推奨ルールはあくまで“提案”です。業務要件に基づくレビュー・調整が必要です。誤検知やビジネス要件に合わないルールが含まれる可能性があります。
- **事前準備**: 対象テーブルがGlue Data Catalogに登録され、十分なサンプルデータが存在することが推奨されます。詳細な前提条件は公式ドキュメントを参照してください。

## [Rds For Sql Server] Amazon RDS Custom now supports the latest CU for Microsoft SQL Server

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: Rds For Sql Server

### 概要

Amazon RDS Custom for SQL Server が Microsoft SQL Server の最新累積更新プログラム（CU）をサポートしました。今回のリリースでは SQL Server 2022 CU26（KB5093420、RDS版 16.00.4265.3.v1）を適用可能です。

### 変更内容・新機能の詳細

Amazon RDS Custom for SQL Server は、Microsoft が提供する最新の累積更新（CU26 / KB5093420）をサポートするようになりました。RDS 側のバージョン表記は 16.00.4265.3.v1 です。これにより Microsoft 側のセキュリティ修正、バグフィックス、安定性・パフォーマンス改善が RDS Custom 環境へ反映可能になります。アップグレードは Amazon RDS マネジメントコンソール、AWS CLI、または AWS SDK を使って実行でき、RDS Custom の特性として基盤 OS や構成へのより細かいアクセス権を保持したまま CU 適用が可能です。詳細な修正内容や既知の変更点は Microsoft の KB5093420 を参照してください。アップグレード前にはバックアップ（自動スナップショットまたは手動スナップショット）の取得、ステージング環境での検証、互換性確認を推奨します。

- **利用シーン**: セキュリティパッチ適用、バグ修正の取り込み、SQL Server 2022 の安定性・パフォーマンス改善を本番環境に反映する際のアップグレード
- **運用効果**: 最新 CU 適用により既知の脆弱性やバグが解消され、システムの安定性・セキュリティが向上。定期的なパッチ適用運用の一環として稼働率維持と障害低減に寄与します。

- **ダウンタイム**: DB インスタンスの再起動やファイル更新が発生するため、ダウンタイムや接続切断が必要になる場合があります。メンテナンスウィンドウや事前通知を計画してください。

- **コスト**: CU の適用自体に追加料金は発生しませんが、スナップショット保存やアップグレードに伴う一時的なリソース利用（テスト環境等）によりストレージや実行コストが増える可能性があります。

## [ECS] Amazon ECS now provides real-time deployment observability in the AWS Management Console

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: ECS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-ecs-console-deployment-observability/

### 概要

Amazon ECS コンソールにリアルタイムのデプロイ可観測性が追加され、ネイティブな Linear、Canary、Blue/Green デプロイにおいてデプロイの進行、ヘルス、障害診断をコンソール上で一元的に確認できるようになりました。

### 変更内容・新機能の詳細

コンソール上で「ライブデプロイメントタイムライン」が提供され、各デプロイフェーズ、サービスイベント、タスクの起動・終了状況をリアルタイムで表示します。デプロイの進行に合わせてソースとターゲットリビジョン間のトラフィックシフト分布や現在のライフサイクル段階（グリーンタスクのスケールアップ、ライフサイクルフック待ち、ベイク時間など）を一目で確認できます。デプロイヘルス関連のシグナル（デプロイメントのサーキットブレーカー状態、タスク失敗のライブトラッキングとしきい値、アラーム状態、コンテナ／ロードバランサーのヘルスチェック、ライフサイクルフックの状態）もタイムラインに統合されます。障害発生時は失敗したタスクがタイムライン上で診断コンテキストと共に表示され、CloudTrail 等へのディープリンクから原因追跡が可能です。これらの機能は追加料金なしで全ての商用リージョンおよび AWS GovCloud (US) で利用可能で、ECS コンソールの対象サービスの Deployments タブから開始できます。なお対象は Amazon ECS のネイティブな Linear、Canary、Blue/Green デプロイタイプであり、CodeDeploy 等の別経路で行うデプロイは本機能の対象外となる可能性があります。裏側では CloudWatch メトリクス／アラーム、ELB ターゲットヘルス、CloudTrail イベントなど既存の監視・ログ情報を集約して表示しています。

### 影響範囲・利用シーン

- **対象ユーザー**: コンテナ運用者、SRE、DevOps エンジニア、プラットフォームチーム
- **利用シーン**: デプロイ進行の可視化（ロールアウト監視）、カナリア/ブルーグリーンのトラフィックシフト確認、デプロイ失敗時の初動調査と根本原因切り分け
- **運用効果**: ツール間の往来を減らしてデプロイ監視・トラブルシュートの時間を短縮、デプロイ失敗の早期検出と迅速な復旧が可能
- **対象デプロイ種別**: Amazon ECS ネイティブ Linear、Canary、Blue/Green デプロイに対応

### 技術的な注意点

- **IAM権限**: コンソールで情報を表示するには ECS の読み取り権限 (例: ecs:DescribeServices, ecs:ListTasks, ecs:DescribeTasks) と CloudWatch (GetMetricData 等)、ELB/ALB の参照権限 (elasticloadbalancing:DescribeTargetHealth 等)、CloudTrail の参照権限が必要となる点を事前に確認してください
- **リージョン制限**: 全ての商用リージョンおよび AWS GovCloud (US) で提供。中国リージョン（北京/寧夏）等は記事に明記がないため未対応の可能性があります
- **コスト**: コンソール機能自体に追加課金はありません。ただし、基盤となる CloudWatch メトリクス/Logs、CloudTrail、ELB の利用に伴う通常の課金は発生する可能性があります
- **対応デプロイ**: Amazon ECS ネイティブの Linear、Canary、Blue/Green のみ対象。CodeDeploy を経由するブルー/グリーン等の別実装は対象外の可能性があります
- **関連サービス**: 検出・診断は CloudWatch、CloudTrail、Elastic Load Balancing（ターゲットグループのヘルス）等のデータに依存します。これらの設定（アラームやヘルスチェック）が適切であることを確認してください
- **利用開始方法**: Amazon ECS コンソールで任意のサービスを開き、Deployments タブを選択してください

## [General] Amazon EVS now in scope for FedRAMP Class C

- **公開日**: 2026-09-22 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-evs-fedramp-class-c/

### 概要

Amazon Elastic VMware Service (EVS) が米国の全リージョンで FedRAMP Class C（旧 Moderate ベースライン）の対象になりました。これにより、FedRAMP 準拠が求められる中堅レベルの連邦ワークロードを EVS 上で運用しやすくなります。

### 変更内容・新機能の詳細

Amazon EVS は AWS 上の VPC 内で EC2 ベアメタルインスタンス上に VMware Cloud Foundation (VCF) を直接展開できるマネージドサービスです。数時間で完全な VCF 環境を構築でき、既存のオンプレミス VMware ワークロードを迅速に移行して老朽化インフラの撤去やデータセンター退出のスケジュール短縮が可能です。今回の更新で EVS は FedRAMP Class C（従来の Moderate 相当）のスコープに入り、米国リージョン（全 United States Regions）で FedRAMP に基づくセキュリティ評価・認可・継続的モニタリングの対象となります。注意点として、FedRAMP 認可はサービス提供側のセキュリティコントロールが対象であり、顧客側で管理するコンポーネント（OS レベル設定、アプリケーション、データの分類や暗号化鍵管理など）は引き続き顧客責任（Shared Responsibility）です。また、連邦機関としてのシステム承認（ATO: Authority to Operate）は顧客側が自組織の要件に基づき手続きする必要があります。

### 影響範囲・利用シーン

- **対象ユーザー**: 連邦政府機関、政府系請負業者、FedRAMP 準拠が必要なエンタープライズ組織
- **利用シーン**: 既存の VMware ワークロード（vSphere/VCF）を AWS に移行して FedRAMP Moderate 相当の環境で運用するケース
- **運用効果**: データセンター退出・リホストの短縮、運用リスク低減、FedRAMP 対応による政府関連案件の受注可能性向上

### 技術的な注意点

- **IAM権限**: EVS や EC2 ベアメタルの操作に必要な IAM 権限を適切に付与・管理してください
- **リージョン制限**: FedRAMP Class C の適用は「All United States Regions」としているため、米国外リージョンや特別な GovCloud/Secret リージョンの対応状況は別途確認が必要です
- **共有責任**: FedRAMP 認可は AWS/サービス側のコントロールが対象で、顧客側の設定・アプリケーション・データ保護は顧客責任です（顧客は ATO 取得プロセスを実行する必要があります）
- **コスト**: EVS は EC2 ベアメタルなど高コストなリソースを利用するため、インスタンス稼働・ライセンス（VMware ライセンスの取り扱い）・ネットワーク転送コストを含めた費用見積を行ってください
- **ログ/監査**: FedRAMP 要件を満たすために CloudTrail、CloudWatch、VPC Flow Logs 等の監査ログ収集と長期保存ポリシーの整備を推奨します

- https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-evs-fedramp-class-c/
