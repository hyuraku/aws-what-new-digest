## [Transcribe] Amazon Transcribe adds customer-managed KMS keys for custom resources

- **公開日**: 2026-09-26 (JST)
- **カテゴリ**: Transcribe
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-transcribe/

### 概要

Amazon Transcribeは、カスタム語彙（custom vocabularies）、カスタム語彙フィルター（custom vocabulary filters）、カスタム言語モデル（custom language models）を、ユーザーが所有・管理する対称のAWS KMSカスタマーマネージドキー（CMK）で保存時に暗号化できる機能を追加しました。既定では従来どおりAWS管理キーが使われますが、作成・更新時に独自のKMSキーを指定して鍵管理と監査を強化できます。

### 変更内容・新機能の詳細

対象リソースはカスタム語彙、カスタム語彙フィルター、カスタム言語モデルで、これらを作成（または更新）する際に対称のAWS KMSキー（CMK）を指定できます。指定しない場合は従来どおりAWSが所有するキーで暗号化されます。カスタマーマネージドキーを利用することで、誰がそのキーで暗号化／復号できるかをキーポリシーやIAMで細かく制御でき、CloudTrailによりキーの使用はすべてログ記録されます。キーを無効化したり、別のキーへリソースを移行してアクセスを計画的に取り消すことも可能です。機能はAmazon Transcribeが提供されているすべてのリージョンで利用可能です。運用面では、KMSキーのポリシーにTranscribeサービス（通常はtranscribe.amazonaws.com）および利用するIAMロール／プリンシパルのアクセス許可を付与する必要があります。

### 影響範囲・利用シーン

- **対象ユーザー**: 音声認識の開発者、機械学習エンジニア、セキュリティ／コンプライアンス担当者
- **利用シーン**: 規制準拠（PII保護、業界規制）、監査証跡の強化、キーのライフサイクル管理（無効化やローテーション）を必要とするワークロード
- **運用効果**: 鍵アクセスを自社で制御・撤回できるため、意図しないアクセスの排除やコンプライアンス要件への対応が容易になる
- **コスト影響**: KMSの使用料金（API呼び出しやキー保持費用）が発生する可能性があるため、暗号化操作の頻度に応じたコスト検討が必要

### 技術的な注意点

- **IAM権限**: Transcribeに対してKMSキーでのEncrypt/Decrypt/GenerateDataKeyなどを許可するキーポリシー／IAM許可が必要です。サービスプリンシパル（通常はtranscribe.amazonaws.com）への許可付与を忘れないでください。
- **キー種類**: 指定できるのは対称CMK（対称暗号キー）。非対称キーはサポートされません。
- **リージョン制限**: Transcribeが提供されているすべてのリージョンで利用可能ですが、KMSキーはリージョン単位のリソースのため、リソースと同一リージョンのキーを使用するかマルチリージョンCMKの設計を検討してください。
- **コスト**: AWS KMSのAPI呼び出しおよびキー管理に対する料金が発生する可能性があります。大量にキーを使用する運用ではコスト見積りが必要です。
- **操作（API/CLI/コンソール）**: カスタムリソースの作成／更新API（またはコンソール）でKMSキーID/ARNを指定するパラメータが追加されています。既存リソースは更新APIでキーを指定して移行できます。
- **監査/ログ**: KMSキーの使用はCloudTrailに記録され、キー利用の完全な監査証跡が取得できます。
- **キー管理注意点**: キーを無効化すると復号ができなくなるため、無効化や削除は運用影響を考慮して行ってください。キーを別のキーに切り替える際は、リソース側での更新手順を実施してください。

### 参考情報

- https://docs.aws.amazon.com/transcribe/latest/dg/

## [Ec2] Amazon EC2 M8i and M8i-flex instances are now available in additional regions

- **カテゴリ**: Ec2
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-ec2-m8i-m8i-flex-thf/

### 概要

Amazon EC2のM8iおよびM8i-flexインスタンスが、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。カスタムIntel Xeon 6プロセッサ採用により、従来のIntelベース世代比でメモリ帯域や価格性能が向上しています。

### 変更内容・新機能の詳細

M8iおよびM8i-flexはAWS専用のカスタムIntel Xeon 6プロセッサを搭載した汎用インスタンスファミリーです。前世代のIntelベースインスタンスに対して最大で15%の価格性能向上、メモリ帯域は最大2.5倍を実現します。M7i/M7i-flex比では最大で20%の総合性能向上が見込まれ、ワークロードによってはさらに大きな差が出ます。具体的なワークロード例では、PostgreSQLが最大30%高速化、NGINX系Webアプリが最大60%高速化、AIのディープラーニング推薦モデルで最大40%向上しています。M8i-flexは一般的なサイズ（large〜16xlarge）を対象にしており、Webサーバ、アプリケーションサーバ、マイクロサービス、中小規模データストア、仮想デスクトップ、エンタープライズアプリといった一般用途でコストパフォーマンスを得やすい設計です。M8iは全般的な汎用ワークロード向けで、継続的な高CPU利用や最大サイズ（新たに追加された96xlargeを含む）を必要とするアプリケーションに適しています。M8iはSAP認定済みで、13サイズ（うち2つはベアメタル）を提供します。導入はAWSマネジメントコンソールから行えます。利用前にはリージョンごとのサイズ提供状況や料金を確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド/インフラエンジニア、SRE、アプリケーション開発者、データベース管理者
- **利用シーン**: Web/アプリサーバ、マイクロサービス、小中規模データストア、仮想デスクトップ、SAPなどの企業アプリケーション、AI推論/推薦モデルの高速化
- **運用効果**: 同等スペックでのコスト削減（価格性能向上）や、既存インスタンスからのリプレースによる処理時間短縮・スループット向上が期待できる

### 技術的な注意点

- **IAM権限**: インスタンス起動には標準のEC2起動権限（ec2:RunInstances等）が必要です。適切なIAMロール/ポリシーを事前に確認してください。
- **リージョン制限**: 今回はAWS European Sovereign Cloud (Germany) リージョンでの利用開始。すべてのリージョンで即時利用可能なわけではないため、他リージョンでの可用性は確認が必要です。
- **サイズと可用性**: M8i-flexはlarge〜16xlargeの一般的サイズを提供。M8iは13サイズ（うち2つがベアメタル）で新たに96xlargeを追加。リージョン／AZごとに提供サイズが異なる場合があります。
- **コスト**: 宣伝値では価格性能が最大15%向上とありますが、実際の料金はリージョン・インスタンスタイプ・購入オプション（オンデマンド、リザーブド、Savings Plans等）によるため、移行前に料金比較とコスト試算を行ってください。
- **互換性／OS**: x86_64（Intel）ベースのため、既存のIntel最適化AMIやソフトウェアとの互換性が高いです。ベアメタルを利用する場合はドライバやライセンス要件を確認してください。
- **SAP／認定**: M8iはSAP認定済み。SAP環境での導入を検討する際はSAPの要件とAWSの認定情報を参照してください。
- **検証**: ワークロード特有の性能差があるため、本番移行前にベンチマーク（アプリケーションプロファイリング、DB負荷試験等）で性能とコスト効果を検証してください。

## [Identity And Access Management] AWS IAM outbound identity federation now supports interface VPC endpoints for OIDC discovery

- **公開日**: 2026-09-26 (JST)
- **カテゴリ**: Identity And Access Management
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/aws-sts-vpc-oidc/

### 概要

AWS IAM の outbound identity federation が OIDC の discovery API（メタデータと JWKS）へ VPC 内からアクセスできるように、AWS PrivateLink（インターフェイス VPC エンドポイント）をサポートしました。これにより検証キー取得トラフィックをパブリックインターネット経由させずに済みます。

### 変更内容・新機能の詳細

これまで IAM の outbound identity federation で発行した短期 JWT を外部サービスが検証する際、検証に必要な OIDC discovery metadata と JSON Web Key Set (JWKS) はパブリックインターネット経由でのみ取得可能でした。本アップデートにより、これら OIDC discovery エンドポイントに対してインターフェイス VPC エンドポイント（AWS PrivateLink）を作成し、VPC 内からプライベートに到達できるようになりました。結果として、VPC にインターネットアクセスが制限されているワークロードでも、外部サービスが必要とするメタデータ／公開鍵を同一 AWS ネットワーク内で取得でき、JWT 検証が可能になります。機能は全ての商用リージョン、AWS GovCloud (US)、中国リージョンで利用可能で、追加料金は標準の AWS PrivateLink 料金のみ適用されます。動作上は既存の JWT 発行・検証のフローに影響はなく、取得経路がパブリックネットワークから PrivateLink 経路へ置き換わる形です。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドセキュリティ要件が厳しい組織、VPC 内で動作するアプリケーションやマイクロサービス、SRE/運用チーム
- **利用シーン**: インターネット接続を制限した VPC から外部サービスへ発行する JWT の検証鍵や OIDC メタデータを取得する必要がある場合（例: 外部 IDP による署名検証、サードパーティ API 連携）
- **運用効果**: 検証キー取得を AWS ネットワーク内に閉じることでネットワークセキュリティ要件（アウトバウンド制限、監査要件）を満たしやすくなり、コンプライアンス対応やリスク低減が可能

### 技術的な注意点

- **IAM権限**: VPC エンドポイント作成には EC2 の権限（例: ec2:CreateVpcEndpoint、ec2:ModifyVpcEndpoint 等）が必要です。IAM/STS の設定や outbound federation の操作には該当する IAM 権限を確認してください。
- **リージョン制限**: 全ての商用リージョン、AWS GovCloud (US)、中国リージョンで利用可能と発表されています（リージョン限定の例外が出た場合は公式ドキュメントで確認してください）。
- **コスト**: 本機能自体に追加料金はなく、インターフェイス VPC エンドポイント利用に関しては標準の AWS PrivateLink（エンドポイント時間料金とデータ処理料金）が発生します。コスト影響を見積もってください。
- **ネットワーク設定**: インターフェイス VPC エンドポイント作成時にプライベート DNS の有効化、適切なセキュリティグループ設定、サブネットの ENI 配置を確認してください。プライベート DNS を有効化すると既存の OIDC ホスト名をエンドポイントへ解決できます。
- **運用上の注意**: TLS 証明書検証や JWKS のキャッシュポリシー等、JWT 検証ロジックは従来通り必要です。PrivateLink 経路へ切り替えても JWT の署名／検証ロジック自体に変更はありません。
- **スケーリングと制限**: VPC エンドポイント数や ENI、セキュリティグループの接続数制限に注意してください。大量のトラフィックが発生する場合は PrivateLink のスループットやコストを考慮してください。

### 概要

AWS DataSyncコンソールにアカウント全体のタスク実行状況を一元的に可視化するモニタリングダッシュボードが追加されました。複数実行のステータス、転送レート、期間、転送済みデータ/ファイル数などをフィルタ・集約して確認できます。

### 変更内容・新機能の詳細

新しいDataSyncダッシュボードは、各タスク実行（Task execution）ごとにステータス、データ転送レート・ファイル転送レート、実行時間、転送済みの合計データ量とファイル数を表示します。実行はステータス、タスク、タスクモード（例: 一回実行/スケジュール実行）、実行ID、開始時間でフィルタ可能で、フィルタ結果をタスク単位で集約した成功／失敗回数や累積転送量・ファイル数のサマリを確認できます。失敗した実行を選択するとエラー詳細（トラブルシューティング用）を参照できます。ダッシュボードにはアカウントに構成済みのタスク数、ロケーション数、エージェント数のカウントや、リアルタイムの総転送レートも表示されます。これにより、従来は各実行を個別に確認するかカスタムCloudWatchダッシュボードを作る必要があったところを、単一画面で並列実行の健康状態、性能、進捗を監視できるようになります。大規模マイグレーションや多数の定期転送が同時に走る運用で特に有用です。ダッシュボード利用に追加料金はなく、DataSyncが利用可能な全ての商用リージョンおよびAWS GovCloud (US)で提供されます。

### 影響範囲・利用シーン

- **対象ユーザー**: DataSyncを使ってオンプレ→クラウド、クラウド間、クラウド→オンプレの大量転送や定期転送を運用するクラウドエンジニア／SRE／データ移行チーム
- **利用シーン**: 大規模データ移行の進捗把握、複数タスクが並列で動作するバッチ転送の性能監視、失敗した実行の原因特定と復旧作業
- **運用効果**: 単一画面で実行状況の一覧・集計・エラー確認ができるためトラブル対応時間が短縮され、並列転送の監視工数が削減される
- **コスト影響**: ダッシュボード自体に追加料金は発生しないが、長期のメトリクス保管やアラート運用をCloudWatchに移す場合はCloudWatchの料金が発生する可能性がある
- **スケーリング/規模**: 多数のタスク・実行を横断して集約表示が可能なため、マイグレーションや定期転送が大量にある環境で有益

### 技術的な注意点

- **IAM権限**: DataSyncコンソールとダッシュボード表示には適切なDataSync関連API権限が必要（例: datasync:ListTasks, datasync:ListTaskExecutions, datasync:DescribeTaskExecution, datasync:ListLocations, datasync:ListAgents）。既存の管理者ロールやコンソール閲覧ロールで権限を確認してください
- **リージョン制限**: DataSyncが提供されている商用AWSリージョンおよびAWS GovCloud (US)で利用可能。未対応のリージョンでは表示されません
- **コスト**: ダッシュボード表示自体は追加費用なし。CloudWatchによるメトリクス長期保存やカスタムダッシュボード／アラームを併用する場合はCloudWatchの料金が発生します
- **ログ/履歴保持**: 記事ではダッシュボードの実行履歴の保持期間は明示されていません。長期履歴やアラート要件がある場合はCloudWatch Logs/メトリクスやS3へのログ保存などを併用してください
- **既存の監視との併用**: DataSyncは引き続きCloudWatchにメトリクスを出力するため、現在の監視・アラート設定は継続利用可能です。ダッシュボードは運用監視の可視化に有用ですが、アラート自動化や長期集計はCloudWatchが適しています
