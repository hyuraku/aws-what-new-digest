## [Bedrock] Amazon Bedrock Managed Agents, powered by OpenAI, is now available in preview

- **公開日**: 2026-09-30 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-managed-agents-preview/

### 概要

Amazon Bedrock Managed Agents (BMA) は、AWS と OpenAI が共同開発した、OpenAI の Agents API を AWS ネイティブにカスタマイズしたプレビュー機能です。AWS 内で動作するエージェントを簡単に構築・管理し、既存の IAM、ガバナンス、監査機能と統合できます。

### 変更内容・新機能の詳細

BMA は OpenAI の Agents API を基に、モデルの状態管理（セッションの永続化）、ツール選択と利用、コード実行、複数ステップのワークフローの調整などを AWS ネイティブで実現します。各エージェントは専用の IAM ロールで動作し、重要なアクションの前に人間の承認を挟む制御が可能です。セッションはメッセージ、ツール呼び出し、中間結果を保持するため、途中で中断して後で再開できます。再利用可能なスキル（特定手順のモジュール化）を追加でき、外部ツールや Model Context Protocol (MCP) サーバー経由での接続にも対応します。サポートされる API 活動は AWS CloudTrail に記録されます。プレビュー中は BMA 自体の追加料金は発生せず、エージェントが消費する基盤となる AWS リソース（Bedrock モデル呼び出し、ストレージ、ネットワーク等）の料金が発生します。プレビュー提供リージョンは米国東部（バージニア北部、オハイオ）と米国西部（オレゴン）です。一般提供（GA）時には料金や対応リージョンが変更される可能性があります。

### 影響範囲・利用シーン

- **対象ユーザー**: ML/AI 開発者、SRE、プラットフォーム/インフラチーム、セキュリティ・ガバナンス担当者
- **利用シーン**: チャットボットや自動化ワークフローにおけるマルチステップの意思決定・ツール連携（例えば、ドキュメント検索→データ抽出→外部 API 呼び出し）
- **運用効果**: IAM と CloudTrail による監査・アクセス制御を維持しつつ、耐久的セッションと再利用可能スキルで運用・メンテナンスが容易になり、人的介入ポイント（承認）を挟むことでリスク管理が可能

### 技術的な注意点

- **IAM権限**: 各エージェントは専用の IAM ロールで動作するため、エージェント作成・実行に必要な権限（Bedrock 関連、役割の割当、必要に応じて外部ツールアクセス権）を事前に設計してください
- **リージョン制限**: プレビューは米国東部（バージニア北部）、米国西部（オレゴン）、米国東部（オハイオ）のみ対応。GA 時にリージョン展開が拡大される可能性あり
- **コスト**: プレビュー期間中は BMA 自体の追加料金は課されませんが、Bedrock モデル呼び出し、ストレージ、ネットワーク、関連する compute リソース等の従量課金は発生します。GA 時に価格体系が変更される可能性があります
- **データ保護・コンプライアンス**: 記載では "AWS 内で実行" とありますが、機密データの取り扱い・モデルへの送信ポリシー、ログ保管ポリシーについては Bedrock のドキュメントと組織のコンプライアンスポリシーを確認してください
- **ロギングと監査**: サポートされた API 活動は CloudTrail に記録されますが、すべての内訳（セッション内容、ツールコールの詳細等）が自動的に記録されるかはドキュメントで確認が必要です
- **プレビュー制限**: プレビュー版の API 仕様や機能は変更される可能性があり、SLA やサポート範囲が GA 時と異なる場合があります
- **サービス統合**: MCP サーバーや外部ツール連携が可能ですが、接続先の認証方式やネットワーク設定（VPC エンドポイント、セキュリティグループ等）を事前に設計する必要があります

## [RDS] Amazon RDS now adds full snapshot size information to the Console and API

- **公開日**: 2026-09-30 (JST)
- **カテゴリ**: RDS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-rds-full-snapshot-size-available/

### 概要

Amazon RDSがスナップショットの「フルスナップショットサイズ」をコンソールとAPIで表示可能になりました。DescribeDBSnapshotsの新フィールド 'FullSnapshotSizeInBytes' とコンソールの「Full Snapshot Size」列で確認できます。

### 変更内容・新機能の詳細

Amazon RDSのスナップショットは増分方式で動作しますが、本機能は各スナップショットを構成する全てのブロック（そのスナップショットに直接格納されたブロックと、過去スナップショットから参照されるブロックの合計）の合計サイズを返します。APIではDescribeDBSnapshotsレスポンスに新しいフィールド 'FullSnapshotSizeInBytes'（バイト単位）が追加されており、コンソールには「Full Snapshot Size」列が表示されます。例えば、データ50 GBを持つ100 GBのボリュームであれば、最初のスナップショットでも後続のスナップショットでもフルサイズは50 GBと表示されます（これは“そのスナップショットを構成する論理的な総容量”であり、そのスナップショット単体に新規格納された増分データサイズとは異なります）。本機能は全ての商用AWSリージョンのAmazon RDSで利用可能で、RDS Management Console、AWS CLI、AWS SDKを通じて本日から利用開始できます。なお、このフィールドは情報提供目的の値であり、スナップショットの課金は実際に保存されているユニークブロックに基づく（増分ストレージ）ため、表示値がそのまま請求額を意味するわけではありません。運用上は容量計画、リストア時間見積もり、コンプライアンス用の監査レポート等に役立ちます。

### 影響範囲・利用シーン

- **対象ユーザー**: データベース管理者、クラウド／バックアップ運用チーム、SRE
- **利用シーン**: スナップショット容量の可視化（容量計画、リストア時間見積もり、バックアップ方針の策定）、監査・レポート作成
- **運用効果**: スナップショットごとの実効データ量を把握できるため、保管戦略の最適化や復旧試算の精度向上が期待できる

### 技術的な注意点

- **IAM権限**: DescribeDBSnapshotsを呼び出せるrds:DescribeDBSnapshots等の権限が必要です
- **リージョン制限**: 全ての商用AWSリージョンで利用可能とされています（パブリックAWSリージョンに適用）
- **コスト**: 本フィールドの利用自体に追加料金は発生しません。スナップショットの課金は実際に保存されているユニークブロックに基づくため、'FullSnapshotSizeInBytes'はあくまで論理サイズの指標です
- **API/CLI**: DescribeDBSnapshotsのレスポンスに'FullSnapshotSizeInBytes'（バイト）を確認できます。AWS CLIやSDKで同フィールドを参照してください
- **注意点**: 'FullSnapshotSizeInBytes'は増分（そのスナップショットに新たに格納されたバイト数）とは異なる値です。増分サイズが必要な場合は別途計測が必要になる可能性があります

### 概要

OpenAIのGPT-6.1 SolがAmazon Bedrockで一般提供（GA）になりました。GPT-6 Solの強化版で、エージェント型コーディングや複雑なマルチステップワークフローに向けた高い性能を低コストで提供します。

### 変更内容・新機能の詳細

GPT-6.1 SolはGPT-6 Solのアップグレード版で、エージェント的なコード生成・デバッグ、コンピュータ操作の自動化、プロフェッショナルな作業（複雑なコードベースの調査や多段階の推論フロー）で非常に高い性能を発揮します。OpenAIの公表によれば、より高性能とされるGPT-6 Astraに近い評価結果を示しつつ、コストはおおむね5分の1程度となる可能性があるとされています。Amazon Bedrock上では、Bedrockの推論エンジンが低レイテンシと信頼性、セキュリティ制御を提供し、コンソールやサポートされるAPIを通じて利用可能です。主な技術的特徴として、明示的なプロンプトキャッシュ（explicit prompt caching）をサポートし、エージェントが繰り返し同じコンテキストを使うワークロードで効率化・コスト削減が期待できます。加えて、AWSのアクセス制御や監査メカニズムを使ってモデル呼び出しのガバナンスやログ記録が行えます。利用前には対応リージョン、エンドポイント、インフェレンスプロファイル（性能とコストのトレードオフ定義）、API仕様、価格を公式ドキュメントで確認してください。

- **利用シーン**: エージェント型の自動化（コーディング支援、デバッグエージェント）、複雑なマルチステップワークフロー、コードベース解析やリファクタリング補助、反復的なコンテキスト再利用が必要な自動化ワークロード
- **運用効果**: 推論コストの削減（OpenAIが示す同等級モデル比で低コスト）、プロダクション運用に耐える低レイテンシ／高信頼な推論基盤、プロンプトキャッシュによるリクエスト重複の低減とスループット向上

### 技術的な注意点

## [Connect] Amazon Connect Customer now lets business users manage more reference data to adjust contact center configurations in real time

- **公開日**: 2026-09-30 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-connect-manage-data-tables/

### 概要

Amazon Connect Customer のデータテーブル機能が拡張され、1テーブルあたり最大20,000件の参照データを保持できるようになりました。ビジネスユーザーがExcelやDynamoDBなど外部ソースからデータを取り込み、テーブルのエクスポート・一括編集・インスタンス間移動を行うことで、コンタクトセンター設定をリアルタイムで柔軟に調整できます。

### 変更内容・新機能の詳細

今回のアップデートでは、Amazon Connect Customer の管理者がコンタクトフローの動作を制御する参照データ（営業時間、エスカレーションルール、AI応答プロンプト、キュー割当てなど）を、データテーブルとしてより大きな容量・柔軟性で管理できるようになりました。主な機能は以下の通りです。
- テーブル容量: 1テーブルあたり最大20,000件の値を保持可能。大規模なルールセットや多数のキュー割当てを管理できます。
- データ入出力: テーブルのエクスポートが可能で、Excel等で編集して再インポートしたり、DynamoDBなど外部システムからデータをロードできます。これにより非エンジニアのビジネス担当者でもデータ更新が容易です。
- 一括編集: 数百レコード単位での編集をサポートし、手動編集の手間を削減します。
- インスタンス間移動: データテーブルを別の Connect Customer インスタンスへ移動可能で、複数環境（開発／検証／本番）間で設定を共有しやすくなっています。
- 運用性: 管理者やビジネスチームが自身で参照データを更新し、条件変化に応じてコンタクトセンターの挙動をリアルタイムに調整できます。
この機能は Amazon Connect Customer が提供されているすべての AWS 商用リージョンおよび AWS GovCloud (US-West) リージョンで利用可能です。詳細は管理者ガイドの「Create and configure data tables」を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンター管理者、コンタクトセンターのビジネス担当者、SRE/運用担当者
- **利用シーン**: 営業時間やエスカレーションルールの即時更新、AIエージェントの応答プロンプト更新、キュー割当ての動的変更、複数環境間での設定移行
- **運用効果**: ビジネス側で参照データを直接更新可能になり、開発者への依存を減らして応答性を向上。運用負荷の軽減と迅速な設定変更によるサービス品質向上が期待される

### 技術的な注意点

- **IAM権限**: データテーブルの作成・更新・エクスポート・インポート・移動には適切な Amazon Connect 管理権限が必要です。管理者ロールやポリシーを事前に確認してください。
- **リージョン制限**: Amazon Connect Customer が提供されている全ての AWS 商用リージョンおよび AWS GovCloud (US-West) で利用可能ですが、利用前に対象リージョンでの提供状況を確認してください。
- **データ制限/クォータ**: 1テーブルあたり最大20,000件の値という上限があります。その他のクォータ（テーブル数、同時API呼び出しなど）は管理者ガイドやサービスクォータを確認してください。
- **インポート/エクスポート**: ExcelやDynamoDBなどからのロードが可能ですが、取り込み時のフォーマットや型整合性に注意してください。大量データは分割して処理すると安定します。
- **コスト**: データテーブル自体の機能利用に直接の追加料金は明示されていない場合が多いですが、外部ストレージ（DynamoDB）利用やデータ転送、API呼び出し頻度に応じた課金影響が発生する可能性があります。コスト見積りを行ってください。
- **運用注意**: 参照データの変更はコンタクトフロー挙動に即時影響するため、変更運用（検証、ロールバック手順、バックアップ/エクスポート）を設計しておくことを推奨します。
- **自動化**: 大量更新や定期同期は AWS CLI / SDK を用いた自動化が可能ですが、使用する API のレート制限やエラーハンドリングを組み込んでください。

## [Workspaces] Amazon WorkSpaces Applications introduces unified graphics images

- **公開日**: 2026-09-30 (JST)
- **カテゴリ**: Workspaces
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-workspaces-applications-unified-graphics-images/

### 概要

Amazon WorkSpaces Applicationsが“unified graphics images”を発表しました。これによりG4dn、G5、G6、G7など複数世代のGPU対応インスタンスで単一のイメージを共通利用でき、イメージ管理と世代移行が簡素化されます。

### 変更内容・新機能の詳細

従来は各GPU世代ごとに専用のグラフィックスイメージが必要でしたが、unified graphics imagesは複数のサポートされたグラフィックスインスタンスファミリー（G4dn、G5、G6、G7）にまたがって動作する単一イメージタイプです。コンソールでフリート作成時に互換性のあるインスタンスタイプ一覧が表示され、価格と性能に応じて選択できます。既存フリートもコンソールまたはUpdateFleet APIを使って、同一ファミリー内に限られていた変更から、サポートされる別ファミリーへのインスタンスタイプ変更が可能になりました。利用開始は既存のグラフィックスイメージをManaged Image Updateでアップグレードするか、unified base imageからイメージビルダーを起動して行います。unified graphics imagesはAmazon WorkSpaces ApplicationsのグラフィックスインスタンスがサポートされるすべてのAWS商用リージョンおよびAWS GovCloud (US)で利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: 仮想デスクトップ環境でGPUを利用するエンタープライズユーザー、VDI運用チーム、アプリケーション配布担当者
- **利用シーン**: マルチ世代GPUへ段階的に移行するワークロード（レンダリング、CAD、機械学習推論、GPUアクセラレーテッドアプリの配布）
- **運用効果**: イメージ数と管理負荷の削減、GPU世代切替時の運用作業軽減、フリート更新の柔軟性向上
- **コスト**: インスタンスタイプを柔軟に選べるため価格最適化が可能。ただし高性能GPUへ切替えるとコストは増加
- **リージョン**: Amazon WorkSpaces ApplicationsのグラフィックスインスタンスがサポートされるすべてのAWS商用リージョンおよびAWS GovCloud (US)で利用可能
- **運用リスク/注意**: 異なるGPU世代間でドライバやランタイムの互換性問題が発生する可能性があるため、切替前にアプリケーションの動作検証が必要

### 技術的な注意点

- **IAM権限**: UpdateFleetやWorkSpaces Applicationsのイメージ管理、イメージビルダー、Managed Image Updateを実行するための適切なIAM権限が必要です（例: workspaces-applications:UpdateFleet, workspaces-applications:CreateImageBuilder, workspaces-applications:StartManagedImageUpdate等）
- **リージョン制限**: すべての商用リージョンおよびAWS GovCloud (US)でサポートされますが、各リージョンでWorkSpaces Applicationsのグラフィックスインスタンスが利用可能か確認してください
- **ドライバ/ランタイム**: 統一イメージでもGPUドライバ（NVIDIAドライバ、CUDAなど）やランタイムのバージョン互換性を確認・管理する必要があります。アプリケーション固有のGPU最適化設定は世代間で挙動が変わる可能性があります
- **移行手順**: 既存イメージはManaged Image Updateでアップグレード、またはunified base imageからイメージビルダーを起動して新規イメージを作成してからフリートへ適用してください。フリートのインスタンスタイプ変更はコンソールまたはUpdateFleet APIで実施できます
- **可用性とテスト**: インスタンスタイプ変更は性能や互換性に影響するためステージング環境での検証を推奨します。変更によりユーザーワークスペースの再起動や再プロビジョニングが必要になる可能性があります

- **IAM権限**: AWS Transform実行、S3等へのインベントリアップロードや読み取りに必要な権限を事前に付与してください
- **リージョン制限**: AWS Transformが提供されているリージョンで利用可。特定リージョンでの可用性は事前に確認してください
- **コスト**: AWS Transformの利用や、検証用に作成するMSKインスタンス／データ転送には課金が発生する可能性があります。TCO試算は見積りであり実コストと差異が出る場合があります
- **データとセキュリティ**: アップロードするインベントリには構成・認証情報のメタデータが含まれる可能性があるため、機密情報の取り扱い方針を遵守してください
- **入力フォーマット**: インベントリファイルはAWS Transformがサポートするフォーマットに従ってください。フォーマット詳細はドキュメントを参照してください
- **精度と検証**: エージェントが提供する互換性チェックやサイズ推奨は推奨値です。最終的な設計・パフォーマンス評価はステージング環境での検証を推奨します
- **MSK Express注意**: MSK Expressは低レイテンシ/短保持のユースケース向けの選択肢です。スループットや保持要件によっては標準MSKが適切な場合があります
