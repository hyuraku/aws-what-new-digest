## [Cognito] Amazon Cognito now supports OAuth 2.0 token exchange

- **公開日**: 2026-11-13 (JST)
- **カテゴリ**: Cognito
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/

### 概要

Amazon CognitoがOAuth 2.0のトークン交換（RFC 8693）に対応しました。ユーザーのトークンを、特定の下流サービス向けに権限を絞ったトークンへ交換でき、ユーザーに代わって動作するサービスやAIエージェントの認可を扱いやすくなります。

### 変更内容・新機能の詳細

サービスやAIエージェントがユーザーに代わって別のサービスを呼び出す際、従来は元のユーザートークンを転送するか、独自のトークン発行機構を構築・運用する必要がありました。今回の機能では、OAuth 2.0トークン交換を使って、元のトークンより狭いスコープを持ち、単一のaudience（利用対象）に限定された新しいトークンを発行できます。交換後のトークンにはリフレッシュトークンは含まれません。中継するサービスやエージェントのトークン（actor token）を指定すると、Cognitoは交換後のトークンにactクレームを追加し、誰がユーザーに代わって処理したかを下流サービスが識別できるようにします。たとえば、MCPサーバーがユーザーのトークンをバックエンドAPI専用のトークンに交換し、actクレームでMCPサーバーを中継者として記録できます。トークン交換は、OAuthトークンエンドポイントまたは新しいGetDerivedToken APIから利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Cognitoを利用するアプリケーション開発者、API・マイクロサービスの設計者、AIエージェントやMCPサーバーの開発者
- **利用シーン**: ユーザーの認証情報を使って、エージェントや中継サービスが特定のバックエンドAPIを呼び出す場合
- **セキュリティ効果**: 元のユーザートークンを複数のサービスへ転送せず、利用先と権限を限定したトークンを渡せます
- **監査効果**: actクレームにより、ユーザー本人の直接操作と、サービスやエージェントがユーザーに代わって行った操作を区別しやすくなります

### 技術的な注意点

- **対応プラン**: EssentialsおよびPlusの機能プランで利用できます
- **リージョン**: Amazon Cognitoが利用可能なすべてのAWSリージョンで提供されます
- **トークンの性質**: 交換後のトークンは単一のaudience向けで、元のトークンより狭いスコープを設定できます。リフレッシュトークンは含まれません
- **下流サービスの検証**: 下流サービスではトークンの署名に加え、audience、scope、必要に応じてactクレームを検証してください
- **コスト**: 利用にはEssentialsまたはPlusの機能プランが必要です。料金への影響は利用プランと契約条件を確認してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/
- https://docs.aws.amazon.com/cognito/latest/developerguide/token-exchange.html

## [General] Amazon Aurora and RDS now support Graviton5-based R9g database instances

- **公開日**: 2026-11-13 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-rds-postgresql-mysql-mariadb-r9g-instances/

### 概要

Amazon Aurora（PostgreSQL互換・MySQL互換）とAmazon RDS（PostgreSQL、MySQL、MariaDB）で、AWS Graviton5搭載のR9gデータベースインスタンスが一般提供されました。Graviton4搭載の同等サイズのAuroraインスタンスと比べ、最大30%の性能向上、オンデマンド料金で最大22%の価格性能向上が見込まれます。

### 変更内容・新機能の詳細

R9gインスタンスはAWS Nitro System上に構築され、largeから48xlargeまでの9サイズを提供します。最大192 vCPU、vCPUあたり8:1のメモリ比、最大100 Gbpsのネットワーク帯域幅、最大72 GbpsのAmazon EBS帯域幅を備えています。性能・価格性能の向上幅は、データベースエンジン、バージョン、ワークロードによって異なります。Amazon RDSコンソールまたはAWS CLIから利用を開始できます。

### 影響範囲・利用シーン

- **対象ユーザー**: Aurora PostgreSQL互換・MySQL互換、およびRDS for PostgreSQL、MySQL、MariaDBを利用するユーザー
- **利用シーン**: メモリやCPU性能が重要なデータベースワークロードの性能向上、または既存インスタンスからの移行検討
- **運用効果**: 同等サイズのGraviton4搭載Auroraインスタンスとの比較で、条件により最大30%の性能向上と最大22%の価格性能向上が期待できます

### 技術的な注意点

- **リージョン制限**: 記事公開時点では米国東部（バージニア北部、オハイオ）、米国西部（オレゴン）、欧州（フランクフルト）で利用できます
- **エンジンバージョン**: 対応する具体的なエンジンバージョンはAuroraおよびRDSの公式ドキュメントで確認してください
- **性能特性**: 性能向上率はエンジン、バージョン、ワークロードに依存し、すべての環境で最大値が得られるとは限りません
- **コスト**: インスタンスサイズや稼働時間に応じて料金が発生します。価格性能の比較はオンデマンド料金を対象としたAuroraのGraviton4同等サイズとの比較です。最新料金は各料金ページで確認してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-rds-postgresql-mysql-mariadb-r9g-instances/
- https://aws.amazon.com/rds/aurora/pricing/
- https://aws.amazon.com/rds/pricing/
- https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Concepts.DBInstanceClass.Types.html

## [Mwaa] Amazon MWAA now supports fine-grained access control with IAM Identity Center and multi-team environments

- **公開日**: 2026-11-13 (JST)
- **カテゴリ**: Mwaa
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/mwaa-fine-grained-access-control/

### 概要

Amazon MWAA に、IAM Identity Center を使ったきめ細かなアクセス制御と、複数チームで環境を共有する機能が追加されました。ユーザーごと・チームごとに、Apache Airflow UI で参照・操作できるワークフローやリソースを制御できます。

### 変更内容・新機能の詳細

IAM Identity Center との連携により、ユーザーは企業の ID プロバイダーを使って Apache Airflow UI にサインインできます。アクセス許可はリクエストごとに評価され、IAM Identity Center の Permission Set に関連付けた IAM ポリシーで制御します。ポリシーの条件キーを使い、DAG、接続、変数、プールなどのリソース種別、操作、個別のリソース ID に応じて権限を限定できます。

マルチチーム環境では、複数のチームが単一の MWAA 環境を共有します。チームごとに Amazon S3 内の専用 DAG フォルダを使用し、ユーザーには共有 DAG と、IAM Identity Center のグループ所属に基づく自チームの DAG が表示されます。インフラストラクチャや環境設定を共有することで、チームごとに環境を用意する場合と比べてコストや管理作業を抑えられます。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon MWAA の管理者、複数チームで Airflow を利用するデータエンジニアや運用チーム
- **利用シーン**: DAG や接続などへのアクセスをチーム・ユーザー単位で分離しつつ、共通の MWAA 環境を利用
- **運用効果**: 環境設定を一元管理し、共有インフラストラクチャによるコスト削減が期待できます

### 技術的な注意点

- **認証と認可**: IAM Identity Center と企業の ID プロバイダーを連携し、Permission Set に関連付けた IAM ポリシーでリクエスト単位の認可を設定します
- **権限設計**: 条件キーを使ってリソース種別、操作、リソース ID ごとにアクセス範囲を制限してください
- **チーム分離**: チームごとの S3 DAG フォルダと IAM Identity Center グループの対応関係を適切に管理してください
- **プレビュー**: マルチチーム環境は Apache Airflow のマルチチーム機能に基づくプレビュー機能です。本番利用前に制約や変更可能性を確認してください
- **リージョン**: Amazon MWAA が提供されているすべての AWS リージョンで利用できます
- **コスト**: 共有環境によりコストを抑えられる可能性があります。実際の料金は環境構成や利用状況に応じて確認してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/mwaa-fine-grained-access-control/

## [Connect] Amazon Connect Customer supports merging and linking related cases in the agent workspace

- **公開日**: 2026-11-13 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-cases-merge-link/

### 概要

Amazon Connect Customerのエージェントワークスペースで、関連するケースを統合または相互にリンクできるようになりました。問い合わせ履歴をまとめたり、複数の顧客に関係する問題への対応を連携したりできます。

### 変更内容・新機能の詳細

同じ顧客から同じ問題について複数のチャネルなどを通じて問い合わせがあり、ケースが分かれている場合、エージェントはそれらを1つのケースにマージできます。マージ後は、関連する問い合わせ履歴をまとめて確認できます。一方、リンク機能ではケース自体は統合せず、たとえば同じ障害の影響を受けた別々の顧客のケースを関連付けられます。これにより、顧客ごとの対応を維持しながら、状況把握や回答方針の調整をしやすくなります。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Connect Casesを利用するコンタクトセンターのエージェント、管理者
- **利用シーン**: 同一顧客による複数チャネルの問い合わせを統合し、履歴を一元的に確認する
- **利用シーン**: 複数の顧客に影響する共通の問題について、各顧客のケースをリンクして対応を連携する
- **運用効果**: 問い合わせの重複や分散を減らし、顧客への回答の一貫性と対応効率の向上が期待できる

### 技術的な注意点

- **前提条件**: Amazon Connect Casesを利用できる環境が必要です
- **リージョン制限**: 利用可能リージョンは米国東部（バージニア北部）、米国西部（オレゴン）、カナダ（中部）、欧州（フランクフルト、ロンドン）、アジアパシフィック（ソウル、シンガポール、シドニー、東京）、アフリカ（ケープタウン）です
- **機能の違い**: マージはケースを1つに統合しますが、リンクはケースを個別に保ったまま関連付けます
- **コスト**: 記事に料金変更の記載はありません。利用料金はAmazon Connectの料金情報を確認してください

### 参考情報

- https://aws.amazon.com/connect/cases/
- https://docs.aws.amazon.com/connect/latest/adminguide/cases.html
- https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-cases-merge-link/

## [Govcloud Us] Amazon SNS now supports push notifications in four additional AWS Regions

- **公開日**: 2026-11-13 (JST)
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-sns-push-four-regions/

### 概要

Amazon SNSでプッシュ通知を送信できるリージョンに、アジアパシフィック（ハイデラバード、メルボルン）、欧州（チューリッヒ）、AWS GovCloud（米国東部）が追加されました。各リージョンから、対応する主要なモバイルプッシュ通知サービスへ配信できます。

### 変更内容・新機能の詳細

Amazon SNSは、複数のエンドポイントにメッセージを配信するマネージド型のPub/Subサービスです。今回の追加により、上記4リージョンから、Amazon Device Messaging（ADM）、Apple Push Notification Service（APNs）、Baidu Cloud Push、Firebase Cloud Messaging（FCM）、Windows Push Notification Services（WNS）へのプッシュ通知送信が可能になりました。Lambda、SQS、Data Firehose、HTTP、SMS、メールなどへの配信機能も引き続き利用できます。プッシュ通知の送信に対応する全リージョンは、Amazon SNS開発者ガイドで確認できます。

### 影響範囲・利用シーン

- **対象ユーザー**: 追加された4リージョンでモバイルアプリの通知を配信する開発者、AWS運用チーム
- **利用シーン**: SNSを利用して、APNsやFCMなどを通じたアプリの通知をリージョン内から送信
- **運用効果**: 対象リージョンでプッシュ通知を利用でき、リージョン要件に合わせたアプリ基盤の構築や通知配信が可能

### 技術的な注意点

- **リージョン**: 対象はアジアパシフィック（ハイデラバード、メルボルン）、欧州（チューリッヒ）、AWS GovCloud（米国東部）です
- **対応サービス**: ADM、APNs、Baidu Cloud Push、FCM、WNSが対象です。利用するプッシュ通知サービスの対応状況や設定要件も確認してください
- **設定**: SNSでプラットフォームアプリケーションやエンドポイントを設定し、各通知サービスの認証情報を登録する必要があります
- **コスト**: SNSの利用料金が適用されます。詳細はAmazon SNS料金ページで確認してください
