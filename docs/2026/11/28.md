## [Timestream] Amazon Timestream for InfluxDB 3 now supports heterogeneous clusters

- **公開日**: 2026-11-28 (JST)
- **カテゴリ**: Timestream
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/influxdb-heterogeneous-cluster/

### 概要

Amazon Timestream for InfluxDB 3 Enterpriseで、Writer、Reader、Compactorの各ノードロールに異なるインスタンスサイズを割り当てられるようになりました。ロールごとの負荷に合わせたサイズ調整ができ、クラスター全体を一律に拡大する必要がなくなります。

### 変更内容・新機能の詳細

クラスター作成時、または既存クラスターへのノード追加時に、Writer、Reader、Compactorそれぞれのインスタンスサイズを個別に指定できます。設定はAmazon Timestreamコンソール、AWS CLI、AWS SDKから行えます。たとえば、クエリキャッシュや複雑なクエリへの対応を重視してReaderを大きくしつつ、Writerは小さく保つことができます。また、バックグラウンドでファイルをマージするCompactorに多くのvCPUを割り当て、他のロールのサイズは変えない構成も可能です。機能の追加料金はなく、各ノードに選択したサイズの標準料金が適用されます。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon Timestream for InfluxDB 3 Enterpriseを利用するデータベース管理者、SRE、クラウド運用チーム
- **利用シーン**: Writer、Reader、Compactorの負荷や性能要件が異なる時系列データベースクラスターの構成
- **運用効果**: 必要なロールだけを個別にスケールでき、クラスター全体を拡大する場合に生じていた過剰なリソース確保を抑えやすくなります
- **コスト影響**: 機能自体の追加料金はありません。各ノードの選択サイズに応じた標準料金が発生します

### 技術的な注意点

- **対象クラスター**: InfluxDB 3 Enterpriseクラスターが対象です
- **設定方法**: クラスター作成時または既存クラスターへのノード追加時に、ロールごとのインスタンスサイズを指定します。コンソール、AWS CLI、AWS SDKを利用できます
- **リージョン制限**: Amazon Timestream for InfluxDBが提供されているすべてのAWSリージョンで利用できます
- **料金**: 追加料金はありませんが、各ノードのインスタンスサイズに基づく通常料金が適用されます

- https://aws.amazon.com/timestream/influxdb/
- https://aws.amazon.com/timestream/influxdb/pricing/

## [General] Amazon CloudWatch announces basic OpenTelemetry enrichment at no additional cost

- **公開日**: 2026-11-28 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/

### 概要

Amazon CloudWatch は、AWS サービスメトリクスを PromQL で扱える OpenTelemetry データポイントに変換する「Basic enrichment」を追加料金なしで提供します。CloudWatch Omni では既定で有効になり、他のアカウントでもコンソール、AWS CLI、AWS SDK から有効化できます。

### 変更内容・新機能の詳細

Basic enrichment は、Amazon EC2 の CPUUtilization（InstanceId ディメンション付き）のように、リソースを識別できる AWS サービスメトリクスを対象とします。変換後のデータポイントには、リソースの ARN、クラウドプロバイダー、リージョン、アカウント ID がリソース属性として付与され、メトリクスを発行した AWS サービス名が instrumentation scope に設定されます。元の CloudWatch ディメンションはデータポイント属性として保持され、PromQL でクエリできます。AWS リソースタグを PromQL のラベルとして利用したい場合は、別途 Resource tag enrichment を選択します。Basic enrichment を利用しても、元の AWS サービスメトリクスは既存の CloudWatch API から引き続き利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: CloudWatch の AWS サービスメトリクスを OpenTelemetry 形式や PromQL で扱いたい、監視・運用担当者およびプラットフォームエンジニア
- **利用シーン**: AWS リソースの識別情報を使って、CloudWatch のサービスメトリクスを PromQL で検索・分析する
- **運用効果**: OpenTelemetry ベースの監視基盤や CloudWatch Omni から AWS サービスメトリクスを利用しやすくなり、メトリクスの相関分析を簡素化できる

### 技術的な注意点

- **料金**: Basic enrichment は追加料金なしです。リソースタグを PromQL ラベルとして利用する Resource tag enrichment は、OTel Vended Metric Enrichment として課金されます
- **リージョン制限**: CloudWatch OpenTelemetry メトリクスがサポートされている AWS リージョンで利用できます
- **有効化**: CloudWatch Omni では既定で有効です。それ以外のアカウントでは CloudWatch コンソール、AWS CLI、AWS SDK から有効化できます
- **互換性**: 既存の CloudWatch API でのメトリクス利用は継続できます。enrichment の設定レベルはいつでも切り替え可能です
- **対象メトリクス**: リソースを識別できる AWS サービスメトリクスが対象です

### 参考情報

- https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-OTel-vended-metrics.html
- https://aws.amazon.com/cloudwatch/pricing/

## [Neptune] Amazon Neptune introduces Neptune Graph Sessions, smaller graphs designed for agents that scale to zero and resume automatically

- **公開日**: 2026-11-28 (JST)
- **カテゴリ**: Neptune
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-neptune-graph-sessions-generally-available

### 概要

Amazon Neptune Analyticsに、エージェントやタスクごとの小規模なグラフを作成できる「Neptune Graph Sessions」が追加されました。使用メモリに応じて容量が調整され、15分間アイドル状態が続くと自動でゼロにスケールし、次のクエリ時には自動再開します。

### 変更内容・新機能の詳細

Graph Sessionsでは、グラフ作成時に開始サイズとして4 s-NCUまたは8 s-NCUを選択します。選択したサイズに対して最大2倍のメモリ余裕があり、4 s-NCUでは最大8 s-NCU、8 s-NCUでは最大16 s-NCUのメモリを利用できます。開始サイズを超える大きさのグラフも扱え、課金はグラフが実際に使用するメモリに基づきます。アイドル状態が15分続くと容量はゼロにスケールしますが、グラフとデータは保持されるため、再開時にデータを再ロードする必要はありません。グラフの作成にはAWS Management Console、AWS CLI、AWS SDKを利用でき、クエリは他のNeptune Analyticsグラフと同様にopenCypherで実行します。

### 影響範囲・利用シーン

- **対象ユーザー**: GraphRAGアシスタントやAIエージェントの開発者、ユーザー単位・タスク単位のグラフ分析を行うチーム
- **利用シーン**: 会話、ユーザー、エージェント、タスクごとに独立した小規模グラフを作成し、関連データを使った検索や分析を行う
- **運用効果**: 使用量に応じたメモリ容量で利用でき、アイドル時は自動でゼロにスケールするため、常時稼働するグラフのコストを抑えやすい

### 技術的な注意点

- **容量**: 作成時に4 s-NCUまたは8 s-NCUを選択します。利用可能なメモリはそれぞれ最大8 s-NCU、16 s-NCUです
- **課金**: 実際に使用するメモリに基づいて課金されます。料金はリージョンなどで異なる可能性があるため、利用前に料金ページを確認してください
- **アイドル時の動作**: 15分間アイドル状態が続くとゼロにスケールします。グラフとデータは保持され、次のクエリで数秒以内に再開します
- **クエリ言語**: グラフへのクエリにはopenCypherを使用します
- **リージョン**: 提供リージョンは元記事に記載されていないため、利用予定リージョンでの対応状況をAWS公式情報で確認してください
