## [Bedrock] Kimi K3.1 Pro (Highspeed) now available on Amazon Bedrock 

- **公開日**: 2026-11-07 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/moonshot-ai-kimi-k3-1-pro-on-amazon-bedrock

### 概要

Moonshot AIのKimi K3.1 Pro（Highspeed）がAmazon Bedrockで利用可能になりました。エージェント系ワークロード向けに高い出力トークン/秒（OTPS）を提供する、1百万トークンのコンテキストウィンドウを持つオープンウェイトのマルチモーダル大規模モデルです。

### 変更内容・新機能の詳細

Kimi K3.1 ProはMoonshot AIの最も高性能な3兆パラメータ級モデルをベースにした、ネイティブにマルチモーダルかつエージェント指向のオープンウェイトモデルです。Amazon Bedrock上では「Highspeed」実装が提供され、高いOTPSにより応答性の向上とスループット改善が見込めます。モデルは最大1,000,000トークンのコンテキストウィンドウをサポートし、コーディング、ドキュメント処理、3D生成、金融調査など長いコンテキストや複雑な推論が必要なエージェント系ユースケースでの利用を想定しています。Bedrock上で提供されるため、プロプライエタリモデルと同じセキュリティ境界内で動作し、明示的なプロンプトキャッシュ機能により入力トークンのコストとレイテンシを削減できます。リージョンについては、Amazon Bedrockが利用可能な全リージョンでクロスリージョン推論を通じて利用可能です。開始はAmazon BedrockコンソールまたはBedrockドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習エンジニア、アプリケーション開発者、データサイエンティスト、SRE/運用チーム
- **利用シーン**: 大規模コンテキストを必要とするコーディング支援、長文ドキュメント処理、マルチモーダル入力を伴うエージェント、3D生成や金融リサーチなどの探索的ワークロード
- **運用効果**: 高OTPSにより応答性とスループットが向上し、プロンプトキャッシュで入力トークンコストとレイテンシを削減可能
- **コスト影響**: 大規模モデルかつ長コンテキスト利用に伴い推論コストが増加する可能性（トークン課金やクロスリージョン通信コストを含む）
- **リージョン可用性**: Amazon Bedrockが提供される全リージョンでクロスリージョン推論を介して利用可能（ただしリージョン間のレイテンシと転送コストに注意）

### 技術的な注意点

- **IAM権限**: Bedrockのモデル呼び出し（例: bedrock:InvokeModel 等）や関連リソースアクセス権限を事前に確認・付与してください
- **リージョン制限**: Bedrockが提供されるリージョンでクロスリージョン推論経由で利用可能。クロスリージョン利用はレイテンシとデータ転送コストに影響します
- **コスト**: 大規模モデル・長コンテキスト利用は入力/出力トークン課金や高額な推論料金につながる可能性があります。プロンプトキャッシュを活用してコストを抑制してください
- **セキュリティ/ガバナンス**: Bedrockのセキュリティ境界内で動作しますが、オープンウェイトモデルのライセンスやデータ保持ポリシーを確認してください
- **パフォーマンス**: HighspeedバリアントはOTPS最適化がされている一方、標準モードや大規模推論ではレイテンシが増す可能性があります。ワークロードに応じてバリアント選定とベンチマークを実施してください
- **入力形式/互換性**: モデルはマルチモーダルをサポートします。画像や長文などの入力フォーマットやAPI仕様はBedrockドキュメントで確認してください
- **プロンプトキャッシュ**: 明示的なプロンプトキャッシュ機能をサポートします。キャッシュの有効期限や整合性、プライバシー（機密データのキャッシュ保存）を設計時に考慮してください
- **特権設定/ネットワーク**: VPCエンドポイントやプライベート接続を利用する場合は、Bedrockのネットワーク設定とエンドポイント要件を確認してください

## [Govcloud Us] Agent Registry is now generally available in AWS GovCloud (US-West) Region

- **公開日**: 2026-11-07 (JST)
- **カテゴリ**: Govcloud Us
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-agent-registry-govcloud-us-west/

### 概要

AWS Agent Registry（Amazon Bedrock AgentCore経由で提供）が AWS GovCloud (US-West) リージョンで一般提供開始されました。組織内のエージェント、ツール、MCPサーバー等を一元的にカタログ化・公開・検索できるマネージドな発見サービスです。

### 変更内容・新機能の詳細

Agent Registry はフルマネージドのディスカバリサービスで、MCP サーバー、ツール、エージェント、エージェントスキル、およびカスタムリソースを組織の中央カタログへ公開（publish）できます。公開アイテムは承認ワークフローによって可視化の可否を制御でき、ハイブリッド検索（キーワード検索とセマンティック検索の組み合わせを想定）やカタログブラウズ、ネイティブな MCP エンドポイントを通じて、人間あるいは AI エージェントが必要なツールやスキルを発見できます。AWS GovCloud (US-West) での提供により、パブリックセクター組織とそのパートナーは、ガバナンスされた単一のエージェント／ツール在庫を持てるようになり、承認ワークフローや AWS CloudTrail による監査ログでコンプライアンスや監督要件を満たす運用が可能です。Amazon Bedrock の AgentCore と連携して動作します。導入手順や設定は公式ドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 公共機関（政府機関）、防衛/法執行機関、これらのパートナー、セキュリティ・コンプライアンス担当者、SRE/プラットフォームエンジニア
- **利用シーンまたは効果**: 組織内で承認済みのエージェントやツールのみを検索・利用させることで、サプライチェーンや運用の安全性を担保（例: 機密ワークロード向けツールの一覧管理、AIエージェントが利用可能なスキルの統制）
- **運用効果**: 中央カタログ化により探索時間の短縮、重複ツールの削減、変更管理の一元化が可能
- **コンプライアンス/監査**: 承認ワークフローと CloudTrail の監査ログにより、誰が何を公開・承認したかのトレーサビリティを保持できる

### 技術的な注意点

- **IAM権限**: エントリの公開/承認/削除、MCP エンドポイントアクセスなど、細かい権限制御が必要です。導入前に必要な IAM ポリシーを確認してください。
- **リージョン制限**: 本リリースは AWS GovCloud (US-West) リージョンでの一般提供開始です。商用パーティション（通常リージョン）とは別の提供状況となるため、利用リージョンを確認してください。
- **コスト**: 公式記事では料金詳細に触れていません。Agent Registry 自体や Bedrock/AgentCore の利用に伴う課金が発生する可能性があるため、事前に料金ドキュメントを確認してください。
- **監査ログ**: CloudTrail によるログ出力を有効にすることで承認履歴や操作履歴を保持できます。監査要件に応じてログの保存期間やログ集約方法を設計してください。
- **Bedrock 依存**: Agent Registry は Amazon Bedrock AgentCore を通じて利用される機能を含むため、Bedrock の利用可否や設定（エンドポイント、認証等）を確認してください。
- **データ主権/コンプライアンス**: GovCloud は公的機関向けリージョンです。データ保護やコンプライアンス要件（例: 所有者/アクセス制御）に沿った設計を行ってください。

## [Msk] Amazon MSK Replicator is now available in AWS GovCloud (US-East, US-West) Regions

- **公開日**: 2026-11-07 (JST)
- **カテゴリ**: Msk
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-replicator-additional-aws-regions

### 概要

Amazon MSK ReplicatorがAWS GovCloud (US-East, US-West) リージョンで利用可能になりました。これにより、GovCloud内でAmazon MSKのクラスタ間および外部のApache KafkaクラスタからMSK Provisionedクラスタへのストリーミングデータの自動複製が可能になります。

### 変更内容・新機能の詳細

MSK ReplicatorはAmazon MSKの機能で、Kafkaクラスタ間のデータ複製を自動化します。今回の拡張で、AWS GovCloud (US‑East, US‑West) リージョンでも利用可能になり、オンプレミス、セルフマネージド（AWS上含む）、他のクラウドにあるKafkaクラスタからMSK Provisionedクラスタへのレプリケーションをサポートします。主な特徴は以下の通りです。
- 自動非同期レプリケーション: クロスクラスタ/クロスリージョンでの非同期複製を提供し、アプリケーションでカスタムレプリケーションコードやMirrorMakerなどの自前インフラを管理する必要をなくします。
- メタデータの複製: トピック設定、Kafka ACL、コンシューマグループのオフセットなど必要なメタデータを複製し、フェイルオーバー後に処理を継続しやすくします。
- 自動スケーリング: レプリケーションに必要な基盤リソースを自動でスケールするため、容量管理や手動スケールの負担を軽減します。
- フェイルオーバー対応: あるリージョンで障害が発生した場合、もう一方のGovCloudリージョンにフェイルオーバーして処理を再開できます。
- 利用手段: Amazon MSKコンソールまたはAWS CLIから設定・利用が可能です。
注: 公開情報では対象はMSK Provisionedクラスタと明示されており、Serverlessクラスタへの対応状況は確認が必要です。

### 影響範囲・利用シーン

- **対象ユーザー**: GovCloudを利用する公共機関や規制準拠が必要な企業、セキュアな環境でKafkaを運用するクラウドエンジニア/プラットフォームチーム
- **利用シーン**: クロスリージョン/クロスクラスタのレプリケーションによるディザスタリカバリ、リージョン冗長化、オンプレ→クラウド移行、分析用データ複製
- **運用効果**: レプリケーション基盤の構築・管理コストを削減し、フェイルオーバー時のダウンタイム短縮と業務継続性を向上
- **移行効果**: オンプレや他クラウドのKafkaからMSKへの段階的移行を容易にし、移行中のデータ整合性を保てる

### 技術的な注意点

- **IAM権限**: MSK Replicatorを操作するためのIAM権限（MSKおよび関連リソースの操作権限）を適切に付与してください。詳細はドキュメントの最低権限ポリシーを参照してください。
- **リージョン制限**: 本リリースはAWS GovCloud (US‑East, US‑West) の追加対応です。他リージョンでの対応状況は各リージョンのドキュメントで確認してください。
- **コスト**: MSK Replicatorの利用に伴う追加料金が発生します。加えて、クロスリージョン転送やプロビジョニングされたMSKブローカーのコスト、データ転送量に対する料金が別途発生します。価格ページを確認してください。
- **ネットワーク要件**: 外部Kafkaクラスタをソースとする場合は、接続経路（VPCピアリング、PrivateLink、VPN、Direct Connect、またはパブリックエンドポイント）と必要なファイアウォール設定を整備する必要があります。
- **認証・暗号化**: TLS/SASLなどのKafka認証方式や証明書、ACL設定の整合性を確認してください。レプリケータがACLやトピック設定を複製しますが、認証情報や証明書は別途適切に設定する必要があります。
- **互換性**: 対象は明示的にMSK Provisionedクラスタへの複製です。利用するKafkaバージョンやカスタムプラグインとの互換性については事前に確認してください。
- **運用上の注意**: コンシューマオフセットの複製はフェイルオーバーを容易にしますが、アプリケーション側での再バランスやトポロジー変更時の取り扱い方針（再処理の可否など）を設計しておくことを推奨します。

## [General] Amazon Redshift expands SUPER data type to store strings up to 16 million bytes

- **公開日**: 2026-11-07 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-redshift-expands-super-to-16-million-bytes/

### 概要

Amazon RedshiftのSUPERデータ型で、個々の文字列を最大16,000,000バイトまで格納できるようになりました。データベースパラメータでオプトインすると、JSON/Parquet/TEXT/CSVからの取り込みやELT処理で大きな文字列をそのまま取り込んでSQLで扱えます。

### 変更内容・新機能の詳細

従来、SUPERデータ型内の個々の文字列は65,535バイトに制限されていましたが、本アップデートにより最大16,000,000バイト（約16MB）の文字列を扱えるようになりました。適用にはデータベースパラメータでのオプトインが必要で、これによりCOPYや外部ファイル（JSON、Parquet、TEXT、CSV）からの取り込み時、あるいはELTプロセスでの変換時に大きな文字列を事前変換せずにSUPERカラムへ直接ロードできます。ロード後はPartiQLを使ってネスト構造を探索したり、JSON_PARSE、CONCAT、LISTAGGなどの文字列関数で最大16MBまでの入力/出力を扱えます。注意点として「16,000,000バイト」はバイト数であり、UTF-8などマルチバイト文字を含む場合は文字数はそれより少なくなります。また、この機能はAmazon Redshiftが利用可能な全リージョン（AWS GovCloud含む）で提供されます。具体的な有効化手順やパラメータ名、互換性については公式ドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、データサイエンティスト、BI/分析担当者、SRE/運用チーム
- **利用シーン**: 長文ドキュメント（契約書、利用規約、ログの大きなフィールド、JSONネスト内の大きな文字列）を事前変換せずにRedshiftへ取り込み、SQL/PartiQLで検索・集計・変換する場面
- **運用効果**: 事前処理（分割や外部ストア移動）の手間削減、ELTパイプラインの簡素化、取り込み速度と運用コスト削減（パイプラインの簡素化により開発・保守工数が減少）
- **制約/注意点**: 大きな文字列を扱うことでクエリ実行時のメモリ使用量やI/Oが増えるため、WLM設定やノードリソースの見直しが必要になる可能性がある

### 技術的な注意点

- **IAM権限**: 特別な権限変更は不要だが、パラメータの変更やテーブル定義変更を行う場合はDB管理者権限（ALTER SYSTEM/パラメータ変更の権限）が必要です
- **リージョン制限**: 発表では全リージョン（AWS GovCloud (US) 含む）対応とされています。利用前に現在のリージョンで有効化可能か公式Region表で確認してください
- **コスト**: 機能自体に追加料金は明記されていませんが、保存データ量の増加およびクエリ実行時のI/O/コンピュート増加によりストレージコストやクエリコストが上がる可能性があります
- **パラメータ/有効化**: データベースパラメータでオプトインが必要（記事ではパラメータ名が記載されていないため、実際のパラメータ名と手順は公式ドキュメントを参照してください）
- **互換性**: 既存アプリやETLツールが内部で想定する文字列長の上限に達すると影響が出る可能性あり。外部システム（クライアントドライバ、ODBC/JDBC、BIツール）が16MBの列を正しく処理できるか確認してください
- **パフォーマンス**: 大きな文字列を多量にスキャン/結合/集計するとメモリとネットワークI/Oのボトルネックになり得ます。WLMキュー設定、ノードタイプ、並列度の調整やサンプリング設計を検討してください
- **バイト/文字**: 上限はバイト数です。UTF-8等のマルチバイト文字を含む場合、最大文字数はバイト数制限で短くなる点に注意してください
- **関数制限**: JSON_PARSE、CONCAT、LISTAGGなど主要な関数は最大16MBの入力/出力をサポートしますが、すべての関数・演算子が同等の扱いをするとは限らないため、利用する関数での挙動を事前検証してください

## [General] AWS launches support for amortization of EC2 Capacity Blocks for ML

- **公開日**: 2026-11-07 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-ec2-capacity-blocks-ml/

### 概要

AWSは、EC2 Capacity Blocks for ML（機械学習向けの予約キャパシティ）の前払料金を予約期間にわたって按分（償却）して表示する機能を、Cost and Usage Report (CUR) 2.0 と Cost Explorer に追加しました。これによりインスタンス単位で償却費用や未使用容量の費用を把握できます。

### 変更内容・新機能の詳細

今回の更新で、Capacity Block の前払料金（upfront fee）が予約期間にわたって分割され、CUR 2.0 のデータ列と Cost Explorer の「amortized cost（償却コスト）」ビューで確認できるようになりました。具体的には、各インスタンスが Capacity Block に投入された期間に対応する償却費がインスタンス利用と並べて出力され、同時に実際に使用されなかった（未消化の）キャパシティに対応する償却費も把握できます。CUR 2.0 では reservation_amortized_upfront_fee_for_billing_period、reservation_effective_cost の列に償却費が出力され、割引後の償却費は reservation_net_effective_cost に反映されます。Cost Explorer では「amortized cost」表示を選択することで、予約に紐づく Capacity Block の費用配分を可視化できます。これにより、GPU 等のリザーブド・キャパシティ費用をチームやプロジェクトに正確に配賦したり、未使用率を見て将来の購入計画を最適化できます。該当機能は追加料金なしで利用可能ですが、AWS GovCloud (US) と中国リージョンでは未対応です。

### 影響範囲・利用シーン

- **対象ユーザー**: ML／AI チーム、クラウドコスト管理（FinOps）担当、SRE・運用チーム、IT購買担当
- **利用シーン**: EC2 Capacity Blocks for ML（GPU等の予約キャパシティ）のコスト配賦（チーム/プロジェクト単位の課金内訳）、未使用キャパシティの検出と将来の予約容量計画
- **運用効果**: 前払費用を予約期間にわたって按分することで実利用に基づく正確なコスト配賦が可能になり、無駄な予約購入の削減や費用の透明化（showback/chargeback）が実現する
- **意思決定支援**: 未使用分の割合を把握して将来の Capacity Block 購入量や期間を調整できる
- **レポーティング**: CUR 2.0 の新列と Cost Explorer の償却ビューを使って自動集計・レポート化が可能

### 技術的な注意点

- **IAM権限**: Cost Explorer のデータ閲覧には ce:GetCostAndUsage 等の Cost Explorer API 権限、CUR ファイルにアクセスする場合は S3 の読み取り権限（s3:GetObject 等）や CUR 関連の権限が必要です
- **リージョン制限**: すべての AWS リージョンで利用可能（注：AWS GovCloud (US) リージョンと中国リージョンは未対応）
- **コスト**: Capacity Block の償却表示自体に追加料金は発生しません。ただし、CUR を S3 に保存するコストや、保存した CUR を Athena や Glue で解析する場合のクエリ実行コスト等は別途発生します
- **CUR 列名/形式**: reservation_amortized_upfront_fee_for_billing_period、reservation_effective_cost、reservation_net_effective_cost の列が出力されます。reservation_net_effective_cost は割引適用後の償却コストを表します
- **表示方法**: Cost Explorer で「amortized cost（償却コスト）」ビューを選択すると Capacity Block の償却分が利用に割り当てられた形で表示されます
- **データ解釈の注意**: 償却は予約期間に均等配分される前提の表示です。実際の内部利用状況（例：特定インスタンスが途中で停止／再配置されたケース）を評価する際は、利用時間データと照合してください
