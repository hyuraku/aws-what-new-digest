## [VPC] Amazon EC2 and VPC now display related resources for all resource types

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: VPC
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/ec2-vpc-related-resources-all-types/

### 概要

Amazon EC2、Amazon VPC、及び AWS Global View のコンソールで、すべての EC2/VPC リソースタイプについて「Related Resources（関連リソース）」が表示されるようになりました。これにより、複数のコンソールページを行き来せずにリソース間の依存関係を把握できます。

### 変更内容・新機能の詳細

従来はセキュリティグループだけに限定されていた「Related Resources」ビューが拡張され、EC2 インスタンス、EBS ボリューム、Launch Template、Auto Scaling グループ、サブネット、ルートテーブル、ネットワーク ACL など、EC2/VPC に関わるほとんどのリソースタイプで関連リソースの一覧を確認できるようになりました。関連リソースタブはコンソールのツールバーに移動してアクセスしやすくなっています。コンソール上での表示は、対象リソースに対して内部的に Describe 系 API 呼び出しを行い、紐付くリソース（アタッチされた EBS、関連するセキュリティグループ、経路・サブネット情報、関連インスタンスや ASG など）を収集して表示します。これによりトラブルシューティング（例：インスタンスの起動失敗やネットワーク接続問題）やネットワーク構成レビュー、セキュリティ監査の際に参照すべきリソース関係を即座に確認できます。機能は商用のすべての AWS リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドエンジニア、ネットワーク管理者、SRE、セキュリティ/監査チーム
- **利用シーン**: インスタンス障害調査時に紐づく EBS/セキュリティグループ/サブネット/ルートテーブルを即時確認
- **運用効果**: コンソール間を移動する手間を削減し、依存関係の把握やトラブルシューティング時間を短縮
- **運用例（ネットワーク）**: サブネットから関連するルートテーブル、ネットワーク ACL、配置されているインスタンスをたどって構成レビューやセキュリティ監査を効率化

### 技術的な注意点

- **IAM権限**: 関連リソース表示には該当リソースを表示するための Describe/Read 権限が必要（例：ec2:DescribeInstances、ec2:DescribeVolumes、ec2:DescribeSecurityGroups、ec2:DescribeSubnets、ec2:DescribeRouteTables、autoscaling:DescribeAutoScalingGroups など）。不足すると関連リソースの一部が表示されない可能性があります
- **リージョン制限**: 商用（commercial）リージョンでは全て利用可能と公表されています。AWS GovCloud/中国リージョンなど商用以外のリージョンでは未適用の可能性があるため確認してください
- **コスト**: 追加料金は発生しませんが、コンソール表示は Describe 系 API 呼び出しを行うため API レート制限に注意してください。大量の一括確認を自動化すると API 制限に抵触する恐れがあります
- **API/CLI対応**: 今回の拡張はコンソールの表示機能に関するものであり、同等の「関連リソース一覧」を直接返す単一 API が提供されているとは限りません。自動化が必要な場合は個別の Describe API を組み合わせて実装してください

## [Datasync] AWS DataSync Enhanced mode supports OpenID Connect (OIDC) for Google Cloud and Microsoft Azure

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Datasync
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/datasync-enhanced-oidc-google-azure/

### 概要

AWS DataSync Enhanced modeがGoogle Cloud StorageおよびMicrosoft Azure Blob Storageに対するOpenID Connect (OIDC) 認証をサポートしました。これによりHMACキーやSASトークンなどの長期資格情報を使わずに、短期間の資格情報を自動取得・更新してクラウド間で安全にデータ転送できます。

### 変更内容・新機能の詳細

DataSync Enhanced modeはGoogle CloudおよびMicrosoft Entra IDのOIDCベース認証を利用して、対象ストレージ（Google Cloud Storage、Azure Blob Storage）へアクセスできるようになりました。DataSyncはAWS側で指定したIAMロールを用い、OIDCを通じてGoogleまたはEntra IDから短命のアクセス資格情報（アクセストークン等）を取得・自動更新します。これにより長期のHMACキーやSASトークンを配置・管理する必要がなくなり、企業のセキュリティポリシー（長期資格情報禁止等）に適合したクロスクラウドデータ転送が可能です。導入は、DataSyncロケーションにIAMロールを追加するだけで開始でき、AWS CLI / API / AWS CloudFormationから設定できます。本機能はDataSync Enhanced modeをサポートするすべてのAWSリージョンで利用可能です。なお、クラウド先側（GCP/Azure）でのOIDC受け入れ側設定（サービスアカウントやアプリ登録、必要なストレージアクセス権付与）は別途必要になります。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウド間で大容量データ移動を行うクラウドエンジニア、SRE、データプラットフォームチーム
- **利用シーン**: マルチクラウド移行・バックアップ、クラウド間レプリケーション、セキュリティ方針上長期資格情報が使えない環境でのデータ転送
- **運用効果**: 長期資格情報の管理・漏洩リスクを低減し、資格情報ローテーション運用を簡素化。転送中の資格情報切れをDataSyncが自動で解消するため、ジョブの中断を抑止できる

### 技術的な注意点

- **IAM権限**: DataSyncロケーション作成/更新とIAMロールの作成・委任設定を行うためのIAM権限が必要です（Least-privilegeを推奨）。
- **クラウド側設定**: Google CloudやMicrosoft Entra ID側でOIDC用のアプリ登録／サービスアカウント設定および対象ストレージへのアクセス権付与が必要です。具体的な手順は環境により異なるため、各クラウドのドキュメントを参照してください。
- **リージョン制限**: 本機能は「DataSync Enhanced mode」をサポートするAWSリージョンで利用可能です。すべてのリージョンで利用できるわけではないため、対象リージョンを事前確認してください。
- **コスト**: DataSyncの通常料金とネットワーク（データ転送/アウトバウンド）料金が発生します。OIDC自体に追加課金は基本的にありませんが、クラウド側でのAPI呼び出しや監査ログ保存に伴う費用は考慮してください。
- **既存認証との互換性**: 既存のHMAC/SAS等によるロケーションは引き続き使用可能で、段階的にOIDCへ移行できます。
- **セキュリティ**: IAMロールの権限は最小権限に抑え、OIDCトークンの信頼設定やロールの信頼ポリシーを適切に構成してください。

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/datasync-enhanced-oidc-google-azure/
- https://docs.aws.amazon.com/datasync/latest/userguide/

## [Simple Storage Service] Amazon S3 Tables now provide a simple, cost-effective path for data lake modernization

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Simple Storage Service
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-s3-tables-managed-migration-hive-to-iceberg/

### 概要

Amazon S3 TablesがApache HiveテーブルをApache Icebergへマネージドで移行できる機能を発表しました。これによりACIDトランザクションやスキーマ進化、タイムトラベルを持つIceberg形式へ短期間で安全に移行できます。

### 変更内容・新機能の詳細

S3 Tablesの管理された移行機能は、Glueに登録されたHiveテーブル（Parquet形式）を検証・変換・コピーしてクエリ実行可能なIcebergテーブルに変換します。移行中も既存の本番ワークロードは継続動作し、各ステップをレビューできるためリスクを低減できます。移行は同一AWSアカウントかつ同一リージョン内で実行され、ソースの変更を指定頻度で同期（incremental sync）したり、必要に応じてロールバックできます。Snappy圧縮のデータは起動時にZstandard（ZSTD）へ再圧縮・コンパクト化され、オブジェクト数とストレージ容量を削減し、クエリ性能が向上します。課金は「ジョブがコピーしたデータ量」に対してのみ発生し、Hive→Icebergの変換処理自体に追加料金はかかりません。移行はAWS管理コンソール、S3 Tablesの移行API、またAgent Toolkit for AWSの移行スキル（AIエージェント向けオーケストレーション）から開始できます。ローンチ時の対応条件はGlue登録済みのHiveテーブル、Parquet格納、同一アカウント・リージョンでの移行です。対応リージョンは（発表時点）：米国東部（バージニア北部、オハイオ）、米国西部（オレゴン）、アジア太平洋（ムンバイ、シンガポール、シドニー、東京）、欧州（フランクフルト、アイルランド、ストックホルム）です。

### 影響範囲・利用シーン

- **対象ユーザー**: データレイク運用者、データエンジニア、SRE/プラットフォームチーム
- **利用シーンまたは効果**: 既存のHive/Parquetベースのデータレイクを短期間でIcebergへ移行し、ACID・スキーマ進化・タイムトラベルなどIcebergの利点を得たいケース
- **運用効果**: 個別テーブルごとの移行パイプライン作成工数を削減し、移行中も本番クエリを継続可能。再圧縮とコンパクト化によりストレージ削減やクエリ性能改善が見込める
- **リスク低減**: 各移行ステップのレビュー、差分同期、ロールバック機能により移行リスクを抑制できる
- **コスト影響**: コピーしたデータ量に対するS3料金とPUT/GET等のリクエスト料金が発生。変換自体の手数料は不要だが、変換後データのストレージ費用が新たに発生する

### 技術的な注意点

- **対応フォーマット**: 現時点ではGlueに登録されたHiveテーブルかつParquetストレージのみ対応です
- **同一アカウント/リージョン**: ソースとデスティネーションは同一AWSアカウントかつ同一リージョン内でのみ移行可能です
- **リージョン制限**: 発表時対応リージョンはUS East (N. Virginia, Ohio), US West (Oregon), Asia Pacific (Mumbai, Singapore, Sydney, Tokyo), Europe (Frankfurt, Ireland, Stockholm)です。その他リージョンは順次対応される可能性があります
- **IAM権限**: Glueメタデータ参照（glue:GetTable等）、S3オブジェクトの読み取り・書き込み・一覧（s3:GetObject,s3:PutObject,s3:ListBucket等）、S3 Tables/API呼び出し権限が必要です。具体的な最小権限は公式ドキュメントで確認してください
- **コスト**: Hive→Iceberg変換処理の手数料はかかりませんが、ジョブがコピーするデータ量に対するS3のストレージ料金およびGET/PUT等のリクエスト料金が発生します。再圧縮によりストレージが減少する可能性がありますが、一時的にデスティネーション分のストレージが増える点に注意してください
- **圧縮変更**: Snappy圧縮のデータは自動でZSTDに再圧縮され、さらにファイルのコンパクト化が行われます。圧縮・コンパクト化によりオブジェクト数とクエリI/Oが減り性能向上が期待できますが、再圧縮処理中は追加のI/Oと一時ストレージが発生します
- **運用上の注意**: 移行前にテーブルのスキーマ、パーティション、データレイアウトを確認し、移行中の同期頻度やロールバック手順を設計してください
- **エージェント自動化**: Agent Toolkit for AWS向けの移行スキルが提供されており、AIエージェント経由でワークフローを自動化可能です。自動化する場合は実行権限と監査ログ設計を忘れずに設定してください

- https://aws.amazon.com/s3/tables/

## [Workspaces] RHEL 10, Rocky 10 and Ubuntu 26.04 Bundles for WorkSpaces

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Workspaces
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/rhel-10-rocky-10-ubuntu-26-04-workspaces/

### 概要

Amazon WorkSpacesで新たにRocky Linux 10、Red Hat Enterprise Linux 10、Ubuntu 26.04 LTSのLinuxバンドルが利用可能になりました。最新のエンタープライズ向けOSとWaylandベースの最新デスクトップ技術を利用できます。

### 変更内容・新機能の詳細

今回のアップデートで、WorkSpaces Personal向けにRocky Linux 10、RHEL 10、Ubuntu 26.04 LTSのマネージドバンドルが追加されました。これらは各ディストリビューションの最新パッケージや強化されたセキュリティ機能、長いサポートライフサイクルを提供します。デスクトップ表示はWaylandベースとなり、最新のLinuxデスクトップ機能（例えばモダンなレンダリングやセッション管理）を利用できます。バンドルはStandard、Performance、Power、PowerProの各サイズで提供され、Amazon WorkSpacesが利用可能なすべてのAWSリージョンで選択可能です。既存のWorkSpaces（Rocky 8/9、RHEL 8/9、Ubuntu 22.04/24.04等）は継続して利用でき、移行は管理者が新しいWorkSpaceを作成してユーザーを移すタイミングで行えます。新バンドルは新規作成時に選択することで利用開始できます。

### 影響範囲・利用シーン

- **対象ユーザー**: エンドユーザー向け仮想デスクトップを提供するIT管理者、VDI導入担当者、Linuxデスクトップを業務で利用する開発者/デザイナー
- **利用シーン**: 最新のOS依存パッケージが必要なアプリケーションの提供、Wayland対応アプリの利用、セキュリティ/サポート期限の長いプラットフォームへの切替
- **運用効果**: 新しいOSのセキュリティ更新や機能を即座に利用可能。段階的にユーザーを移行できるため業務への影響を抑えつつ最新環境へ移行できる
- **制限/留意点**: 既存WorkSpacesは自動で切替されないため移行計画（アプリ互換性テスト、イメージ検証）が必要

### 技術的な注意点

- **IAM権限**: 新しいWorkSpaceを作成・管理するためのWorkSpaces関連のIAM権限が必要です（作成、バンドル選択、ユーザー割当て等）
- **リージョン制限**: 記事の通り「Amazon WorkSpacesが利用可能なすべてのリージョン」で提供されていますが、利用前に対象リージョンでバンドルが表示されることを確認してください
- **コスト**: 新バンドルは選択するインスタンスタイプ（Standard/Performance/Power/PowerPro）に応じた通常のWorkSpaces利用料金が発生します。料金はリージョンや構成により異なるため料金ページで確認してください
- **互換性**: Waylandをデフォルトの表示サーバとして採用しているため、X11に依存する一部アプリケーションやドライバで挙動が変わる可能性があります。アプリケーションの動作検証を事前に行ってください
- **既存WorkSpacesへの影響**: 既存のWorkSpacesは自動的にアップグレードされません。ユーザー移行は新規WorkSpace作成→データ/設定移行の手順で実施する必要があります
- **サポートライフサイクル**: 各ディストリビューションのサポートポリシーに従います。長期サポート（LTS）版のUbuntuやRHELのサポート期間が利点になります

## [Connect] Amazon Connect Customer lets agents pause and resume emails

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/connect-pause-resume-email/

### 概要

Amazon Connect Customerのメール機能に、エージェントが情報待ちや承認待ちの間にメールを一時停止（pause）し、後で再開（resume）できる機能が追加されました。停止時間は稼働時間と分離して計測され、監督者はリアルタイムで確認・自動処理できます。

### 変更内容・新機能の詳細

エージェントはAgent WorkspaceまたはContact Control Panel (CCP) からメールを一時停止・再開できます。たとえば上長の承認待ちで処理を中断する場合にメールをpauseして、着信通話など高優先のコンタクトに応対できるようになります。pause中の時間は「アクティブな対応時間」とは別に記録されるため、スーパーバイザはエージェントが実際に対応に費やした時間と待ち時間を明確に把握できます。管理者はコンタクトフローを使って、一定閾値を超えてpauseされたメールを自動的に再開（resume）したり、別のエージェントやキューに転送するよう設定できます。機能は複数リージョン（US East (N. Virginia), US West (Oregon), Africa (Cape Town), Asia Pacific (Seoul), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (London)）で利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: コールセンターのエージェント、スーパーバイザ、コンタクトセンター運用/管理者
- **利用シーン**: 上長や外部チームの承認待ち、顧客の追加情報待ち、外部システムレスポンス待ちなどで一時的にメール処理を中断して他業務にリソースを振り向ける場面
- **運用効果**: エージェントのマルチタスクが容易になり高優先度のコンタクト対応が迅速化される。pause時間を分離して記録することで勤務評価やKPI（平均処理時間、稼働率、ハンドルタイム）の解釈が正確になる
- **監督/自動化効果**: スーパーバイザはリアルタイムでpause状況を把握でき、閾値超過時の自動再開や転送で放置メールの減少やSLA遵守が期待できる

### 技術的な注意点

- **IAM権限**: エージェント／スーパーバイザ用ロールにAgent Workspace/CCPでのメール操作（pause/resume）および該当コンタクトフローの実行・編集権限が必要です。管理者は既存のConnectポリシーで該当操作を許可してください
- **リージョン制限**: 利用可能リージョンは記事記載の10リージョン（US East (N. Virginia), US West (Oregon), Africa (Cape Town), Asia Pacific (Seoul), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Canada (Central), Europe (Frankfurt), Europe (London)）に限定されます。未対応リージョンでは利用不可です
- **コスト**: AWSからの明示的な追加料金の案内はありませんが、メールのpause/resumeによるContact Trace Recordsやログ・ストレージ増加、Contact Flowの追加処理に伴うLambda/API連携の使用料などが発生する可能性があります。自社の課金モデルで影響を確認してください
- **互換性/設定**: Agent WorkspaceやCCPのUI更新や、コンタクトフローの編集が必要です。自動再開/転送を行う場合は既存フローに閾値チェックと遷移を組み込んでください
- **観点(メトリクス)**: pause時間が別集計されるため、既存のレポート・ダッシュボード（平均処理時間、稼働率、SLA）を見直し、pause時間を含めるか除外するか方針を決める必要があります

## [Connect] Amazon Connect Customer prefills the email address for new threads started from cases

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-cases-email-addresses/

### 概要

Amazon Connect の Cases 機能で、ケースから新しいメールスレッドを開始する際に、リンクされた顧客プロファイルから顧客のメールアドレスを自動入力する機能が追加されました。エージェントの入力工数と手入力ミスを削減します。

### 変更内容・新機能の詳細

エージェントが Amazon Connect のケース（Cases）から新しいメールスレッドを作成する際、当該ケースに紐づく顧客プロファイルに登録されているメールアドレスを自動でプレフィル（事前入力）します。これにより、エージェントがメールアドレスを検索してコピーしたり手入力する必要がなくなり、送信先ミスのリスクが低減します。技術的には、Cases UI が顧客プロファイル（Customer Profiles）内の email フィールドを参照して自動入力を行う動作で、顧客プロファイルにメールアドレスが存在しない場合は手動入力が必要です。また、プロファイルに複数のメールアドレスがある設計や優先ルールがある場合は、管理者設定や UI の挙動に従って選択または提示されます（既存の設定に依存）。この機能は指定のリージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンターのエージェント、運用/サポートチーム、Amazon Connect 管理者
- **利用シーン**: ケース対応で新規メールスレッドを作成する際の宛先入力の自動化（問い合わせ返信、フォローアップ送信）
- **運用効果**: エージェントの作業時間短縮、メールアドレス入力ミスや誤送信の低減、対応スループット改善
- **導入効果**: 顧客体験の一貫性向上とオペレーションコスト削減（手作業による確認作業の削減）

### 技術的な注意点

- **IAM権限**: Cases と Customer Profiles（およびそれらに関連する Connect リソース）への読み取り権限が必要です。エージェントのロールに該当アクセス許可が割り当てられているか確認してください。
- **リージョン制限**: 本機能は以下リージョンで利用可能です：US East (N. Virginia), US West (Oregon), Canada (Central), Europe (Frankfurt), Europe (London), Asia Pacific (Seoul), Asia Pacific (Singapore), Asia Pacific (Sydney), Asia Pacific (Tokyo), Africa (Cape Town)。その他のリージョンでは未対応の可能性があります。
- **前提条件**: ケースと顧客プロファイルが紐づいていること、プロファイルに email フィールドが登録されていることが必要です。プロファイル側のデータ品質が自動入力の有効性に直結します。
- **コスト**: この記事に特化した追加料金の記載はありませんが、Amazon Connect（および Cases / Customer Profiles）利用に伴う通常の課金は発生します。詳細な課金は利用する機能とリージョンに依存します。
- **データ保護/コンプライアンス**: 顧客のメールアドレスを UI で自動表示するため、PII の取り扱いとアクセス制御を適切に設定してください。ロギングや監査要件も確認してください。

## [Config] AWS Config now supports 10 new resource types

- **公開日**: 2026-11-04 (JST)
- **カテゴリ**: Config
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-config-new-resource-types

### 概要

AWS Configが10個の新しいリソースタイプをサポートしました。これにより、ElastiCacheやQuickSightなどを含むより広範なAWSリソースの設定履歴・監査・検出・評価が可能になります。

### 変更内容・新機能の詳細

今回追加された10件のリソースタイプは、AWS Configの記録対象、Configルール、Configアグリゲーターで利用可能になりました。既に「すべてのリソースタイプの記録」を有効にしているアカウントでは、自動的にこれらの新規リソースの構成アイテム（Configuration Item）が収集されます。追加されたリソースタイプ一覧:
- AWS::Billing::BillingView
- AWS::MPA::IdentitySource
- AWS::Connect::HoursOfOperation
- AWS::Notifications::OrganizationalUnitAssociation
- AWS::ElastiCache::CacheCluster
- AWS::NotificationsContacts::EmailContact
- AWS::ElastiCache::ReplicationGroup
- AWS::Oam::Link
- AWS::MediaLive::SignalMap
- AWS::QuickSight::Agent

技術的には、これらのリソースについてConfigは構成スナップショットと差分（変更履歴）を収集し、リソースインベントリ、差分検出、ルール評価、アグリゲーション（複数アカウント/リージョンからの集約）で利用できるようになります。Configルールでこれらのリソースタイプを対象にした評価を作成したり、既存のカスタムルールでリソース識別子を参照して監査・評価を行えます。自動修復（Remediation）を組み合わせる場合は、その修復アクションが該当リソースをサポートしている必要があります。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティ/コンプライアンス担当者、クラウド運用（SRE/DevOps）チーム、監査・ガバナンス担当者
- **利用シーン**: リソースの検出・構成変更の追跡、コンプライアンスチェックの拡張、マルチアカウント/マルチリージョンの設定集約
- **運用効果**: 可視化範囲が拡大することで設定逸脱や設定変更の検出率が向上し、監査証跡や自動対応の適用範囲が広がる

### 技術的な注意点

- **IAM権限**: AWS Configのサービスロールに該当リソースの読み取り（Describe/Get/List 等）API呼び出し権限が必要。アグリゲーター利用時は集約先に対する追加権限が必要になる場合があります。
- **リージョン制限**: 記事の通り「リソースが利用可能な全リージョン」でサポート。ただし各リソースはサービスの提供リージョンに依存するため、リージョンごとのサービス提供状況を確認してください。
- **コスト**: AWS Configは記録されるリソースごとに課金されます。新たに記録対象となるリソースが増えると、記録アイテム数・スナップショット・履歴保持コストが増加する可能性があります（詳細はConfigの料金ページを確認）。
- **Config設定**: 「すべてのリソースタイプを記録」していない場合は、必要に応じて該当リソースタイプを個別に記録対象に追加してください。既に「すべて」を有効にしている場合は自動的に収集されます。
- **Configルール/自動修復**: これらのリソースを対象にしたルール評価は可能ですが、自動修復アクションを使う場合はそのアクションが対象リソースに対して実行可能か（サポート状況）を事前に確認してください。
