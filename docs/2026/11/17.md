## [ECR] Amazon ECR now replicates image deletions across regions and accounts

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: ECR
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/replication-deletes-amazon-ecr

### 概要

Amazon ECR は、レプリケーション元で行ったイメージの削除やタグの削除を、レプリケーション先のリージョン・アカウントにも反映できるようになりました。これにより、複数の保存先でイメージの状態を自動的にそろえられます。

### 変更内容・新機能の詳細

従来の ECR レプリケーションはイメージのコピーを行う一方、削除は保存先へ反映しませんでした。今回の機能では、レプリケーション元でイメージを削除した場合やタグを削除した場合、その操作がレプリケーションルールの各保存先にも伝播します。削除は直接実行した場合だけでなく、ライフサイクルポリシーによる削除も対象です。複製された削除は EventBridge イベントとして通知され、CloudTrail にも記録されます。利用を開始するには、ECR コンソールまたは AWS CLI でレプリケーション設定を更新します。

### 影響範囲・利用シーン

- **対象ユーザー**: 複数リージョン・複数アカウントで ECR を利用する開発チーム、プラットフォームチーム、運用担当者
- **利用シーン**: レプリケーション元で削除したイメージやタグを、各保存先のリポジトリにも反映する
- **運用効果**: 保存先ごとの手動削除や個別スクリプトを減らし、リポジトリ間の状態を一貫させやすくなる
- **監査・通知**: 複製された削除を EventBridge と CloudTrail で把握できる

### 技術的な注意点

- **設定**: 利用開始には ECR のレプリケーション設定をコンソールまたは AWS CLI で更新してください
- **削除の影響**: 元での削除が保存先にも伝播するため、削除前に保持要件やライフサイクルポリシーを確認してください
- **対象操作**: イメージの削除とタグの削除が対象で、ライフサイクルポリシーによる削除も含まれます
- **リージョン制限**: Amazon ECR が利用可能なすべての AWS リージョンで利用できます
- **コスト**: 削除のレプリケーションに追加料金はありません

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/replication-deletes-amazon-ecr
- https://docs.aws.amazon.com/AmazonECR/latest/userguide/replication.html

## [KMS] Amazon EBS now supports associating additional KMS keys with snapshots

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: KMS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/ebs-snapshots-associate-kms-keys/

### 概要

Amazon EBS スナップショットに、追加の AWS KMS キーを関連付けられるようになりました。既存データを再暗号化せずに、カスタマーマネージドキーを使ったスナップショット共有やコピーを行えるため、アカウント間のバックアップや災害復旧を簡素化できます。

### 変更内容・新機能の詳細

AWS マネージドキー（AMK）で暗号化された EBS スナップショットに、追加のカスタマーマネージドキー（CMK）を関連付けられます。追加した CMK を利用することで、スナップショットのデータを再暗号化する工程を挟まずに、別アカウントとの共有やコピーを進められます。従来必要だった再暗号化の作業を減らし、バックアップや災害復旧の運用を効率化できます。AWS マネジメントコンソール、AWS CLI、AWS SDK から利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: EBS スナップショットを管理するバックアップ管理者、災害復旧チーム、複数アカウントを運用するクラウド管理者
- **利用シーン**: AWS マネージドキーで暗号化されたスナップショットを、別アカウントへ共有・コピーする場合
- **運用効果**: スナップショットデータの再暗号化を省き、バックアップや災害復旧の手順と所要時間を削減できます

### 技術的な注意点

- **KMSキー**: 追加で関連付けるキーにはカスタマーマネージドキーを使用します。共有先アカウントから利用できるよう、KMS キーのポリシーや IAM 権限を適切に設定してください
- **リージョン対応**: 商用リージョン、中国リージョン、AWS GovCloud (US)、AWS European Sovereign Cloud (Germany)、AWS Local Zones、AWS Outposts が対象です。利用前に対象環境での対応状況を確認してください
- **コスト**: カスタマーマネージドキーの維持や KMS API リクエストに、料金が発生する場合があります

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/ebs-snapshots-associate-kms-keys/
- https://docs.aws.amazon.com/ebs/latest/userguide/ebs-encryption.html
- https://docs.aws.amazon.com/ebs/latest/userguide/ebs-modifying-snapshot-permissions.html

## [S3] Amazon S3 Vectors now supports hybrid search combining vector and full text for more relevant search results

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: S3
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/s3-vectors-hybrid-search/

### 概要

Amazon S3 Vectorsで、ベクトル類似検索と全文検索を1回のクエリで組み合わせるハイブリッド検索が利用可能になりました。意味的な関連性とキーワードの一致を統合して順位付けすることで、RAGや検索アプリケーションの検索精度向上を支援します。

### 変更内容・新機能の詳細

PutVectors APIでベクトルとともに検索対象のテキストをメタデータフィールドとして保存すると、S3 Vectorsがそのフィールドを自動的に全文検索用にインデックス化し、BM25で関連度を評価します。既定では多くの言語で利用できる言語非依存のテキストアナライザーを使用し、必要に応じて言語固有のアナライザーを選択できます。

検索時はQueryVectors APIにクエリテキストとクエリベクトルを同時に渡します。S3 Vectorsが全文検索とベクトル検索を実行し、Reciprocal Rank Fusion（RRF）で両方の順位を統合して、指定した上位K件を単一のランキングとして返します。全文検索とベクトル検索を個別に実行して独自の順位付けを行うことや、1回のクエリで複数のテキストフィールドを検索すること、既存データに対してその場で全文検索を有効化することも可能です。既存のS3 Vectors APIを利用し、記事によると、低頻度のクエリではサブ秒、頻繁なクエリではおおむね100ミリ秒以下のレイテンシーを実現します。

### 影響範囲・利用シーン

- **対象ユーザー**: RAGやエージェントメモリ、検索アプリケーションを構築・運用する開発者、データエンジニア
- **利用シーン**: 意味的な類似性に加え、製品名・識別子などの正確なキーワード一致も重視する検索
- **運用効果**: ベクトル検索と全文検索の結果を単一のランキングに統合し、どちらか一方だけの場合より関連性の高い検索結果を目指せます
- **コスト効果**: S3 Vectorsは代替のベクトルソリューションと比べ、ベクトルの保存・クエリにかかる総コストを最大90%削減できるとされています。実際の料金は利用状況と料金体系を確認してください

### 技術的な注意点

- **API**: データ登録にはPutVectors、ハイブリッド検索にはQueryVectorsを使用します。クエリテキストとクエリベクトルの両方が必要です
- **検索・順位付け**: 全文検索のBM25スコアとベクトル検索の順位はRRFで統合されます。独自の順位付けが必要な場合は、それぞれを個別に実行できます
- **インデックス**: 全文検索対象のテキストをメタデータフィールドとして保存します。既存データでも全文検索を有効化できます
- **言語対応**: 既定の言語非依存アナライザーに加え、より適切な言語別照合のために言語固有のアナライザーを選択できます
- **リージョン制限**: Amazon S3 Vectorsが提供されているすべての商用AWSリージョンおよびAWS中国リージョンで利用可能です。利用前に対象リージョンでの提供状況を確認してください
- **コスト**: S3 Vectorsの料金が適用されます。詳細はAmazon S3の料金ページを確認してください
- **レイテンシー**: 記事記載のレイテンシーは目安であり、実際の性能はデータやクエリ、利用状況に依存します

## [Redshift] Amazon Redshift now supports multi-statement transactions, conflict resolution, and time travel for Apache Iceberg

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Redshift
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/redshift-time-travel-multi-statement

### 概要

Amazon Redshift は Apache Iceberg テーブルに対し、複数ステートメントトランザクション、自動書き込み競合解決、Time Travel をサポートしました。これにより、複数段階の更新を原子的に実行しながら、同じテーブルへの並行書き込みや過去時点のデータ参照が可能になります。

### 変更内容・新機能の詳細

複数ステートメントトランザクションでは、複数の SQL 文を BEGIN…COMMIT でまとめ、変更を単一の Iceberg スナップショットとして公開できます。たとえば MERGE の後に DELETE を実行する処理を一括でコミットでき、途中状態がクエリから見えることを防ぎます。処理に失敗した場合はロールバックできます。
自動書き込み競合解決により、ストリーミングの INSERT と定期ジョブの DELETE など、複数の処理が同じテーブルへ並行して書き込めます。変更箇所が重ならない場合は、競合による失敗や手動リトライを避けてコミットできます。
Time Travel では AS OF TIMESTAMP を使い、テーブルの過去時点の状態をクエリできます。過去のレポートの再現、変更監査、不適切な書き込み後のデータ確認・復旧に活用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: Apache Iceberg テーブルに書き込むデータエンジニア、分析担当者、監査担当者、AI エージェントの開発者
- **利用シーン**: MERGE や DELETE など複数段階のバッチ処理を一括で適用し、ストリーミング処理とスケジュール処理を同じテーブルで並行実行
- **運用効果**: 部分適用を防ぎ、並行書き込み時の競合による失敗やリトライを減らせる
- **監査・復旧**: 過去時点のテーブル状態を参照し、レポートの再現や変更の調査に利用できる

### 技術的な注意点

- **対象テーブル**: Apache Iceberg テーブルが対象です
- **トランザクション**: BEGIN…COMMIT で複数の変更をまとめ、単一の Iceberg スナップショットとしてコミットします
- **競合解決**: 変更箇所が重ならない並行書き込みが対象です。変更が重なる場合の動作や必要な再試行については、公式ドキュメントで確認してください
- **Time Travel**: AS OF TIMESTAMP を使って過去時点を指定します
- **利用環境**: 記事によると、商用 AWS リージョンの Amazon Redshift プロビジョンドクラスターおよび Serverless クラスターで利用できます
- **コスト**: 記事に追加料金の有無は記載されていません。Redshift の実行環境や Iceberg データの保存・クエリに伴う通常の料金を確認してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/redshift-time-travel-multi-statement

AWS DevOps Agent が AWS GovCloud (US-West) で利用可能になりました。インシデント調査や運用改善を支援し、AWS、マルチクラウド、オンプレミス環境の信頼性・パフォーマンス向上を目指す運用エージェントです。

### 変更内容・新機能の詳細

DevOps Agent は、アプリケーションとその依存関係を把握し、可観測性ツール、ランブック、コードリポジトリ、CI/CD パイプラインの情報を関連付けて分析します。インシデント発生時には自律的にトリアージを行い、迅速な解決を支援します。また、過去のインシデントの傾向を分析し、将来の障害を防ぐための実行可能な改善案を提示します。AWS は、これにより平均解決時間（MTTR）を数時間から数分に短縮できる場合があるとしています。AWS Support の利用者には、前月の AWS Support 料金に応じた DevOps Agent クレジットが提供されます。Unified Operations は 100%、Enterprise Support は 75%、Business Support+ は 30% 相当です。

### 影響範囲・利用シーン

- **利用シーン**: AWS、マルチクラウド、オンプレミス環境のインシデント調査、オンデマンドの SRE 作業、運用改善
- **運用効果**: テレメトリ、コード、デプロイ情報を相関分析し、インシデントのトリアージと解決を迅速化できます
- **コスト影響**: DevOps Agent の利用料金が発生します。対象の AWS Support プランでは、前月の Support 料金に基づくクレジットで費用が軽減または相殺される場合があります

### 技術的な注意点

- **リージョン**: 今回の提供開始対象は AWS GovCloud (US-West) です。他リージョンの提供状況は公式のリージョン一覧で確認してください
- **連携準備**: 調査対象の環境、可観測性ツール、ランブック、コードリポジトリ、CI/CD パイプラインとの接続や権限設定が必要です
- **コスト**: 利用料金やクレジットの適用条件は料金ページおよび AWS Support の案内を確認してください。クレジットは前月の Support 料金に基づき、プランごとに割合が異なります

## [General] Amazon Connect Customer agent assist now supports interactive responses

- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/Connect-Custom-agent-interactive-responses

Amazon Connect Customer agent assistで、カード、カルーセル、ボタン、入力欄などのインタラクティブな応答を利用できるようになりました。エージェントは画面上で情報を確認・入力・選択し、AIエージェントによる情報取得やタスク実行を効率よく進められます。

## [General] AWS KMS now supports key sharing with AWS Resource Access Manager

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/kms-key-sharing-resource-access-manager/

### 概要

AWS KMS のキーを AWS Resource Access Manager（RAM）経由で他の AWS アカウントや組織内のプリンシパルと共有できるようになりました。再利用可能な管理アクセス許可を使って共有範囲を設定でき、既存の KMS キーポリシーを手作業で変更せずにクロスアカウントアクセスを管理できます。

### 変更内容・新機能の詳細

RAM でリソース共有を作成し、共有する KMS キー、適用する管理アクセス許可、共有先のプリンシパルを指定します。一般的な用途には AWS 管理アクセス許可を、独自の要件にはカスタマー管理アクセス許可（CMP）を利用できます。CMP は複数のポリシーステートメントや StringNotEquals、BoolIfExists、ArnLike などの IAM 条件演算子、および ForAnyValue／ForAllValues プレフィックスに対応し、より細かな最小権限の設定が可能です。また、パラメーター化された CMP を使うと、共有先ごとに値を設定してアクセス範囲を絞り込めます。CMP の作成者は、CMP を複数アカウントに公開し、バージョンを一元管理できます。新しい CMP バージョンを共有へ適用するタイミングは、共有の所有者が決定します。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS KMS キーを複数アカウント、AWS Organizations 内のアカウント、または特定の IAM ロールやユーザーと共有する管理者
- **利用シーン**: SaaS プロバイダー、中央セキュリティチーム、複数アカウントを運用する組織が、再利用可能なアクセス許可を使って KMS キーへのアクセスを提供する
- **運用効果**: キーポリシーをアカウントごとに手作業で変更する負担を減らし、共有設定とアクセス許可のバージョン管理を一元化できる
- **リージョン**: KMS と RAM の両方が利用可能な AWS リージョンで利用できます。ただし、中東（UAE）と中東（バーレーン）は対象外です

### 技術的な注意点

- **キーポリシー**: RAM による共有では既存の KMS キーポリシーは変更されません。共有先やアクセス範囲を確認したうえで、リソース共有に適切な管理アクセス許可を設定してください
- **CMP の更新**: CMP の新しいバージョンは自動で既存のリソース共有に適用されません。適用するバージョンとタイミングを共有の所有者が判断します
- **最小権限**: パラメーター化された CMP の値を環境に合わせて設定し、共有先ごとに必要な範囲へアクセスを限定してください
- **リージョン制限**: 中東（UAE）および中東（バーレーン）では利用できません
- **コスト**: 記事には本機能の追加料金に関する記載はありません。KMS キーの利用に伴う通常の料金は適用されます

## [Workspaces]  Set up, connect, and govern AI agents faster with Amazon WorkSpaces

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Workspaces
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern

### 概要

Amazon WorkSpaces for AI agentsに、エージェントのセットアップ・接続を簡素化する機能と、企業のID・ポリシーに基づく認証、操作記録を実現する機能が追加されました。AIエージェントを既存の業務環境で、より少ない手順で本番運用へ移行しやすくなります。

### 変更内容・新機能の詳細

・セットアップの簡素化: Claude Code、Codex、KiroなどのAIコーディングアシスタントに必要な環境を説明すると、AWS MCPスキルを利用してWorkSpaceを構成できます。作成された設定はデフォルトを基に調整できます。
・既存エージェントとの接続: Amazon Bedrock AgentCore上で構築したエージェントは、AWS認証情報を使ってWorkSpacesに直接接続でき、WorkSpaces用のエージェントコードを別途記述せずに連携できます。
・エージェント操作の効率化: 複数の操作を1回の呼び出しで実行するツールや、モデルが認識済みのコンピューター操作アクションを利用できるようになり、呼び出し回数や操作ミスの削減が期待できます。
・認証方式の拡張: 従来のSAMLに加えて、OIDCに対応した任意のIdPを利用できます。管理者はサインインをIdPへ直接誘導でき、利用者は通常の企業認証情報で認証できます。
・ユーザー代理でのサインイン: On-behalf-of（OBO）サインインにより、エージェントはサインイン中のユーザーのディレクトリ上のID、権限、デスクトップに適用されるグループポリシーを使って動作します。
・セッションリプレイ: セッション中のスクリーンショットを動画にし、エージェントの操作を自然言語で示す記録と組み合わせて確認できます。記録は利用者自身のAmazon S3バケットに保存され、利用者自身の暗号化キーで暗号化されます。セキュリティ調査や監査証跡に活用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AIエージェントを開発・運用するチーム、WorkSpaces管理者、セキュリティ・コンプライアンス担当者
- **利用シーン**: ERP処理や保険請求の処理など、既存の業務アプリケーションを操作するエージェントの構築・本番運用
- **運用効果**: 既存のIdPやユーザー権限、グループポリシーを活用し、独自の認証基盤や監視ツールを作り込まずに統制しやすくなる
- **監査・セキュリティ**: エージェントが見た画面と実行した操作を確認でき、調査や監査に必要な記録を残せる
- **コスト・精度**: 複数操作をまとめて実行することで、呼び出しコストや操作ミスの低減が期待できる

### 技術的な注意点

- **IdP要件**: OIDCまたはSAMLに対応するIdPが必要です。利用するIdPとの接続設定や認証フローは、WorkSpacesの公式ドキュメントで確認してください
- **OBO権限**: エージェントがユーザーの権限で動作するため、ユーザーに付与する権限とグループポリシーを最小権限で設計してください
- **セッション記録**: リプレイデータは利用者のS3バケットに保存されます。バケットへのアクセス制御、暗号化キーの管理、保存期間や削除方針を確認してください
- **コスト**: WorkSpacesの利用に加え、セッション記録のS3ストレージや暗号化キーの利用に応じた料金が発生する可能性があります。操作の集約による削減効果と合わせて見積もってください
- **リージョン制限**: 記事では提供リージョンが明記されていません。利用するWorkSpaces、AgentCore、IdP連携機能のリージョン対応状況を事前に確認してください

## [Marketplace] AWS Marketplace Metering Service now supports decimal usage quantities

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Marketplace
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-marketplace-metering-service-decimal-usage-quantities/

### 概要

AWS Marketplace Metering Service の MeterUsage および BatchMeterUsage API で、小数を含む使用量を報告できるようになりました。最大6桁の小数を扱えるため、顧客の実際の消費単位に合わせた従量課金が可能です。

### 変更内容・新機能の詳細

従来、AWS Marketplace の販売者は MeterUsage と BatchMeterUsage API に使用量を整数で報告する必要がありました。今回、MeterUsage では UsageQuantityAsDecimal、BatchMeterUsage では QuantityAsDecimal パラメータを使い、最大6桁の小数を含む数量を報告できます。たとえば、ストレージ使用量を1 TBまたは2 TBではなく、1.5 TBとして計測できます。タグごとに使用量を分割する使用量割り当て（usage allocations）も、小数に対応する AllocatedUsageQuantityAsDecimal パラメータが追加されました。従来どおり整数で報告する既存の連携は、変更せずに利用を継続できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Marketplaceで従量課金型ソフトウェアやサービスを販売し、Metering Service APIを利用する販売者
- **利用シーン**: ストレージ容量など、顧客の消費量を小数単位で測定・報告する場合
- **運用効果**: 実際の利用量に近い単位で課金でき、整数単位への丸めによる計測の粗さを避けやすくなります

### 技術的な注意点

- **APIパラメータ**: MeterUsageではUsageQuantityAsDecimal、BatchMeterUsageではQuantityAsDecimalを使用します。使用量割り当てにはAllocatedUsageQuantityAsDecimalを使用します
- **精度**: 報告できる小数の桁数は最大6桁です
- **互換性**: 整数を報告する既存の連携は、変更なしで継続利用できます
- **リージョン制限**: AWS Marketplace Metering Serviceが利用可能なすべてのAWSリージョンで利用できます
- **コスト**: 本機能は使用量報告の精度に関する変更です。料金は販売者が設定する価格および報告された使用量に基づきます
