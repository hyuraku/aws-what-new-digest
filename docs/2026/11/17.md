## [S3] Amazon S3 now provides post-quantum TLS visibility in AWS CloudTrail

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: S3
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-s3-post-quantum-tls-aws-cloudtrail/

### 概要

Amazon S3 のリクエストに対して、CloudTrail がTLS接続でネゴシエートされた鍵交換アルゴリズムを記録するようになりました。ログから、ポスト量子TLS（PQ-TLS）を利用している通信と、従来型の鍵交換を使うクライアントを確認できます。

### 変更内容・新機能の詳細

CloudTrail の S3 管理イベントおよびデータイベントに含まれる tlsDetails フィールドへ、新しい keyExchange 値が記録されます。値はそのTLS接続で合意された鍵交換アルゴリズムを示し、たとえばハイブリッド型のポスト量子アルゴリズム X25519MLKEM768 や、従来型の x25519 などを確認できます。

この情報をユーザーエージェントやIAMプリンシパルなどと組み合わせて分析することで、PQ-TLSを使っていないアプリケーションやSDKを特定し、移行の優先順位付けに役立てられます。汎用バケット、ディレクトリバケット、テーブルバケット、ベクターバケットへのリクエストが対象で、AWS PrivateLink 経由のリクエストも含まれます。

### 影響範囲・利用シーン

- **対象ユーザー**: S3の通信を監査・運用するクラウドエンジニア、セキュリティチーム、アプリケーション開発者
- **利用シーン**: CloudTrailログを分析し、PQ-TLSを利用していないユーザーエージェント、SDK、IAMプリンシパルを特定
- **運用効果**: PQ-TLS対応クライアントの利用状況を把握し、移行対象の特定や進捗確認を行いやすくなります

### 技術的な注意点

- **記録対象**: tlsDetails.keyExchange に、リクエストのTLS接続でネゴシエートされた鍵交換アルゴリズムが記録されます
- **CloudTrail設定**: 確認したいイベントが記録されるよう、対象の管理イベントまたはS3データイベントの記録設定を確認してください
- **料金**: 鍵交換情報の記録自体に追加料金はありません。S3データイベントには通常のCloudTrail料金が適用されます
- **リージョン**: すべてのAWSリージョンで利用できます

- https://docs.aws.amazon.com/AmazonS3/latest/userguide/post-quantum-tls.html

## [S3] Amazon S3 adds post-quantum TLS key exchange support to additional S3 endpoints

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: S3
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-s3-post-quantum-tls-key-exchange-support/

### 概要

Amazon S3で、S3 VectorsとS3のAWS PrivateLinkインターフェイスエンドポイントが、耐量子計算機暗号（PQC）を用いたTLS鍵交換に対応しました。ML-KEMに対応したクライアントは、アプリケーションやエンドポイント設定を変更せずに、対応する最も強い鍵交換方式を自動的に利用できます。

### 変更内容・新機能の詳細

新たに対応したのは、NIST標準の耐量子鍵カプセル化メカニズムであるML-KEM（Module-Lattice-Based Key-Encapsulation Mechanism）を利用するPQ-TLS鍵交換です。この対応により、S3 VectorsおよびS3のAWS PrivateLinkインターフェイスエンドポイントでも、TLS接続時にセッション鍵を確立する段階で耐量子性を利用できます。すでに対応済みのリージョナルS3、S3 Tables、S3 Express One Zoneの各エンドポイントに対象が拡大されました。エンドポイントはクライアントがサポートする最も強い鍵交換方式を自動的にネゴシエートするため、ML-KEM対応クライアントではPQ-TLSが使用されます。

### 影響範囲・利用シーン

- **対象ユーザー**: S3 VectorsまたはS3のAWS PrivateLinkインターフェイスエンドポイントを利用するアプリケーションの開発者、セキュリティ担当者、運用担当者
- **利用シーン**: S3へのTLS接続で、量子コンピューターによる将来的な暗号解読リスクを見据えて鍵交換の耐量子性を高めたい場合
- **運用効果**: クライアントがML-KEMに対応していれば、アプリケーションやエンドポイント設定を変更せずにPQ-TLS鍵交換を利用できます

### 技術的な注意点

- **対応方式**: NIST標準のML-KEMによるTLS鍵交換に対応します。TLS接続時の鍵交換に関する機能であり、保存データの暗号化方式を変更するものではありません
- **クライアント要件**: PQ-TLSを利用するには、クライアントソフトウェアがML-KEM鍵交換に対応し、利用するよう設定されている必要があります。非対応クライアントはサポートする方式で接続します
- **ネゴシエーション**: エンドポイントがクライアントの対応方式を確認し、サポートする最も強い鍵交換方式を自動的に選択します
- **リージョン制限**: 全AWSリージョンで利用できます
- **コスト**: 追加料金はありません

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-s3-post-quantum-tls-key-exchange-support/
- https://docs.aws.amazon.com/AmazonS3/latest/userguide/

## [Inspector] AWS Security Hub extends unified security management to Google Cloud Platform

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Inspector
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-gcp/

### 概要

AWS Security Hubは、既存のAWSおよびMicrosoft Azureに加えて、Google Cloud Platform（GCP）のリソース監視に対応しました。AWSとGCPの検出結果を一元的に確認し、リスクの優先順位付けや対応の自動化を行えます。

### 変更内容・新機能の詳細

Security HubはGCPリソースを自動検出し、設定ミス、インターネットへの公開状況、ソフトウェアの脆弱性を評価します。対象にはGCP Virtual Machines（VM）、Google Artifact Registry（GAR）のコンテナイメージ、Cloud Run functions、GCPのアイデンティティが含まれます。

CIS Benchmarks for Google Cloud Platform Foundationsなどのセキュリティ標準に基づくチェック、AWSとGCPを横断したリソースインベントリ、リスク・露出度の分析を利用できます。検出結果は共通の形式で優先順位付けされたビューに集約され、既存のAmazon EventBridge連携を利用した自動対応ワークフローにも組み込めます。なお、GCP向けの連携はSecurity Hub本体の統合だけでなく、姿勢管理チェック用のAWS Security Hub CSPM、脆弱性管理用のAmazon Inspectorとして個別に作成することもできます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWSとGCPの両方を利用するセキュリティチーム、クラウド運用チーム
- **利用シーン**: 複数クラウドの設定不備、外部公開、脆弱性を一元的に把握し、優先順位付けする
- **運用効果**: クラウドごとに別々のツールを切り替える負担を減らし、共通の検出結果とEventBridge連携を使って対応を標準化できる

### 技術的な注意点

- **料金**: GCPリソースの監視には、GCPとの連携作成後に独立した30日間の無料トライアルがあります。トライアル終了後は、同等のAWSリソース監視と同じ料金が適用されます
- **リージョン制限**: Security Hubが利用可能なAWSリージョンで連携を作成できます。ただし、中東（UAE）、中東（バーレーン）、アジアパシフィック（台北）、アジアパシフィック（ニュージーランド）は対象外です
- **連携方式**: Security Hub、Security Hub CSPM、Amazon InspectorのGCP連携は、それぞれ独立して構成できます。必要な機能に応じて連携方式を選択してください
- **設定要件**: GCPとの連携作成が必要です。必要な権限や構成手順は公式ドキュメントで確認してください

### 参考情報

- https://aws.amazon.com/security-hub/pricing/
- https://docs.aws.amazon.com/securityhub/latest/userguide/what-is-securityhub.html

## [Account Billing] AWS launches credit splitting and transfers

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Account Billing
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-credit-splitting-transfers/

### 概要

AWS Billing で、AWS クレジットを複数に分割し、支払者アカウント配下のリンクアカウントへ移転できるようになりました。チームや事業部門ごとにクレジットを割り当てやすくなり、FinOps の配賦作業を簡素化できます。

### 変更内容・新機能の詳細

AWS Billing コンソール、AWS CLI、API から、任意の種類のクレジットを金額、割合、または均等配分で分割し、分割したクレジットをリンクアカウントへ移転できます。移転されたクレジットは、受け取り先アカウントで優先的に消費されます。分割後のクレジットは、元のクレジットと同じ有効期限および対象サービスの適用条件を引き継ぎます。既定ではクレジット共有の設定も引き継ぐため、未使用残高を他の適格なアカウントに共有できます。分割後は各クレジットを個別に管理でき、共有対象の調整やクレジットの一時停止・再開も既存機能と組み合わせて利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Organizations の支払者アカウントを管理する FinOps チーム、財務・請求担当者、複数のチームや事業部門で AWS を利用する組織
- **利用シーン**: 大口クレジットを部門別に分割し、該当するリンクアカウントへ移転する場合
- **運用効果**: クレジットの配賦と月次の手作業によるチャージバックを減らし、チームごとのクレジット予算を把握しやすくなります
- **提供範囲**: すべての AWS 商用リージョンで利用できます
- **コスト**: 本機能の追加料金はありません

### 技術的な注意点

- **分割上限**: クレジットファミリーごとに最大100件まで分割できます
- **最小金額**: 分割後の各クレジットは最低100 USDです
- **使用済みクレジット**: 一部消費済みのクレジットも分割できますが、分割対象は残高のみです
- **引き継がれる条件**: 分割クレジットは元のクレジットの有効期限と対象サービスを引き継ぎます。共有設定も既定で引き継がれます
- **取り消し**: 分割は恒久的な操作で、元に戻す機能はありません。分割前に金額、配分先、共有設定を確認してください
- **アクセス方法**: AWS Billing コンソール、AWS CLI、API から操作できます

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/aws-credit-splitting-transfers/

## [IAM] AWS IAM announces Access Troubleshooter to debug access denied errors

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: IAM
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/iam-access-troubleshooter/

### 概要

AWS IAMのAccess Troubleshooterにより、対応するサービスやAPIで発生したアクセス拒否について、認可判断の詳細を確認できるようになりました。エラーに含まれる一意の識別子を使って、評価されたポリシーや認可コンテキスト、評価結果を調べ、原因を特定できます。

### 変更内容・新機能の詳細

従来は、アクセス拒否エラーに示された拒否ポリシーのARNを手掛かりに調査する方法が中心で、リクエスト時に評価された他のポリシーや認可コンテキストを把握しにくいという課題がありました。Access Troubleshooterでは、対応するサービスおよびAPIのアクセス拒否エラーに付与される一意の識別子を使い、そのリクエストで実施された認可判断の詳細を取得できます。評価対象となったポリシー、リクエストの認可コンテキスト、各評価の結果を確認できるため、どの条件やポリシーがアクセスを拒否したかを絞り込みやすくなります。

### 影響範囲・利用シーン

- **対象ユーザー**: IAM権限を設計・管理する開発者、セキュリティ担当者、クラウド運用チーム
- **利用シーン**: 対応するサービスやAPIで発生したアクセス拒否の原因調査
- **運用効果**: 認可判断の詳細を手掛かりに原因を特定でき、試行錯誤によるデバッグ時間を削減できます

### 技術的な注意点

- **対応範囲**: 利用できるのは、Access Troubleshooterに対応するサービスおよびAPIのアクセス拒否エラーです。すべてのサービスやAPIが対象とは限りません
- **利用方法**: エラーに含まれる一意の識別子を使って、認可判断の詳細を取得します。具体的な取得手順や必要な権限はユーザーガイドを確認してください
- **リージョン**: 記事にリージョン別の提供状況は記載されていません
- **コスト**: 記事に追加料金の有無は記載されていません

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/iam-access-troubleshooter/
- https://docs.aws.amazon.com/IAM/latest/UserGuide/troubleshoot_access-denied.html

コーディングエージェントからAWSのサインアップを開始すると、ブラウザーが自動的に開き、アカウント作成後に短期認証情報がエージェント側へ返されます。従来必要だった、開発者が手動でAWSサイトへ移動してアカウントを作成し、認証情報を設定する手順を減らせます。新しいAWS体験では、ホームリージョンとIAMロールマネージャーが用意され、短期認証情報は自動更新されます。利用するには、エージェント型コーディング環境にAWSプラグインをインストールするか、AWS Agent Toolkitを設定します。

- **コスト**: アカウント作成自体ではなく、デプロイしたAWSリソースの利用に応じて料金が発生する場合があります
- **リージョン**: 記事では利用可能なリージョンの制限は明示されていません

## [Account Billing] AWS announces consistent sharing controls for credits, Savings Plans, and Reserved Instances

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Account Billing
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-benefits-sharing-capabilities/

### 概要

AWS Billing and Cost Management で、クレジット、Reserved Instances（RI）、Savings Plans（SP）の組織内共有を、既定値と個別設定の両方で制御できるようになりました。Cost Categories を使って共有先を指定でき、手作業での配賦・照合作業を減らせます。

### 変更内容・新機能の詳細

クレジットは Billing Preferences ページで Credit Group Sharing の既定設定を行うと、新しく追加されるクレジットに自動適用されます。RI と SP は、購入アカウントがリンクアカウントか支払アカウントかを問わず、各コミットメントのインベントリページから共有設定を変更できます。いずれも Cost Categories を共有先のグループ化に利用します。Cost Categories は Cost Explorer、AWS Budgets、Cost and Usage Report でも利用される分類機能です。設定は AWS Billing and Cost Management コンソールまたはパブリック API から行えます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Organizations を利用する複数アカウント構成の組織、助成金・規制要件・複数法人などに応じてコスト配賦を管理する財務担当者やクラウド運用チーム
- **利用シーン**: クレジット、RI、SP の共有先を Cost Categories に基づいて設定し、組織内のアカウントやグループへ配賦する
- **運用効果**: クレジットの既定共有設定を新規クレジットに適用でき、RI/SP は個別に調整できるため、手動設定や請求後のチャージバック照合を減らせる

- **運用効果**: 推奨設定、検出結果の信頼度分類、最新ルールへの自動追従により、設定やルール更新の運用負荷を軽減できます
- **適用範囲**: Targeted bot controlの簡易設定は、Amazon CloudFrontで使用するWeb ACLが対象です

### 技術的な注意点

- **有効化方法**: AWS WAFコンソールでTargeted bot controlを有効にすると、Bot Controlルールグループ、推奨アクション、LATESTバージョン、自動SDK統合が設定されます
- **SDK統合**: 自動統合はCloudFrontがページにAWS WAF JavaScript SDKを追加する仕組みです。従来のように各ページへ手動でSDKを組み込む作業を省けます

Time Travel では AS OF TIMESTAMP を使い、テーブルの過去時点の状態をクエリできます。過去のレポートの再現、変更監査、不適切な書き込み後のデータ確認・復旧に活用できます。

- **運用効果**: 部分適用を防ぎ、並行書き込み時の競合による失敗やリトライを減らせる
- **監査・復旧**: 過去時点のテーブル状態を参照し、レポートの再現や変更の調査に利用できる

### 技術的な注意点

- **対象テーブル**: Apache Iceberg テーブルが対象です
- **トランザクション**: BEGIN…COMMIT で複数の変更をまとめ、単一の Iceberg スナップショットとしてコミットします
- **競合解決**: 変更箇所が重ならない並行書き込みが対象です。変更が重なる場合の動作や必要な再試行については、公式ドキュメントで確認してください

## [General] AWS KMS now supports key sharing with AWS Resource Access Manager

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/kms-key-sharing-resource-access-manager/

### 概要

AWS KMS のキーを AWS Resource Access Manager（RAM）経由で他の AWS アカウントや組織内のプリンシパルと共有できるようになりました。再利用可能な管理アクセス許可を使って共有範囲を設定でき、既存の KMS キーポリシーを手作業で変更せずにクロスアカウントアクセスを管理できます。

### 変更内容・新機能の詳細

RAM でリソース共有を作成し、共有する KMS キー、適用する管理アクセス許可、共有先のプリンシパルを指定します。一般的な用途には AWS 管理アクセス許可を、独自の要件にはカスタマー管理アクセス許可（CMP）を利用できます。CMP は複数のポリシーステートメントや StringNotEquals、BoolIfExists、ArnLike などの IAM 条件演算子、および ForAnyValue／ForAllValues プレフィックスに対応し、より細かな最小権限の設定が可能です。また、パラメーター化された CMP を使うと、共有先ごとに値を設定してアクセス範囲を絞り込めます。CMP の作成者は、CMP を複数アカウントに公開し、バージョンを一元管理できます。新しい CMP バージョンを共有へ適用するタイミングは、共有の所有者が決定します。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS KMS キーを複数アカウント、AWS Organizations 内のアカウント、または特定の IAM ロールやユーザーと共有する管理者
- **利用シーン**: SaaS プロバイダー、中央セキュリティチーム、複数アカウントを運用する組織が、再利用可能なアクセス許可を使って KMS キーへのアクセスを提供する
- **運用効果**: キーポリシーをアカウントごとに手作業で変更する負担を減らし、共有設定とアクセス許可のバージョン管理を一元化できる
- **リージョン**: KMS と RAM の両方が利用可能な AWS リージョンで利用できます。ただし、中東（UAE）と中東（バーレーン）は対象外です

### 技術的な注意点

- **キーポリシー**: RAM による共有では既存の KMS キーポリシーは変更されません。共有先やアクセス範囲を確認したうえで、リソース共有に適切な管理アクセス許可を設定してください
- **CMP の更新**: CMP の新しいバージョンは自動で既存のリソース共有に適用されません。適用するバージョンとタイミングを共有の所有者が判断します
- **最小権限**: パラメーター化された CMP の値を環境に合わせて設定し、共有先ごとに必要な範囲へアクセスを限定してください
- **リージョン制限**: 中東（UAE）および中東（バーレーン）では利用できません
- **コスト**: 記事には本機能の追加料金に関する記載はありません。KMS キーの利用に伴う通常の料金は適用されます

## [Workspaces] Set up, connect, and govern AI agents faster with Amazon WorkSpaces

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Workspaces
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern

### 概要

Amazon WorkSpaces for AI agentsに、エージェントのセットアップ・接続を簡素化する機能と、企業のID・ポリシーに基づく認証、操作記録を実現する機能が追加されました。AIエージェントを既存の業務環境で、より少ない手順で本番運用へ移行しやすくなります。

### 変更内容・新機能の詳細

・セットアップの簡素化: Claude Code、Codex、KiroなどのAIコーディングアシスタントに必要な環境を説明すると、AWS MCPスキルを利用してWorkSpaceを構成できます。作成された設定はデフォルトを基に調整できます。
・既存エージェントとの接続: Amazon Bedrock AgentCore上で構築したエージェントは、AWS認証情報を使ってWorkSpacesに直接接続でき、WorkSpaces用のエージェントコードを別途記述せずに連携できます。
・エージェント操作の効率化: 複数の操作を1回の呼び出しで実行するツールや、モデルが認識済みのコンピューター操作アクションを利用できるようになり、呼び出し回数や操作ミスの削減が期待できます。
・認証方式の拡張: 従来のSAMLに加えて、OIDCに対応した任意のIdPを利用できます。管理者はサインインをIdPへ直接誘導でき、利用者は通常の企業認証情報で認証できます。
・ユーザー代理でのサインイン: On-behalf-of（OBO）サインインにより、エージェントはサインイン中のユーザーのディレクトリ上のID、権限、デスクトップに適用されるグループポリシーを使って動作します。
・セッションリプレイ: セッション中のスクリーンショットを動画にし、エージェントの操作を自然言語で示す記録と組み合わせて確認できます。記録は利用者自身のAmazon S3バケットに保存され、利用者自身の暗号化キーで暗号化されます。セキュリティ調査や監査証跡に活用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AIエージェントを開発・運用するチーム、WorkSpaces管理者、セキュリティ・コンプライアンス担当者
- **利用シーン**: ERP処理や保険請求の処理など、既存の業務アプリケーションを操作するエージェントの構築・本番運用
- **運用効果**: 既存のIdPやユーザー権限、グループポリシーを活用し、独自の認証基盤や監視ツールを作り込まずに統制しやすくなる
- **監査・セキュリティ**: エージェントが見た画面と実行した操作を確認でき、調査や監査に必要な記録を残せる
- **コスト・精度**: 複数操作をまとめて実行することで、呼び出しコストや操作ミスの低減が期待できる

### 技術的な注意点

- **IdP要件**: OIDCまたはSAMLに対応するIdPが必要です。利用するIdPとの接続設定や認証フローは、WorkSpacesの公式ドキュメントで確認してください
- **OBO権限**: エージェントがユーザーの権限で動作するため、ユーザーに付与する権限とグループポリシーを最小権限で設計してください
- **セッション記録**: リプレイデータは利用者のS3バケットに保存されます。バケットへのアクセス制御、暗号化キーの管理、保存期間や削除方針を確認してください
- **コスト**: WorkSpacesの利用に加え、セッション記録のS3ストレージや暗号化キーの利用に応じた料金が発生する可能性があります。操作の集約による削減効果と合わせて見積もってください
- **リージョン制限**: 記事では提供リージョンが明記されていません。利用するWorkSpaces、AgentCore、IdP連携機能のリージョン対応状況を事前に確認してください

## [Marketplace] AWS Marketplace Metering Service now supports decimal usage quantities

- **公開日**: 2026-11-17 (JST)
- **カテゴリ**: Marketplace
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-marketplace-metering-service-decimal-usage-quantities/

### 概要

AWS Marketplace Metering Service の MeterUsage および BatchMeterUsage API で、小数を含む使用量を報告できるようになりました。最大6桁の小数を扱えるため、顧客の実際の消費単位に合わせた従量課金が可能です。

### 変更内容・新機能の詳細

従来、AWS Marketplace の販売者は MeterUsage と BatchMeterUsage API に使用量を整数で報告する必要がありました。今回、MeterUsage では UsageQuantityAsDecimal、BatchMeterUsage では QuantityAsDecimal パラメータを使い、最大6桁の小数を含む数量を報告できます。たとえば、ストレージ使用量を1 TBまたは2 TBではなく、1.5 TBとして計測できます。タグごとに使用量を分割する使用量割り当て（usage allocations）も、小数に対応する AllocatedUsageQuantityAsDecimal パラメータが追加されました。従来どおり整数で報告する既存の連携は、変更せずに利用を継続できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Marketplaceで従量課金型ソフトウェアやサービスを販売し、Metering Service APIを利用する販売者
- **利用シーン**: ストレージ容量など、顧客の消費量を小数単位で測定・報告する場合
- **運用効果**: 実際の利用量に近い単位で課金でき、整数単位への丸めによる計測の粗さを避けやすくなります

### 技術的な注意点

- **APIパラメータ**: MeterUsageではUsageQuantityAsDecimal、BatchMeterUsageではQuantityAsDecimalを使用します。使用量割り当てにはAllocatedUsageQuantityAsDecimalを使用します
- **精度**: 報告できる小数の桁数は最大6桁です
- **互換性**: 整数を報告する既存の連携は、変更なしで継続利用できます
- **リージョン制限**: AWS Marketplace Metering Serviceが利用可能なすべてのAWSリージョンで利用できます
- **コスト**: 本機能は使用量報告の精度に関する変更です。料金は販売者が設定する価格および報告された使用量に基づきます

- https://docs.aws.amazon.com/marketplacemetering/latest/APIReference/API_MeterUsage.html
