## [Bedrock] Amazon Bedrock AgentCore now offers a Web Search API

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-web-search-api/

### 概要

Amazon Bedrock AgentCore の Web Search API（InvokeWebSearch）が一般提供されました。単一の API コールで Amazon 管理のウェブインデックスからランク付けされた検索結果を取得できます。

### 変更内容・新機能の詳細

InvokeWebSearch API は AgentCore Gateway の MCP ツールとして提供されていた Web Search を、ゲートウェイ不要で直接呼び出せる一般提供版 API として公開します。呼び出しは AWS SDK または AWS CLI 経由、IAM で認可し、VPC からは AWS PrivateLink 経由でアクセス可能です。API は Amazon 運営のウェブインデックスを検索し、各結果についてテキスト抜粋（サマリ）、可能ならページタイトル、URL、公開日時を返します。ドメインや公開日時でフィルタをかけられるため、信頼できるドメインだけを対象に検証したり、最近の製品発表を探す用途に適しています。クエリはログを CloudTrail のデータイベントとして記録でき、課金は 1,000 クエリあたり $7（AgentCore Gateway 経由の料金と同じ）で、ゲートウェイ料金は不要です。現時点で利用可能なリージョンは米国東部（北バージニア）、米国東部（オハイオ）、米国西部（オレゴン）、アジア太平洋（シドニー）、アジア太平洋（東京）、欧州（アイルランド）です。

### 影響範囲・利用シーン

- **対象ユーザー**: LLM 開発者、カスタムエージェント作成者、データパイプライン開発者、SRE/運用チーム
- **利用シーンまたは効果**: エージェントループやデータパイプラインで外部情報を即時検索して応答を補強（ファクトチェック、最新情報取得、製品発表検出など）
- **運用効果**: ゲートウェイを用意せずに直接検索結果を取得できるため、構成が簡素化され、検索導線の遅延・運用コストを削減可能

### 技術的な注意点

- **IAM権限**: InvokeWebSearch を呼び出すための適切な IAM ポリシーが必要です（API 呼び出し権限と必要に応じて CloudTrail へのログ記録設定権限）。
- **リージョン制限**: 現時点で利用可能なリージョンは US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Sydney), Asia Pacific (Tokyo), Europe (Ireland) のみです。未対応リージョンでは利用できません。
- **コスト**: クエリ課金は $7/1,000 クエリ（AgentCore Gateway と同料金）で、ゲートウェイ料金は不要。頻繁な検索を行うワークロードではコスト設計が必要です。
- **VPC/PrivateLink**: VPC から安全に呼び出すには AWS PrivateLink を利用できます。ネットワーク設計とエンドポイントの設定が必要です。
- **監査/ログ**: リクエストは CloudTrail のデータイベントとして記録可能。監査要件がある場合は CloudTrail 設定を確認してください。
- **レスポンス/機能**: 結果はランク付けされた項目とテキスト抜粋、可能であればタイトル/URL/公開日時を含みます。全文取得ではなく抜粋中心である点に留意してください。
- **フィルタ**: ドメイン指定や公開日時フィルタで検索対象を絞れます（信頼できるドメインでのファクトチェック等に有効）。
- **制限/クォータ**: レート制限やクォータの詳細はドキュメントを参照してください（必要に応じてサービスクォータ申請が必要になる可能性あり）。

## [General] Amazon CloudWatch Logs announces account-level retention policies

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-log-retention/

### 概要

Amazon CloudWatch Logs にアカウント単位の保持ポリシーが追加され、アカウント内の複数またはすべてのロググループに対して一括で保存期間を設定できるようになりました。コンソール・CLI・SDK でポリシーを作成・管理できます。

### 変更内容・新機能の詳細

アカウントレベルの保持ポリシーは、アカウント内のロググループ全体または名前のプレフィックス（例: /aws/lambda）で始まるロググループのサブセットに対して一括で保存期間を指定できます。ポリシーは既存のロググループに適用するか新規グループのみを対象にするかを選択可能です。複数のポリシーが同じロググループに適用される場合は、最長の保持期間が優先適用されます（例: アカウント全体で90日を基準に設定し、/security プレフィックスには1年を適用して監査要件に対応）。作成・管理は AWS マネジメントコンソール、AWS CLI、AWS SDK から行え、アカウント・リージョンごとに最大20件のポリシーを設定できます。なお、本機能は追加料金なしで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: プラットフォームチーム、セキュリティ／コンプライアンス担当、SRE、運用チーム
- **利用シーンまたは効果**: アカウント全体のログ保持ポリシーの一元管理（例：監査ログの長期保存、開発環境ログの短期削除）により個別ロググループの追跡を削減
- **運用効果**: 各ロググループ名を個別に管理する手間を省き、コンプライアンス要件やコスト方針に沿った一貫した保持設定を迅速に適用可能

### 技術的な注意点

- **IAM権限**: アカウントレベルの保持ポリシーを作成・更新・削除できる CloudWatch Logs に関する操作権限を付与してください（コンソール/CLI/SDK を用いるための適切な IAM ポリシーが必要です）。
- **リージョン制限**: すべての商用リージョンで利用可能。ただし Middle East (Bahrain) および Middle East (UAE) では未対応です。
- **コスト**: 本機能自体に追加料金は発生しませんが、保持期間を長くするとログ保存量が増え、ストレージコストが上昇します。短くすることでコスト削減が可能です。
- **ポリシー上限**: アカウントおよびリージョンごとに最大20件のアカウントレベル保持ポリシーを作成できます。
- **適用ルール**: プレフィックスマッチでサブセット指定が可能。既存ロググループへの適用可否はポリシー作成時に選択できます。複数ポリシーが該当する場合は最大（最も長い）保持期間が適用されます。
- **運用上の注意**: 保持期間変更によるログ削除は復元できないため、監査・調査に必要なログが誤って削除されないようポリシー設計とテストを行ってください。

## [Glue] AWS Glue adds 100 new native connectors for popular SaaS applications

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Glue
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-glue-adds-100-new-native-connectors/

### 概要

AWS Glueが100種類のネイティブコネクタを追加しました。これにより、SaaSやREST APIベースのアプリケーションからのデータ取り込みがコード不要で簡単になり、接続をGlue Data Catalogで一度作成してETLジョブ間で再利用できます。

### 変更内容・新機能の詳細

追加された100個のネイティブコネクタは、生成AI、財務・決済、マーケティング、プロダクト分析、HR、エンジニアリング、IT運用、コラボレーション等の主要SaaSやREST APIを対象とします。各コネクタはGlueのコネクションモデルで管理され、Data Catalogに定義した接続を複数のETLジョブで再利用できます（既存のGlueの権限モデルに準拠）。取り込んだデータはAmazon S3やAmazon Redshiftにロードして分析・レポートに利用可能です。代表的なユースケースとして、Anthropic等のモデルプロバイダの使用量・コスト集約、Adyen/Square/Xero等のトランザクション統合、Chargebee/Amplitude/Klaviyo等の請求・利用・キャンペーンデータ統合、BambooHR/Gusto等の人事データ統合、PagerDuty/Sentry/Jenkins/Vercel等のインシデント／デプロイデータの結合などが挙げられます。コネクタはAWS Commercial RegionsのGlueバージョン5.0以上で利用可能です。個別コネクタの認証方式（OAuth、APIキー、トークン等）、増分取得/フルロード/ページングやAPIレート制限などの詳細はコネクタ毎のドキュメントを参照する必要があります。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、ETL開発者、データ分析チーム、SRE/プラットフォームチーム
- **利用シーンまたは効果**: SaaSデータの定期取り込み・統合（請求/利用分析、BI用データレイク構築、信頼性指標の集約など）をコードを書かずに迅速に構築できる
- **運用効果**: コネクションの再利用により開発工数が削減され、メンテナンス負荷（APIラッパーや個別クライアント実装の維持）が低減する
- **導入上の期待**: 異なるSaaSのデータをS3/Redshiftで横断的に結合しやすくなり、分析サイクルの短縮や単一ソース・オブ・トゥルース構築が容易になる

### 技術的な注意点

- **IAM権限**: Glueでの接続作成・利用にはGlue関連のIAM権限（例: glue:CreateConnection, glue:GetConnection, glue:UpdateConnection等）と、ジョブ実行ロールの権限を確認してください。シークレットを使用する場合はSecrets Managerのアクセス権も必要です。
- **リージョン制限**: すべてのAWS Commercial Regionsで利用可能としていますが、AWS GovCloudや中国リージョンは対象外の可能性があるため利用前に確認してください。
- **コスト**: GlueのETL/ジョブ実行コスト、Data Catalogのストレージ、S3/Redshiftの保存費用、データ転送（リージョン間やインターネット経由）に基づく追加コストが発生します。APIコール量に起因するSaaS側の課金がある場合は別途注意が必要です。
- **認証/シークレット**: 各コネクタの認証方式はコネクタ依存（OAuth、APIキー、アクセストークン等）です。資格情報はAWS Secrets Manager等で安全に管理し、Glue接続から参照する運用を推奨します。
- **Glueバージョン**: GlueコネクタはGlueバージョン5.0以上で利用可能です。ジョブ・開発エンドポイントのバージョンを確認してください。
- **ネットワーク接続**: コネクタはSaaSのパブリックAPIへアクセスするため、Glueジョブの実行環境（VPC設定、NAT Gateway、VPCエンドポイント等）のネットワーク構成を確認してください。プライベートAPIやVPC内のエンドポイントを使う場合は追加設定が必要です。
- **APIレート制限とスロットリング**: 各SaaSのAPIレート制限やペイジネーション仕様はコネクタ毎に異なります。大量取得時はリトライ・スロットリング挙動やバッチサイズ設定を確認してください。
- **増分取り込み/スキーマ**: 増分取得（インクリメンタル）やスキーマ推論、型変換、タイムスタンプ処理などの動作はコネクタ毎に異なります。変更データキャプチャ（CDC）のサポート有無も要確認です。
- **ログと監査**: ジョブのCloudWatchログやGlueの監査情報で接続エラーやAPI応答を監視してください。アクセスキーのローテーションや監査要件を満たす運用設計が必要です。

## [Security Token Service] AWS STS now supports cross-partition federation for AWS identities

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Security Token Service
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-sts-cross-partition

### 概要

AWS STS が異なる AWS パーティション間で IAM アイデンティティを使ったフェデレーション（短期認証情報の取得）をサポートしました。長期キーを保持せずに、あるパーティションの IAM 身元で別パーティションのロールを引き受けられます。

### 変更内容・新機能の詳細

今回の拡張により、ワークロードは自身のパーティション内で短期トークンを AWS STS から取得し（GetWebIdentityToken）、そのトークンを別パーティション側で AssumeRoleWithWebIdentity を呼び出して一時的な AWS 認証情報に交換できます。パーティションは商用（aws）、AWS GovCloud (US)、中国リージョン、AWS European Sovereign Cloud (Germany) 等のグループであり、各パーティションは独立した IAM を持つため従来は強い境界がありました。本機能により、長期アクセスキーに依存することなくクロスパーティションでのアクセスを実現できます。ロール側の信頼ポリシーとアイデンティティの許可設定により、どのアイデンティティがロールを引き受けられるかを制御可能で、両パーティションの AWS CloudTrail でトークン利用を監査できます。既に組織で PKI を運用している場合は IAM Roles Anywhere を代替手段として利用可能です。クロスパーティションフェデレーションは追加料金なしで、商用リージョン、AWS GovCloud (US)、中国リージョン、AWS European Sovereign Cloud (Germany) で利用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: マルチパーティションでサービスや運用を行うクラウドエンジニア、セキュリティチーム、SRE、コンプライアンス担当者
- **利用シーン**: 異なるパーティション（例: 商用 ⇄ GovCloud、商用 ⇄ 中国）間での集中化された運用ツール、セキュリティ/コンプライアンス集約、監査用の一時的認証情報付与
- **運用効果**: 長期アクセスキーを削減して秘匿情報漏洩リスクを低減、中央集権的なガバナンスとクロスパーティション監査を実現し、運用と監査の一貫性が向上

### 技術的な注意点

- **IAM権限**: ソース側で短期トークンを取得する際に適切な STS API 呼び出し権限（例: sts:GetWebIdentityToken）と、ターゲット側ロールでの sts:AssumeRoleWithWebIdentity を許可する必要があります。ターゲットロールの信頼ポリシーはソース側アイデンティティを明示的に許可するよう設定してください。
- **リージョン制限**: 機能は商用リージョン、AWS GovCloud (US)、中国リージョン、AWS European Sovereign Cloud (Germany) で利用可能です。各パーティションは独立した IAM を持つためアカウント構造やコンプライアンス要件の確認が必要です。
- **コスト**: クロスパーティションフェデレーション自体に追加料金はありませんが、関連するサービス利用（データ転送、CloudTrail 保存、ログ集約等）には通常の料金が発生します。
- **監査/ログ**: CloudTrail を両パーティションで有効にしておくことで、トークン発行とロール引受けのログを収集できます。クロスパーティションの監査設計を事前に検討してください。
- **互換性/代替**: 組織で PKI を運用している場合は IAM Roles Anywhere が代替となります。既存の ID プロバイダーと連携する場合は、信頼チェーンとトラストポリシーの設定に注意してください。

## [Aiml] Amazon Quick is now AWS Quick

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-quick-aws-quick/

### 概要

Amazon Quickがサービス名をAWS Quickに変更しました。名称変更のみで既存ユーザーの操作や設定、料金に変更はなく、エンタープライズ向けのセキュリティ・ガバナンスやコンプライアンスは引き続き適用されます。

### 変更内容・新機能の詳細

・名称変更: サービス名称が「Amazon Quick」から「AWS Quick」に変更され、Webサイト、デスクトップ/モバイルアプリ、ドキュメント上で表記が更新されます。既存ユーザーによる操作は不要で、動作や設定は従来どおりです。
・Quick Sight: Quick内のBI機能「Amazon Quick Sight」も「AWS Quick Sight」に名称変更。ダッシュボード、データセット、分析など既存資産や設定、価格には影響しません。
・機能概要: AWS Quickは部署向けAIワークスペースで、AIエージェントを使い既存のデータやアプリケーション（ベンダー非依存）を横断して調査・分析・実行できます。ロールやチームコンテキストを理解し、プレーンランゲージでエージェント、アプリ、オートメーションを作成してチーム共有資産として運用可能です。
・セキュリティとコンプライアンス: HIPAA適格、FedRAMP、SOC 2、ISO 27001などの認証を保有。データは顧客の環境内に留まり、他者のモデル学習には使用されない（データ不使用ポリシー）。
・リージョン提供: 多くのAWSリージョンで利用可能。リージョン毎の可用性はAWSのリージョン製品テーブルを確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: エンタープライズのデータチーム、SRE/運用、プロダクト/ビジネスアナリスト、AI/MLチーム
- **利用シーン**: 社内データ横断の調査・分析（ダッシュボード参照、レポート生成）、プレーンランゲージでの自動化ワークフロー作成、マルチベンダー環境のデータ連携と意思決定支援
- **運用効果**: 既存資産をそのまま継続利用できるため移行コスト不要、エンタープライズ準拠のセキュリティ下でAIエージェント運用が可能になり、チームのナレッジ共有と自動化による生産性向上が期待できる

### 技術的な注意点

- **IAM権限**: AWS QuickおよびQuick Sightの管理・利用には専用のIAM権限が必要です。既存の役割やポリシーで対象サービスへのアクセスを許可しているか確認してください。
- **リージョン制限**: 「多くのAWSリージョンで利用可能」と明記されていますが、全リージョンでの提供を保証するものではありません。実稼働前に対象リージョンでのサービス提供状況を確認してください（リージョン製品テーブル参照）。
- **データ保護・モデル学習**: AWSの説明によるとデータは顧客環境内に留まり、他者のモデル訓練には使用されません。機密データを扱う場合はVPC、暗号化、監査ログなど既存のセキュリティ設計を適用してください。
- **既存ユーザーの対応**: 名称変更のみで操作不要。Quick/Quick Sightのダッシュボードやデータ、設定、価格に変更はありませんが、ドキュメント表記の更新や社内向け教育資料の名称差し替えは必要になる場合があります。
- **コスト**: 公表された情報では既存の価格体系に変更はないとされています。ただし、新機能やリージョンによっては追加料金が発生する可能性があるため、利用前に料金表を確認してください。

## [Bedrock] Claude Fable 5.2 is now available on AWS GovCloud (US)

### 変更内容・新機能の詳細

- **IAM権限**: 実行ロール（execution role）にS3等のデータストアへのアクセス権を付与する必要があります。権限不足だとDuckDBタスクがデータにアクセスできません

## [Documentdb] Amazon DocumentDB Serverless now provides up to 35% higher throughput

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Documentdb
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/documentdb-serverless-platform-version-4/

### 概要

Amazon DocumentDB Serverlessのプラットフォームバージョン4が公開され、最大で約35%のスループット向上を実現します。新規サーバレスクラスターは各リージョンで自動的に最新バージョンで起動し、既存のv3クラスターはメンテナンスアクションでv4へアップグレード可能です。

### 変更内容・新機能の詳細

プラットフォームバージョンは性能、スケーリング能力、機能改善を表すクラスタ単位のソフトウェア基盤です。Platform Version 4（v4）は内部実装の最適化により、従来比で最大35%のスループット向上を提供します。新規に作成するServerlessクラスターは利用可能な最新プラットフォームバージョンで起動します。既存のプラットフォームバージョン3（v3）クラスターは、'serverless-platform-version-update' という保留中のメンテナンスアクションを適用することでv4へ切り替えが可能で、適用は即時または次回のスケジュール済みメンテナンスウィンドウで実行できます。アップグレード後はダウングレードできません。クラスターのプラットフォームバージョンはAWS Management Consoleで確認できるほか、DescribeDBClusters APIのServerlessV2PlatformVersionフィールドでも確認できます。アップグレード前にはステージング環境でワークロード検証を行うことを推奨します。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon DocumentDB Serverlessを利用するアプリケーション開発者、SRE、Databases/Platformチーム
- **利用シーン**: 高スループットが求められるWeb/APIバックエンド、バースト性のあるワークロード、レイテンシ低減が重要なクエリ処理
- **運用効果**: 同等のコストで高いスループットを得られる可能性があり、スケールアウト頻度やレスポンスタイムが改善される可能性がある
- **導入注意点**: アップグレードは不可逆（ダウングレード不可）なので、本番適用前にステージングで性能・互換性検証が必要

### 技術的な注意点

- **IAM権限**: クラスターの表示・更新（保留中メンテナンスアクションの適用）を行える権限が必要。Console/APIでの操作に関する権限を確認してください
- **リージョン制限**: 新しいプラットフォームバージョンの提供はリージョン単位でロールアウトされます。利用前に対象リージョンでv4が利用可能か確認してください
- **コスト**: プラットフォームのアップデート自体に追加料金は発生しませんが、スループット向上に伴い消費リソース（vCPU・メモリ相当のサーバレス容量やI/O）が変化する可能性があり、結果としてコストに影響する場合があります
- **運用手順**: v3→v4は 'serverless-platform-version-update' の保留中メンテナンスアクションを適用することで実施。適用は即時またはスケジュールで選択可能
- **不可逆性**: 一度v4へアップグレードするとダウングレード不可のため、ロールバック手順は事前に検討（スナップショットやテスト環境での検証）してください
- **確認方法**: AWS Management Consoleのクラスター表示、またはDescribeDBClusters APIのServerlessV2PlatformVersionフィールドで現在のプラットフォームバージョンを確認可能
- **互換性**: 多くのケースで透過的に性能改善が適用されますが、プラットフォーム内部の挙動変化が影響する可能性があるため、クエリパターンや接続動作の検証を推奨します

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/documentdb-serverless-platform-version-4/
- https://docs.aws.amazon.com/documentdb/latest/developerguide/serverless.html

## [Athena] Amazon Athena introduces system tables for observability, auditing, and usage analytics

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Athena
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/athena-system-tables/

### 概要

Amazon Athenaがシステムテーブル機能を導入しました。クエリ実行の利用データを自動的にApache Iceberg形式の読み取り専用テーブル（S3上、サービス管理）として数分以内に出力し、可観測性・監査・利用分析に活用できるようになります。

### 変更内容・新機能の詳細

有効化すると、Athenaはワークグループ単位でクエリ実行・利用データを自動収集し、サービス管理されたApache Iceberg形式の読み取り専用テーブルとしてAmazon S3上に保持します。データはクエリ完了から数分以内に利用可能になり、スキーマ定義、パーティショニング、圧縮・コンパクション、スナップショット保守などの運用はAWS側で管理されます。出力されるテーブル（例: query_executions）はAthenaから直接SQLで検索・フィルタ・集約・結合が可能で、コスト配分ダッシュボードや利用パターン分析をETLなしで実装できます。併せて、GetQueryExecution等のAPI、CloudWatchメトリクス、CloudTrailログ経由での利用データ提供も継続されます。データはオープンなApache Icebergフォーマットなので、DuckDB、Amazon Redshift（Iceberg対応）、Amazon EMRなど他のIceberg互換エンジンでも照会可能です。保持期間は設定可能で、AthenaコンソールまたはAPIから有効化・設定を行えます。AWS Agent Toolkitにはシステムテーブルをクエリして利用傾向や最適化提案を抽出するスキルも提供されます。

### 影響範囲・利用シーン

- **対象ユーザー**: Athenaを利用するデータ分析者、SRE/運用チーム、プラットフォーム/費用管理チーム
- **利用シーン**: コスト配分ダッシュボード作成（ワークグループ/ユーザー/テーブル別のスキャン量集計）、監査ログ照合、クエリパフォーマンス可視化、利用傾向分析
- **運用効果**: カスタムETLを作らずにSQLで直接分析できるため、導入工数と運用負荷が低減され、コスト最適化や異常検知が迅速に行える
- **リスク/留意点**: 利用データにはクエリテキストやテーブル名など機微情報が含まれる可能性があるため、アクセス制御と保持ポリシーの設計が重要

### 技術的な注意点

- **IAM権限**: システムテーブルの有効化・参照にはAthenaコンソール/APIを操作する権限が必要。クエリ実行にはathena:StartQueryExecution等の実行権限および必要に応じてS3アクセス権が求められる
- **リージョン制限**: AthenaおよびAmazon S3 Tablesが利用可能な全リージョンで提供されますが、詳細は地域ごとのサービス可用性を確認してください
- **コスト**: システムテーブルのストレージはS3の標準料金が発生し、テーブルをクエリする際はAthenaのクエリ料金（読み取りスキャン量）や、他のエンジンを使う場合は当該エンジンの料金が発生します。保持期間設定によってストレージコストが変動します
- **スキーマと操作性**: テーブルはサービス管理の読み取り専用（スキーマやパーティションはAWSが定義・管理）。ユーザーによる書き込みやスキーマ変更はできません
- **データ遅延**: 利用データは『数分以内』に反映されますが、厳密なリアルタイム要件がある用途では遅延を考慮してください
- **互換性**: データはApache Iceberg形式のため、Iceberg互換のクエリエンジン（DuckDB、Amazon RedshiftのIceberg対応、Amazon EMR等）で照会可能
- **プライバシー/ガバナンス**: クエリ内容に機密情報が含まれる場合は、アクセス権限・ログ保存期間・監査ポリシーを適切に設定してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/athena-system-tables/
- https://docs.aws.amazon.com/athena/latest/ug/

## [Bedrock] Claude Fable 5.2 is now available on AWS 

- **公開日**: 2026-11-10 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/claude-fable-5-2-aws/

### 概要

Anthropicの最新大規模モデル「Claude Fable 5.2」がAWS上で利用可能になりました。ソフトウェア開発、科学研究、定量ファイナンスなど高い判断力・反復・精度が必要な技術業務向けに最適化されています。

### 変更内容・新機能の詳細

Claude Fable 5.2は、コーディング、数学、科学分野の難易度の高い課題へ対応できる能力を強化したAnthropicの汎用モデルです。長時間（数時間〜数日）にわたる自律的な作業を行えるよう設計されており、複数リポジトリやモノレポに跨る大規模で曖昧なエンジニアリング問題に取り組み、自己テストや結果の再現性チェックを行いながら根本原因を探索します。Anthropicの試験では多数のサブエージェントを協調して統括するリードエージェントとしての運用や、再現しない結果のフラグ付けが可能であることが示されています。Claude Mythos 5.2は同一の基盤モデルで、サイバー／バイオ関連の能力（リスク帯域を含む）を保持し、Anthropicの検証プログラム経由で提供されます。Bedrock上の提供に際して、Fable 5.2／Mythos 5.2は“covered model”に指定されており、安全性監視のためのデータ保持要件があります。ただし、Enterprise Frontier Safeguardsが利用可能になるまでの間、条件を満たす顧客はゼロデータ保持でFable 5.2を利用できるオプションがあります。AWSでのアクセス方法は主にAmazon BedrockとClaude Platform on AWSの二通りで、利用には各プラットフォームのドキュメントやリージョン提供状況を確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: ソフトウェアエンジニア、データサイエンティスト、研究者（ライフサイエンス含む）、クオンツ/ファイナンスエンジニア
- **利用シーンまたは効果**: 大規模リポジトリ横断の自動化的コード改修、複雑な数理解析や実験デザインの補助、定量取引戦略の先端的推論・リスク評価
- **運用効果**: 自律的に長時間稼働して多段階タスクを実行・自己検証するため、人的介入を減らし大規模プロジェクトの生産性を向上
- **制約・リスク**: Mythos系（サイバー/バイオ能力保持）はアクセス制限・検証が必要で、covered modelのデータ保持要件や規制対応が発生する可能性がある

### 技術的な注意点

- **IAM権限**: Amazon BedrockまたはClaude Platform利用に必要なIAMポリシー（BedrockのInvoke系権限など）を事前に設定してください。Anthropic側の契約・認証（Mythosアクセス等）が必要な場合があります。
- **リージョン制限**: 提供はリージョン依存です。Amazon Bedrockが利用可能なリージョンでの提供となるため、利用前にリージョン対応状況を確認してください。
- **コスト**: 大規模モデルの推論は高コストになる可能性があります。長時間の自律処理や大量のログ／データ保持を行う場合、追加の使用料やストレージコストが発生します。BedrockとClaude Platformで価格モデルが異なるため事前に確認してください。
- **データ保持／コンプライアンス**: Fable 5.2／Mythos 5.2は“covered model”に指定されており、安全性監視のためのデータ保持要件があります。条件を満たす顧客はEnterprise Frontier Safeguardsが有効になるまでゼロデータ保持オプションを選べる場合がありますが、規制や内部ポリシーに照らした扱いを必ず確認してください。
- **セキュリティ運用**: 長時間・自律実行のワークロードでは監視、タイムアウト、コストアラート、結果の再現性チェックを組み込むことを推奨します。
- **アクセス制限（Mythos）**: サイバー・バイオ関連能力を持つモデル（Mythos 5.2）はAnthropicの検証プログラム等を通じた限定提供となるため、追加の審査や利用条件が必要です。
