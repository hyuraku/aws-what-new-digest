## [Bedrock] Amazon Bedrock adds bedrock-runtime endpoint support for OpenAI Daybreak Red in AWS GovCloud (US)

- **公開日**: 2026-11-25 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/gpt-daybreak-red-runtime-govcloud/

### 概要

Amazon Bedrockで、OpenAIのサイバーセキュリティ特化モデル「Daybreak Red: GPT-5.6 Cyber」がAWS GovCloud (US)から利用可能になりました。利用にはOpenAIによるDaybreakアクセスの承認と、AWS側でのアクセス申請が必要です。

### 変更内容・新機能の詳細

本モデルは、脆弱性調査、エクスプロイトの再現、緩和策の開発など、許可された高度なサイバーセキュリティ業務向けに設計されています。調査を進めやすくするため拒否のしきい値を低くする一方、本人確認、監視、アクセス制御を強化しています。AWS GovCloud (US)では、Amazon Bedrockのbedrock-runtimeエンドポイントから、米国政府向けのGeoクロスリージョン推論（CRIS）プロファイルを通じて利用できます。推論データはモデルのトレーニングに使用されず、OpenAIとのデータ共有へのオプトインも不要です。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS GovCloud (US)を利用する、承認済みのセキュリティ研究者、インシデント対応担当者、脆弱性対策チーム
- **利用シーン**: 許可を得た脆弱性調査、エクスプロイト再現、緩和策の検討
- **利用効果**: サイバーセキュリティ調査を支援し、調査の速度と深さの向上が期待できます
- **利用開始**: OpenAIにDaybreakアクセスを申請し、承認後にAWSアカウントチームを通じてAWSでのアクセスを申請します

### 技術的な注意点

- **アクセス条件**: OpenAIのDaybreakアクセス承認と、AWSでのアクセス申請が必要です。対象となる顧客や利用条件はOpenAIまたはAWSアカウントチームに確認してください
- **エンドポイント**: AWS GovCloud (US)ではbedrock-runtimeエンドポイントから利用し、US Gov Geoクロスリージョン推論プロファイルを使用します
- **リージョンとエンドポイント**: 本記事での対象はAWS GovCloud (US)のbedrock-runtimeです。bedrock-mantleエンドポイントでのリージョン別提供状況は公式ドキュメントを確認してください
- **データ利用**: 推論データはモデルのトレーニングに使用されず、OpenAIとのデータ共有へのオプトインは不要です
- **安全な利用**: 拒否のしきい値が低いモデルのため、許可された業務に限定し、組織の本人確認・監視・アクセス制御を適用してください
- **コスト**: 料金は利用量や適用条件をAWSの料金情報で確認してください

### 参考情報

## [Opensearch Service] Amazon OpenSearch Serverless is now available in the Africa (Cape Town) Region

- **公開日**: 2026-11-25 (JST)
- **カテゴリ**: Opensearch Service
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-serverless-available-cape-town-region/

### 概要

Amazon OpenSearch Serverlessの次世代機能が、AWS Africa（Cape Town）リージョンで利用可能になりました。クラスターを管理せずに検索、ベクトル検索、分析などを実行でき、需要に応じた自動スケーリングやアイドル時のスケール・トゥ・ゼロを利用できます。

### 変更内容・新機能の詳細

Cape Townリージョンの利用者は、OpenSearchクラスターをプロビジョニング・運用することなく、エージェント型AI、検索、オブザーバビリティなどのワークロードを実行できます。コンピューティングとストレージが分離されているため、コンピューティング容量をストレージとは独立して調整でき、トラフィックが少ない時間帯のコスト削減と急増への対応を両立できます。リソースは数秒で用意され、需要に合わせて自動的にスケールします。また、アイドル時にスケール・トゥ・ゼロとなり、使用したコンピューティングに応じた料金体系を利用できます。ピーク時の負荷を前提にクラスターを常時プロビジョニングする場合と比べ、最大60%のコスト削減が可能とされています。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Africa（Cape Town）リージョンで検索、ベクトル検索、分析、オブザーバビリティ、エージェント型AIの基盤を構築するチーム
- **利用シーン**: 需要が変動する検索・分析ワークロードや、ベクトル検索を含むAIアプリケーションの実行
- **運用効果**: クラスターの容量設計や管理の負担を抑え、需要に応じたスケーリングを実現
- **コスト効果**: アイドル時のスケール・トゥ・ゼロなどにより、ピーク負荷に合わせて常時容量を確保する構成と比べてコスト削減が期待できる

### 技術的な注意点

- **リージョン**: 本記事の対象はAWS Africa（Cape Town）リージョンです。利用可能な機能やリージョンの最新情報は、AWSのリージョン別サービス一覧で確認してください
- **料金**: 最大60%の削減は記事に記載された比較条件での値であり、実際の費用は利用量や構成によって異なります。コンピューティング料金に加え、ストレージなど適用される料金も料金ページで確認してください
- **スケール・トゥ・ゼロ**: アイドル時のスケール・トゥ・ゼロの適用条件や、利用するコレクション・機能の要件を公式ドキュメントで確認してください
- **運用**: クラスター管理は不要ですが、コレクションやアクセス制御などの設定・管理は引き続き必要です

## [Cloudformation] AWS CloudFormation makes resource coverage comprehensive with 206 new types

- **公開日**: 2026-11-25 (JST)
- **カテゴリ**: Cloudformation
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/cloudformation-coverage-expansion/

### 概要

AWS CloudFormationに、88サービスにまたがる206種類のリソースタイプが追加されました。Cloud Control APIにも新しいリソースタイプと224種類の読み取り専用リソースタイプが追加され、AWSリソースの構築・管理や既存リソースの確認をより幅広く行えるようになりました。

### 変更内容・新機能の詳細

追加されたリソースタイプには、Amazon SageMaker Hub、Amazon Bedrock AgentCore PolicyEngine、Amazon EC2 Snapshotなどが含まれます。これにより、従来CloudFormationで扱えなかったリソースをテンプレートやスタックで管理しやすくなり、インフラの標準化や安全な変更管理を進められます。今回追加されたリソースタイプはCloud Control APIでもサポートされます。また、Cloud Control APIでは99サービスにわたる224種類の読み取り専用リソースタイプが新たにサポートされ、既存リソースの検索・参照が容易になりました。AWSはリソースタイプの追加を効率化するため、AIを活用した社内フレームワークを導入したと説明しています。

### 影響範囲・利用シーン

- **対象ユーザー**: CloudFormationでAWSインフラを管理するクラウドエンジニア、プラットフォームチーム、運用チーム
- **利用シーン**: SageMaker HubやBedrock AgentCore PolicyEngineなどを含む環境のテンプレート化、スタック管理、既存リソースの確認
- **運用効果**: CloudFormationで管理できる範囲が広がり、手作業や個別の管理手段への依存を減らして、インフラ管理を標準化しやすくなります
- **対象範囲**: CloudFormationのリソースカバレッジは、対象サービスが利用可能なすべてのAWSリージョンで提供されます

### 技術的な注意点

- **リージョン制限**: リソースタイプの利用可否は基盤となるAWSサービスのリージョン提供状況に依存します。利用予定リージョンで対象サービスが利用可能か確認してください
- **読み取り専用タイプ**: Cloud Control APIで追加された224種類は読み取り専用です。これらのタイプを使った作成・更新・削除はできません
- **権限**: 実際のリソース操作や参照には、対象サービスおよびCloudFormation／Cloud Control APIに必要なIAM権限が必要です
- **コスト**: リソースタイプの追加自体による料金変更は記事で示されていません。作成・利用するAWSリソースには、各サービスの通常の料金が発生します

- https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/resource-type-scope.html

## [Connect] Amazon Connect Customer dashboards now support grouping historical metrics by time interval

- **公開日**: 2026-11-25 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-time-interval/

### 概要

Amazon Connect Customer の分析ダッシュボードで、トレーリングウィジェットの履歴メトリクスを時間間隔ごとにグループ化できるようになりました。15分から週単位まで表示粒度を切り替え、短期的な変化の特定や長期傾向の確認に利用できます。

### 変更内容・新機能の詳細

トレーリングウィジェットで、履歴メトリクスを15分、30分、1時間、日単位、週単位の間隔に分けて表示できます。たとえば平均処理時間（Average Handle Time）の上昇を調査する際、日単位の表示から15分単位に切り替えて発生した時間帯を絞り込み、その後、週単位でより広い傾向を確認できます。この機能は、Amazon Connect Customer が提供されているすべてのAWSリージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: コンタクトセンターのマネージャー、ワークフォース管理担当者、運用・分析担当者
- **利用シーン**: 平均処理時間などの履歴メトリクスについて、特定の時間帯の変化や週単位の傾向を調査
- **運用効果**: 表示粒度を切り替えて、パフォーマンス変化の発生時点を特定しやすくなります

### 技術的な注意点

- **対象ウィジェット**: 時間間隔によるグループ化はトレーリングウィジェットで利用できます
- **選択可能な間隔**: 15分、30分、1時間、日単位、週単位です
- **リージョン制限**: Amazon Connect Customer が提供されているすべてのAWSリージョンで利用できます
- **料金**: 追加料金の有無は記事に記載されていません

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-time-interval/
