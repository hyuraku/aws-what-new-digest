## [General] Amazon WorkSpaces Applications adds support for smart card redirection

- **公開日**: 2026-11-18 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-applications-smart-card-redirection/

### 概要

Amazon WorkSpaces Applicationsで、スマートカードのリダイレクトがシングルセッション／マルチセッションの両方で利用可能になりました。これにより、マルチセッション環境でもスマートカードによるサインインや、セッション内での認証・電子署名などを利用できます。

### 変更内容・新機能の詳細

スマートカードリダイレクトを有効にすると、ユーザーのローカルデバイスに接続されたスマートカードをストリーミングセッション内のアプリケーションから利用できます。用途には、セッション内での認証、デジタル署名、メールの暗号化などがあります。また、これまでシングルセッションフリートに限られていたActive Directory向けのスマートカードサインインが、マルチセッションフリートにも拡張されました。スマートカードサインインでは、ドメイン参加済みのストリーミングインスタンスへのログインにパスワードの代わりにスマートカードを使用します。管理者はスタックごとに、スマートカードサインインとスマートカードリダイレクトを個別に有効・無効にできます。

### 影響範囲・利用シーン

- **対象ユーザー**: CAC（Common Access Card）やPIV（Personal Identity Verification）カードを使用する公共機関、医療機関などの規制対象組織
- **利用シーン**: CAC利用者をシングルセッションからマルチセッションフリートへ移行しながら、スマートカードでのサインインを継続
- **運用効果**: ローカルデバイスのスマートカードをストリーミングセッション内で利用でき、認証、電子署名、メール暗号化などの業務を実行可能

### 技術的な注意点

- **リージョン**: WorkSpaces Applicationsを提供するすべてのAWS商用リージョンおよびAWS GovCloud（米国）リージョンで利用できます
- **前提条件**: 最新のWorkSpaces Applicationsエージェントを含むWindowsイメージを使用し、Windows版WorkSpaces Applicationsクライアントから接続してください
- **設定**: 各スタックのUser settingsで、Active Directory向けスマートカードサインインとスマートカードリダイレクトを個別に設定します
- **デフォルト動作**: 新規スタックでは両設定ともオフです。既存スタックでスマートカードリダイレクトを使用中の場合、その設定はオンのまま維持されます
- **サインイン要件**: スマートカードサインインには、ドメイン参加済みのストリーミングインスタンスが必要です
- **コスト**: 記事に追加料金の有無に関する記載はありません

## [Emr] Amazon EMR 8.2 is now available

- **公開日**: 2026-11-18 (JST)
- **カテゴリ**: Emr
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-emr-8.2/

### 概要

Amazon EMR 8.2 は、EMR on EC2、EMR on EKS、EMR Serverless を対象とする LTS リリースです。Spark 4.1.3 などへの更新に加え、Delta Lake の同時書き込み、Iceberg の増分更新、Lake Formation によるガバナンス強化が追加されました。

### 変更内容・新機能の詳細

主な変更は次のとおりです。
・主要コンポーネントの更新: Apache Spark 4.1.3、Apache Iceberg 1.11.0、Delta Lake 4.2.0 を採用しています。
・Delta Lake の同時書き込み: Amazon S3 の条件付き書き込みを利用し、複数クラスターから同じ Delta Lake テーブルへ同時に書き込めます。この方式では DynamoDB のログストアを必要としません。
・Iceberg マテリアライズドビュー: SQL でパイプラインの各段階をビューとして事前計算できます。更新時は、射影、内部結合、フィルター、SUM や COUNT などの集計を含む処理をソース全体に対して再実行するのではなく、変更分を増分処理します。
・Lake Formation の機能拡張: 細粒度アクセス制御（FGAC）の対象がマテリアライズドビュー、管理対象のユーザー定義関数（UDF）、追加の Iceberg 操作や Spark SQL 機能に広がりました。EMR Serverless では Lake Formation で管理された Glue UDF も実行できます。
・データリネージとユーザーID: OpenLineage ベースのリネージ情報を AWS Glue Data Catalog に記録できます。また、ジョブのステップやインタラクティブセッションから、実行ユーザーのIDを Lake Formation や Amazon S3 まで伝播し、元のユーザーとしてアクセス認可・監査できるようになりました。
・EMR on EC2: マルチプライマリークラスターで Spark Connect をサポートします。Secret Agent の改善により、高い同時実行負荷の下でユーザーのプロビジョニング遅延を最大97%削減します。
・EMR Serverless: Spark のスケーリングプロファイルとして、パフォーマンス優先、バランス、コスト優先を選択でき、エグゼキューターのスケール速度を調整できます。
・EMR on EKS: Spark Operator を、オープンソースの Spark Operator 2.5.0 を基にしたバージョン2へ更新しています。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon EMR 上で Spark、Delta Lake、Iceberg を利用するデータエンジニア、分析基盤チーム、データガバナンス・セキュリティ担当者
- **利用シーン**: 複数クラスターからの Delta Lake への並行書き込み、Iceberg を使った増分処理、Lake Formation によるユーザー単位のアクセス制御、データリネージの記録
- **運用効果**: 全件再計算の削減、ユーザーIDに基づく認可・監査、Serverless のスケーリング特性の調整により、性能・ガバナンス・コストの要件に合わせやすくなります。
- **対象環境**: EMR on EC2、EMR on EKS、EMR Serverless。記事によると、Amazon EMR が利用可能なすべての AWS リージョンで提供されています。

### 技術的な注意点

- **LTS**: LTS リリースとしてのサポート期間や適用条件は、利用前にリリースガイドで確認してください。
- **互換性**: Spark、Iceberg、Delta Lake のバージョン更新に伴い、既存のジョブ、コネクター、UDF、依存ライブラリとの互換性を検証してください。
- **Delta Lake 同時書き込み**: S3 条件付き書き込みを利用する新しい方式の動作要件を確認し、既存のログストア構成から移行する場合は、同時実行時の挙動と障害復旧をテストしてください。
- **Lake Formation とID伝播**: 利用するデプロイ方式やジョブ／セッションに応じて、Lake Formation、Glue Data Catalog、S3 の権限・信頼設定を確認してください。元のユーザーとして認可・監査するには、ID伝播の構成が必要です。
- **スケーリングとコスト**: EMR Serverless のプロファイルはスケール速度とコストのトレードオフに影響します。ワークロードに応じて選択し、実行時間やリソース消費を評価してください。料金は利用する EMR のデプロイ方式と消費リソースに応じて発生します。

## [Emr] Introducing the Apache Spark Optimization Agent for Amazon EMR Serverless

- **公開日**: 2026-11-18 (JST)
- **カテゴリ**: Emr
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/apache-spark-optimization-agent/

### 概要

Amazon EMR Serverlessに、完了済みのApache Sparkジョブを分析して、コストまたは性能の改善案を提示するSpark Optimization Agentが追加されました。推奨設定に加え、根拠となるテレメトリと平易な説明も確認できます。

### 変更内容・新機能の詳細

エージェントはジョブの設定、ログ、Sparkテレメトリをまとめて分析し、指定した目標（コストまたは性能）に沿った具体的な設定変更を提案します。分析対象は単一のジョブ実行、または既知の正常な実行（ベースライン）との比較から選択でき、実行間で何が変わったかを把握できます。

分析では、並列度不足、結合キーのデータ偏り（skew）、メモリ不足によるディスクへのスピル、アイドル状態のエグゼキューター、利用状況に対して過剰なキャパシティなど、実行時間やコストの要因を特定します。提案はAWS上の多数のSparkジョブでよく調整される設定を対象とし、コストと性能がトレードオフになる場合は、選択した目標を改善しながら、もう一方の指標の悪化を定められた範囲内に抑えます。

また、新しいSparkバージョンへのアップグレードやGravitonプロセッサの利用など、プラットフォーム面のベストプラクティスも評価します。各提案には、変更対象がインフラ、Spark設定、コード、データレイアウトのどれかが表示されます。EMR ServerlessコンソールまたはSageMaker Unified Studio MCP Serverから利用でき、決定論的な推奨エンジンが分析を行います。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon EMR ServerlessでApache Sparkジョブを開発・運用するデータエンジニア、分析チーム、プラットフォーム運用チーム
- **利用シーン**: 完了済みジョブのコスト・性能改善、ベースライン実行との差分調査、本番昇格前の設定チューニング
- **運用効果**: 改善候補とそのテレメトリ上の根拠を短時間で確認でき、原因調査や試行錯誤の負担を軽減
- **コスト**: エージェントの利用に追加料金はありません。提案を適用した場合の実行コストは、変更する設定や利用するリソースによって変わります

### 技術的な注意点

- **対応条件**: EMR Serverlessのリリースバージョン7.6以降が対象です
- **リージョン制限**: EMR Serverlessが利用可能なリージョンで提供されます。ただしAWS GovCloud (US)リージョンおよび中国リージョンは対象外です
- **分析対象**: 完了済みSparkジョブの設定、ログ、テレメトリを分析します。提案内容は適用前に確認し、対象ジョブで検証してください
- **認証と監査**: AWS IAMでアクセスを認証し、利用状況はAWS CloudTrailに記録されます。必要なIAM権限と監査要件を確認してください
- **推奨の性質**: エンジンは決定論的に推奨を算出しますが、提案がすべてのジョブやワークロードで最適とは限らないため、性能・コストを実測して判断してください

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/apache-spark-optimization-agent/
- https://docs.aws.amazon.com/emr/latest/EMR-Serverless-UserGuide/

## [Marketplace] AWS Transform now accelerates migration deals for Migration Acceleration Program (MAP) benefits

- **公開日**: 2026-11-18 (JST)
- **カテゴリ**: Marketplace
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/map-integration-with-aws-transform/

### 概要

AWS Transform に、AWS Migration Acceleration Program（MAP）の案件管理を一貫して進められるエージェント型ワークフローが追加されました。AWS Partner Centralとの連携により、案件の適格性確認から移行実行、インセンティブの支払いまでをAWS Transform内で管理できます。

### 変更内容・新機能の詳細

従来は、機会の発見、評価、案件の適格性確認、資金承認、契約、リソースへのタグ付け、インセンティブ支払いなどに複数のシステムを使い、手動で引き継ぐ必要がありました。新しいMAP体験では、パートナーがAWS Partner Centralアカウントを接続し、顧客を同じエンゲージメントに招待して、MAPのライフサイクルをAWS Transform内で管理できます。

移行対象の環境情報は、AWS Transformのエージェント型ディスカバリーツールで収集するか、RVToolsまたはAWS Marketplace掲載のAWS検証済みISVツールから取り込めます。AWS Transformはこの情報とAPN Customer Engagements（ACE）の機会情報を組み合わせ、パートナー起点の機会についてガイド付きフローで適格性を判定します。移行の進行に応じてMAPリソースタグを自動適用し、実際の使用量データに基づいてパートナーへの現金インセンティブや顧客クレジットを支給します。顧客とパートナーは、移行プロジェクトの状況をリアルタイムで共有できます。

### 影響範囲・利用シーン

- **対象ユーザー**: MAPを利用するAWSパートナー、移行プロジェクトを進める顧客
- **利用シーン**: MAP案件の適格性確認、承認・契約、移行計画と実行、リソースタグ付け、インセンティブ管理
- **運用効果**: 複数システム間の切り替えや手動引き継ぎを減らし、案件の審査・成立を迅速化できます
- **顧客への効果**: パートナーと移行プロジェクトの状況をリアルタイムで共有できます

### 技術的な注意点

- **利用条件**: パートナーはAWS Partner CentralアカウントをAWS Transformに接続する必要があります。開始方法はPartner Centralユーザーガイド（ログインが必要）を確認するか、Partner Development Managerに相談してください
- **データ取り込み**: 環境情報はAWS Transformのディスカバリーツールから収集するほか、RVToolsまたはAWS Marketplace掲載のAWS検証済みISVツールから取り込めます
- **適格性判定**: AWS Transformはディスカバリー情報とAPN Customer Engagements（ACE）の機会情報を組み合わせて、パートナー起点の機会を判定します
- **タグと支給**: MAPリソースタグは移行の進行に応じて自動適用され、現金インセンティブや顧客クレジットは実際の使用量データに基づいて支給されます
- **リージョン制限**: AWS Transformが提供されているすべてのAWSリージョンで利用可能です。利用前に対象リージョンでAWS Transformが提供されていることを確認してください
- **コスト**: 本記事にはAWS Transformの利用料金や追加料金の詳細は記載されていません。料金条件はAWS Transformおよび関連サービスの公式情報で確認してください

これまでは、トラフィックがない間も最低数の実行環境を維持する必要がありました。今回の変更により、関数の MinExecutionEnvironments を 0 に設定すると、一定期間アクティビティがない場合に Lambda が実行環境をゼロまで縮小し、リクエストを受け取ると必要な実行環境を再度プロビジョニングします。設定は Lambda コンソール、AWS CLI、AWS SDK、CloudFormation、AWS SAM、AWS CDK から行えます。LMI は Lambda の運用モデルを保ちながら EC2 インスタンス上で関数を実行する機能であり、専用のコンピューティング構成や EC2 の料金上の利点を活用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: Lambda Managed Instances で Event Functions を実行する開発者、プラットフォーム担当者、運用チーム
- **利用シーン**: 非同期処理、開発・テスト環境など、トラフィックが断続的または長時間発生しないワークロード
- **運用効果**: アイドル時に最低実行環境を維持する必要がなくなり、利用状況に応じたコスト効率の改善が期待できます

### 技術的な注意点

- **設定**: ゼロまでスケールさせるには、関数の MinExecutionEnvironments を 0 に設定します
- **対象範囲**: 対象は Lambda Managed Instances 上で実行する Event Functions です
- **スケール時の遅延**: ゼロから再度スケールする際には実行環境のプロビジョニングが必要になるため、遅延が許容されるかワークロード要件を確認してください
- **リージョン**: LMI が提供されているすべての AWS 商用リージョンで利用できます。LMI 自体の提供リージョンは公式情報で確認してください
- **コスト**: アイドル時の実行環境をなくすことでコスト削減が期待できますが、実際の料金は Lambda および LMI の料金体系、その他の利用リソースを含めて確認してください

Amazon API GatewayのREST APIで、JWTをゲートウェイ上で直接検証するネイティブJWTオーソライザーが利用可能になりました。外部のOpenID Connect（OIDC）／OAuth 2.0プロバイダーのトークン検証に、Lambdaオーソライザーを実装・運用する必要がなくなります。

### 変更内容・新機能の詳細

JWTオーソライザーでは、許可するトークン発行者（issuer）、発行者ごとの受け入れ対象Audience、許可する署名アルゴリズム、追加で検証するクレームを設定できます。リクエストごとにAPI Gatewayがトークンの署名、発行者、Audience、有効期限、および設定したクレームを検証します。1つのオーソライザーを複数のメソッドに適用しつつ、メソッドごとに異なるOAuthスコープを要求できます。機械間API、モバイル／Webアプリのバックエンド、複数のIDプロバイダーを受け入れるマルチテナントAPIなどに適しています。

### 影響範囲・利用シーン

- **対象ユーザー**: API Gateway REST APIを利用する開発者、認証基盤・API基盤の運用チーム
- **利用シーン**: Amazon Cognito以外のOIDC／OAuth 2.0プロバイダーが発行するJWTを使ったAPI認証
- **運用効果**: トークン検証用Lambdaの実装・デプロイ・監視が不要になり、認証設定をAPI Gatewayに集約できます
- **対応API**: Regional、エッジ最適化、プライベートのREST API
- **提供リージョン**: すべての商用AWSリージョンおよびAWS GovCloud（米国）リージョン

### 技術的な注意点

- **設定項目**: issuer、issuerごとのAudience、許可する署名アルゴリズム、追加クレームを適切に設定してください
- **スコープ**: オーソライザーを複数メソッドで共有し、各メソッドに異なる必要スコープを設定できます
- **認可設計**: JWTの検証に加え、アプリケーション固有の権限やリソース単位の認可が必要な場合は、別途設計してください
- **リージョン制限**: 発表内容では、商用AWSリージョンおよびAWS GovCloud（米国）リージョンで利用可能です
- **コスト**: 発表内容に追加料金の有無は記載されていません。最新のAPI Gateway料金を確認してください
