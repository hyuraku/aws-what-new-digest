## [Fargate] Amazon ECS Managed Daemons can now collect json-file logs from application containers on Amazon ECS Managed Instances

- **公開日**: 2026-11-05 (JST)
- **カテゴリ**: Fargate
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-ecs-managed-instances-json-file-log-driver/

### 概要

Amazon ECSのManaged InstancesでアプリケーションコンテナのログをDockerのjson-file形式で出力できるようになり、Managed Daemonsがそのログファイルをボリューム経由で安全に読み取れるようになりました。これにより、各種オブザーバビリティエージェントでローカルファイルをネイティブに収集・転送できます。

### 変更内容・新機能の詳細

今回の追加で、アプリケーションタスクのlogConfigurationにjson-fileログドライバを指定すると、コンテナログが各コンテナID名のディレクトリにDocker json-file形式のファイルとしてインスタンス上に保存されます。Managed Daemonはホストのパスを直接bindマウントしたりroot権限を要求したりすることなく、タスク定義で定義するlogDriverVolumeConfigurationを使ってログファイルを含むボリュームを宣言し、そのボリュームをdaemonコンテナにmountPointsでマウントしてファイルを読み取れます。結果として、各インスタンス上で稼働する1つのManaged Daemonタスクが、そのインスタンス上のjson-fileドライバを使う全アプリケーションコンテナのログを収集可能です。ログはコンテナが削除されるまで保持され、ログファイルから起点のコンテナIDへトレースできます。設定はAWS Management Console、AWS CLI、API、SDK、CloudFormationで可能で、追加料金は発生しません。

### 影響範囲・利用シーン

- **対象ユーザー**: コンテナ運用チーム、SRE、プラットフォーム/インフラエンジニア
- **利用シーンまたは効果**: 既存のファイルベース（json-file）対応のオブザーバビリティエージェント（例: Fluentd, Vector, Filebeat等）を利用して、ECS Managed Instances上の全コンテナログを中央集約／任意の送信先へ転送できる
- **運用効果**: ホストの直接マウントやroot権限不要でログ収集を統一でき、エージェント設定やコスト効率の改善、ログのコンテナ単位トレーサビリティ（コンテナIDでの紐づけ）が可能になる

### 技術的な注意点

- **IAM権限**: Daemonタスクの実行には通常のECSタスク実行ロールが必要。ログ転送先（CloudWatch、S3、外部API等）へのアクセスが必要な場合は該当サービスへの権限を付与してください。
- **リージョン制限**: 本機能はAmazon ECS Managed InstancesおよびManaged Daemonsが利用可能な商用リージョンで提供されています。お使いのリージョンで両機能が有効か事前に確認してください。
- **コスト**: 機能自体に追加料金はありません。ただし、収集したログを転送・保管する先（CloudWatch Logs、S3、サードパーティApm等）では通常の転送/保存コストが発生します。
- **互換性**: json-fileログドライバを使用するタスクに限定されます。awslogsやfirelensなど他のログドライバとは動作が異なります。
- **ログ保持/ローテーション**: コンテナのログはコンテナが削除されるまで保持されます。json-fileのローテーションやサイズ制限は各コンテナのlogOptions（例: max-size, max-file）で管理されるため、エージェント側でローテート済みファイルの扱いを考慮してください。
- **設定手順のポイント**: アプリケーションタスクでlogConfigurationに"json-file"を指定し、Daemonのタスク定義でvolumesにlogDriverVolumeConfigurationを設定、daemonコンテナにmountPointsでマウントする必要があります。
- **セキュリティ**: ボリュームはコンテナ間でファイル共有する形になるため、daemon側で読み取りのみとする等の権限制御を検討してください。

## [General] Amazon DocumentDB (with MongoDB compatibility) is now available in the Asia Pacific (Taipei) and Asia Pacific (New Zealand) Regions

- **公開日**: 2026-11-05 (JST)
- **カテゴリ**: General
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-documentdb-mongodb-compatibility-asia-pacific-taipei-new-zealand-regions/

### 概要

Amazon DocumentDB (MongoDB互換) がアジアパシフィック（台北）およびアジアパシフィック（ニュージーランド）リージョンで利用可能になりました。これにより両リージョンでマネージドなドキュメントDBを利用できます。

### 変更内容・新機能の詳細

Amazon DocumentDB はフルマネージドのネーティブJSONデータベースで、MongoDB 互換のAPIを提供し、インフラ管理なしで大規模なドキュメントワークロードを運用できます。今回のローンチで台北およびニュージーランドのリージョンでもクラスタ作成が可能になりました。主な技術的特徴は、ストレージ自動拡張（最大128 TiB）、最大15台までの低レイテンシ読み取りレプリカへのスケールアウト（数分で反映、アプリケーションにダウンタイムなし）、高スループット（数百万リクエスト/秒をサポート）、および Amazon CloudWatch、AWS CloudTrail、AWS Lambda、AWS Backup 等とのネイティブ統合です。クラスタは AWS マネジメントコンソール、AWS CLI、または AWS SDK から作成・管理できます。リージョン固有の料金や利用可能な付帯サービス（例えば KMS、AWS Backup のサポート状況）は確認してください。

### 影響範囲・利用シーン

- **対象ユーザー**: アプリ開発者、データベース管理者、SRE/運用チーム、MongoDB 互換アプリケーションをクラウド移行・運用したい組織
- **利用シーンまたは効果**: 既存のMongoDB互換アプリケーションを台北／ニュージーランド近傍で低レイテンシに移行してデータ主権やレイテンシ要件を満たす、または現地リージョンで新規にマネージドなドキュメントDBを構築する
- **運用効果**: インフラ管理負荷を低減し、ストレージ自動拡張や短時間でのリードスケールアウトによりキャパシティ計画が容易になる
- **可用性/レイテンシ効果**: リージョン内のアプリからのレイテンシ低下と、リージョン内冗長性により可用性向上が期待できる
- **コスト影響**: リージョン別の料金が適用されるため、導入前に該当リージョンの価格表でストレージ・インスタンス・I/O料金を確認する必要あり

### 技術的な注意点

- **IAM権限**: クラスタ作成・管理には DocumentDB や VPC、KMS（暗号化利用時）等に対する適切な IAM 権限が必要です
- **リージョン制限**: 台北／ニュージーランドの各リージョンで利用可能になりましたが、特定の付帯サービス（例: AWS Backup、跨リージョンレプリケーション等）のサポート状況はリージョン毎に異なる可能性があるため事前確認を推奨します
- **互換性**: DocumentDB は MongoDB 互換API を提供しますが、MongoDB のすべてのネイティブ機能（特定の管理コマンドや最新ドライバの機能など）が完全に一致するとは限りません。サポートされる MongoDB 互換バージョンやドキュメントを確認してください
- **スケーリング/容量**: ストレージは自動で最大128 TiBまで拡張、読み取りレプリカは最大15台まで追加可能です。運用時はレプリカ数とインスタンスタイプ、ネットワーク帯域のバランスを検討してください
- **ネットワーク/接続**: VPC、サブネット、セキュリティグループ、サブネットグループの設定が必要です。クラスタエンドポイント（クラスターエンドポイント／リーダーエンドポイント）を用いて接続する点はMongoDBと異なる場合があります
- **バックアップ/暗号化**: 暗号化（KMS）や自動バックアップ、スナップショットが利用可能ですが、リージョンでの AWS Backup 統合や KMS キーの可用性を確認してください
- **コスト**: インスタンス、ストレージ、I/O、データ転送等の料金が発生します。新リージョンの料金は既存リージョンと異なるため導入前に見積りを行ってください

## [RDS] Amazon RDS for Oracle now supports copying option groups during cross-Region snapshot copy

- **公開日**: 2026-11-05 (JST)
- **カテゴリ**: RDS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-rds-oracle-cross-region-snapshot-copy-option-group/

### 概要

Amazon RDS for Oracle で、スナップショットを別リージョンへコピーする際に、そのスナップショットに関連づくオプショングループを同時にコピーできるようになりました。CopyDBSnapshot API/CLI の CopyOptionGroup パラメータがクロスリージョンコピーに対応しています。

### 変更内容・新機能の詳細

RDS for Oracle はオプショングループを使って DB の追加機能（例: 特定オプションの有効化や設定）を管理します。オプショングループはリージョン固有のリソースでしたが、従来はスナップショットを別リージョンへコピーする場合、オプショングループを手動でターゲットリージョンに再作成する必要がありました。今回の更新により、CopyDBSnapshot API（および対応する CLI コマンド）の boolean パラメータ CopyOptionGroup を true に設定すると、スナップショットのクロスリージョンコピーと同一リクエスト内でオプショングループをターゲットリージョンへコピーできます。クロスアカウントコピーも同様にサポートされます。コピー後はターゲットリージョンにオプショングループが作成され、スナップショット復元時に同等のオプション設定を利用できるようになります。本機能は全ての商用リージョンおよび AWS GovCloud (US) で利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: RDS for Oracle を運用・バックアップ/復旧/レプリケーションするクラウドエンジニア、DBA、SRE
- **利用シーン**: 異なる AWS リージョンへスナップショットをコピーして DR（ディザスタリカバリ）やリージョン移行、リージョン間バックアップを行う場面で、オプション設定も含めて一括で移行したい場合
- **運用効果**: スナップショットコピーとオプショングループの再作成を別工程で行う必要がなくなり、手戻り・ヒューマンエラーを削減して復元や移行作業を効率化できる

### 技術的な注意点

- **IAM権限**: CopyDBSnapshot API を呼び出せる権限（rds:CopyDBSnapshot 等）と、ターゲットリージョンでオプショングループを作成できる権限を確認してください。クロスアカウントの場合は適切な共有/許可設定が必要です
- **リージョン制限**: 本機能は全商用リージョンおよび AWS GovCloud (US) で利用可能とされていますが、必ず使用するリージョンでのサポート状況を確認してください
- **コスト**: クロスリージョンのスナップショットコピーはデータ転送・スナップショット保存に対する料金が発生します。オプショングループ自体のコピーに別料金が発生するかは通常ありませんが、関連する復元や追加リソースの利用コストは考慮してください
- **互換性/制限**: オプショングループはエンジンとバージョンに依存する設定を含むため、ターゲットリージョンで同一のエンジンバージョンや該当オプションがサポートされていない場合はコピーや復元が失敗する可能性があります
- **リソース参照**: オプション設定が地域固有のリソース（例: 特定リージョンの S3 バケット、IAM ロール、KMS キーなど）を参照している場合、コピー後にそれらの参照先を手動で調整する必要があります
- **名前衝突**: ターゲットリージョンに同名のオプショングループが既に存在する場合の挙動（上書きされるか、新しい名前で作成されるか等）を事前に確認してください
- **CLI/SDK**: AWS CLI/SDK では CopyDBSnapshot 呼び出し時に CopyOptionGroup を true に設定します（例: aws rds copy-db-snapshot --source-db-snapshot-identifier ... --target-db-snapshot-identifier ... --copy-option-group）。API ドキュメントのパラメータ仕様を参照してください

- https://docs.aws.amazon.com/AmazonRDS/latest/APIReference/API_CopyDBSnapshot.html

## [Direct Connect] AWS announces AWS Interconnect - last mile preview with Equinix

- **公開日**: 2026-11-05 (JST)
- **カテゴリ**: Direct Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/interconnect-last-mile-preview-equinix/

### 概要

AWS Interconnect - last mile がEquinixとのプレビューで利用可能になりました。Equinixのデータセンターネットワークから数クリックでAWSへの管理されたプライベート接続を構築でき、MACsec暗号化と99.99%の可用性SLAを提供します。

### 変更内容・新機能の詳細

Interconnect - last mile は、Equinix Fabric One を介してEquinixのグローバルデータセンターネットワーク（282拠点）からAWSへ直接かつ管理された接続を迅速に確立するサービスです。AWSコンソールでAWSリージョン、帯域幅、Direct Connect gateway、Equinix Fabric OneのプロジェクトIDを選択するとAWS側でアクティベーションキーが発行され、Equinixポータルにキーを入力してセットアップを完了します（またはEquinix側から開始可能）。AWSとEquinixは事前に2箇所×4リンクの「クアッド冗長」構成を用意し、BGPピアリング、VLAN、ASNをあらかじめ設定してくれるため、クロスコネクト発注やルータの手作業設定が不要になります。各接続はMACsecでの暗号化がデフォルトで有効化され、99.99%の可用性SLAが付与されます。プレビュー期間中は、サンノゼ（San Jose）メトロ経由で米国西部（北カリフォルニア）リージョン、及びノーザンバージニア（Northern Virginia）メトロ経由で米国東部（北バージニア）リージョンへの1 Gbps接続を無料で発注可能です。GA後はコンソール上で1 Gbps〜100 Gbpsまでスケール可能になり、接続作成はコンソール/CLI/APIに対応します。パートナー向けにオープンAPIパッケージ（GitHub）も提供されています。

### 影響範囲・利用シーン

- **対象ユーザー**: ハイブリッドクラウド設計者、ネットワークエンジニア、SRE、クラウド導入を検討するエンタープライズ
- **利用シーンまたは効果**: 低遅延／高帯域のデータ転送、オンプレミスとAWS間の直接接続（バックアップ、レプリケーション、データ移行）、マルチリージョン接続の冗長化
- **運用効果**: クロスコネクト発注やオンプレ側ルータ設定の手間を削減し、導入時間を短縮。Quad冗長とBGP/VLAN/ASNの事前設定により高可用性運用が容易になる

### 技術的な注意点

- **IAM権限**: コンソール／CLI／APIでDirect Connect周りの操作を行うために必要なIAM権限（Direct Connect関連の作成・参照・削除権限）を事前に確認してください（環境に応じてポリシーを最小権限で設定することを推奨）。
- **リージョン制限**: プレビューは米国西部（北カリフォルニア）へのサンノゼ経路と米国東部（北バージニア）へのノーザンバージニア経路の1 Gbpsのみ。GA時点で他リージョンや帯域（最大100 Gbps）に拡張されますが、リージョン対応状況を公式情報で確認してください。
- **コスト**: プレビュー中のAWS側1 Gbpsは無料ですが、Equinixのポート料金やデータセンター側のクロスコネクト／ポート使用料、パートナー側の課金が別途発生する可能性があります。GA時はAWS Direct Connectの通常料金が適用されます。
- **セキュリティ**: トランスポート層はAWS⇔Equinixエッジ間でMACsecにより暗号化されますが、MACsecがカバーする範囲（最後尾のオンプレISEや内部ネットワーク）を設計段階で確認してください。BGPとASNの事前設定によりルート設計の確認が必要です。
- **オンプレ前提条件**: Equinixファシリティまでの物理的接続（お客様設備→Equinixポート）やEquinix Fabric OneのプロジェクトIDが必要です。オンプレ側での経路設計や接続先冗長性の検討は必須です。
- **運用/監視**: BGPセッションやVLAN、帯域利用の監視、SLA逸脱時のエスカレーションフローを事前に整備してください。
- **API/自動化**: コンソールに加えCLI/APIでの作成が可能。パートナー向けのオープンAPIパッケージ（GitHub）を利用してプロビジョニングの自動化ができます。

## [Connect] Amazon Connect Customer now shows associated cases in contact records 

- **公開日**: 2026-11-05 (JST)
- **カテゴリ**: Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-cases-contact-records/

### 概要

Amazon Connect のコンタクトレコードに、関連する Cases のケースIDおよび参照番号が表示されるようになりました。スーパーバイザーやアナリストがどの顧客課題（例：返金、請求トラブル）がコンタクト量を生んでいるかを即座に把握できます。

### 変更内容・新機能の詳細

Connect の Contact Details ページ上で、該当のインタラクションに紐づく Cases のケースIDと参照番号が表示されるようになりました。これにより、スーパーバイザーは個々の通話やチャットの詳細画面を開くだけで関連ケースを確認でき、個別にケース検索する手間が省けます。また、同情報は DescribeContact API とコンタクトイベントストリームでも取得可能になり、アナリストはケースごとのインタラクション数を計測・集計できます。Cases は複数のやり取りやチームにまたがる顧客問題（返金要求、請求異議など）を追跡する機能で、今回の連携によりオペレーションの可視化と分析が容易になります。対応リージョンは US East (N. Virginia)、US West (Oregon)、Canada (Central)、Europe (Frankfurt)、Europe (London)、Asia Pacific (Seoul)、Asia Pacific (Singapore)、Asia Pacific (Sydney)、Asia Pacific (Tokyo)、Africa (Cape Town) です。導入方法や詳細は Cases の製品ページとドキュメントを参照してください。

- **対象ユーザー**: コンタクトセンターのスーパーバイザー、品質管理者、データアナリスト、SRE/運用チーム

- **API/イベント**: DescribeContact API でケースIDを取得可能。コンタクトイベントストリームで継続的に集計する設計にする場合はストリーム有効化とイベント処理の実装が必要です
- **リージョン制限**: 本機能は発表時点で指定のリージョン（N. Virginia, Oregon, Canada Central, Frankfurt, London, Seoul, Singapore, Sydney, Tokyo, Cape Town）のみ対応です
- **コスト**: Cases の利用やコンタクトイベントのストリーミング（Kinesis、S3 など）には追加料金が発生する可能性があります。利用量に応じた請求影響を事前に確認してください
- **有効化・設定**: Connect インスタンスで Cases を有効化している必要があります。既存の Connect 環境では追加設定や権限調整が必要になる場合があります
- **データの遡及性**: 過去のコンタクトに対するケース紐付けが自動的にバックフィルされるかは環境依存のため、導入前にドキュメントで確認してください
