## [Aiml] Ornith-1.0-9B and Ornith-1.0-35B models now available on Amazon SageMaker JumpStart

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Aiml
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/ornith-1-0-9b-ornith-1-0-35b-on-sagemaker-jumpstart/

### 概要

DeepReinforce AIのオープンソース・エージェント型コーディングモデル「Ornith-1.0-9B」と「Ornith-1.0-35B」が、Amazon SageMaker JumpStartで利用可能になりました。SageMaker JumpStartからモデルを選び、AWS環境へデプロイしてコーディング用途に活用できます。

### 変更内容・新機能の詳細

両モデルはMITライセンスで公開されたOrnith 1.0ファミリーのモデルです。強化学習を用いて、コーディングタスクの進め方を組み立てる「スキャフォールド」と、そこから得られる解決策の生成を共同で最適化することで、より良い探索経路とコード生成を目指します。記事では、Terminal-Bench 2.1、SWE-Bench、NL2Repo、OpenClawなどのベンチマークで、同程度の規模のオープンソースモデルの中で高い性能を達成したと説明されています。

Ornith-1.0-9Bは90億パラメータのDenseモデルで、Qwen 3.5 9Bをベースに追加学習されています。256Kトークンのコンテキストウィンドウを備え、単一GPUでの効率的な実行を想定したモデルです。Ornith-1.0-35Bは350億パラメータのMixture-of-Experts（MoE）モデルで、トークンごとに一部のパラメータのみを活性化する構成により、性能と計算効率の両立を狙います。記事によると、35Bモデルも24GBのコンシューマー向けGPUでのデプロイが可能です。

利用開始時はSageMakerコンソールのJumpStartモデルカタログからモデルを選択するか、SageMaker Python SDKを利用してデプロイします。

### 影響範囲・利用シーン

- **対象ユーザー**: エージェント型コーディング機能を開発・運用する開発者、AI/MLエンジニア、チーム
- **利用シーン**: コード生成、リポジトリを対象とした修正・タスク実行などのコーディングエージェントの構築
- **選択の目安**: 単一GPUでの軽量な実行を重視する場合は9B、より高い性能とMoEによる効率を重視する場合は35Bが候補
- **導入効果**: JumpStartのモデルカタログやSageMaker Python SDKからデプロイでき、モデル導入の手間を軽減できます

### 技術的な注意点

- **ライセンス**: 記事ではMITライセンスとされています。利用・再配布の際は、モデル配布元のライセンス条件も確認してください
- **GPU要件**: 記事の単一GPU・24GB GPUに関する説明はモデルの特性として示されたものです。SageMakerでの実際のインスタンスタイプや必要メモリは、推論設定、入力長、同時実行数などに応じて検証してください
- **コンテキスト長**: 9Bモデルは256Kトークンのコンテキストウィンドウに対応しますが、長い入力はメモリ使用量や応答時間、推論コストに影響します
- **コスト**: SageMakerへのデプロイでは、選択したインスタンスの稼働時間やストレージなどに応じて料金が発生します。利用前に料金と停止・削除方法を確認してください
- **リージョン制限**: 記事に利用可能リージョンの一覧は記載されていません。JumpStartのカタログで対象リージョンの提供状況を確認してください
- **性能評価**: ベンチマーク性能は記事に記載された評価結果であり、実際の業務データやタスクでの性能を事前に評価してください

## [Sagemaker Jumpstart] DeepSeek-V4-Pro, DeepSeek-V4-Flash, and DeepSeek-V4.1-Flash models now available on Amazon SageMaker JumpStart

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Sagemaker Jumpstart
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/01/deepseek-v4-pro-v4-flash-v4.1-flash-on-sagemaker-jumpstart/

### 概要

DeepSeek-V4-Pro、DeepSeek-V4-Flash、DeepSeek-V4.1-FlashがAmazon SageMaker JumpStartで利用可能になりました。用途やコスト要件に応じて選べる、MITライセンスのオープンウェイト言語モデルを、SageMakerからデプロイできます。

### 変更内容・新機能の詳細

3モデルはいずれもMixture-of-Experts（MoE）方式を採用し、各トークンの処理時には総パラメータの一部だけを活性化することで、モデル規模に対する計算効率の向上を目指しています。
・DeepSeek-V4-Pro: 総パラメータ数1.6兆、トークン当たり活性化パラメータ数490億。100万トークンのコンテキストウィンドウを備え、複雑な推論、高品質な文章生成、長文書の分析など、最大限のモデル能力が必要な用途向けです。
・DeepSeek-V4-Flash: 総パラメータ数2,840億、トークン当たり活性化パラメータ数130億。V4-Proと同じ100万トークンのコンテキストウィンドウを持ち、低レイテンシや計算コストを重視する本番用途に適しています。
・DeepSeek-V4.1-Flash: 5,520億パラメータの基盤を持つモデルで、Causal Encoder-Decoder（CED）アーキテクチャを採用しています。prefill時は80億、decode時は160億パラメータを活性化し、100万トークンのコンテキストと最大38万4,000トークンの出力に対応します。Compressed Sparse Attention 2（CSA2）とFP4 KVキャッシュにより、記事によるとグローバルKVキャッシュのフットプリントをV4-Flashの約4分の1に抑えます。エージェント、コーディング、画像を扱うタスクなどを想定しています。
SageMaker JumpStartのモデルカタログ、またはSageMaker Python SDKから、対象モデルをAWSアカウントにデプロイできます。

### 影響範囲・利用シーン

- **対象ユーザー**: SageMakerで生成AIアプリケーションを構築・運用する開発者、MLエンジニア、データサイエンティスト
- **利用シーン**: 長文書の分析や複雑な推論にはV4-Pro、コストやレイテンシを重視する処理にはV4-Flash、エージェント・コーディング・画像関連の処理にはV4.1-Flashを選択
- **運用効果**: JumpStartからモデルを選択してデプロイでき、モデルの用途に応じた基盤モデルの比較・導入を進めやすくなります
- **コストへの影響**: 活性化パラメータ数やKVキャッシュ量の削減は計算効率の改善につながる可能性がありますが、実際の料金はデプロイ構成や利用量に依存します

### 技術的な注意点

- **ライセンス**: 記事では3モデルがMITライセンスで公開されているとされています。利用前にモデルごとのライセンス条件も確認してください
- **デプロイ要件**: モデル規模が大きいため、必要なインスタンスタイプ、メモリ、SageMakerのクォータをデプロイ前に確認してください
- **コンテキストと出力**: 記事記載の上限はコンテキストウィンドウが最大100万トークン、V4.1-Flashの最大出力が38万4,000トークンです。実際の設定・利用可能上限はデプロイ方法や構成を確認してください
- **リージョン制限**: 記事に利用可能リージョンの記載はありません。JumpStartカタログで対象リージョンの提供状況を確認してください
- **コスト**: SageMakerのデプロイ先リソースなどに応じて料金が発生します。活性化パラメータ数やKVキャッシュ削減だけで実際の料金が決まるわけではありません

## [Shield] AWS Network Security Manager now available in AWS European Sovereign Cloud and Additional New Regions

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Shield
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/network-security-mgr-eu-sovereign-cloud/

### 概要

AWS Network Security Manager（NSM）がAWS European Sovereign Cloudおよび追加の31リージョンで一般提供されました。対象アカウントやリソースに対するAWS WAFの保護設定を自動化し、セキュリティポリシーの一元管理と設定ドリフトへの対処を支援します。

### 変更内容・新機能の詳細

NSMは、インターネット向けのAWSリソース（例: Application Load Balancer）にAWS WAFのセキュリティ保護を継続的に適用するネットワークセキュリティ管理サービスです。セキュリティチームはポリシーを一元管理でき、設定のずれ（ドリフト）を自動検知して修正を適用できます。これにより、複数のアカウントやリソースに対するWAFルールやAWS Shield Advancedの保護管理を効率化し、手作業による運用負荷を抑えながら、対象範囲で一貫したセキュリティ態勢を維持できます。AWS European Sovereign CloudではAWS WAFおよびAWS Shieldをサポートします。

新たに利用可能になったリージョンは、米国東部（オハイオ）、米国西部（北カリフォルニア、オレゴン）、アジアパシフィック（ムンバイ、香港、台北、ソウル、大阪、ハイデラバード、シンガポール、シドニー、メルボルン、マレーシア、ニュージーランド、タイ、ジョホール、東京）、カナダ（中部、カルガリー）、メキシコ（中部）、欧州（フランクフルト、チューリッヒ、ストックホルム、アイルランド、ミラノ、スペイン、ロンドン、パリ）、イスラエル（テルアビブ）、南米（サンパウロ）、アフリカ（ケープタウン）です。

### 影響範囲・利用シーン

- **対象ユーザー**: 複数のAWSアカウントやインターネット向けリソースのWAF・Shield保護を管理するセキュリティチーム、クラウド運用チーム
- **利用シーン**: ALBなどの対象リソースにWAF保護を展開し、ポリシーを一元管理する場合
- **運用効果**: 保護設定の自動適用、設定ドリフトの検知・修正により、手動運用の負荷を軽減し、リソース間のセキュリティ設定の一貫性を高められます
- **利用可能リージョン**: 記事に記載された追加31リージョンおよびAWS European Sovereign Cloud。最新の提供状況とサービスごとの対応範囲はリージョン表で確認してください

### 技術的な注意点

- **対応サービス**: AWS European Sovereign CloudではAWS WAFおよびAWS Shieldをサポートします。Shield Advancedなどの機能・保護対象は、利用するリージョンとサービスの対応状況を確認してください
- **対象リソース**: 自動適用の対象や条件はNSMのポリシー設定に依存します。導入前に対象アカウント、リソース、WAFルールの適用範囲を確認してください
- **コスト**: NSM、AWS WAF、AWS Shield Advancedなどの料金条件をそれぞれ料金ページで確認してください。European Sovereign Cloudには専用の料金ページがあります
- **リージョン制限**: 新規提供リージョンでも、関連するAWSサービスや機能の対応状況が異なる場合があります。リージョン表で個別に確認してください

## [Cloud Wan] AWS Cloud WAN now supports Flow Logs

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Cloud Wan
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-cloud-wan-flow-logs/

### 概要

AWS Cloud WAN に Flow Logs 機能が追加され、グローバルネットワーク内の IP トラフィックを一元的に記録・分析できるようになりました。コアネットワーク全体、個別のコアネットワークエッジ、またはアタッチメント単位で有効化できます。

### 変更内容・新機能の詳細

Flow Logs は、VPC 間、リージョン間、および AWS Direct Connect、AWS Site-to-Site VPN、SD-WAN 経由で接続されたオンプレミスネットワークとの間のトラフィックを記録します。レコードには送信元・宛先 IP アドレス、ポート、プロトコル、トラフィック量、パケット損失カウンターに加え、セグメント、リージョン、サービス挿入ホップ、アタッチメントなどの Cloud WAN メタデータが含まれます。ログは Amazon CloudWatch Logs、Amazon S3、または Amazon Data Firehose に配信でき、接続や性能のトラブルシューティング、過去の帯域利用傾向に基づく容量計画、異常なトラフィックの検知、セキュリティ・コンプライアンス目的の記録に活用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWS Cloud WAN のコアネットワーク所有者、ネットワーク管理者、SRE／運用チーム、セキュリティ・コンプライアンス担当者
- **利用シーン**: VPC、リージョン、オンプレミスネットワーク間のトラフィック確認と、接続・性能問題の調査
- **運用効果**: 複数の VPC、アカウント、リージョンから個別にログを集める手間を減らし、コアネットワーク全体のトラフィックを一元的に把握できます
- **分析用途**: 帯域利用の履歴分析、異常な通信パターンの調査、監査・コンプライアンス用の記録に利用できます

### 技術的な注意点

- **有効化範囲**: コアネットワーク全体、単一のコアネットワークエッジ、または個別のアタッチメントを指定できます
- **配信先**: Amazon CloudWatch Logs、Amazon S3、Amazon Data Firehose に配信できます
- **リージョン制限**: AWS Cloud WAN が利用可能なすべての AWS リージョンで利用できます
- **コスト**: Cloud WAN による Flow Logs の追加料金はありません。ログの配信先サービスには通常の料金が適用されます
- **設定方法**: AWS Management Console、AWS CLI、または API から設定できます

### 参考情報

- https://docs.aws.amazon.com/network-manager/latest/cloudwan/cloudwan-flow-logs.html

## [EKS] Amazon EKS Provisioned Control Plane now offers a 24 GB etcd database on 4XL and 8XL tiers

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: EKS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eks-provisioned-control-plane-larger-etcd-database/

### 概要

Amazon EKS の Provisioned Control Plane で、4XL／8XL ティアの etcd データベース容量が16 GBから24 GBに拡大しました。EKS 1.34以降の対象クラスターでは、より多くの Kubernetes オブジェクトを保持でき、オブジェクトの作成・更新が多い大規模ワークロードの拡張余地が増えます。

### 変更内容・新機能の詳細

etcd は Kubernetes クラスターの状態や各種オブジェクトを保存するキーバリューストアです。容量が上限に達すると、クラスターへのオブジェクト追加や変更ができなくなる可能性があります。今回の変更により、4XL／8XL ティアでは容量が50%増え、Pod、Job、Event、カスタムリソースなどをより多く管理できます。EKS 1.34以降で Provisioned Control Plane の4XLまたは8XLティアを選択すると利用できます。対象バージョンで既に4XL／8XLを利用しているクラスターには自動適用され、追加作業は不要です。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon EKS Provisioned Control Plane の4XLまたは8XLティアを利用するユーザー
- **利用シーン**: 大規模なAI/MLの学習・推論、バッチ処理、CI/CDなど、多数のKubernetesオブジェクトを作成・更新するワークロード
- **運用効果**: etcd容量の余裕が増え、クラスターの拡大時に容量上限へ達するリスクを抑えられます

### 技術的な注意点

- **バージョン要件**: クラスターはEKS 1.34以降である必要があります
- **ティア要件**: 24 GBの容量はProvisioned Control Planeの4XL／8XLティアが対象です
- **既存クラスター**: 条件を満たす既存クラスターには自動適用され、操作は不要です
- **リージョン**: Provisioned Control Planeが提供されているすべての商用AWSリージョンで利用可能です
- **コスト**: 記事では追加料金の有無は明示されていません。ティアの料金や変更に伴う費用はAmazon EKSの料金情報を確認してください

## [Cognito] Amazon Cognito now supports user pool session management

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Cognito
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-session-management/

### 概要

Amazon Cognito ユーザープールで、ユーザーのSSOセッションとトークンセッションを確認・失効できるセッション管理機能が利用可能になりました。アプリクライアントごとのSSOセッション再利用時間や、ユーザーごとのアクティブなトークンセッション数も設定できます。

### 変更内容・新機能の詳細

SSOセッションは、ユーザーがマネージドログインでサインインした際に作成され、再認証せずに他のアプリクライアントへアクセスするために使われます。トークンセッションは、ユーザーがアプリクライアントにサインインしてトークンを取得した際に作成されます。新機能では、ユーザーの全デバイス・全アプリクライアントにまたがる有効な両セッションを一覧でき、セッション種別、アプリクライアントID、デバイス種別、最終アクティビティの時刻と場所、初回サインイン時刻などを確認できます。個別セッションの失効、関連するセッションを含む失効、またはユーザーの全セッションを終了するグローバルサインアウトが可能です。また、従来固定だった1時間のSSOセッション再利用時間をアプリクライアントごとに設定できるほか、ユーザーごとのアクティブなトークンセッション数に上限を設定できます。AWS Management Console、API、AWS CLI、AWS SDKから利用でき、設定はAWS CloudFormationでも行えます。

- **運用効果**: 不審なセッションを個別または一括で失効し、ユーザーのサインイン状態をより細かく制御できます
- **認証体験**: アプリクライアントごとにSSOセッションの再認証タイミングを調整し、利便性とセキュリティのバランスを設定できます

### 技術的な注意点

- **対応プラン**: EssentialsまたはPlusのユーザープールで利用できます
- **リージョン**: Amazon Cognitoが提供されているすべてのAWSリージョンで利用可能です
- **セッションの区別**: SSOセッションとトークンセッションは別のセッション種別です。要件に応じて一覧・失効の対象を設計してください
- **失効範囲**: 個別セッション、関連セッションを含む失効、ユーザーの全セッションを終了するグローバルサインアウトを使い分けてください
- **設定と権限**: コンソール、API、CLI、SDK、CloudFormationで管理できます。実行主体に必要なIAM権限を確認してください
- **セッション数の上限**: ユーザーごとのアクティブなトークンセッション数を設定できます。具体的な上限値や制約は公式ドキュメントで確認してください
- **コスト**: 発表内容では追加料金の有無は明示されていません。最新の料金情報を確認してください

## [Lambda] AWS Lambda MicroVMs now supports the x86 CPU architecture

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Lambda
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-microvms-x86-architecture/

### 概要

AWS Lambda MicroVMsでx86 CPUアーキテクチャが選択可能になりました。既存のx86アプリケーションや依存ソフトウェアを再コンパイル・移植せずに実行できます。

### 変更内容・新機能の詳細

MicroVMイメージをDockerfileから作成する際に、CPUアーキテクチャとしてx86またはArm（AWS Graviton）を選べるようになりました。選択したアーキテクチャのイメージからMicroVMを起動し、ユーザーやジョブごとに分離された実行環境を提供できます。Lambda MicroVMsは、VMレベルの分離、短時間での起動・再開、実行状態の保持を備えたサーバーレスコンピュート機能です。AIコーディングアシスタント、CI/CDランナー、対話型開発環境、脆弱性スキャナーなどで、ユーザーコードやAI生成コードを実行する用途に利用できます。Arm向けのワークロードでは、引き続きデフォルトのAWS Gravitonを選択できます。AWS Management Console、CloudFormation、AWS CDK、またはAgent Toolkit for AWSを利用して構築できます。

### 影響範囲・利用シーン

- **対象ユーザー**: x86向けの既存アプリケーションやツール、ライブラリをMicroVM上で実行したい開発者・運用チーム
- **利用シーン**: AIコーディングアシスタント、CI/CDランナー、対話型開発環境、脆弱性スキャナーなどで、ユーザーやジョブごとに隔離した実行環境を提供
- **運用効果**: x86ワークロードの再コンパイルやArmへの移植をせずにMicroVMへ移行でき、既存の依存関係を活用しやすくなります

### 技術的な注意点

- **アーキテクチャ選択**: MicroVMイメージ作成時にx86またはArm（AWS Graviton）を指定し、対応するイメージからMicroVMを起動してください
- **リージョン制限**: Lambda MicroVMsの提供リージョンのうち、アジアパシフィック（香港、マレーシア、タイ）および欧州（スペイン）ではx86を利用できません
- **コスト**: 料金はLambda MicroVMsの料金ページで確認してください。記事では既存料金からの変更について明記されていません

## [EKS] Amazon EKS Auto Mode now supports security groups for Pods

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: EKS
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eks-auto-mode-security-groups-for-pods/

### 概要

Amazon EKS Auto Modeで、Podごとに専用のAmazon EC2セキュリティグループを適用できるようになりました。同一ノード上のワークロードをネットワークレベルで分離し、VPC内のデータベースなどへのアクセスを既存のセキュリティグループルールで制御できます。

### 変更内容・新機能の詳細

SecurityGroupPolicyリソースを使って、ポリシーの対象となるPodに適用するセキュリティグループを指定します。これにより、アプリケーションごとにノードプールを分けずに、同じノード上のPodへ異なるセキュリティグループを割り当てられます。ポリシーに一致しないPodは、引き続きノードのセキュリティグループを使用します。PodからAmazon RDSやAmazon ElastiCacheなどへ接続する際も、VPCのセキュリティグループを使った既存のアクセス制御を適用できます。

### 影響範囲・利用シーン

- **対象ユーザー**: Amazon EKS Auto Modeでワークロードを運用するクラウドエンジニア、ネットワーク・セキュリティ担当者
- **利用シーン**: 同一クラスター内のアプリケーションPodごとに通信許可を分け、RDSやElastiCacheなどへの接続をセキュリティグループで制御する
- **運用効果**: アプリケーションごとにノードプールを分割せずにPod単位のネットワーク分離を実現できる

### 技術的な注意点

- **利用条件**: Kubernetes 1.36以降のEKS Auto Modeクラスターが必要です
- **リージョン制限**: EKS Auto Modeが利用可能なすべてのAWSリージョンで利用できます
- **ポリシー適用**: SecurityGroupPolicyで対象Podと適用するセキュリティグループを指定します。ポリシーに一致しないPodはノードのセキュリティグループを使用します
- **コスト**: EKS Auto Modeの機能に含まれ、追加料金はありません

### 参考情報

- https://docs.aws.amazon.com/eks/latest/userguide/security-groups-for-pods.html
- https://aws.amazon.com/eks/eks-auto-mode/

## [Tools And Sdks] AWS Emulator is now available for building and testing AWS applications locally

- **公開日**: 2026-11-12 (JST)
- **カテゴリ**: Tools And Sdks
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/

### 概要

AWS Emulatorが公開され、AWSアプリケーションを開発者のローカル環境やCI環境で、AWSアカウントやデプロイなしに構築・テストできるようになりました。AWS SDKやAWS CLIからの対応操作に対して、AWSに近い応答やエラーを高速に返します。

### 変更内容・新機能の詳細

AWS Emulatorは、既存のAWS SDKおよびAWS CLIの呼び出し先をエミュレーターに向けて、AWSリソースの作成やアプリケーションのテストをローカルで行うツールです。エミュレーターが提供する認証情報を使用してリクエストに署名します。対応済みの操作では、有効なリクエストにAWSと同等の結果を返し、無効なリクエストには同等のエラーを返すことを目指しています。未対応の操作はHTTP 501（Not Implemented）を返します。

リソースの状態はエミュレーターの実行中、メモリ上に保持されます。起動した各インスタンスは個別のポート、キー、状態を持つため、コーディングエージェント、テストスイート、CIジョブ間でリソースが共有されません。たとえば、DynamoDBテーブルを作成してオフラインでアプリケーションを検証し、AWSへデプロイする前に問題を修正できます。

サービス定義はAWSが公開するAPIモデルを基に生成されますが、すべての操作が初めから実装済みとは限りません。AWSで新しいサービスやAPIが追加された場合も、動作はリリースごとに実装・検証されます。AWSとの応答の一致度はFidelity Reportで確認できます。

### 影響範囲・利用シーン

- **対象ユーザー**: AWSアプリケーションの開発者、テスト担当者、コーディングエージェントの利用者、CI/CDを管理するチーム
- **利用シーン**: SDKやCLIを使ったアプリケーションのローカル開発、AWSリソースに依存する自動テスト、CI環境での統合テスト
- **運用効果**: AWSへのデプロイやAWSアカウントを用意せずに、対応するAWS APIの動作確認やエラー検証を素早く実施できます
- **並行実行**: インスタンスごとにポート、キー、メモリ上の状態が分離されるため、複数のエージェントやテストジョブを独立して実行できます
- **コスト**: AWS Emulator自体の追加サービス料金はありません。AWSへデプロイした後は、利用するAWSリソースの料金が発生します

### 技術的な注意点

- **API対応範囲**: 対応していない操作は501 Not Implementedを返します。利用予定のサービスやAPIが実装済みか、Fidelity Reportで事前に確認してください
- **データの永続性**: リソース状態はメモリ上に保持され、エミュレーターを停止すると失われます。永続化が必要なデータの保管先としては使用できません
- **認証情報**: AWSの認証情報ではなく、エミュレーターが提供する認証情報を使用してリクエストに署名します
- **接続先設定**: SDKやCLIのリクエストをエミュレーターに送るよう設定する必要があります。誤って実AWSへ接続しないよう、テスト環境のエンドポイント設定を確認してください
- **リージョン**: AWSリージョンに依存せず利用できます
- **ライセンス**: ソースコードはCC0 1.0 Universalのパブリックドメイン提供です

### 参考情報

- https://aws.amazon.com/about-aws/whats-new/2026/11/aws-emulator-now-available/
