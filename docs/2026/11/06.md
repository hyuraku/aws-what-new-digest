## [Security Hub] AWS Security Hub now provides an SBOM inventory for your compute resources

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Security Hub
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-sbom-inventory/

### 概要

AWS Security Hubは、Amazon Inspectorが生成するSBOM（Software Bill of Materials）を元に、組織全体のコンピュートリソース上にインストールされたソフトウェアパッケージの継続的なインベントリを提供します。追加設定なしで自動的に集約され、UIおよびAPIで検索/絞り込み/確認が可能です。

### 変更内容・新機能の詳細

Security HubはAmazon Inspectorが生成するSBOMを収集してインベントリを構築します。対象はAmazon EC2インスタンス、Amazon ECRのコンテナイメージ、AWS Lambda関数のSBOMで、追加の有効化作業は不要（Amazon Inspectorが有効なアカウント/リージョンで自動的に反映）。SBOMページでは各パッケージの名称、バージョン、種別（libraryやapplication等）と、そのパッケージがインストールされているリソース数を一覧表示します。パッケージ属性、アカウント、リージョンでのフィルタ／グループ化が可能です。リソース詳細画面の「Installed software」タブではそのリソースに含まれる全パッケージを確認でき、トリアージ時に機能や重要度を判断できます。インベントリはSecurity Hub API経由でもクエリ可能です。SBOMインベントリ機能はSecurity Hub Essentialsに含まれ、追加コストなしで利用できます。対応リージョンはSecurity Hubが利用可能なすべてのリージョンで、Amazon Inspectorが有効な領域で自動的にデータが反映されます。なお、SBOMの具体的なフォーマット（例: CycloneDX/SPDX等）はAmazon Inspector側の仕様に従うため、必要に応じてInspectorのドキュメントを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: セキュリティチーム、SRE/運用、資産管理チーム、サプライチェーン/コンプライアンス担当者
- **利用シーン**: 組織全体のソフトウェア資産管理（SBOMベースの可視化）、脆弱性トリアージ、ライセンスコンプライアンス確認、サプライチェーンリスク評価
- **運用効果**: 手動収集を減らし迅速な影響範囲の特定が可能に。脆弱性対応やインシデント対応時の原因追跡が高速化される
- **スケーラビリティ**: 複数アカウント／リージョンのリソースを一元的に集約して検索・集計できるため大規模環境でも管理負荷が低減

### 技術的な注意点

- **前提条件**: Amazon Inspectorが対象アカウント／リージョンで有効であること（InspectorのSBOM生成がデータ源）
- **IAM権限**: Security Hubの読み取りアクセスおよび必要に応じてInspectorの出力参照権限が必要。APIでのクエリ時は適切なSecurity Hub権限を付与
- **リージョン制限**: Security Hubが利用可能な全リージョンで提供。ただしInspectorが未対応のリージョンではデータが得られない
- **コスト**: SBOMインベントリ自体はSecurity Hub Essentialsに含まれ追加料金なし。ただしAmazon Inspectorの使用（SBOM生成やそのほかのInspector機能）には別途料金が発生する可能性あり
- **データ鮮度**: 「継続的に更新」と記載あり。更新タイミングや遅延はInspectorのスキャン頻度と実行状況に依存
- **SBOMフォーマット**: SBOMの具体フォーマットはAmazon Inspectorの仕様に従うため、必要に応じてInspectorドキュメントで確認すること
- **API/自動化**: Security Hub API経由でインベントリを取得・統合可能。SIEMや資産管理ツールとの連携が容易

## [Direct Connect] AWS Interconnect - last mile announces new metro in Northern Virginia, USA

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Direct Connect
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/interconnect-last-mile-northern-virginia/

### 概要

AWSは北バージニア（Northern Virginia）にAWS Interconnect - last mileの新しいメトロを追加しました。これにより、データセンターやブランチ、コロケーション施設からAWSへの管理された専用のラストマイル接続を簡単に確立できます。

### 変更内容・新機能の詳細

AWS Interconnect - last mileは、クロスコネクトの手配やルーター設定を必要としないマネージドなプライベート接続サービスです。北バージニアのメトロは物理的に分離された2拠点にまたがって標準でプロビジョニングされ、4本の冗長リンクを備えており、デフォルトで最大限の耐障害性を提供します。リンク間トラフィックはMACsecでデフォルト暗号化されます。可用性はDirect Connectポートまでを対象に99.99%のSLAで保護されます。Lumenの顧客は大陸米国内で一般提供（GA）として北バージニア経由の接続を発注でき、中国リージョンを除く全てのパブリックAWSリージョンおよびAWS Local Zonesへ到達可能です。さらに、MegaportおよびEquinix経由の接続は北バージニアでプレビュー提供されています。接続の作成はAWS Management Console、AWS CLI、またはAWS Interconnect APIで行えます。

### 影響範囲・利用シーン

- **対象ユーザー**: データセンター運用者、ネットワークエンジニア、SRE、コロケーション利用者
- **利用シーン**: オンプレミスやコロケーションからAWSへ冗長かつ管理された専用回線で接続したい場合（ハイブリッドクラウド、低遅延アクセス、規制対応ワークロード）
- **運用効果**: クロスコネクトの個別手配やエッジルーターの複雑な設定を省略でき、デフォルトで高可用性・暗号化された接続を迅速に導入可能

### 技術的な注意点

- **IAM権限**: AWS Interconnect API／Direct Connect関連の作成・表示権限（例: directconnect:CreateConnection 等）が必要です。事前にIAMロール／ポリシーを確認してください。
- **リージョン制限**: 北バージニアメトロからは中国リージョン（cn-）への到達は対象外です。Local Zonesおよびその他のパブリックリージョンへは到達可能です。
- **コスト**: AWS側の料金に加え、Lumen／Megaport／Equinix等パートナーのサービス料金（月額料金、初期費用、ローカル回線費用等）が発生する可能性があります。データ転送料金は通常のAWSのデータ転送課金が適用されます。
- **接続プロバイダ/プレビュー**: Lumenは大陸米国でGA提供。MegaportとEquinixは北バージニアでプレビュー提供のため、利用条件や機能が限定される場合があります。
- **可用性/SLA**: 表示されている99.99%のSLAはDirect Connectポートまでを対象とします。オンプレ／パートナー側の設備やローカル回線はSLA対象外となる場合があるため、運用設計時に確認してください。
- **暗号化**: MACsecはリンク層の暗号化を提供しますが、アプリケーションレイヤーのエンドツーエンド暗号化（例: TLS）とは別物です。要件に応じて併用を検討してください。
- **設定方法**: 接続作成はAWS Management Console、AWS CLI、AWS Interconnect APIで可能です。パートナーとの契約・ローカル施設側での手続き（設備アクセス、ケーブル配線、ラックスペース等）は別途必要です。

### 参考情報

## [Bedrock] Announcing Web Answer on Amazon Bedrock AgentCore 

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Bedrock
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/web-answer-amazon-bedrock/

### 概要

Amazon Bedrock AgentCore上のマネージド機能「Web Answer」がGAになりました。単一のツールコールでウェブ検索→抽出→要約・根拠付き引用まで行い、最新のウェブ情報に基づく回答を返します。

### 変更内容・新機能の詳細

Web Answerは、ユーザーが自然言語で質問を送ると、内部で複数のウェブ検索を並列実行して必要な証拠を集め、自動的に合成（synthesis）した根拠付きの回答（出典の引用を含む）を単一のAPIコールで返すマネージドツールです。AgentCoreのツールとしてAgentにアタッチ可能で、AgentCore Gatewayのターゲットとして設定し、MCP経由でIAM認証された呼び出しが可能です。検索対象の範囲はドメインのinclude/denyリストや公開日フィルタで制御でき、データは外部へ流出しない（zero data egress）設計です。2026-11-05時点で一般提供（GA）され、US East (N. Virginia) リージョン（us-east-1）で利用可能。課金はツールコール毎の従量課金です。なお、本機能は今年6月に発表された「Web Search on Amazon Bedrock AgentCore」を拡張し、「ウェブコンテンツの検出」から「完成した引用付き回答の生成」へと機能を上げたものです。

### 影響範囲・利用シーン

- **対象ユーザー**: エージェント開発者、ナレッジチーム、SRE/運用チーム、プロダクト担当者
- **利用シーン**: 最新のウェブ情報でFAQ応答、顧客サポートの自動応答、調査レポート作成、チャットボットの事実検証（fact-grounding）
- **運用効果**: 検索→取得→合成→引用の独自実装が不要になり開発工数削減、最新情報に基づく回答提供でユーザー信頼性向上
- **導入効果**: エージェント単体で根拠付き回答を即時に返せるため、外部検索パイプラインの運用負担と誤回答リスクを低減
- **コスト影響**: ツールコールごとの従量課金が発生するため、頻繁な自動問い合わせがあるワークロードではコスト試算が必要

### 技術的な注意点

- **IAM権限**: AgentCore GatewayとMCP呼び出しに必要なIAM権限（Bedrock/AgentCoreへの呼び出し権限）を設定する必要があります
- **リージョン制限**: 現時点で利用可能リージョンは US East (N. Virginia) (us-east-1)。他リージョンは未対応のため事前確認が必要です
- **コスト**: per-tool call の従量課金。高頻度呼び出しではコストが増大するため利用想定に応じた見積り推奨
- **データ保護**: 記事では "zero data egress" を謳っていますが、入力クエリや応答のログ要件は自社ポリシーに合わせて設計してください
- **前提/構成**: AgentCore Gatewayにターゲットとしてアタッチし、MCP経由で呼び出す構成が必要。AgentCore/Bedrockの利用設定が前提です
- **出力の取り扱い**: 自動で引用を付与しますが、引用元の信頼性や最新性は運用で検証する必要があります（誤情報や不完全な証拠のリスクへ注意）

## [Elastic Load Balancing] AWS Network Load Balancer is now available in the AWS Phoenix Local Zone

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Elastic Load Balancing
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/10/aws-nlb-available-phx-local-zone/

### 概要

Phoenixローカルゾーン (us-west-2-phx-2a) に AWS Network Load Balancer (NLB) が利用可能になりました。これにより、同ゾーン内で動作するターゲットに対してローカルにルーティングされ、レイテンシ低減と一貫性の向上が期待できます。

### 変更内容・新機能の詳細

従来は、Phoenix Local Zone 内で稼働するターゲットに対してロードバランサーを配置する場合、親リージョン（us-west-2）のアベイラビリティゾーン内に NLB を作成する必要があり、トラフィックが親リージョンへ出入りすることで遅延が発生していました。今回の対応により、us-west-2-phx-2a に直接 NLB を作成できるようになり、接続ルーティングがローカルゾーン内に留まるため、レイテンシが低くかつ安定します。特にリアルタイムゲーム、メディアストリーミング、金融トランザクションなどレイテンシに敏感なワークロードで有効です。Local Zones は compute/storage/database 等のサービスを大都市圏近傍に配置する仕組みで、Local Zone の有効化は AWS Global View コンソールの Local Zones タブ、または ModifyAvailabilityZoneGroup API から行えます。NLB の作成時は Local Zone のサブネットを指定してデプロイしてください。

### 影響範囲・利用シーン

- **対象ユーザー**: Phoenix（フェニックス）地域で低レイテンシを求めるアプリケーション運用者、ゲーム・メディア・金融系アプリ開発者
- **利用シーン**: リアルタイムゲームサーバ、ライブストリーミング配信、低遅延が要求される取引システムなど、エンドユーザーがフェニックス都市圏に集中するサービスの負荷分散
- **運用効果**: トラフィックが親リージョンへ往復しなくなることでレイテンシとそのばらつきが低減され、ユーザー体験の向上と障害切り分けの容易化が期待できる

### 技術的な注意点

- **リージョン制限**: 対象は Phoenix Local Zone (us-west-2-phx-2a) のみ。Local Zone を有効化していない場合は事前に有効化が必要
- **有効化方法**: AWS Global View コンソールの Local Zones タブ、または ModifyAvailabilityZoneGroup API を使用して Local Zone を有効にしてください
- **サブネット選択**: NLB 作成時に Local Zone のサブネットを指定する必要があります。ターゲット（EC2/ENI 等）が同ゾーンに配置されていることを確認してください
- **IAM権限**: NLB の作成・サブネット参照・関連リソース操作に必要な IAM 権限（ElasticLoadBalancing と EC2 関連の権限）を付与してください
- **互換性**: 既存の構成でロードバランサーが親リージョンにある場合、Local Zone に移行するとトラフィック経路が変わるため接続やセッション管理の挙動を検証してください
- **コスト**: Local Zone を利用することでデータ転送経路が変わるため、データ転送コストや Local Zone 固有の料金への影響がある可能性があります。移行前に料金表を確認してください

## [DynamoDB] Amazon DynamoDB now supports bulk put items

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: DynamoDB
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-dynamodb-now-supports-bulk-put-items/

### 概要

Amazon DynamoDBがS3上のファイルを既存テーブルへ直接書き込む「bulk put items」機能をGAで提供開始しました。カスタムパイプラインやテーブル容量管理なしで大規模データの取り込みを低コストで実行できます。

### 変更内容・新機能の詳細

bulk put itemsはS3の入力ファイルを指定するだけで、DynamoDB側が既存テーブルへデータを一括で書き込むフルマネージド機能です。各アイテムに対して個別の条件式（condition expression）を指定でき、挿入のみ許可する（insert-only）やバージョンを用いたガード付き書き込みといった整合性ルールを適用できます。パフォーマンス/遅延要件に応じてStandard層（大半のワークロード向け）とAccelerated層（時間的制約が厳しいワークロード向け）の2つのティアがあり、DynamoDBが読み取り・書き込みのスループット管理・取り込み処理を担います。代表的なユースケースは、日次リフレッシュ、大規模カタログの更新、バックフィル、データ移行などです。Standard層は全ての商用リージョンとAWS GovCloud(US)で利用可能で、Accelerated層はリージョン制限があります。詳細な入力ファイルフォーマット、エラー/リトライ動作、料金やリージョン可用性は公式ブログと開発者ガイドを参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: データエンジニア、バッチETL開発者、アプリケーション開発者、SRE/運用チーム
- **利用シーン**: S3に蓄積された外部システム出力を既存のDynamoDBテーブルへ取り込む（日次更新、カタログ一括更新、バックフィル、マイグレーション）
- **運用効果**: カスタムインジェストパイプラインやプロビジョニング済みキャパシティ管理を削減でき、既存ワークロードへの影響を最小化しつつ大量データを効率的に書き込める
- **コスト影響**: Standardは一般的にコスト効率が高いが、Acceleratedは低レイテンシを提供するため追加料金が発生する可能性がある（S3読み取りやKMS、データ転送もコスト要因）
- **リージョン**: Standardは全商用リージョン＋AWS GovCloud(US)で利用可能、Acceleratedは限定リージョンでの提供（公式のリージョン可用性を確認すること）

### 技術的な注意点

- **IAM権限**: S3オブジェクト読み取り（s3:GetObject 等）とDynamoDBへの書き込み権限が必要。KMSで暗号化されたオブジェクトを読み取る場合はKMSのDecrypt権限も必要
- **リージョン制限**: Standardは全商用リージョンとAWS GovCloud(US)で利用可能。Acceleratedは利用可能リージョンが限定されているため事前にリージョン対応状況を確認してください
- **入力フォーマット**: 本文では形式を明示していません。サポートされるファイル形式やスキーマ（JSON/CSV等）、パーティショニング要件は開発者ガイドで確認してください
- **一貫性と条件式**: 各アイテムに対するcondition expressionを利用可能で、insert-onlyやバージョンガードが設定できるが、複雑なトランザクション整合性は既存のDynamoDBトランザクションAPIとは挙動が異なる可能性があるため検証が必要です
- **エラー処理/再試行**: 大量取り込み処理では部分失敗やスキーマ不整合が発生する可能性があるため、失敗レポートやリトライ戦略、デッドレター処理の設計を行ってください
- **スロットリング/スループット**: DynamoDB側でスループット制御が行われるが、Accelerated層の使用や取り込みウィンドウに応じて料金とスループットパフォーマンスが変わるため事前に性能試験を実施してください
- **コスト**: Accelerated層は追加料金の可能性あり。S3のGET、データ転送、KMS利用料は別途発生します。料金ページを確認してください

## [Cognito] Amazon Cognito announces 99.99% Service Level Agreement for the Plus feature plan

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Cognito
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cognito-sla-update/

### 概要

2026年11月1日付で、Amazon Cognitoのユーザープール（Plus機能プラン）が月間稼働率（Monthly Uptime Percentage）99.99%のSLA対象になりました。既にPlusのユーザープールは自動的に新しいサービス保証に含まれ、Essentials/Liteは従来の99.9%のままです。

### 変更内容・新機能の詳細

変更点は主にSLAの強化とPlusプランの利用促進です。具体的には、Plusプランのユーザープールに対して月間稼働率99.99%を保証（従来は99.9%）するサービスコミットメントが適用されます。Plusプランへの移行はAWS Management Console、AWS CLI、またはAWS SDKから行えます。Plusには脅威防御機能（アダプティブ認証、漏洩/侵害済み認証情報の検出、脅威およびユーザーアクティビティのログとエクスポート機能）が含まれ、これらの機能を有効化することで認証関連の可用性・セキュリティが向上します。SLAの詳細や免責事項はAmazon Cognito SLAドキュメントを参照してください。なお、本SLAの適用対象は「ユーザープール」に限定され、IDプールなど他のCognito機能は対象外の可能性があります。

### 影響範囲・利用シーン

- **対象ユーザー**: アプリケーション開発者、SRE/運用チーム、エンタープライズ認証を必要とするプロダクトオーナー
- **利用シーン**: ミッションクリティカルなユーザー認証／セッション管理（大規模Web/モバイルサービス、SaaS、エンタープライズSSO、ゲーム認証など）
- **運用効果**: 月間許容ダウンタイムが大幅に短縮（99.9% → 約43.2分/月から99.99% → 約4.32分/月に削減）、可用性要件の厳しいサービスでSLAを満たしやすくなる
- **切り替え方法**: Console／CLI／SDKでユーザープールをPlusプランに変更（既にPlusのプールは自動適用）
- **コスト影響**: Plusプランは追加料金または料金体系の変更が発生する可能性があるため、導入前に料金ページを確認してください

### 技術的な注意点

- **IAM権限**: ユーザープール設定を変更する権限（Amazon Cognito IDP関連のAPI呼び出し権限、例: UpdateUserPool 相当の権限）が必要です
- **リージョン制限**: 記載なし。利用可能リージョンやリージョンごとの機能差は公式ドキュメントで確認してください
- **コスト**: Plus機能プランは追加料金の対象となる可能性があります。請求影響を事前に評価してください（トライアルや見積もりを推奨）

- **運用上の注意**: プラン切替後は接続・認証フロー、各種クライアント設定、ログ出力先（CloudWatch Logs/S3/Kinesisなど）の設定が意図通り動作するかステージングで検証してください
- **脅威防御の有効化**: アダプティブ認証や侵害認証情報検出などは追加設定やログ出力の構成が必要です。ログの保存先と保持ポリシー、監視アラートを整備してください

## [IAM] IAM Roles Anywhere now supports automatic certificate revocation checking

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: IAM
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/iam-roles-anywhere-cdp/

### 概要

IAM Roles Anywhereが証明書のCRL配布ポイント（CDP）を使った自動失効チェックをサポートしました。これによりCA側の失効情報と同期した検証が自動化され、運用負荷とセキュリティリスクが低減します。

### 変更内容・新機能の詳細

新機能では、トラストアンカーで自動失効チェックを有効にすると、IAM Roles Anywhereが認証に使用される証明書内に埋め込まれたCDP（CRL Distribution Point）URLを読み取り、該当するCRLをダウンロードして定期的に更新します。ダウンロードしたCRLに基づき、CRLに登録された失効済み証明書の使用による認証要求を拒否します。従来はCRLを手動でIAM Roles Anywhereに取り込み、CAがCRLを更新するたびに再インポートする必要がありましたが、本機能によりCRLの自動取得と定期更新が可能になり、手動運用を削減します。AWS Private Certificate Authority（AWS Private CA）や社内PKIとも併用可能ですが、証明書に含まれるCDP URLが外部からアクセス可能であり、配布ポイント要件を満たしている必要があります。トラストアンカーへの適用や設定はIAM Roles Anywhereコンソール、AWS SDK、AWS CLIで行えます。本機能は追加料金なしで全ての商用リージョンで利用可能です。

### 影響範囲・利用シーン

- **対象ユーザー**: クラウドエンジニア、セキュリティチーム、SRE/運用担当者
- **利用シーン**: オンプレPKIやAWS Private CAで発行した証明書を使ってIAMロールを取得するワークロードの認証における失効確認
- **運用効果**: CRLの手動インポート作業が不要になり運用コスト削減、CA側の失効情報と同期したリアルタイム性向上によるセキュリティ強化

### 技術的な注意点

- **IAM権限**: トラストアンカーの設定変更・有効化を行うためのIAM権限（IAM Roles Anywhereのトラストアンカー編集権限）を事前に付与してください
- **リージョン制限**: 発表によれば全商用リージョンで利用可能です。特殊リージョン（AWS GovCloud/中国リージョン等）は個別確認してください
- **コスト**: 機能自体に追加料金はありませんが、CRLのダウンロード時のネットワーク転送（アウトバウンド）やS3等への保存に伴う通常のデータ転送/ストレージ費用が発生する可能性があります
- **証明書要件**: 証明書に埋め込まれたCDP URLが公開かつIAM Roles Anywhereから到達可能であること（HTTP/HTTPS等）、配布ポイント要件を満たしていることが必要です
- **ネットワーク/アクセス**: CDPホストがファイアウォールやVPC内にあり外部から到達できない場合は自動取得できません。必要に応じてCDPの公開設定やプロキシ／アウトバウンドアクセスを検討してください
- **互換性と振る舞い**: AWS Private CAおよび外部PKIで利用可能。CRLの取得頻度やキャッシュ期間などの具体的な挙動はドキュメントを参照して確認してください
- **運用注意**: CRL配布の遅延や一時的な到達不能により失効反映にタイムラグが生じる可能性があります。重要証明書の失効運用ポリシーを見直してください

## [Opensearch Service] Amazon OpenSearch Service optimized engine now supports agent traces

- **公開日**: 2026-11-06 (JST)
- **カテゴリ**: Opensearch Service
- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-service-support-traces

### 概要

Amazon OpenSearch Service の最適化エンジンがエージェントトレース（OpenTelemetry を含む）をサポートしました。トレースとログを同じストアで扱えるようになり、リクエスト/セッションの開始から終了までの追跡や、該当箇所のログ参照がツール切替なしで可能になります。

### 変更内容・新機能の詳細

最適化エンジンは OpenTelemetry トレースやエージェントトレースを受け入れ、データを object、nested、flat object フィールドにマッピングします。マルチバリュー配列をサポートし、span events、span links、prompts、tool calls などのネストされた構造は保持されるため、取り込み時にフラット化することなくフィールド単位でのクエリが可能です。ホットティアのデータに対してはドキュメント ID による update/delete/upsert をサポートするため、遅延到着データや誤ったデータをその場で修正でき、ダッシュボードやアラートは正しいデータに基づいて動作します。OpenSearch UI では Discover Traces、Application Performance Monitoring（APM）、Service Map、Agent Traces and Sessions ビュー等で解析・可視化できます。対応は OpenSearch 3.7 上で提供され、追加料金は不要です。対応リージョンは US East (N. Virginia)、US East (Ohio)、US West (Oregon)、Canada (Central)、Asia Pacific (Mumbai)、Asia Pacific (Singapore)、Asia Pacific (Sydney)、Asia Pacific (Tokyo)、Europe (Frankfurt)、Europe (Ireland)、Europe (London)、Europe (Spain) です。データ送信は OpenTelemetry 互換のエクスポーターや Amazon OpenSearch Ingestion 等を利用します。

### 影響範囲・利用シーン

- **対象ユーザー**: トレーシング/ログを使うアプリケーション開発者、SRE、APM チーム
- **利用シーン**: トレースとログを横断した障害調査、遅延原因の特定、エンドツーエンドのトランザクション追跡
- **運用効果**: トレースとログを同一ストアで関連付け可能になり、切替・相互参照の手間が減り、障害対応時間（MTTR）の短縮が期待される
- **データ管理**: ホットティアでの update/delete/upsert により遅延到着データや誤データの修正が容易になり、ダッシュボード/アラートの精度向上に寄与
- **可観測性の向上**: ネスト構造を保持したままフィールドレベルのクエリが可能なため、複雑なスパン構造やイベント情報を高精度に検索・集計できる

### 技術的な注意点

- **OpenSearch バージョン**: 本機能は OpenSearch 3.7 で利用可能です（ドメインが該当バージョンであることを確認してください）
- **リージョン制限**: 現時点でサポートされるリージョンは記事記載の一覧のみ（US East (N. Virginia), US East (Ohio), US West (Oregon), Canada (Central), AP-NorthIndia (Mumbai), AP-Southeast1 (Singapore), AP-Southeast2 (Sydney), AP-Northeast1 (Tokyo), EU-Central1 (Frankfurt), EU-West1 (Ireland), EU-West2 (London), EU-South1 (Spain)）です。非対応リージョンでは利用不可です
- **インジェスト要件**: update/delete/upsert を利用するには適切なドキュメント ID を付与してデータを送る必要があります。Amazon OpenSearch Ingestion など既存のパイプラインを使用可能
- **マッピング**: エンジン側で object/nested/flat object にマッピングされますが、既存インデックスとの互換性や検索要件に応じて明示的なマッピング設計（nested 型の理解や nested クエリの利用）を検討してください
- **クエリ設計**: ネスト構造を活かすには nested クエリ／nested aggregations を使用する必要があります。フラット化前提のクエリは誤った結果を返す可能性があります
- **コスト**: 機能自体に追加料金はありませんが、インデータ量、インデックス/ストレージ、検索・更新リクエストに対する通常の料金が発生します。hot-tier での頻繁な updates が発生すると書き込み/ストレージコストやパフォーマンスに影響します
- **互換性**: OpenTelemetry のバージョンやエクスポーター設定により、送られてくるフィールド構成が変わるため、受信側でのフィールド整合性（traceId、spanId、timestamp 等）を確認してください
- **セキュリティ/IAM**: データ送信・管理に必要な IAM ポリシーやドメインアクセスポリシーを事前に設定してください（インデックスの書き込み・更新・削除権限など）

- **リンク**: https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-fsx-for-lustre-intelligent-tiering-16x-higher-metadata-iops

### 概要

Amazon FSx for LustreのIntelligent-Tieringストレージクラスで、メタデータI/O性能が最大で192,000 IOPSに向上しました（従来の最大12,000 IOPSから16倍）。新規のIntelligent-Tieringファイルシステムで利用可能です。

### 変更内容・新機能の詳細

今回の更新により、FSx for LustreのIntelligent-Tieringストレージクラスを利用する新規ファイルシステムで、ファイル/ディレクトリの作成・列挙・読み取り・削除などに影響するメタデータI/O性能が最大192,000 IOPSまでスケールします。Intelligent-Tieringはクラウド上で最も低コストかつフルエラスティックなLustreストレージを提供し、ホットデータとコールドデータが混在するワークロード向けに最適化されています（ただしSSDレベルの一貫した性能を必要とするケース向けではありません）。この性能向上により、メタデータ集約型の機械学習研究や高性能コンピューティング（HPC）ワークロードでのレスポンス向上と処理時間短縮、およびストレージコストの最適化が期待できます。なお、本改善はIntelligent-Tieringが利用可能な全リージョンの新規ファイルシステムに対して提供されます。詳細はAmazon FSx for Lustre User Guideのファイルシステムメタデータ性能の項目を参照してください。

### 影響範囲・利用シーン

- **対象ユーザー**: 機械学習研究者、HPCエンジニア、メタデータ集約型のアプリケーション開発者およびSRE/運用チーム
- **利用シーンまたは効果**: 大量のファイル作成・列挙・削除を行うワークロード（例: 大規模MLデータ前処理、科学計算のチェックポイント管理、メタデータ集約の分析処理）で処理時間短縮とスループット向上が得られる
- **運用効果**: メタデータ操作のボトルネック緩和によりジョブのスループット向上、結果の短時間取得、ジョブ待ち時間の低減が可能
- **導入制約**: 本改善はIntelligent-Tieringストレージクラスを選択した“新規”ファイルシステムに適用されるため、既存ファイルシステムは再作成または別途移行が必要な場合がある

### 技術的な注意点

- **IAM権限**: ファイルシステム作成・変更に必要なIAM権限（例: fsx:CreateFileSystem、fsx:DeleteFileSystem、fsx:DescribeFileSystems等）を事前に確認してください

- **コスト**: Intelligent-Tieringは低コスト設計ですが、ストレージクラスおよび使用量により料金が決まります。高いメタデータIOPSが直接追加課金になるかは構成によるため、料金表と見積もりを事前に確認してください

- **性能特性**: Intelligent-Tieringはホット/コールド混在用途向けであり、SSDレベルの一貫した低レイテンシ性能を要求するワークロード（例: 極めて低遅延が必須のリアルタイム処理）には他のストレージクラスを検討してください
